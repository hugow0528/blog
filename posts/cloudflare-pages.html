Cloudflare Pages: Deploy Static Sites in Seconds

2026-06-25 9 min read New

If you've ever built a static website — a blog, documentation, a portfolio — you know the pain of finding hosting. Traditional web hosts are overkill. VPS servers need maintenance. Cloudflare Pages solves all of this by connecting directly to your Git repository and deploying automatically every time you push code.

Best part? It's free for personal projects, includes automatic HTTPS, and serves your site from Cloudflare's global edge network of 300+ cities. Let's build and deploy a static site from scratch.

What Are Cloudflare Pages?

Cloudflare Pages is a hosting platform for static websites. You point it at a Git repository, and it:

  • BUILDs your site automatically from your build tool (Hugo, Jekyll, Next.js, Astro, or plain HTML)
  • DEPLOYS every commit as a preview URL you can share for review
  • PUBLISHES your production branch to a custom domain with free HTTPS
  • CACHES content at the edge for lightning-fast global load times

It's the Cloudflare equivalent of Vercel or Netlify — but with the added benefit of running on the same edge network that powers Cloudflare's CDN, WAF, and DDoS protection.

Prerequisites

  • A free Cloudflare account (sign up at dash.cloudflare.com)
  • A GitHub or GitLab account with a repository containing your site
  • Your domain's DNS managed by Cloudflare (for custom domains)

Create a Simple Static Site

Let's create a minimal static site so we have something to deploy. Make a project directory:

$ mkdir my-site && cd my-site

# Create the HTML file
cat > index.html << 'EOF'
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Static Site</title>
    <style>
        body { font-family: system-ui; max-width: 800px; margin: 2rem auto; padding: 0 1rem; }
        h1 { color: #2563eb; }
        .card { background: #f8fafc; padding: 1.5rem; border-radius: 8px; margin: 1rem 0; }
    </style>
</head>
<body>
    <h1>Hello from Cloudflare Pages!</h1>
    <p>This site is deployed on Cloudflare's global edge network.</p>
    <div class="card">
        <h2>Why Pages?</h2>
        <ul>
            <li>Free forever for personal use</li>
            <li>Automatic HTTPS</li>
            <li>Git-based deployments</li>
            <li>Edge caching in 300+ cities</li>
        </ul>
    </div>
</body>
</html>
EOF

# Initialize Git and push
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/my-site.git
git push -u origin main

Connect to Cloudflare Pages

Now deploy it through the Cloudflare dashboard:

  1. Log in to dash.cloudflare.com
  2. Navigate to Workers & Pages → Pages → Create a project
  3. Choose Connect to Git and select your GitHub/GitLab account
  4. Select the repository you just pushed
  5. Configure the build settings:

For plain HTML:

  • Framework preset: None (or "Other")
  • Build command: leave empty (or echo "No build needed")
  • Build output directory: . (root) or your output folder

For Hugo (static site generator):

  • Framework preset: Hugo
  • Build command: hugo
  • Build output directory: public

For Next.js:

  • Framework preset: Next.js
  • Build command: npm run build
  • Build output directory: .next

Click Save and Deploy. Cloudflare clones your repo, runs the build command, and deploys. Your first deployment gets a URL like your-project.pages.dev.

Preview Deployments

Every branch or pull request gets its own unique URL. This means you can:

# Create a feature branch
git checkout -b feature/new-page

# Create a new page
cat > about.html << 'EOF'
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>About</title>
    <style>body{font-family:system-ui;max-width:600px;margin:2rem auto}</style>
</head>
<body>
    <h1>About This Site</h1>
    <p>Built with static HTML and deployed on Cloudflare Pages.</p>
    <a href="index.html">← Back home</a>
</body>
</html>
EOF

git add .
git commit -m "Add about page"
git push -u origin feature/new-page

Cloudflare automatically detects the new branch and deploys a preview. You'll get a URL like feature-new-page-your-project.pages.dev to share with collaborators for review — without touching production.

Custom Domains and Redirects

To use your own domain (like blog.hugow.dev):

  1. Go to your Pages project → Custom Domains
  2. Enter your domain name (e.g., blog.hugow.dev)
  3. Cloudflare automatically creates the DNS records
  4. Free HTTPS certificate provisions automatically

You can also add redirects and rewrites using a _redirects file in your build output directory:

# _redirects file (placed in build output root)
# Syntax: from to [options]

# Simple redirect
/old-page /new-page 301

# Redirect with proxy
/api/* https://api.example.com/:splat 200

# Wildcard redirect
/blog/* /posts/:splat 302

Environment Variables

Pages supports environment variables for builds and runtime. Set them in the dashboard under Settings → Environment Variables, or use the CLI:

# Install the Cloudflare CLI
npm install -g wrangler

# Set an environment variable
wrangler pages secret put API_KEY

# It prompts for the value, stores it encrypted

# Use in your code (Node.js / Workers runtime)
const apiKey = process.env.API_KEY

Common use cases: API keys for build-time data fetching, analytics IDs, feature flags, and different settings per environment (production vs preview).

Using the Cloudflare CLI (wrangler)

You can deploy entirely from the command line:

# Install wrangler
npm install -g wrangler

# Log in
wrangler login

# Deploy from local directory
wrangler pages deploy ./my-site --project-name=my-site

# Deploy with a branch name (triggers preview)
wrangler pages deploy ./my-site \
    --project-name=my-site \
    --branch=feature/new-layout

# List deployments
wrangler pages deployment list --project-name=my-site

Pages vs R2 vs Workers

Cloudflare offers multiple hosting options. Here's when to use which:

Feature Pages R2 Workers
Best for Static sites, blogs File storage, backups Serverless APIs
Free tier 100K builds/mo 10 GB storage 100K req/day
CI/CD Built-in Manual / API Git / CLI

Deploy a Hugo Blog to Pages

Since many of our readers are building blogs, here's a quick Hugo + Pages walkthrough:

# Install Hugo
brew install hugo    # macOS
# or: sudo apt install hugo  # Ubuntu

# Create a new Hugo site
hugo new site my-blog
cd my-blog

# Add a theme
git init
git submodule add https://github.com/theNewDynamic/gohugo-theme-ananke themes/ananke

# Configure Hugo
cat > config.toml << 'EOF'
baseURL = 'https://my-blog.pages.dev/'
languageCode = 'en-us'
title = 'My Blog'
theme = 'ananke'

[params]
  favicon = ''
EOF

# Create a post
hugo new posts/hello-world.md

# Build locally to test
hugo server

# Commit and push
git add .
git commit -m "Initial Hugo blog"
git remote add origin https://github.com/YOUR_USERNAME/my-blog.git
git push -u origin main

Then connect to Cloudflare Pages as described above, using Hugo as the framework preset. Within minutes, your blog is live.

Performance Tips

  • Use a lightweight theme — fewer dependencies mean faster builds and faster pages
  • Optimize images — use WebP format, compress before uploading
  • Leverage browser caching — Pages sets strong cache headers by default
  • Minify assets — enable minification in your build tool
  • Use a CDN for large assets — pair Pages with R2 for file downloads

Quick-Start Checklist

  • Create a Git repo with your site files
  • Connect the repo to Cloudflare Pages
  • Set the build command and output directory
  • Deploy — Cloudflare handles the rest
  • Add a custom domain and enable HTTPS
  • Use preview deployments for every branch

Cloudflare Pages removes the entire "how do I host this" problem. Push code, get a URL. Preview branches, review changes. Connect a domain, get free HTTPS. It's hosting that gets out of your way so you can focus on building.
