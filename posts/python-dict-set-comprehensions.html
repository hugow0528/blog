Python Dict & Set Comprehensions: Beyond Lists — Pythonic Data Processing

July 2, 2026 · 8 min read

You've probably seen list comprehensions — that neat one-liner syntax that lets you build lists in a single expression. But Python offers two equally powerful siblings: dictionary comprehensions and set comprehensions. Together, they let you transform, filter, and restructure data with minimal code.

If you already know list comprehensions from our previous tutorial, these will feel natural. If not, don't worry — the pattern is the same across all three.

Quick Refresher: The Comprehension Pattern

All Python comprehensions share the same structure:

# List comprehension
[expression for item in iterable if condition]

# Dict comprehension  ← curly braces, key:value pairs
{key_expr: value_expr for item in iterable if condition}

# Set comprehension    ← curly braces, single expression
{expression for item in iterable if condition}

The only difference? [] for lists, {} for dicts and sets. Dict comprehensions need a colon to separate keys from values. Set comprehensions work just like list comprehensions but return a set instead.

Dictionary Comprehensions: Build Mappings in One Line

Basic Example: Square Numbers

Create a dictionary where keys are numbers and values are their squares:

squares = {x: x**2 for x in range(1, 6)}
print(squares)
# {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}

Without comprehensions, you'd write:

squares = {}
for x in range(1, 6):
    squares[x] = x**2

Inverting a Dictionary

One of the most common use cases: swap keys and values:

prices = {"apple": 1.20, "banana": 0.50, "cherry": 3.00}
lookup = {price: fruit for fruit, price in prices.items()}
print(lookup)
# {1.2: 'apple', 0.5: 'banana', 3.0: 'cherry'}

Now you can look up a fruit by its price. Note that this only works when values are unique — duplicate values will overwrite keys in the result.

Filtering Dictionaries

Keep only entries that meet a condition:

scores = {"alice": 92, "bob": 45, "charlie": 78, "diana": 88, "eve": 34}

# Pass: score >= 60
passing = {name: score for name, score in scores.items() if score >= 60}
print(passing)
# {'alice': 92, 'charlie': 78, 'diana': 88}

# Grade letter mapping
grades = {name: "A" if s >= 90 else "B" if s >= 80 
          else "C" if s >= 70 else "F" 
          for name, s in scores.items()}
print(grades)
# {'alice': 'A', 'bob': 'F', 'charlie': 'C', 'diana': 'B', 'eve': 'F'}

Grouping Data with Dict Comprehensions

Combine with setdefault or use a regular loop for complex grouping:

from collections import defaultdict

words = ["hello", "world", "lol", "ok", "python", "hi", "code", "ai"]
by_length = defaultdict(list)
for word in words:
    by_length[len(word)].append(word)

print(dict(by_length))
# {5: ['hello', 'world', 'python'], 3: ['lol', 'ok', 'hi', 'code'], 2: ['ai']}

Or build an index for fast lookups:

users = [
    {"id": 1, "name": "Alice", "dept": "engineering"},
    {"id": 2, "name": "Bob", "dept": "marketing"},
    {"id": 3, "name": "Charlie", "dept": "engineering"},
    {"id": 4, "name": "Diana", "dept": "sales"},
]

# Index by department
by_dept = {}
for user in users:
    dept = user["dept"]
    by_dept.setdefault(dept, []).append(user["name"])

print(by_dept)
# {'engineering': ['Alice', 'Charlie'], 'marketing': ['Bob'], 'sales': ['Diana']}

Merging Two Lists into a Dictionary

Use zip() with a dict comprehension:

names = ["Alice", "Bob", "Charlie"]
ages = [30, 25, 35]

people = {name: age for name, age in zip(names, ages)}
print(people)
# {'Alice': 30, 'Bob': 25, 'Charlie': 35}

Nested Dict Comprehensions

Create matrices or lookup tables:

# Multiplication table as a nested dict
mult_table = {x: {y: x * y for y in range(1, 4)} for x in range(1, 4)}
print(mult_table)
# {1: {1: 1, 2: 2, 3: 3}, 2: {1: 2, 2: 4, 3: 6}, 3: {1: 3, 2: 6, 3: 9}}

Set Comprehensions: Unique Values Made Easy

Basic Example

Set comprehensions look identical to list comprehensions but use {} instead of []:

numbers = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
unique = {n for n in numbers}
print(unique)
# {1, 2, 3, 4}

# Squares of even numbers
even_squares = {x**2 for x in range(10) if x % 2 == 0}
print(even_squares)
# {0, 4, 16, 36, 64}

Extracting Unique Words

Remove duplicates from text:

text = "the quick brown fox jumps over the lazy dog and the fox"
unique_words = {word.lower() for word in text.split()}
print(unique_words)
# {'the', 'quick', 'brown', 'fox', 'jumps', 'over', 'lazy', 'dog', 'and'}

# Only words longer than 3 characters
long_words = {word for word in text.split() if len(word) > 3}
print(long_words)
# {'quick', 'brown', 'jumps', 'over', 'lazy'}

Set Operations with Comprehensions

Find common or unique elements across collections:

students_cs = {"Alice", "Bob", "Charlie", "Diana"}
students_math = {"Bob", "Diana", "Eve", "Frank"}

# Students in both classes (intersection)
both = students_cs & students_math
print(both)
# {'Bob', 'Diana'}

# Students in only one class (symmetric difference)
either = students_cs ^ students_math
print(either)
# {'Alice', 'Charlie', 'Eve', 'Frank'}

# Combine with comprehension for filtering
# Students whose names start with a vowel
vowel_students = {name for name in students_cs if name[0].lower() in "aeiou"}
print(vowel_students)
# {'Alice'}

Practical Example: Processing API Response

Here's a real-world pattern you'll encounter when working with APIs:

response = [
    {"user": "alice", "role": "admin", "active": True},
    {"user": "bob", "role": "editor", "active": True},
    {"user": "charlie", "role": "admin", "active": False},
    {"user": "diana", "role": "viewer", "active": True},
]

# Get all unique roles
roles = {entry["role"] for entry in response}
print(roles)
# {'admin', 'editor', 'viewer'}

# Map active users to their roles
active_roles = {entry["user"]: entry["role"] for entry in response if entry["active"]}
print(active_roles)
# {'alice': 'admin', 'bob': 'editor', 'diana': 'viewer'}

# Group users by role
role_groups = {}
for entry in response:
    role_groups.setdefault(entry["role"], []).append(entry["user"])
print(role_groups)
# {'admin': ['alice', 'charlie'], 'editor': ['bob'], 'viewer': ['diana']}

When NOT to Use Comprehensions

Comprehensions are powerful, but not always the right tool:

  • Complex logic: If your comprehension spans more than 2 lines or has nested conditions, use a regular loop. Readability matters more than brevity.
  • Side effects: Comprehensions should create new data structures, not perform actions like printing or file I/O.
  • Memory concerns: Like list comprehensions, dict and set comprehensions load everything into memory. For massive datasets, use generators or process in chunks.
  • Empty set trap: {} creates an empty dict, NOT an empty set. Use set() for an empty set.
# ❌ This creates a dict, not a set!
empty = {}
print(type(empty))
# <class 'dict'>

# ✅ Correct way to create an empty set
empty_set = set()
print(type(empty_set))
# <class 'set'>

Performance Comparison

Comprehensions are not just cleaner — they're usually faster:

import time

# Method 1: Regular loop
start = time.time()
result = {}
for i in range(100000):
    result[i] = i * 2
loop_time = time.time() - start

# Method 2: Dict comprehension
start = time.time()
result = {i: i * 2 for i in range(100000)}
comp_time = time.time() - start

print(f"Loop: {loop_time:.4f}s, Comprehension: {comp_time:.4f}s")
# Loop: 0.0156s, Comprehension: 0.0098s

The comprehension wins because Python optimizes the internal loop at the C level. The difference is small for small datasets but adds up with millions of items.

Summary Cheat Sheet

# List comprehension
[x*2 for x in range(5)]           # [0, 2, 4, 6, 8]

# Dict comprehension
{x: x*2 for x in range(5)}        # {0: 0, 1: 2, 2: 4, 3: 6, 4: 8}

# Set comprehension
{x*2 for x in range(5) if x > 0}  # {2, 4, 6, 8}

# Invert a dict
{k: v for v, k in original.items()}

# Filter a dict
{k: v for k, v in d.items() if v > 0}

# Zip two lists into a dict
{k: v for k, v in zip(keys, values)}

Master these three comprehension types and you'll write significantly more Pythonic code. They're everywhere in the standard library, data science, and production codebases.
