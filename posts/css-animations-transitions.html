CSS Animations & Transitions: Bring Your Websites to Life

2026-06-26 12 min read New

Ever visit a website where buttons smoothly change color when you hover, cards lift up elegantly, or a loading spinner spins perfectly? That's the power of CSS animations and transitions. In this guide, you'll learn everything from basic hover effects to full @keyframe animations — no JavaScript required.

Transitions vs Animations: What's the Difference?

Transitions are simple state changes. They animate a property when it changes — like a button color shifting on hover. You define the property, duration, and easing. Think of them as the "from A to B" approach.

Animations are more powerful. With @keyframes, you define multiple stages of an animation — start, middle points, and end. You can loop them, reverse them, and control timing precisely. These are for when you need a "movie," not just a fade.

Part 1: CSS Transitions

The Transition Shorthand

The transition property has four sub-properties. You usually use the shorthand:

/* Shorthand: property duration timing-function delay */
.btn {
    transition: background-color 0.3s ease-in-out;
}

Hover Button Example

Let's build a button that smoothly transitions color, lifts up, and casts a deeper shadow when hovered:

.btn {
    background: #2563eb;
    color: white;
    padding: 12px 24px;
    border: none;
    border-radius: 8px;
    cursor: pointer;
    font-size: 16px;

    /* The magic: smooth transition on all properties */
    transition: background-color 0.3s ease,
                transform 0.2s ease,
                box-shadow 0.3s ease;
}

.btn:hover {
    background-color: #1d4ed8;
    transform: translateY(-2px);
    box-shadow: 0 8px 25px rgba(37, 99, 235, 0.4);
}

.btn:active {
    transform: translateY(0);
    box-shadow: 0 2px 10px rgba(37, 99, 235, 0.3);
}

Notice we transition three properties in one declaration, separated by commas. Each can have its own duration and easing. The transform: translateY(-2px) lifts the button by 2 pixels — a subtle but satisfying effect.

Timing Functions (Easing)

The timing function controls the speed curve of an animation. Common values:

  • ease — starts slow, speeds up, slows down (default)
  • linear — constant speed throughout
  • ease-in — starts slow, speeds up
  • ease-out — starts fast, slows down (great for sliding in)
  • ease-in-out — slow start AND slow finish
  • cubic-bezier(x1, y1, x2, y2) — custom curve

A cubic-bezier(0.68, -0.55, 0.27, 1.55) creates a "bouncy" effect where the element overshoots its target slightly before settling. It's a great trick for playful UI.

Common Transition Properties

Not all CSS properties can be transitioned, but most visual ones can. The most useful:

  • opacity — fade in/out (very performant!)
  • transform — translate, rotate, scale (GPU-accelerated)
  • color, background-color — smooth color changes
  • box-shadow — shadow growth/shrink
  • border-radius — shape morphing
  • width, height — size changes (use carefully — not performant)

Pro tip: Always prefer transform and opacity for animations. They're handled by the GPU and won't cause layout recalculations. Avoid animating width, height, margin, or padding — they trigger expensive reflows.

Expanding Card Example

.card {
    background: white;
    border-radius: 12px;
    padding: 24px;
    box-shadow: 0 2px 8px rgba(0,0,0,0.1);
    overflow: hidden;
    transition: transform 0.3s ease-out, box-shadow 0.3s ease-out;
    cursor: pointer;
}

.card:hover {
    transform: translateY(-4px) scale(1.02);
    box-shadow: 0 12px 30px rgba(0,0,0,0.15);
}

/* Hidden detail section that reveals on hover */
.card-detail {
    max-height: 0;
    opacity: 0;
    overflow: hidden;
    transition: max-height 0.4s ease, opacity 0.3s ease;
}

.card:hover .card-detail {
    max-height: 200px;
    opacity: 1;
}

Part 2: CSS Animations with @keyframes

Basic Syntax

An animation has two parts: a @keyframes rule defining the stages, and an animation property applying it:

/* Step 1: Define the animation */
@keyframes fadeIn {
    from {
        opacity: 0;
        transform: translateY(20px);
    }
    to {
        opacity: 1;
        transform: translateY(0);
    }
}

/* Step 2: Apply it */
.element {
    animation: fadeIn 0.5s ease-out forwards;
}

The forwards keyword is crucial — without it, the element reverts to its original state after the animation ends. forwards tells it to stay at the final keyframe.

Multiple Keyframe Steps

Use percentage values for multi-step animations:

@keyframes slideBounce {
    0% {
        transform: translateX(-100%);
        opacity: 0;
    }
    60% {
        transform: translateX(10px);
        opacity: 1;
    }
    80% {
        transform: translateX(-5px);
    }
    100% {
        transform: translateX(0);
    }
}

This animation slides an element in from the left, overshoots to the right by 10px, bounces back to -5px, then settles at 0. The overshoot at 60% creates a natural bounce effect.

Loading Spinner

A classic use case — a loading spinner that loops continuously:

.spinner {
    width: 40px;
    height: 40px;
    border: 4px solid #e2e8f0;
    border-top-color: #2563eb;
    border-radius: 50%;
    animation: spin 0.8s linear infinite;
}

@keyframes spin {
    to {
        transform: rotate(360deg);
    }
}

The key properties here:

  • infinite — loops forever
  • linear — constant rotation speed
  • Only the to keyframe is needed for continuous rotation since from defaults to the element's current state

Pulsing Notification Badge

.notification-badge {
    background: #ef4444;
    color: white;
    width: 20px;
    height: 20px;
    border-radius: 50%;
    display: flex;
    align-items: center;
    justify-content: center;
    font-size: 12px;
    animation: pulse 1.5s ease-in-out infinite;
}

@keyframes pulse {
    0%, 100% {
        transform: scale(1);
        opacity: 1;
    }
    50% {
        transform: scale(1.2);
        opacity: 0.8;
    }
}

Part 3: Animation Properties Reference

The animation shorthand packs seven sub-properties:

/* Shorthand: name duration timing-function delay iteration-count direction fill-mode play-state */
animation: slideIn 0.5s ease-out 0.2s 1 normal forwards paused;
Property Common Values Default
animation-name Your @keyframes name none
animation-duration 1s, 500ms, 2s 0s
animation-timing-function ease, linear, ease-in-out ease
animation-delay 0.5s, 200ms 0s
animation-iteration-count 1, 3, infinite 1
animation-direction normal, reverse, alternate normal
animation-fill-mode none, forwards, backwards, both none
animation-play-state running, paused running

Part 4: Scroll-Triggered Animations

Modern browsers support the Intersection Observer API — perfect for triggering CSS animations when elements enter the viewport. Add just a few lines of JavaScript:

/* CSS: Elements start invisible and slide up */
.reveal {
    opacity: 0;
    transform: translateY(30px);
    transition: opacity 0.6s ease-out, transform 0.6s ease-out;
}

.reveal.visible {
    opacity: 1;
    transform: translateY(0);
}

/* JavaScript: Add .visible when scrolled into view */

Apply class="reveal" to any element (headings, cards, images) and it will smoothly fade and slide up when the user scrolls to it. The threshold: 0.1 means the animation triggers when 10% of the element is visible.

Part 5: Performance Best Practices

Smooth animations at 60fps (one frame every 16ms) require care. Follow these rules:

✅ Always Animate These (GPU-accelerated)

  • transform — translate, rotate, scale, skew
  • opacity — fade effects

⚠️ Sometimes Okay

  • color, background-color, box-shadow
  • filter, backdrop-filter

❌ Avoid Animating These (triggers layout)

  • width, height — use transform: scale() instead
  • margin, padding, top, left — use transform: translate()
  • font-size, line-height

Use will-change Sparingly

.animated-element {
    will-change: transform, opacity;
}

will-change hints to the browser to optimize rendering. Use it only for elements you know will animate — overusing it wastes memory. Remove it when the animation ends.

Add Reduced Motion Support

Always respect users who prefer reduced motion (a common accessibility setting):

@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        transition-duration: 0.01ms !important;
    }
}

Complete Example: Animated Dashboard Card

Let's combine everything into one polished component:

.dashboard-card {
    background: white;
    border-radius: 16px;
    padding: 32px;
    box-shadow: 0 2px 8px rgba(0,0,0,0.08);
    position: relative;
    overflow: hidden;
    transition: transform 0.3s ease-out, box-shadow 0.3s ease-out;

    /* Entrance animation */
    opacity: 0;
    animation: cardEntrance 0.6s ease-out forwards;
}

/* Stagger entrance: each card appears 0.1s after the last */
.dashboard-card:nth-child(1) { animation-delay: 0s; }
.dashboard-card:nth-child(2) { animation-delay: 0.1s; }
.dashboard-card:nth-child(3) { animation-delay: 0.2s; }
.dashboard-card:nth-child(4) { animation-delay: 0.3s; }

@keyframes cardEntrance {
    from {
        opacity: 0;
        transform: translateY(20px) scale(0.95);
    }
    to {
        opacity: 1;
        transform: translateY(0) scale(1);
    }
}

.dashboard-card:hover {
    transform: translateY(-4px);
    box-shadow: 0 12px 40px rgba(0,0,0,0.12);
}

/* Gradient accent bar */
.dashboard-card::before {
    content: '';
    position: absolute;
    top: 0;
    left: 0;
    right: 0;
    height: 4px;
    background: linear-gradient(90deg, #2563eb, #7c3aed);
    transform: scaleX(0);
    transform-origin: left;
    transition: transform 0.3s ease;
}

.dashboard-card:hover::before {
    transform: scaleX(1);
}

Summary

CSS animations and transitions give your website professional polish with zero JavaScript overhead. Remember the key principles:

  1. Use transitions for simple state changes (hover, focus, toggle)
  2. Use @keyframes animations for multi-step effects, loops, and entrance sequences
  3. Always animate transform and opacity for best performance
  4. Add animation-fill-mode: forwards so animations persist after ending
  5. Respect prefers-reduced-motion for accessibility
  6. Use IntersectionObserver for scroll-triggered effects

Practice by building small components — a hover button, a loading spinner, an entrance animation. Each takes 10 minutes but the visual impact is huge. Your users will notice the difference.
