Claude Code: Terminal-Based AI Agent for Real Development Work

July 19, 2026 10 min read

Claude Code is Anthropic's terminal-based AI coding agent that runs directly in your shell. Unlike IDE extensions that suggest one line at a time, Claude Code can read your entire codebase, understand context across files, run commands, edit multiple files in a single turn, and execute a complete task from start to finish. It's designed to feel like having a senior developer at your terminal.

This guide covers everything from installing Claude Code to advanced workflows including custom instructions, project-specific memory, multi-file refactoring, and automated testing. Every example includes real terminal commands and prompt patterns you can use immediately.

Install Claude Code

Claude Code runs as a CLI tool. Install it with npm (requires Node.js 18+):

# Install globally with npm
npm install -g @anthropic-ai/claude-code

# Verify installation
claude --version

# First run — it will prompt for your API key
claude

You need an Anthropic API key. Set it as an environment variable or configure it on first launch:

# Set API key (add to ~/.bashrc or ~/.zshrc)
export ANTHROPIC_API_KEY="sk-ant-your-key-here"

# Or use AWS Bedrock as the backend
export AWS_PROFILE="your-profile"
claude --backend-bedrock

Basic Commands and Interactions

Claude Code has a conversational interface but also supports direct commands:

# Start interactive mode in current directory
claude

# Quick one-shot task (non-interactive)
claude "Add type hints to all functions in utils.py"

# Ask a question without making changes
claude --print "Explain the architecture of this project"

# Edit a specific file with a prompt
claude "Refactor database.py to use async connections" database.py

# Run with a specific project context
claude "Fix the failing tests" --continue

In interactive mode, Claude shows you proposed changes before applying them. Type /help to see all slash commands:

/help          — Show available commands
/compact       — Compact conversation history to save tokens
/clear         — Clear the conversation
/files         — List watched files
/agents        — Show active sub-agents
/permissions   — Manage tool permissions
/cut          — Remove last exchange from history

Project Instructions (.clinerules)

One of the most powerful features is project-specific instructions. Create a .clinerules file in your project root to define how Claude should behave:

# .clinerules — Project-specific instructions for Claude Code

# Code style
- Use Python type hints on all function signatures
- Follow PEP 8 naming conventions
- Write docstrings using Google style
- Prefer f-strings over format() or % formatting

# Testing
- Always write tests before implementing features
- Use pytest with fixtures for shared setup
- Target 80%+ line coverage
- Include edge case tests for error conditions

# Architecture
- Use dependency injection, not global state
- Separate I/O from business logic
- Keep functions under 50 lines
- Use context managers for resource management

# Git workflow
- Write descriptive commit messages
- Create feature branches, not direct main commits
- Include related issue numbers in commits

Claude reads this file on every session and applies the rules automatically. You can also create a global rules file at ~/.claude/CLAUDE.md that applies to all projects.

Multi-File Editing Workflows

Claude Code excels at tasks that span multiple files. Here are common workflows:

Add a new API endpoint across your project:

claude "Add a DELETE /api/items/{id} endpoint. Update the router in routes.py, add the handler in handlers.py, create a Pydantic response model in schemas.py, and write a test in test_routes.py"

Claude will:

  • Read all four files to understand existing patterns
  • Generate consistent code matching your project style
  • Show a diff of all changes before applying
  • Apply all edits atomically

Refactor a module with imports:

claude "Extract the email validation logic from forms.py into its own validators.py module. Update all imports and references."

Fix a bug across the codebase:

claude "The date parsing fails when users submit ISO 8601 strings. Find all date parsing code and fix it to handle both 'YYYY-MM-DD' and ISO 8601 formats. Update tests too."

Automated Testing Workflow

Claude Code can run and debug tests directly from the terminal. Here's a complete workflow:

# Ask Claude to run tests and fix failures
claude "Run the test suite with pytest. If any tests fail, analyze the output and fix the underlying issues. Run tests again after each fix until everything passes."

Claude will:

  1. Execute pytest and capture the output
  2. Analyze failure messages and stack traces
  3. Locate the source files causing failures
  4. Edit the code to fix the bugs
  5. Re-run tests to verify the fix
  6. Repeat until green

Write tests from scratch:

claude "Write comprehensive tests for services/auth.py. Cover successful login, expired tokens, invalid credentials, rate limiting, and token refresh. Use pytest fixtures for the test database setup."

Debugging with Claude Code

When you have a running error, paste it directly to Claude Code:

claude "Here's the error I'm getting:

Traceback (most recent call last):
  File 'app.py', line 42, in fetch_user
    user = db.query(User).filter(User.id == request.json['id']).one()
sqlalchemy.orm.exc.NoResultFound

Fix the error and add proper error handling so we return 404 instead of crashing."

Claude will analyze the traceback, identify the root cause (.one() raises when no result is found), and fix it with .one_or_none() plus proper HTTP 404 response handling.

Debug a slow query:

claude "The /api/reports endpoint takes 3 seconds to respond. Profile the code path from the route handler through database queries. Identify the N+1 query problem and fix it with eager loading."

Agent Mode and Sub-Agents

For complex tasks, Claude Code can spawn sub-agents that work in parallel. This is particularly useful for large refactoring:

claude "I need to upgrade this project from Python 3.9 to 3.12. 

Task 1: Update pyproject.toml and requirements files for Python 3.12 compatibility
Task 2: Find and fix all uses of removed 3.9-only features
Task 3: Update the Dockerfile to use python:3.12-slim
Task 4: Run all tests and fix any failures

Use sub-agents to work on these tasks in parallel."

Use /agents to monitor progress. Each sub-agent works independently and reports back when complete.

Production-Ready Patterns

1. Set permissions for CI/CD:

# In a GitHub Actions workflow, Claude runs unattended
# Set auto-approve for specific actions
claude --permissions approve-edits --no-prompt "Fix the build by resolving all lint errors"

2. Use a MCP server for database access:

# Configure MCP (Model Context Protocol) server in .mcp.json
# Claude can then query your database directly during debugging

{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    }
  }
}

3. Review before merging:

claude "Review all uncommitted changes as if you're doing a code review. Check for:
- Security issues (hardcoded secrets, SQL injection)
- Performance problems (N+1 queries, missing indexes)
- Edge cases that aren't handled
- Test coverage gaps
- Documentation that needs updating

Report issues as a numbered list with file:line references."

Pro Tips

  • Use /compact when a conversation gets long — it summarizes history to save tokens without losing context
  • Add a .gitignore entry for large generated files you don't want Claude to index
  • Use --print mode in scripts for non-interactive usage (great for CI)
  • Create a scripts/claude/ directory with reusable prompt files for common tasks
  • Set ANTHROPIC_MODEL=claude-sonnet-4-20250514 for a cheaper model on routine tasks
  • Use /cut to remove accidental or incorrect exchanges from conversation history

Claude Code shines when you're comfortable in the terminal and need an agent that can work across files, run tests, and execute tasks without an IDE. It's the best tool for SSH sessions, server debugging, CI/CD automation, and quick scripting.

Next Steps

Start with a simple refactoring task in a non-critical project. Give Claude Code a clear prompt, review its changes, and iterate on your .clinerules file to match your preferences. Over time, you'll develop a set of prompt patterns that make Claude Code an incredibly productive pair programmer.
