Cloudflare Pages: Deploy Static Sites and JAMstack Apps in Minutes

July 7, 2026 9 min read New

Cloudflare Pages is a serverless platform for deploying static websites and full-stack JAMstack applications. Connect your GitHub repository, and Cloudflare automatically builds and deploys your site every time you push code. No servers to manage, no deployment scripts to write — just push and go.

Best of all, it's generous with the free tier: 500 builds per month, 500K requests per day, and automatic HTTPS with a global CDN. In this guide, we'll walk through everything from your first deployment to advanced configuration.

What Is Cloudflare Pages?

Cloudflare Pages is a deployment platform that combines:

  • CI/CD pipeline — automatic builds triggered by git pushes
  • Global CDN — your site served from 300+ data centers worldwide
  • Serverless functions — add API endpoints without a backend
  • Preview deployments — unique URLs for every pull request
  • Automatic HTTPS — free SSL certificates with zero configuration

It works with any static site generator: Hugo, Next.js, Gatsby, Eleventy, Jekyll, Docusaurus, Astro, or plain HTML/CSS/JS. If your build process outputs HTML, CSS, and JavaScript files, Pages can deploy it.

Prerequisites

  • A Cloudflare account (free)
  • A GitHub account
  • A project with static site output (HTML, CSS, JS files)
  • Git installed on your machine

Quick Start: Deploy Your First Site

Step 1: Create a Simple Static Site

Let's start with a minimal project. Create a directory and add an index.html:

mkdir my-site
cd my-site

# Create index.html
cat > index.html <<'EOF'
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My First Cloudflare Pages Site</title>
    <style>
        body {
            font-family: system-ui, sans-serif;
            max-width: 800px;
            margin: 0 auto;
            padding: 2rem;
            background: #0a0a0a;
            color: #e0e0e0;
        }
        h1 { color: #f5a623; }
        .card {
            background: #1a1a1a;
            padding: 1.5rem;
            border-radius: 8px;
            margin: 1rem 0;
            border: 1px solid #333;
        }
    </style>
</head>
<body>
    <h1>Hello from Cloudflare Pages! </h1>
    <div class="card">
        <p>This site is deployed on Cloudflare's global network.</p>
        <p>Zero server configuration needed.</p>
    </div>
</body>
</html>
EOF

Step 2: Push to GitHub

# Initialize git repository
git init
git add .
git commit -m "Initial commit"

# Create a new repo on GitHub, then push
git remote add origin git@github.com:YOUR_USERNAME/my-site.git
git branch -M main
git push -u origin main

Step 3: Connect to Cloudflare Pages

  1. Log into your Cloudflare Dashboard
  2. Navigate to Workers & Pages → Pages
  3. Click Create a project
  4. Select Connect to Git
  5. Choose your GitHub repository (my-site)
  6. Fill in the project settings:
    • Project name: your-site (auto-generated from repo name)
    • Production branch: main
    • Build command: Leave empty for plain HTML (or set npm run build for frameworks)
    • Build output directory: Leave empty for root directory (or set dist, build, public for frameworks)
  7. Click Save and Deploy

Cloudflare will build your site and provide a URL like my-site-abc123.pages.dev. Your site is live in under a minute.

Preview Deployments

One of the best features of Cloudflare Pages is automatic preview deployments. Every pull request gets its own unique URL:

  • Open a pull request on GitHub
  • Cloudflare automatically builds and deploys a preview
  • The preview URL looks like deploy-preview-42--my-site.pages.dev
  • Cloudflare adds a comment to your PR with the preview link
  • Reviewers can click the link to see the exact changes

This is incredibly useful for design reviews, feature testing, and stakeholder feedback. No manual deployment steps needed.

Custom Domains

Replace the .pages.dev URL with your own domain:

  1. In your Pages project, go to Custom domains
  2. Enter your domain (e.g., www.yoursite.com)
  3. Cloudflare shows you the DNS records to create
  4. If your domain is already on Cloudflare, the records are set automatically
  5. If not, add a CNAME record pointing to your Pages URL

Cloudflare automatically provisions and renews an SSL certificate for your custom domain — completely free.

Environment Variables

Store secrets and configuration separately from your code:

# Set environment variables in the dashboard:
# Pages project → Settings → Environment variables

# Example: set a GitHub token for a build-time API call
Name: GITHUB_TOKEN
Value: ghp_xxxxxxxxxxxxxxxxxxxx
Environment: Production (or all environments)

# Access in your code at build time
import os
token = os.environ.get('GITHUB_TOKEN')

You can also set them via the Cloudflare CLI:

# Install Wrangler (Cloudflare's CLI)
npm install -g wrangler

# Set an environment variable
npx wrangler pages secret put DATABASE_URL

# It will prompt you to enter the value
# The value is encrypted and never stored in plain text

Build-Time vs Runtime Variables

Cloudflare Pages distinguishes between two types of environment variables:

  • Build-time variables: Available during the build process. Used by frameworks to generate static content. Accessible via process.env in Node-based frameworks.
  • Runtime variables (bound to functions): Available only in Workers and Pages Functions. Cannot be accessed during static builds. Set with the --binding flag for function-specific access.

Pages Functions (Serverless API Endpoints)

Even though Pages is a static site platform, you can add serverless API endpoints using Pages Functions. Create a functions directory in your project root:

# Project structure
my-site/
├── index.html
├── functions/
│   └── api/
│       ├── greeting.js
│       └── weather.js
└── _routes.json

Each file in the functions directory becomes an API endpoint:

// functions/api/greeting.js
export async function onRequest(context) {
    const name = context.url.searchParams.get('name') || 'World';

    return new Response(JSON.stringify({
        message: `Hello, ${name}!`,
        timestamp: new Date().toISOString()
    }), {
        headers: { 'Content-Type': 'application/json' }
    });
}

Now visit https://your-site.pages.dev/api/greeting?name=Alice:

{
    "message": "Hello, Alice!",
    "timestamp": "2026-07-07T12:00:00.000Z"
}

Catching All Routes

Use [slug].js to handle dynamic paths:

// functions/api/users/[id].js
export async function onRequest({ params }) {
    const userId = params.id;

    // In production, query a database here
    const users = {
        '1': { name: 'Alice', role: 'admin' },
        '2': { name: 'Bob', role: 'user' }
    };

    const user = users[userId] || { error: 'User not found' };

    return new Response(JSON.stringify(user), {
        headers: { 'Content-Type': 'application/json' }
    });
}

Now /api/users/1 returns Alice's data, and /api/users/99 returns an error.

Route Configuration with _routes.json

Control which paths are handled by functions and which serve static files:

// _routes.json
{
    "include": [
        "/api/*"
    ],
    "exclude": [
        "/api/public/*"
    ]
}

This configuration routes all /api/* requests through Workers (for server-side processing) but excludes /api/public/* (served as static files).

Redirects and Rewrites

Configure redirects and rewrites with a _redirects file in your build output directory:

# _redirects (place in your build output directory)

# Permanent redirect (301)
/old-page  /new-page  301

# Temporary redirect (302)
/temp  /alternative  302

# Rewrite (200 — serve /about.html at /about URL)
/about  /about.html  200

# Wildcard redirect
/blog/*  /posts/:splat  301

# Force HTTPS (already default on Cloudflare)
http://example.com/*  https://example.com/:splat  301

Deploy via CLI (Wrangler)

For more control, use the Wrangler CLI instead of the dashboard:

# Install Wrangler
npm install -g wrangler

# Login to Cloudflare
npx wrangler login

# Deploy directly from your project directory
npx wrangler pages deploy ./dist --project-name=my-site

# Set a custom domain
npx wrangler pages domain create my-site hugo.dev

# List deployments
npx wrangler pages deployment list --project-name=my-site

Integration with Cloudflare Ecosystem

Pages integrates seamlessly with other Cloudflare services:

  • Cloudflare Workers: Run serverless code alongside your static site
  • D1 Database: Add SQL database to your Pages Functions
  • KV Storage: Key-value storage for caches and configuration
  • R2 Storage: Object storage for user uploads and media
  • Cloudflare Access: Add authentication to internal tools
  • Cloudflare Analytics: Built-in visitor and bandwidth analytics
  • DNS: Manage your domain's DNS records in the same dashboard
  • SSL/TLS: Automatic HTTPS with flexible, full, or strict modes
  • Cloudflare Turnstile: Add bot protection to forms

Summary

Cloudflare Pages makes deploying static sites ridiculously easy:

  1. Push your code to GitHub
  2. Connect the repository in the Cloudflare dashboard
  3. Your site is live with automatic HTTPS and a global CDN
  4. Add serverless functions for dynamic features
  5. Customize with your own domain name

From a simple HTML page to a full JAMstack application with API endpoints, databases, and authentication — Cloudflare Pages handles it all without any server management. Whether you're deploying a portfolio, a blog, or a documentation site, Pages is one of the fastest paths from code to production.
