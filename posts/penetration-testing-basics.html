Penetration Testing Basics: A Beginner's Guide to Ethical Hacking

June 22, 2026 · 12 min read

Ever wondered how security professionals find weaknesses in systems before hackers exploit them? Penetration testing (or "pentesting") is the practice of simulating real-world attacks on computers, networks, and web applications to discover and fix vulnerabilities. It's one of the most valuable skills in cybersecurity — and it's entirely legal when done with permission.

In this guide, we'll walk through what penetration testing is, the standard methodology, the tools you need, and how to start practicing legally with hands-on examples.

What Is Penetration Testing?

Penetration testing is an authorized, simulated cyber attack against a system to evaluate its security. Unlike vulnerability scanning (which automatically detects known issues), pentesting involves creative, manual techniques that mimic how real attackers think and operate.

Think of it like hiring a master locksmith to test your home security. They try every possible entry point, report what works, and help you lock those doors before a burglar finds them.

Golden rule: Never test a system you don't own or have written permission to test. Unauthorized access is a crime in most countries.

The Penetration Testing Methodology

Professional pentesters follow a structured methodology. The most widely used framework has five phases:

Phase 1: Reconnaissance   — Gather information about the target
Phase 2: Scanning         — Discover open ports, services, and vulnerabilities
Phase 3: Exploitation     — Attempt to breach security controls
Phase 4: Post-Exploitation — See what you can access once inside
Phase 5: Reporting       — Document everything for the client

Phase 1: Reconnaissance

This is the intelligence-gathering stage. You want to know everything about the target — domain names, IP addresses, technologies used, employees, social media, DNS records, and more. There are two types:

  • Passive recon — gathering info without touching the target (Google searches, WHOIS lookups, Shodan)
  • Active recon — directly interacting with the target (ping sweeps, port scans)

A simple passive recon using command-line tools:

# WHOIS lookup — who owns the domain?
whois example.com

# DNS lookup — what records exist?
nslookup example.com
dig example.com ANY

# Find subdomains
host -l example.com ns1.example.com

Phase 2: Scanning

Now that you know what you're dealing with, it's time to scan. The #1 tool here is Nmap (Network Mapper), which discovers hosts and services on a network.

# Basic scan — find open ports
nmap 192.168.1.1

# Scan with service version detection
nmap -sV 192.168.1.1

# Scan with OS detection
nmap -O 192.168.1.1

# Full scan of all 65535 ports
nmap -p- 192.168.1.1

# Aggressive scan (combines several techniques)
nmap -A 192.168.1.1

# Scan an entire subnet
nmap 192.168.1.0/24

For web applications specifically, Nikto is a popular web server scanner:

# Scan a web server for vulnerabilities
nikto -h http://example.com

# Scan with SSL check
nikto -h https://example.com -ssl

# Save results to file
nikto -h http://example.com -o report.txt -Format txt

Phase 3: Exploitation

This is where pentesters attempt to exploit the vulnerabilities they found. For web application testing, Burp Suite is the go-to tool — it acts as a proxy between your browser and the target, letting you inspect and modify every HTTP request and response. Professional pentesters also use frameworks like Metasploit for exploit development and sqlmap for automated SQL injection testing.

Phase 4: Post-Exploitation

Once inside, you assess the damage: What data is accessible? Can you escalate privileges? Can you move laterally to other systems? This phase helps understand the real impact of a breach.

# After gaining a shell, common checks:

# Who am I?
whoami

# What privileges?
id

# What's running?
ps aux

# What users exist?
cat /etc/passwd

# Any configuration or key files in common locations?
ls -la /var/www/ && ls -la /home/

Phase 5: Reporting

A pentest without a report is useless. Your report should include:

  • Executive summary — high-level findings for management
  • Technical details — step-by-step reproduction for engineers
  • Risk ratings — Critical, High, Medium, Low, Informational
  • Remediation steps — how to fix each issue
  • Score — overall security posture assessment

Common Vulnerability Categories

Understanding what to look for is as important as the tools. Here are the most common categories:

OWASP Top 10 (Web Applications)

  • A01 — Broken Access Control — users accessing resources they shouldn't
  • A02 — Cryptographic Failures — sensitive data exposed due to weak encryption
  • A03 — Injection — SQL injection, command injection, XSS
  • A04 — Insecure Design — missing security by design principles
  • A05 — Security Misconfiguration — default passwords, open ports, verbose errors

Legal Ways to Practice

You need legal targets to practice. Here are great options:

  1. TryHackMe (tryhackme.com) — guided learning rooms with legal vulnerable machines
  2. HackTheBox (hackthebox.com) — realistic vulnerable machines to pwn
  3. OWASP Juice Shop — intentionally vulnerable web app you can run locally
  4. PortSwigger Web Security Academy — free labs for every OWASP category
  5. CTF competitions — Capture The Flag events with legal challenges
  6. Bug Bounty programs — HackerOne, Bugcrowd let you test companies legally for rewards

Building Your First Lab

Set up a safe, legal environment on your own computer:

# Install common security tools on Ubuntu/Debian
sudo apt update
sudo apt install -y nmap nikto burpsuite

# Or run Kali Linux in a VM (VirtualBox/VMware)

# Download an intentionally vulnerable web app
git clone https://github.com/juice-shop/juice-shop
cd juice-shop && npm install && npm start

# Now scan your local lab
nmap -sV -p- localhost:3000
nikto -h http://localhost:3000

Essential Tools Summary

Recon:     theHarvester, Maltego, Shodan, WHOIS
Scanning:  Nmap, Nikto, OpenVAS, Nessus
Exploit:   Metasploit, sqlmap, Burp Suite, Curl
Web:       OWASP ZAP, Burp Suite, ffuf, Gobuster
Wireless:  Aircrack-ng, Wireshark
Social Eng: SET, GoPhish
Reporting: Dradis, Pentera

Next Steps for Beginners

Here's a realistic learning path:

  1. Start with TryHackMe — complete the "Pre Security" and "Jr Penetration Tester" paths
  2. Learn Linux command line — it's the backbone of security tools
  3. Study networking fundamentals — TCP/IP, DNS, HTTP, ports, protocols
  4. Practice with PortSwigger Academy for web app security
  5. Consider certifications: CompTIA Security+, then eJPT or OSCP
Penetration testing is a journey, not a destination. New vulnerabilities are discovered every day. Stay curious, stay ethical, and keep practicing.
