Python Virtual Environments and pip: Isolate Your Projects

June 24, 2026 · 10 min read

You've been writing Python scripts. Now you need a library — maybe requests for APIs, or beautifulsoup4 for web scraping. You install it with pip install, everything works... until your next project needs a different version of the same library. Or your script breaks on a friend's computer because they're missing a dependency.

This is the dependency hell that every Python developer encounters. The solution? Virtual environments and requirements files. In this tutorial, you'll learn how to create isolated project environments, manage packages with pip, and share your projects reproducibly.

Why Do We Need Virtual Environments?

Imagine two projects:

  • Project A: A web scraper using requests==2.28.0
  • Project B: A modern API client using requests==2.31.0

If both projects share the same Python installation, installing version 2.31.0 for Project B breaks Project A. And if you install packages globally, your system Python becomes cluttered with dozens of libraries that conflict with each other.

A virtual environment creates an isolated folder with its own Python interpreter and packages. Each project gets its own clean sandbox:

my-web-scraper/
├── venv/              ← Isolated Python + packages
│   ├── bin/python
│   ├── bin/pip
│   └── lib/python3.12/site-packages/
│       └── requests-2.28.0/
├── scraper.py
└── requirements.txt

my-api-client/
├── venv/              ← Different isolated environment
│   ├── bin/python
│   ├── bin/pip
│   └── lib/python3.12/site-packages/
│       └── requests-2.31.0/
├── api_client.py
└── requirements.txt

Each project is independent. No conflicts. No surprises.

Creating a Virtual Environment

Python includes a built-in module called venv (available since Python 3.3). No extra installation needed:

# 1. Create a project directory
mkdir my-project
cd my-project

# 2. Create a virtual environment named "venv"
python3 -m venv venv

# 3. Activate the virtual environment
# On macOS/Linux:
source venv/bin/activate

# On Windows (Command Prompt):
# venv\Scripts\activate

# On Windows (PowerShell):
# venv\Scripts\Activate.ps1

# 4. Verify it's activated
# Your terminal prompt should now show (venv)
which python
# Output: /path/to/my-project/venv/bin/python

pip list
# Shows only the default packages in this environment

How activation works: The source venv/bin/activate command modifies your shell's PATH so that python and pip point to the virtual environment's copies instead of your system copies. It's temporary — closing the terminal deactivates it automatically.

Convention: Most Python projects name their virtual environment folder venv or .venv. Pick one and be consistent.

Installing Packages with pip

pip is Python's package manager. Once your virtual environment is activated, pip installs packages into that isolated environment:

# Install a single package
pip install requests

# Install a specific version
pip install requests==2.28.0

# Install a minimum version
pip install requests>=2.25.0

# Install from a range
pip install requests>=2.25.0,<3.0.0

# Install multiple packages at once
pip install requests beautifulsoup4 lxml

# Upgrade a package to latest version
pip install --upgrade requests

# Uninstall a package
pip uninstall requests

Understanding pip Version Specifiers

# Exact version (reproducible, recommended for requirements.txt)
requests==2.28.0

# Minimum version (allows upgrades)
requests>=2.28.0

# Version range
requests>=2.25.0,<3.0.0

# Compatible release (same major version)
requests~=2.28.0   # Equivalent to >=2.28.0,<2.29.0

# Pre-release versions
requests==2.31.0a1  # Alpha
requests==2.31.0b1  # Beta
requests==2.31.0rc1 # Release candidate

Managing Dependencies with requirements.txt

A requirements.txt file is the standard way to record your project's dependencies. Anyone can install all required packages with one command:

Exporting Requirements

# Export all installed packages with exact versions
pip freeze > requirements.txt

# The file looks like this:
# requirements.txt
beautifulsoup4==4.12.3
certifi==2024.2.2
charset-normalizer==3.3.2
idna==3.6
lxml==5.1.0
requests==2.31.0
soupsieve==2.5
urllib3==2.2.1

Installing from Requirements

# Install everything from requirements.txt
pip install -r requirements.txt

# This installs every package with the exact version listed
# Ensures everyone works with the same versions

When to share your requirements.txt:

  • Push it to Git alongside your code
  • Include it in project documentation
  • Ship it with deployment scripts
  • Reference it in Dockerfiles

Real Project: Setting Up a Web Scraper

Let's walk through a complete setup from scratch:

# Step 1: Create and enter project directory
mkdir weather-scraper
cd weather-scraper

# Step 2: Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate

# Step 3: Install needed packages
pip install requests beautifulsoup4

# Step 4: Create your scraper script
# File: scraper.py
# scraper.py
import requests
from bs4 import BeautifulSoup

def fetch_weather(city):
    """Fetch current weather from wttr.in"""
    url = f"https://wttr.in/{city}?format=j1"
    
    response = requests.get(url)
    response.raise_for_status()  # Raise error for bad status codes
    
    data = response.json()
    current = data['current_condition'][0]
    
    return {
        'city': city,
        'temp_c': current['temp_C'],
        'temp_f': current['temp_F'],
        'desc': current['weatherDesc'][0]['value'],
        'humidity': current['humidity'],
        'wind_kph': current['windspeedKmph']
    }

def main():
    cities = ["London", "Tokyo", "New York", "Sydney"]
    
    print("🌤️  Weather Report\n" + "=" * 40)
    
    for city in cities:
        try:
            weather = fetch_weather(city)
            print(f"\n📍 {weather['city']}")
            print(f"   🌡️  {weather['temp_c']}°C / {weather['temp_f']}°F")
            print(f"   ☁️  {weather['desc']}")
            print(f"   💧 Humidity: {weather['humidity']}%")
            print(f"   💨 Wind: {weather['wind_kph']} km/h")
        except Exception as e:
            print(f"\n⚠️  Could not fetch weather for {city}: {e}")

if __name__ == "__main__":
    main()
# Step 5: Run the scraper
python scraper.py

# Output:
# 🌤️  Weather Report
# ========================================
# 
# 📍 London
#    🌡️  15°C / 59°F
#    ☁️  Partly Cloudy
#    💧 Humidity: 78%
#    💨 Wind: 19 km/h
# 
# 📍 Tokyo
#    🌡️  22°C / 72°F
#    ☁️  Sunny
#    💧 Humidity: 55%
#    💨 Wind: 12 km/h
# ...

# Step 6: Export your requirements
pip freeze > requirements.txt

# Step 7: Create a .gitignore
# File: .gitignore
venv/
__pycache__/
*.pyc
.env

Deactivating and Reusing Environments

# Deactivate when you're done
deactivate
# Your prompt returns to normal, system Python is back

# Later, come back to the project
cd my-project
source venv/bin/activate
# All your packages are exactly as you left them

# On a new computer, recreate from requirements
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# You now have the exact same environment

Best Practices

  • Always use a virtual environment for any project that installs packages (not just hello-world scripts)
  • Never commit the venv folder to Git — add venv/ to your .gitignore
  • Always commit requirements.txt — it's how others recreate your environment
  • Use exact versions (==) in requirements.txt for reproducibility
  • Update requirements.txt after installing or removing packages
  • Use one virtual environment per project — don't mix projects in one environment
  • Test with a fresh environment periodically — delete venv/, recreate from requirements.txt to ensure it still works

pip vs pip3

On many systems, both pip and pip3 exist. Inside an activated virtual environment, they both point to the same thing. Outside, pip3 is more explicit:

# These are equivalent inside an activated venv:
pip install requests
pip3 install requests

# Outside a venv, prefer pip3 for clarity:
pip3 install --user requests  # Installs to user directory
Tip: The --user flag installs packages to your user directory instead of system-wide. Useful for your personal dotfiles, but not recommended for projects — use virtual environments instead.

Summary

Virtual environments and pip are fundamental tools for every Python developer:

  • python3 -m venv venv — Create an isolated environment
  • source venv/bin/activate — Activate it (macOS/Linux)
  • pip install <package> — Install packages into the environment
  • pip freeze > requirements.txt — Export your dependencies
  • pip install -r requirements.txt — Recreate the environment anywhere
  • deactivate — Exit the virtual environment

Start using virtual environments today. Your future self — and anyone who works with your code — will thank you.
