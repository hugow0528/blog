Python Async/Await (asyncio): Do Multiple Things at Once

June 28, 2026

Imagine you're making coffee while waiting for the kettle to boil. You don't just stand there staring at it — you grab a mug, measure the coffee, maybe check your phone. That's exactly what asynchronous programming is in Python. Instead of blocking and waiting for one task to finish before starting the next, your code can do other things while waiting for I/O operations like network requests, file reads, or database queries.

Python's asyncio library (built into the standard library since Python 3.4) makes this possible with the async and await keywords. Let's walk through it from zero to running real concurrent tasks.

Why Async? The Problem with Sequential Code

Here's a simple example of sequential (blocking) code:

import time

def download_file(url):
    """Simulates a file download that takes 2 seconds."""
    print(f"Downloading {url}...")
    time.sleep(2)
    print(f"Done: {url}")

# Run three downloads one after another
download_file("file1.txt")
download_file("file2.txt")
download_file("file3.txt")

print("All done!")

This takes 6 seconds because each download must finish before the next one starts. In real life, you could download all three simultaneously. That's where async comes in.

Async/await: Your First Async Function

The key concepts:

  • async def — declares an async function (called a coroutine)
  • await — pauses the function while waiting, letting other coroutines run
  • asyncio.run() — the entry point that starts the async event loop
import asyncio

async def download_file(url):
    """Simulates a file download with async."""
    print(f"Downloading {url}...")
    await asyncio.sleep(2)  # Non-blocking wait
    print(f"Done: {url}")

# Run the async function
asyncio.run(download_file("file1.txt"))

Notice await asyncio.sleep(2) instead of time.sleep(2). The await keyword tells Python: "I'm going to wait for 2 seconds, but you can run other tasks while I wait." The asyncio.sleep() function is the async version of time.sleep() — it yields control back to the event loop instead of blocking the entire program.

Running Tasks Concurrently

Now let's run all three downloads at the same time using asyncio.gather():

import asyncio

async def download_file(url, duration=2):
    print(f"Starting {url}...")
    await asyncio.sleep(duration)
    print(f"Done: {url}")
    return url

async def main():
    # Run all three downloads concurrently
    results = await asyncio.gather(
        download_file("file1.txt"),
        download_file("file2.txt"),
        download_file("file3.txt"),
    )
    print(f"Downloaded: {results}")

asyncio.run(main())

Output:

Starting file1.txt...
Starting file2.txt...
Starting file3.txt...
Done: file1.txt
Done: file2.txt
Done: file3.txt
Downloaded: ['file1.txt', 'file2.txt', 'file3.txt']

All three downloads start immediately, and the total time is 2 seconds instead of 6! The gather() function runs all coroutines concurrently and returns their results as a list.

Real-World Example: Fetching Multiple APIs

The most common use case for async in Python is making HTTP requests. Let's use httpx, an async HTTP client:

import httpx
import asyncio

async def fetch_data(url, client):
    """Fetch data from a URL using an async HTTP client."""
    response = await client.get(url)
    response.raise_for_status()
    data = response.json()
    print(f"Got {len(data)} results from {url}")
    return data

async def main():
    # Create a shared async client with connection pooling
    async with httpx.AsyncClient() as client:
        urls = [
            "https://jsonplaceholder.typicode.com/posts",
            "https://jsonplaceholder.typicode.com/users",
            "https://jsonplaceholder.typicode.com/comments",
        ]

        # Fetch all URLs concurrently
        tasks = [fetch_data(url, client) for url in urls]
        results = await asyncio.gather(*tasks)

        for url, data in zip(urls, results):
            print(f"{url}: {len(data)} items")

asyncio.run(main())

Three API calls that might take 3 seconds total in sequential code complete in roughly the time of the slowest single call. For even more URLs, the speedup is dramatic.

asyncio.create_task() for Flexible Concurrency

While gather() works for running everything at once, sometimes you need more control. asyncio.create_task() schedules a coroutine to run in the background:

import asyncio

async def worker(name, delay):
    print(f"Worker {name} started")
    await asyncio.sleep(delay)
    print(f"Worker {name} finished after {delay}s")
    return f"Worker {name}"

async def main():
    # Create tasks — they start running immediately
    task1 = asyncio.create_task(worker("A", 1))
    task2 = asyncio.create_task(worker("B", 2))
    task3 = asyncio.create_task(worker("C", 0.5))

    print("All tasks created, waiting for results...")

    # Wait for each task to complete
    result1 = await task1
    result2 = await task2
    result3 = await task3

    print(f"Results: {result1}, {result2}, {result3}")

asyncio.run(main())

Output:

Worker A started
Worker B started
Worker C started
All tasks created, waiting for results...
Worker C finished after 0.5s
Worker A finished after 1s
Worker B finished after 2s
Results: Worker A, Worker B, Worker C

Notice the order: all workers start when created, but they finish in order of their delay. The await on each task only blocks on that specific task — others continue running in the background.

Error Handling with Async

Errors in async code need special handling. When using gather(), one failure cancels all remaining tasks by default. Use return_exceptions=True to keep running:

import asyncio

async def risky_task(name):
    if name == "B":
        raise ValueError(f"Task {name} failed!")
    await asyncio.sleep(1)
    return f"Task {name} succeeded"

async def main():
    # Catch errors without stopping other tasks
    results = await asyncio.gather(
        risky_task("A"),
        risky_task("B"),
        risky_task("C"),
        return_exceptions=True,  # Don't stop on error
    )

    for result in results:
        if isinstance(result, Exception):
            print(f"Error: {result}")
        else:
            print(f"Success: {result}")

asyncio.run(main())

Async with Timeout

Prevent slow tasks from hanging your program with asyncio.wait_for():

import asyncio

async def slow_task():
    print("Starting slow task...")
    await asyncio.sleep(10)
    return "Finally done!"

async def main():
    try:
        result = await asyncio.wait_for(slow_task(), timeout=2)
        print(result)
    except asyncio.TimeoutError:
        print("Task took too long — cancelled!")

asyncio.run(main())

Output:

Starting slow task...
Task took too long — cancelled!

When to Use Async (and When Not To)

Use async when:

  • Making many network/HTTP requests concurrently
  • Reading/writing many files at once
  • Building high-performance web servers (FastAPI, aiohttp)
  • Connecting to databases with async drivers (asyncpg, aiomysql)

Stick with regular code when:

  • Your program is CPU-bound (async doesn't help with math)
  • You only make one or two I/O calls
  • You're using libraries without async support
  • You're just starting out — learn regular Python first!

Pro tip: Async makes your code faster for I/O, but it adds complexity. Only use it when you actually have concurrent I/O to do. For CPU-intensive work, use asyncio.to_thread() or the multiprocessing module instead.

Summary

Python's asyncio lets you write concurrent programs that handle many I/O operations simultaneously without multithreading complexity. The key building blocks are:

  1. async def — define a coroutine
  2. await — pause and let other tasks run
  3. asyncio.run() — start the event loop
  4. asyncio.gather() — run multiple tasks concurrently
  5. asyncio.create_task() — schedule background tasks
  6. asyncio.wait_for() — add timeouts

With these tools, you can build programs that handle hundreds of concurrent connections — web scrapers, API clients, chat servers, and more — all in pure Python.
