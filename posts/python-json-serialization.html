Python JSON & Data Serialization: Save, Load, and Exchange Data

2026-06-28 11 min read New

JSON (JavaScript Object Notation) is the universal language of data on the web. APIs return JSON, configuration files use JSON, and your Python programs often need to save or load structured data. Python's built-in json module makes this effortless. This tutorial covers everything from basic serialization to real-world API integration.

What Is JSON?

JSON is a lightweight text format for storing and exchanging data. It uses key-value pairs, arrays, and nested structures — concepts you already know from Python dictionaries and lists.

# JSON looks like this (in a file or string):
{
    "name": "Alice",
    "age": 30,
    "hobbies": ["coding", "hiking"],
    "address": {
        "city": "Seattle",
        "zip": "98101"
    }
}

# Python equivalent (dictionary):
data = {
    "name": "Alice",
    "age": 30,
    "hobbies": ["coding", "hiking"],
    "address": {
        "city": "Seattle",
        "zip": "98101"
    }
}

The mapping is straightforward: JSON objects become Python dicts, JSON arrays become Python lists, JSON strings/numbers/booleans become Python str/int/float/bool, and null becomes None.

The Four Core Functions

The json module provides four functions. Think of them as two pairs: strings (loads/dumps) and files (load/dump).

json.dumps() — Python Object to String

dumps = "dump string". Converts a Python object into a JSON-formatted string:

import json

# Python dict → JSON string
user = {
    "name": "Alice",
    "age": 30,
    "active": True
}

json_string = json.dumps(user)
print(json_string)
# Output: {"name": "Alice", "age": 30, "active": true}

# Pretty-print with indent for readability
pretty = json.dumps(user, indent=2)
print(pretty)
# Output:
# {
#   "name": "Alice",
#   "age": 30,
#   "active": true
# }

Common arguments for dumps:

# Sort keys alphabetically (great for consistent output)
json.dumps(data, sort_keys=True)

# Pretty-print with custom indentation
json.dumps(data, indent=4)

# Ensure non-ASCII characters are preserved (not escaped)
json.dumps(data, ensure_ascii=False)

# Use a specific separator for compact output
json.dumps(data, separators=(',', ':'))

json.loads() — JSON String to Python Object

loads = "load string". Parses a JSON string back into a Python object:

import json

json_string = '{"name": "Alice", "age": 30, "active": true}'

# JSON string → Python dict
user = json.loads(json_string)

print(user["name"])      # Alice
print(user["age"])       # 30
print(type(user["age"])) # <class 'int'> — not a string!

This is especially useful when you receive JSON from an API or read it from a file as text.

json.dump() — Python Object to File

dump = "dump to file". Writes a Python object directly to a file:

import json

users = [
    {"name": "Alice", "age": 30, "role": "admin"},
    {"name": "Bob", "age": 25, "role": "user"},
    {"name": "Carol", "age": 35, "role": "user"}
]

# Write to file (creates or overwrites)
with open("users.json", "w") as f:
    json.dump(users, f, indent=2)

# The file "users.json" now contains nicely formatted JSON
print("File saved! ✓")

json.load() — File to Python Object

load = "load from file". Reads and parses a JSON file:

import json

# Read from file
with open("users.json", "r") as f:
    users = json.load(f)

print(users[0]["name"])  # Alice
print(len(users))        # 3

# Find all users with the "admin" role
admins = [u for u in users if u["role"] == "admin"]
print(admins)
# Output: [{'name': 'Alice', 'age': 30, 'role': 'admin'}]

Complete Type Conversion Reference

Understanding the type mapping prevents surprises when working with JSON data:

# Python → JSON          JSON → Python
# dict              →      object    →   dict
# list, tuple       →      array     →   list
# str               →      string    →   str
# int               →      number    →   int
# float             →      number    →   float
# True              →      true      →   True
# False             →      false     →   False
# None              →      null      →   None

Important notes: Tuples become lists (JSON has no tuple type). Sets are not supported and will raise a TypeError. You'll need to convert them first.

import json

# Sets need to be converted to lists first
tags = {"python", "json", "tutorial"}
json.dumps({"tags": list(tags)})  # Works!

# Dates aren't natively supported — convert to string
from datetime import datetime
now = datetime.now()
json.dumps({"created": now.isoformat()})  # "2026-06-28T10:30:00.123456"

Handling Errors Gracefully

JSON data might be malformed, missing keys, or have unexpected types. Always handle these cases:

import json

# Handle invalid JSON
bad_data = '{"name": "Alice", age: 30}'  # Missing quotes around "age"

try:
    user = json.loads(bad_data)
except json.JSONDecodeError as e:
    print(f"Invalid JSON: {e}")
    # Output: Invalid JSON: Expecting property name enclosed in double quotes

# Handle missing keys safely
user = {"name": "Alice"}
age = user.get("age", 0)  # Returns 0 if "age" doesn't exist

# Handle nested data safely
user = {"name": "Alice", "address": {"city": "Seattle"}}
zip_code = user.get("address", {}).get("zip", "Unknown")
# Returns "Unknown" — no KeyError!

Real-World Project: JSON Configuration Manager

Let's build a practical utility that manages application settings in a JSON file. This pattern is used in countless real projects:

import json
import os

CONFIG_FILE = "app_config.json"
DEFAULT_CONFIG = {
    "app_name": "MyApp",
    "version": "1.0.0",
    "debug": False,
    "database": {
        "host": "localhost",
        "port": 5432,
        "name": "mydb"
    },
    "features": {
        "notifications": True,
        "dark_mode": True,
        "analytics": False
    }
}

def load_config():
    """Load config from file, or create default if missing."""
    if os.path.exists(CONFIG_FILE):
        with open(CONFIG_FILE, "r") as f:
            config = json.load(f)
        print(f"Config loaded from {CONFIG_FILE}")
        return config
    else:
        config = DEFAULT_CONFIG.copy()
        save_config(config)
        print(f"Default config created at {CONFIG_FILE}")
        return config

def save_config(config):
    """Save config to file with pretty formatting."""
    with open(CONFIG_FILE, "w") as f:
        json.dump(config, f, indent=2)
    print(f"Config saved to {CONFIG_FILE}")

def update_config(config, section, key, value):
    """Update a nested config value like config.database.host"""
    if section in config:
        config[section][key] = value
        save_config(config)
        print(f"Updated {section}.{key} = {value}")
    else:
        print(f"Section '{section}' not found")

# ---- Use it ----
config = load_config()
print(config["database"]["host"])  # localhost

update_config(config, "database", "host", "db.production.com")
update_config(config, "features", "analytics", True)
update_config(config, "database", "port", 3306)

# Final config file contains:
# {
#   "app_name": "MyApp",
#   "database": {
#     "host": "db.production.com",
#     "port": 3306,
#     "name": "mydb"
#   },
#   ...
# }

Real-World Project: Fetch & Save API Data

Combine JSON with the requests library to fetch and store API data. This is one of the most common patterns in Python development:

import json
import requests

# Fetch data from a public API
response = requests.get(
    "https://jsonplaceholder.typicode.com/posts?_limit=5"
)

# Check for errors
if response.status_code == 200:
    posts = response.json()  # Built-in JSON parsing!
    
    # Save to local file for offline use
    with open("posts_cache.json", "w") as f:
        json.dump(posts, f, indent=2)
    print(f"Cached {len(posts)} posts ✓")
    
    # Process the data
    for post in posts:
        print(f"#{post['id']} — {post['title'][:40]}...")
else:
    print(f"API error: {response.status_code}")

# Later — load cached data instead of hitting the API
with open("posts_cache.json", "r") as f:
    posts = json.load(f)

# Search for posts containing "lorem"
lorem_posts = [p for p in posts if "lorem" in p["body"].lower()]
print(f"Found {len(lorem_posts)} posts with 'lorem'")

Custom JSON Encoding with a Converter Class

When you need to serialize objects that aren't natively JSON-compatible (like datetime, sets, or custom classes), extend json.JSONEncoder:

import json
from datetime import datetime, date

class CustomEncoder(json.JSONEncoder):
    """Custom JSON encoder for unsupported types."""
    
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        if isinstance(obj, date):
            return obj.isoformat()
        if isinstance(obj, set):
            return list(obj)
        if isinstance(obj, bytes):
            return obj.decode("utf-8")
        return super().default(obj)

# Use the custom encoder
data = {
    "created": datetime.now(),
    "tags": {"python", "json", "tutorial"},
    "raw": b"binary data"
}

output = json.dumps(data, cls=CustomEncoder, indent=2)
print(output)
# {
#   "created": "2026-06-28T10:30:00.123456",
#   "tags": ["json", "python", "tutorial"],
#   "raw": "binary data"
# }

Best Practices Summary

1. Use json.load()/dump() for files — simpler than read/write + loads/dumps
2. Always use indent=2 for human-readable config files
3. Use sort_keys=True for consistent output (great for diffing)
4. Wrap json.loads() in try/except JSONDecodeError for safety
5. Use dict.get() with defaults to avoid KeyError on missing keys
6. Convert unsupported types (datetime, set) before serialization
7. Never trust external JSON — validate structure before processing
8. Cache API responses as JSON files to avoid repeated network calls
9. Use requests.json() instead of json.loads(response.text) when possible
