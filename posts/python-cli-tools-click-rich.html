Python CLI Tools: Build Beautiful Command-Line Apps with Click and Rich

July 2, 2026 10 min read New

Every developer loves a well-built CLI tool. git, docker, terraform — they all share something: intuitive commands, clear output, and helpful error messages. In this guide, you'll learn to build your own professional CLI tool in Python using two libraries: Click for argument parsing and Rich for beautiful terminal output.

Why Click and Rich?

Python has argparse in the standard library, but it gets verbose fast. Click provides a declarative, decorator-based approach that reads like documentation. Rich adds tables, progress bars, colors, and formatting that make your CLI look like a native app.

Install both libraries:

pip install click rich

Your First CLI Tool with Click

Let's start simple. Create hello.py:

import click

@click.command()
@click.option('--name', '-n', default='World', help='Name to greet')
@click.option('--count', '-c', default=1, type=int, help='Number of greetings')
def hello(name, count):
    """Say hello to someone, multiple times."""
    for _ in range(count):
        click.echo(f"Hello, {name}!")

if __name__ == '__main__':
    hello()

Run it with different arguments:

$ python hello.py --name Hugo --count 3
Hello, Hugo!
Hello, Hugo!
Hello, Hugo!

$ python hello.py --help
Usage: hello.py [OPTIONS]

  Say hello to someone, multiple times.

Options:
  -n, --name TEXT  Name to greet
  -c, --count INTEGER  Number of greetings
  --help            Show this message and exit.

Notice that Click automatically generates a --help message from your docstring. No manual argument parsing needed.

Adding Beautiful Output with Rich

Now let's make it look good. Replace click.echo() with Rich's print():

from rich.console import Console
from rich.table import Table
from rich.progress import Progress, SpinnerColumn, TextColumn
import click

console = Console()

@click.command()
@click.argument('files', nargs=-1, type=click.Path(exists=True))
def analyze(files):
    """Analyze files and show stats in a beautiful table."""
    table = Table(title="File Analysis Report")
    table.add_column("File", style="cyan")
    table.add_column("Size", style="magenta", justify="right")
    table.add_column("Lines", style="green", justify="right")

    for filepath in files:
        with open(filepath) as f:
            content = f.read()
        lines = len(content.splitlines())
        size = len(content)
        table.add_row(filepath, f"{size:,} B", str(lines))

    console.print(table)
    console.print(f"\n[bold green]✓ Analyzed {len(files)} files[/bold green]")

if __name__ == '__main__':
    analyze()

Running this produces a formatted table with colored columns — something that would take 50+ lines with just standard library tools.

Subcommands: The Git Pattern

Most CLI tools have subcommands. Click handles this with @click.group():

import click
from rich.console import Console

console = Console()

@click.group()
@click.version_option(version="1.0.0")
def cli():
    """MyTool - A sample CLI application."""
    pass

@cli.command()
@click.argument('name')
def create(name):
    """Create a new resource."""
    console.print(f"[bold yellow]Creating[/bold yellow] [cyan]{name}[/cyan]...")
    console.print("[bold green]✓ Created successfully![/bold green]")

@cli.command()
@click.argument('name')
@click.option('--force', '-f', is_flag=True, help='Force deletion')
def delete(name, force):
    """Delete a resource."""
    if not force:
        confirm = click.confirm(f"Delete '{name}'?")
        if not confirm:
            console.print("[dim]Cancelled.[/dim]")
            return
    console.print(f"[bold red]Deleted[/bold red] [cyan]{name}[/cyan]")

@cli.command('list')
def list_resources():
    """List all resources."""
    console.print("[dim]No resources found.[/dim]")

if __name__ == '__main__':
    cli()

Now you have a CLI with create, delete, and list subcommands, plus a --version flag and interactive confirmation for destructive actions.

Progress Bars and Spinners

Loading indicators keep users informed during long operations:

from rich.progress import Progress, SpinnerColumn, BarColumn, TextColumn
import time

def long_operation():
    """Simulate a multi-step process."""
    tasks = [
        "Fetching data from API",
        "Processing records",
        "Generating report",
        "Uploading results"
    ]

    with Progress(
        SpinnerColumn(),
        TextColumn("[progress.description]{task.description}"),
        BarColumn(),
        TextColumn("{task.percentage:>3.0f}%"),
    ) as progress:
        for task_name in tasks:
            task_id = progress.add_task(task_name, total=100)
            for i in range(100):
                progress.update(task_id, advance=1)
                time.sleep(0.02)

long_operation()

This produces an animated progress bar with a spinner, percentage, and description — just like pip install or docker pull.

Configuration Files

Professional tools let users set defaults in a config file. Here's how to support .mytool.yaml:

import click
import yaml

def load_config(ctx):
    """Load config file if it exists."""
    config_file = ctx.params.get('config') or '.mytool.yaml'
    config = {}

    if os.path.exists(config_file):
        with open(config_file) as f:
            config = yaml.safe_load(f) or {}

    ctx.obj = config

@click.command()
@click.option('--config', '-c', help='Path to config file')
@click.option('--output', '-o', help='Output directory')
@click.pass_context
def main(ctx, config, output):
    """Main command."""
    # Merge CLI args with config
    output = output or ctx.obj.get('output', './output')
    ctx.obj['output'] = output

    click.echo(f"Output will go to: {output}")

if __name__ == '__main__':
    main()

Users can create a .mytool.yaml in their project:

# .mytool.yaml
output: /tmp/results
verbose: true
format: json

Real-World Project: Docker Container Monitor

Let's combine everything into a practical tool that monitors Docker containers:

#!/usr/bin/env python3
import click
import subprocess
import json
from rich.console import Console
from rich.table import Table
from rich.panel import Panel
from rich import box

console = Console()

@click.group()
def cli():
    """Container Monitor - Quick Docker status at a glance."""
    pass

@cli.command()
def status():
    """Show container status overview."""
    try:
        result = subprocess.run(
            ["docker", "ps", "--format", "{{json .}}"],
            capture_output=True, text=True
        )
    except FileNotFoundError:
        console.print("[bold red]Docker not found. Is it installed?[/bold red]")
        return

    if not result.stdout.strip():
        console.print("[dim]No running containers.[/dim]")
        return

    table = Table(box=box.ROUNDED, title="Running Containers")
    table.add_column("Name", style="bold cyan")
    table.add_column("Image", style="magenta")
    table.add_column("Status", style="green")
    table.add_column("Ports", style="yellow")

    for line in result.stdout.strip().split("\n"):
        container = json.loads(line)
        table.add_row(
            container.get("Names", ""),
            container.get("Image", ""),
            container.get("Status", ""),
            container.get("Ports", "")
        )

    console.print(table)

@cli.command()
@click.argument('name')
def logs(name):
    """Show recent logs from a container."""
    result = subprocess.run(
        ["docker", "logs", "--tail", "50", name],
        capture_output=True, text=True
    )
    console.print(Panel(result.stdout, title=f"[bold]{name}[/bold] logs"))

if __name__ == '__main__':
    cli()

Packaging Your CLI Tool

Make it installable with pip. Create pyproject.toml:

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "my-tool"
version = "1.0.0"
description = "A beautiful CLI tool"
dependencies = ["click>=8.0", "rich>=10.0"]

[project.scripts]
my-tool = "my_tool.cli:cli"

After pip install -e ., users run my-tool --help from anywhere. Publish to PyPI to share it with the world.

Best Practices

  • Always provide --help: Click does this automatically from docstrings
  • Use consistent naming: kebab-case for CLI args (Click converts to snake_case)
  • Show progress for long operations: Users hate staring at a blank terminal
  • Respect NO_COLOR: Rich auto-detects this environment variable
  • Handle errors gracefully: Use try/except with Rich error panels
  • Support --verbose and --quiet flags: Let users control output

Summary

Click handles the hard work of argument parsing, subcommands, and help text. Rich transforms boring terminal output into professional-looking reports. Together, they let you build CLI tools that feel like the best Unix utilities — with a fraction of the code.

Start small with a single command, add Rich formatting early (it makes debugging easier too), and grow your tool into something you'll actually want to use every day.
