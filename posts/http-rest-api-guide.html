HTTP & REST APIs: Understanding the Web's Language

June 28, 2026 12 min read

Every time you visit a website, submit a form, or use a mobile app, HTTP is working behind the scenes. HTTP (Hypertext Transfer Protocol) is the language that powers the entire web. Understanding it is essential for any developer, whether you're building websites, APIs, or debugging network problems.

This guide covers everything from basic HTTP methods to building and consuming REST APIs, with practical examples in Python and JavaScript that you can run today.

What Is HTTP?

HTTP is a request-response protocol. A client (like your browser or a Python script) sends a request to a server, and the server sends back a response. That's it — but the details matter.

Every HTTP request has four main parts:

  • Method — What action to perform (GET, POST, PUT, DELETE)
  • URL/Path — Which resource to act on
  • Headers — Metadata about the request (content type, authentication, etc.)
  • Body — Optional data sent to the server

Every HTTP response has three main parts:

  • Status code — What happened (200 = success, 404 = not found)
  • Headers — Metadata about the response
  • Body — The actual data (HTML, JSON, an image, etc.)

HTTP Methods (Verbs)

HTTP methods define what you want to do with a resource. Think of them like database operations:

# GET — Read data (like SELECT)
GET /api/users/42

# POST — Create new data (like INSERT)
POST /api/users
Body: {"name": "Hugo", "email": "hugo@example.com"}

# PUT — Replace existing data entirely (like UPDATE full record)
PUT /api/users/42
Body: {"name": "Hugo", "email": "hugo@newdomain.com"}

# PATCH — Partially update data (like UPDATE specific columns)
PATCH /api/users/42
Body: {"email": "hugo@newdomain.com"}

# DELETE — Remove data (like DELETE)
DELETE /api/users/42

Memory trick: Think of CRUD — Create (POST), Read (GET), Update (PUT/PATCH), Delete (DELETE).

HTTP Status Codes

Status codes tell you what happened. They fall into five categories:

1xx — Informational  (100 Continue, 101 Switching Protocols)
2xx — Success         (200 OK, 201 Created, 204 No Content)
3xx — Redirection     (301 Moved Permanently, 302 Found, 304 Not Modified)
4xx — Client Error    (400 Bad Request, 401 Unauthorized, 403 Forbidden,
                       404 Not Found, 405 Method Not Allowed, 429 Too Many Requests)
5xx — Server Error    (500 Internal Server Error, 502 Bad Gateway,
                       503 Service Unavailable)

The most important ones to memorize:

  • 200 — Everything worked
  • 201 — New resource created
  • 304 — Use your cached copy (browser optimization)
  • 401 — You're not logged in (Authentication)
  • 403 — You're logged in but can't do that (Authorization)
  • 404 — Resource doesn't exist
  • 422 — Your data format is wrong (common in API validation)
  • 429 — You're making requests too fast (rate limited)
  • 500 — Server crashed, not your fault

HTTP Headers: The Metadata

Headers carry important information that isn't the actual content. Here are the most common ones:

# Common request headers
Accept: application/json           # "I want JSON back"
Content-Type: application/json     # "I'm sending JSON"
Authorization: Bearer abc123token  # "Here's my API key"
User-Agent: Mozilla/5.0            # "Here's what browser/tool I'm using"
X-Request-ID: unique-id            # "Track this specific request"

# Common response headers
Content-Type: application/json     # "Here's your JSON"
Cache-Control: max-age=3600        # "Cache this for 1 hour"
Set-Cookie: session=abc123         # "Save this cookie"
X-RateLimit-Remaining: 49          # "You have 49 requests left"
Content-Length: 2048               # "The body is 2048 bytes"

Making API Requests with curl

curl is a command-line tool for making HTTP requests. It's pre-installed on most computers and is the universal debugging tool for APIs.

# GET request — fetch data
curl https://jsonplaceholder.typicode.com/posts/1

# GET with custom headers
curl -H "Accept: application/json" \
     -H "Authorization: Bearer your-token" \
     https://api.example.com/users

# POST request — send JSON data
curl -X POST https://jsonplaceholder.typicode.com/posts \
     -H "Content-Type: application/json" \
     -d '{"title": "Hello", "body": "World", "userId": 1}'

# PUT request — update data
curl -X PUT https://jsonplaceholder.typicode.com/posts/1 \
     -H "Content-Type: application/json" \
     -d '{"title": "Updated Title", "body": "New body text"}'

# DELETE request — remove data
curl -X DELETE https://jsonplaceholder.typicode.com/posts/1

# Save response to a file
curl -o response.json https://jsonplaceholder.typicode.com/posts

Key curl flags: -X sets the method, -H adds headers, -d sends data, -o saves output, and -v shows verbose details including all headers.

Consuming APIs in Python with requests

The requests library is the most popular way to make HTTP calls in Python. Install it with pip install requests.

import requests

# GET request
response = requests.get("https://jsonplaceholder.typicode.com/posts/1")
print(response.status_code)  # 200
print(response.json())       # Parse JSON response as dict
# {'userId': 1, 'id': 1, 'title': '...', 'body': '...'}

# POST request — create new resource
data = {"title": "My Post", "body": "Hello World!", "userId": 1}
response = requests.post(
    "https://jsonplaceholder.typicode.com/posts",
    json=data,              # Automatically sets Content-Type and serializes
    timeout=10              # Don't wait forever
)
print(response.status_code) # 201 Created
print(response.json())      # Returns the created post with an 'id'

# Handling errors
response = requests.get("https://jsonplaceholder.typicode.com/posts/999999")
if response.status_code == 404:
    print("Resource not found!")
elif response.status_code != 200:
    print(f"Unexpected error: {response.status_code}")
else:
    print(response.json())

# Raise an exception on any error (recommended)
try:
    response = requests.get(
        "https://jsonplaceholder.typicode.com/posts/1",
        timeout=5
    )
    response.raise_for_status()  # Raises HTTPError if status >= 400
    print(response.json())
except requests.exceptions.Timeout:
    print("Request timed out!")
except requests.exceptions.ConnectionError:
    print("Check your internet connection!")
except requests.exceptions.HTTPError as e:
    print(f"HTTP error: {e}")

Working with API Authentication

Most real APIs require authentication. Here are the most common patterns:

import requests

# 1. API Key in header
response = requests.get(
    "https://api.example.com/data",
    headers={"X-API-Key": "your-secret-key"}
)

# 2. Bearer Token (OAuth / JWT)
response = requests.get(
    "https://api.example.com/protected",
    headers={"Authorization": "Bearer eyJhbGciOi..."}
)

# 3. Basic Auth (username/password encoded)
response = requests.get(
    "https://api.example.com/data",
    auth=("username", "password")
)

# 4. Session-based (cookies)
session = requests.Session()
session.post("https://api.example.com/login", json={"user": "me", "pass": "***"})
response = session.get("https://api.example.com/profile")  # Cookie sent automatically

Fetch API in JavaScript

Browsers have a built-in fetch API for making HTTP requests. No libraries needed.

// GET request
fetch('https://jsonplaceholder.typicode.com/posts/1')
    .then(response => {
        if (!response.ok) {
            throw new Error(`HTTP error: ${response.status}`);
        }
        return response.json();
    })
    .then(data => console.log(data))
    .catch(error => console.error('Request failed:', error));

// GET with async/await (cleaner syntax)
async function getPost(id) {
    const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`);
    if (!response.ok) {
        throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }
    return await response.json();
}

// POST request
async function createPost(title, body) {
    const response = await fetch('https://jsonplaceholder.typicode.com/posts', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
        },
        body: JSON.stringify({ title, body, userId: 1 }),
    });
    return await response.json();
}

// Using AbortController to cancel requests
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 5000); // 5 second timeout

try {
    const response = await fetch('https://api.example.com/data', {
        signal: controller.signal,
    });
} catch (error) {
    if (error.name === 'AbortError') {
        console.log('Request was cancelled');
    }
}
clearTimeout(timeoutId);

REST API Design Principles

When you build APIs, REST (Representational State Transfer) provides conventions that make APIs predictable and easy to use. Key principles:

  • Use nouns for resources, not verbs. /api/users, not /api/getUsers
  • Use HTTP methods for actions. GET to read, POST to create, PUT to update, DELETE to remove
  • Nest resources to show relationships. /api/users/42/posts for user 42's posts
  • Use proper status codes. 200 for success, 201 for created, 404 for not found, etc.
  • Return JSON as your default format
  • Support pagination. Don't return 10,000 records at once
  • Be consistent. Use the same patterns throughout your API

Practical Project: Building a Simple REST API

Let's build a mini API using Flask that follows REST conventions:

# pip install flask

from flask import Flask, request, jsonify

app = Flask(__name__)

# In-memory "database"
tasks = [
    {"id": 1, "title": "Learn HTTP", "done": True},
    {"id": 2, "title": "Build REST API", "done": False},
]
next_id = 3

@app.route('/api/tasks', methods=['GET'])
def get_tasks():
    """GET /api/tasks — Return all tasks"""
    return jsonify(tasks), 200

@app.route('/api/tasks/', methods=['GET'])
def get_task(task_id):
    """GET /api/tasks/1 — Return a specific task"""
    task = next((t for t in tasks if t["id"] == task_id), None)
    if task is None:
        return jsonify({"error": "Task not found"}), 404
    return jsonify(task), 200

@app.route('/api/tasks', methods=['POST'])
def create_task():
    """POST /api/tasks — Create a new task"""
    global next_id
    data = request.get_json()

    if not data or "title" not in data:
        return jsonify({"error": "Title is required"}), 400

    task = {
        "id": next_id,
        "title": data["title"],
        "done": False,
    }
    tasks.append(task)
    next_id += 1
    return jsonify(task), 201

@app.route('/api/tasks/', methods=['PUT'])
def update_task(task_id):
    """PUT /api/tasks/1 — Update a task"""
    task = next((t for t in tasks if t["id"] == task_id), None)
    if task is None:
        return jsonify({"error": "Task not found"}), 404

    data = request.get_json()
    if "title" in data:
        task["title"] = data["title"]
    if "done" in data:
        task["done"] = data["done"]

    return jsonify(task), 200

@app.route('/api/tasks/', methods=['DELETE'])
def delete_task(task_id):
    """DELETE /api/tasks/1 — Remove a task"""
    global tasks
    task = next((t for t in tasks if t["id"] == task_id), None)
    if task is None:
        return jsonify({"error": "Task not found"}), 404

    tasks = [t for t in tasks if t["id"] != task_id]
    return jsonify({"message": "Task deleted"}), 200

if __name__ == '__main__':
    app.run(debug=True, port=5000)

Run it with python app.py, then test it:

# {"id": 1, "title": "Learn HTTP", "done": true}

# {"id": 1, "title": "Learn HTTP", "done": true}

curl -X DELETE http://localhost:5000/api/tasks/1
# {"message": "Task deleted"}

API Best Practices

Whether you're building or consuming APIs, follow these practices:

  • Always set timeouts — never wait forever for a response
  • Handle errors gracefully — network calls fail; your code should survive
  • Use HTTPS everywhere — never send credentials over plain HTTP
  • Don't hardcode API keys — use environment variables
  • Respect rate limits — check X-RateLimit headers and back off
  • Cache responses — use Cache-Control headers to avoid redundant requests
  • Validate input — check that required fields exist and have correct types
  • Version your APIs — use /api/v1/users so you can make breaking changes later

Summary

HTTP is the foundation of web communication. The key concepts to remember:

  • Methods (GET, POST, PUT, DELETE) define the action
  • Status codes (200, 404, 500) tell you the result
  • Headers carry metadata (authentication, content type, caching)
  • REST conventions make APIs predictable and intuitive
  • curl is your best debugging tool
  • requests (Python) and fetch (JavaScript) make API calls simple

Understanding HTTP deeply will make you a better developer — you'll debug faster, build better APIs, and understand the tools and frameworks you use. The next time you see a 404 or a 500, you'll know exactly what happened.
