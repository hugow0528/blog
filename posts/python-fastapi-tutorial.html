Python FastAPI Tutorial: Build Your First REST API in 30 Minutes

July 2, 2026 · 12 min read

You've learned Python basics — variables, functions, loops, and maybe APIs as a client. Now let's flip the script and build your own API. FastAPI is the modern Python web framework that makes this shockingly simple.

FastAPI is fast (literally — one of the fastest Python frameworks), generates automatic API documentation, handles data validation for free, and supports async out of the box. It's the go-to framework for Python microservices in 2026.

Why FastAPI Over Flask or Django?

  • Flask is great for small projects but requires extra packages for validation, serialization, and OpenAPI docs
  • Django is a full-stack framework with ORM, admin panel, and auth — but that's overkill for an API
  • FastAPI hits the sweet spot: lightweight, type-driven validation, auto-generated docs, and async support

Step 1: Set Up the Project

First, create a project directory and virtual environment:

# Create project
mkdir myapi && cd myapi

# Virtual environment
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install fastapi uvicorn pydantic

What's what:

  • FastAPI — the web framework
  • uvicorn — the ASGI server that runs FastAPI
  • pydantic — data validation (bundled with FastAPI)

Step 2: Your First Endpoint

Create a file called main.py:

from fastapi import FastAPI

app = FastAPI(title="My First API")

@app.get("/")
def root():
    return {"message": "Hello, API!", "status": "running"}

@app.get("/health")
def health_check():
    return {"status": "healthy"}

Run it:

uvicorn main:app --reload

The --reload flag restarts the server whenever you change code (development only!). Visit http://localhost:8000 and you'll see your JSON response. But wait — visit http://localhost:8000/docs and you'll see auto-generated API documentation. That's FastAPI magic.

Step 3: Path Parameters and Query Parameters

Let's add endpoints that accept input:

from fastapi import FastAPI, Query

app = FastAPI()

# Path parameter — the ID is part of the URL
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id, "name": "Hugo", "email": "hugo@example.com"}

# Query parameters — passed as ?key=value
@app.get("/search")
def search(q: str = Query(..., min_length=1, description="Search term"),
           limit: int = Query(10, ge=1, le=100),
           page: int = Query(1, ge=1)):
    offset = (page - 1) * limit
    return {
        "query": q,
        "limit": limit,
        "page": page,
        "offset": offset,
        "results": []
    }

Try these URLs:

  • /users/42 — path parameter (user_id = 42)
  • /search?q=python&limit=5&page=2 — query parameters
  • /search?q= — FastAPI automatically returns a 422 error because of min_length=1

Notice how limit: int = Query(10, ge=1, le=100) validates the input. If someone sends limit=-5 or limit=200, FastAPI rejects it with a clear error message. No manual validation needed.

Step 4: Request Bodies with Pydantic Models

This is where FastAPI really shines. Define your data model once, and FastAPI handles validation, documentation, and serialization:

from pydantic import BaseModel, EmailStr, Field
from typing import Optional

class UserCreate(BaseModel):
    email: EmailStr
    full_name: str = Field(..., min_length=1, max_length=100)
    age: Optional[int] = Field(None, ge=0, le=150)

    class Config:
        json_schema_extra = {
            "example": {
                "email": "hugo@example.com",
                "full_name": "Hugo Wong",
                "age": 28
            }
        }

class UserResponse(BaseModel):
    id: int
    email: str
    full_name: str
    age: Optional[int]

    class Config:
        from_attributes = True  # Allows loading from ORM objects

@app.post("/users", status_code=201)
def create_user(user: UserCreate):
    # In a real app, you'd save to a database here
    new_user = {
        "id": 1,
        "email": user.email,
        "full_name": user.full_name,
        "age": user.age
    }
    return new_user

Test it with curl:

curl -X POST http://localhost:8000/users \
  -H "Content-Type: application/json" \
  -d '{"email": "hugo@example.com", "full_name": "Hugo Wong", "age": 28}'

# Returns: {"id": 1, "email": "hugo@example.com", "full_name": "Hugo Wong", "age": 28}

# Try bad data:
curl -X POST http://localhost:8000/users \
  -H "Content-Type: application/json" \
  -d '{"email": "not-an-email", "full_name": ""}'

# Returns 422 with detailed validation errors!

The EmailStr type automatically validates email format. The Field(..., ge=0, le=150) constrains age. FastAPI returns structured error messages for every validation failure.

Step 5: Add a Database with SQLAlchemy

Let's make our API persistent. Install the async database dependencies:

pip install sqlalchemy aiosqlite alembic

Create database.py for the connection:

from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from sqlalchemy.orm import DeclarativeBase

# SQLite for development — swap to PostgreSQL for production
DATABASE_URL = "sqlite+aiosqlite:///./app.db"

engine = create_async_engine(DATABASE_URL, echo=True)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

class Base(DeclarativeBase):
    pass

async def get_db():
    async with async_session() as session:
        yield session

Create models.py for your tables:

from sqlalchemy import Column, Integer, String, Boolean
from database import Base

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True, index=True)
    email = Column(String(255), unique=True, nullable=False, index=True)
    full_name = Column(String(100), nullable=False)
    age = Column(Integer, nullable=True)
    is_active = Column(Boolean, default=True)

Create crud.py for database operations:

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from models import User

async def get_user(db: AsyncSession, user_id: int):
    result = await db.execute(select(User).where(User.id == user_id))
    return result.scalar_one_or_none()

async def get_user_by_email(db: AsyncSession, email: str):
    result = await db.execute(select(User).where(User.email == email))
    return result.scalar_one_or_none()

async def create_user(db: AsyncSession, email: str, full_name: str, age: int = None):
    user = User(email=email, full_name=full_name, age=age)
    db.add(user)
    await db.commit()
    await db.refresh(user)
    return user

async def list_users(db: AsyncSession, skip: int = 0, limit: int = 100):
    result = await db.execute(select(User).offset(skip).limit(limit))
    return result.scalars().all()

async def delete_user(db: AsyncSession, user_id: int):
    user = await get_user(db, user_id)
    if user:
        await db.delete(user)
        await db.commit()
        return True
    return False

Now wire everything together in main.py:

from fastapi import FastAPI, Depends, HTTPException
from sqlalchemy.ext.asyncio import AsyncSession
from database import get_db, engine, Base
from models import User
from crud import get_user, get_user_by_email, create_user, list_users, delete_user
from schemas import UserCreate, UserResponse

app = FastAPI(title="User API")

# Create tables on startup
@app.on_event("startup")
async def startup():
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

@app.post("/users", response_model=UserResponse, status_code=201)
async def create_user_endpoint(user: UserCreate, db: AsyncSession = Depends(get_db)):
    existing = await get_user_by_email(db, user.email)
    if existing:
        raise HTTPException(status_code=400, detail="Email already registered")
    
    db_user = await create_user(db, email=user.email, full_name=user.full_name, age=user.age)
    return db_user

@app.get("/users", response_model=list[UserResponse])
async def get_users(skip: int = 0, limit: int = 100, db: AsyncSession = Depends(get_db)):
    return await list_users(db, skip=skip, limit=limit)

@app.get("/users/{user_id}", response_model=UserResponse)
async def get_user_endpoint(user_id: int, db: AsyncSession = Depends(get_db)):
    user = await get_user(db, user_id)
    if not user:
        raise HTTPException(status_code=404, detail="User not found")
    return user

@app.delete("/users/{user_id}", status_code=204)
async def delete_user_endpoint(user_id: int, db: AsyncSession = Depends(get_db)):
    success = await delete_user(db, user_id)
    if not success:
        raise HTTPException(status_code=404, detail="User not found")

The Depends(get_db) pattern is FastAPI's dependency injection. It automatically creates a database session, yields it to your endpoint, and closes it afterward. Clean separation of concerns.

Step 6: Add Error Handling Middleware

Professional APIs handle errors gracefully. Add middleware for consistent error responses:

from fastapi import Request, status
from fastapi.responses import JSONResponse
from fastapi.exceptions import RequestValidationError

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
        content={
            "error": "Validation failed",
            "details": exc.errors()
        }
    )

@app.exception_handler(HTTPException)
async def http_exception_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"error": exc.detail}
    )

Step 7: Run It

uvicorn main:app --reload

Visit the auto-generated docs at:

  • Swagger UI: http://localhost:8000/docs — interactive API explorer
  • ReDoc: http://localhost:8000/redoc — clean reference docs

Both are generated automatically from your type hints and Pydantic models. No extra configuration needed.

Next Steps

You now have a working REST API with data validation, database persistence, and auto-generated docs. Here's where to go next:

  • Authentication: Add JWT-based auth with python-jose and passlib
  • Production database: Swap SQLite for PostgreSQL with asyncpg
  • Migrations: Use alembic to manage database schema changes
  • Docker: Containerize with a Dockerfile and docker-compose.yml
  • Background tasks: Use FastAPI's BackgroundTasks for email sending
  • Testing: Use httpx with FastAPI's TestClient

FastAPI is one of those frameworks where the learning curve is gentle but the ceiling is high. Start with simple endpoints like we did here, and gradually add complexity — auth, caching, background tasks, WebSocket support. The type-driven approach means your code is always self-documenting and self-validating.
