Python Threading and Multiprocessing: Speed Up Your Code with Concurrency — Complete Beginner's Guide

July 18, 2026 12 min read

Your Python scripts run great for one task at a time. But what happens when you need to download 100 files, process 1000 images, or serve 1000 concurrent API requests? Running things one after another (sequentially) just won't cut it. This is where concurrency and parallelism come in — and Python gives you two powerful tools: threading and multiprocessing.

In this guide, you'll learn when to use each approach, how to share data safely between threads and processes, and how to build real concurrent programs. Every concept comes with working code you can copy and run.

Why Concurrency Matters

Imagine you're downloading 10 web pages. Doing it sequentially means waiting for page 1 to finish, then page 2, and so on. If each download takes 2 seconds, that's 20 seconds total. With concurrency, you can download all 10 simultaneously — finishing in about 2 seconds instead.

But Python has a twist: the Global Interpreter Lock (GIL). The GIL prevents multiple threads from executing Python bytecode simultaneously in the same process. This means:

  • Threading is great for I/O-bound tasks (network calls, file reads, database queries) because threads release the GIL while waiting.
  • Multiprocessing is needed for CPU-bound tasks (math, image processing, data analysis) because each process has its own Python interpreter and its own GIL.

Quick Demo: Sequential vs Concurrent

Let's see the difference in action. Here's a sequential version that "downloads" 5 URLs:

import time

def download_url(url):
    """Simulate downloading a URL (takes 2 seconds)"""
    print(f"Downloading {url}...")
    time.sleep(2)
    print(f"Done: {url}")
    return f"Content of {url}"

urls = [f"https://example.com/page{i}" for i in range(1, 6)]

start = time.time()
for url in urls:
    download_url(url)
print(f"Sequential: {time.time() - start:.1f} seconds")
# Output: ~10.0 seconds

Now the same logic with ThreadPoolExecutor:

import time
from concurrent.futures import ThreadPoolExecutor

def download_url(url):
    print(f"Downloading {url}...")
    time.sleep(2)
    print(f"Done: {url}")
    return f"Content of {url}"

urls = [f"https://example.com/page{i}" for i in range(1, 6)]

start = time.time()
with ThreadPoolExecutor(max_workers=5) as executor:
    results = list(executor.map(download_url, urls))
print(f"Concurrent: {time.time() - start:.1f} seconds")
# Output: ~2.0 seconds!

Five times faster with three lines of changed code. Let's learn how this works under the hood.

Threading: The Basics

The threading module lets you create lightweight threads within the same process. Threads share the same memory space, which makes communication easy — but also introduces the risk of data races.

Creating and Starting a Thread

import threading
import time

def worker(name, duration):
    """A thread worker that prints its name periodically"""
    print(f"Thread {name} starting")
    for i in range(3):
        print(f"  {name}: working on task {i+1}")
        time.sleep(duration)
    print(f"Thread {name} finished")

# Create threads
t1 = threading.Thread(target=worker, args=("A", 0.5))
t2 = threading.Thread(target=worker, args=("B", 0.7))

# Start them
t1.start()
t2.start()

# Wait for both to finish
t1.join()
t2.join()

print("All threads done!")

Key concepts here:

  • threading.Thread(target=func, args=(...)) creates a thread
  • .start() begins execution in a new thread
  • .join() blocks the calling thread until the target thread finishes

Thread Safety with Locks

When multiple threads modify the same variable, you get a race condition — unpredictable results because operations interleave. Here's the problem:

import threading

counter = 0

def unsafe_increment():
    global counter
    for _ in range(100000):
        counter += 1  # NOT atomic! read -> add -> write

threads = [threading.Thread(target=unsafe_increment) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()

print(f"Counter = {counter}")  # Expected: 400000, actual: ?

The output is not 400000. It might be 310482, or 287651 — it varies each run. The fix is a Lock:

import threading

counter = 0
lock = threading.Lock()

def safe_increment():
    global counter
    for _ in range(100000):
        with lock:  # Only one thread enters at a time
            counter += 1

threads = [threading.Thread(target=safe_increment) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()

print(f"Counter = {counter}")  # Always 400000 ✓

The with lock: context manager acquires the lock before entering and releases it after exiting, even if an exception occurs.

Thread Pools with ThreadPoolExecutor

Manually creating and managing threads is error-prone. The concurrent.futures module provides a cleaner API:

from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request
import time

def fetch_page(url):
    """Download a URL and return its content length"""
    try:
        with urllib.request.urlopen(url, timeout=5) as response:
            data = response.read()
            return url, len(data)
    except Exception as e:
        return url, str(e)

urls = [
    "https://www.python.org",
    "https://www.google.com",
    "https://github.com",
    "https://stackoverflow.com",
    "https://news.ycombinator.com",
]

start = time.time()
with ThreadPoolExecutor(max_workers=4) as executor:
    # Submit all tasks
    future_to_url = {executor.submit(fetch_page, url): url for url in urls}
    
    # Process results as they complete
    for future in as_completed(future_to_url):
        url, result = future.result()
        print(f"{url}: {result} bytes")

print(f"Total time: {time.time() - start:.2f}s")

This pattern — submit all tasks, collect results as they complete — is the most common concurrent pattern in Python web scraping, API calling, and batch processing.

Real-World: Concurrent API Fetcher

Here's a practical example that fetches data from multiple GitHub API endpoints simultaneously:

import requests
from concurrent.futures import ThreadPoolExecutor

def get_user_info(username):
    """Fetch GitHub user info"""
    resp = requests.get(f"https://api.github.com/users/{username}")
    if resp.status_code == 200:
        data = resp.json()
        return {
            "name": username,
            "repos": data.get("public_repos", 0),
            "followers": data.get("followers", 0),
        }
    return {"name": username, "error": resp.status_code}

users = ["torvalds", "guido", "sarah-dravis", "gvanrossum", "hugow0528"]

with ThreadPoolExecutor(max_workers=5) as executor:
    results = list(executor.map(get_user_info, users))

for info in results:
    if "error" in info:
        print(f"{info['name']}: Error {info['error']}")
    else:
        print(f"{info['name']}: {info['repos']} repos, {info['followers']} followers")

Without threading, this would take ~3-5 seconds (each API call takes 500ms-1s). With 5 threads, it finishes in ~1 second.

Multiprocessing: True Parallelism

When your task is CPU-intensive, threading won't help (thanks to the GIL). multiprocessing spawns separate Python processes, each with its own memory and GIL — enabling true parallel computation.

Basic Process Pool

import multiprocessing
import math

def compute_primes(limit):
    """Find all prime numbers up to limit"""
    primes = []
    for num in range(2, limit):
        is_prime = True
        for i in range(2, int(math.sqrt(num)) + 1):
            if num % i == 0:
                is_prime = False
                break
        if is_prime:
            primes.append(num)
    return len(primes), limit  # return count and upper bound

# Split work across 4 processes
limits = [50000, 60000, 70000, 80000]

if __name__ == "__main__":
    with multiprocessing.Pool(processes=4) as pool:
        results = pool.map(compute_primes, limits)
    
    for count, limit in results:
        print(f"Primes up to {limit}: {count}")
    print(f"Total primes found: {sum(r[0] for r in results)}")

Important: on Windows, you must wrap multiprocessing code in if __name__ == "__main__": because new processes import the module, and they shouldn't start new processes recursively.

ProcessPoolExecutor (Modern API)

Just like ThreadPoolExecutor, there's a ProcessPoolExecutor for parallelism:

from concurrent.futures import ProcessPoolExecutor
import time

def heavy_computation(n):
    """CPU-intensive task: compute sum of squares"""
    total = sum(i * i for i in range(n))
    time.sleep(0.1)  # simulate additional work
    return n, total

numbers = [10_000_000, 20_000_000, 30_000_000, 40_000_000]

if __name__ == "__main__":
    # Sequential
    start = time.time()
    for n in numbers:
        heavy_computation(n)
    print(f"Sequential: {time.time() - start:.2f}s")
    
    # Parallel
    start = time.time()
    with ProcessPoolExecutor(max_workers=4) as executor:
        results = list(executor.map(heavy_computation, numbers))
    print(f"Parallel: {time.time() - start:.2f}s")
    print(f"Results: {results}")

Sharing Data: Queue vs Pipe

Unlike threads, processes don't share memory. To communicate, use Queue or Pipe:

import multiprocessing

def producer(queue):
    """Send numbers to the queue"""
    for i in range(10):
        queue.put(i * i)
    queue.put(None)  # sentinel: tell consumer we're done

def consumer(queue):
    """Receive and print numbers"""
    total = 0
    while True:
        item = queue.get()
        if item is None:
            break
        total += item
        print(f"Received: {item}, running total: {total}")
    print(f"Final total: {total}")

if __name__ == "__main__":
    q = multiprocessing.Queue()
    p1 = multiprocessing.Process(target=producer, args=(q,))
    p2 = multiprocessing.Process(target=consumer, args=(q,))
    
    p1.start()
    p2.start()
    p1.join()
    p2.join()

When to Use What: Decision Guide

Here's a simple decision tree for choosing the right tool:

Task Type Example Use
I/O-bound Web scraping, API calls, file I/O, database queries ThreadPoolExecutor
CPU-bound Math computations, image processing, data analysis ProcessPoolExecutor
Mixed Download files then process them Thread pool + process pool

Complete Real-World Project: Concurrent Web Scraper

Let's combine everything into a practical project — a concurrent web scraper that fetches pages and extracts data in parallel:

import requests
from concurrent.futures import ThreadPoolExecutor, as_completed
from bs4 import BeautifulSoup
import time
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")
logger = logging.getLogger(__name__)

class WebScraper:
    def __init__(self, max_workers=5, timeout=10):
        self.session = requests.Session()
        self.session.headers["User-Agent"] = "ScraperBot/1.0"
        self.max_workers = max_workers
        self.timeout = timeout
    
    def fetch_page(self, url):
        """Fetch a single page and return its HTML"""
        try:
            resp = self.session.get(url, timeout=self.timeout)
            resp.raise_for_status()
            return {"url": url, "status": 200, "html": resp.text}
        except Exception as e:
            logger.error(f"Failed: {url} — {e}")
            return {"url": url, "status": 0, "error": str(e)}
    
    def extract_title(self, html):
        """Extract page title from HTML"""
        soup = BeautifulSoup(html, "html.parser")
        return soup.title.string.strip() if soup.title else "No title"
    
    def scrape(self, urls):
        """Scrape multiple URLs concurrently"""
        start = time.time()
        results = []
        
        with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
            futures = {executor.submit(self.fetch_page, url): url for url in urls}
            
            for future in as_completed(futures):
                page = future.result()
                if page["status"] == 200:
                    title = self.extract_title(page["html"])
                    results.append({"url": page["url"], "title": title})
                    logger.info(f"{page['url']}: {title}")
                else:
                    results.append({"url": page["url"], "title": "ERROR"})
        
        elapsed = time.time() - start
        logger.info(f"Scraped {len(results)} pages in {elapsed:.2f}s")
        return results

if __name__ == "__main__":
    urls = [
        "https://www.python.org",
        "https://github.com",
        "https://stackoverflow.com",
        "https://news.ycombinator.com",
        "https://www.reddit.com",
    ]
    
    scraper = WebScraper(max_workers=3)
    results = scraper.scrape(urls)
    
    for r in results:
        print(f"  {r['url']} → {r['title']}")

Common Pitfalls

  • Don't use multiprocessing for I/O tasks. Processes have heavy startup overhead (~100ms each). Use threads instead.
  • Don't share mutable state between threads without a lock. Race conditions are hard to reproduce and debug.
  • Don't create more threads than you need. A pool of 4-8 workers handles most real-world cases. More threads can slow things down due to context switching.
  • Don't forget if __name__ == "__main__" on Windows. Multiprocessing imports the module in new processes, which can cause infinite recursion.
  • Don't use threads with C extensions that hold the GIL. Some libraries (like NumPy) hold the GIL, blocking other threads. Use multiprocessing instead.

Summary

Here's what we covered:

  • Threading — lightweight, shared memory, best for I/O-bound tasks
  • Multiprocessing — separate processes, true parallelism, best for CPU-bound tasks
  • Executor APIs — ThreadPoolExecutor and ProcessPoolExecutor for clean concurrent code
  • Locks and Queues — safe communication and shared state management
  • Real-world scraper — combining threads with HTTP requests and HTML parsing

Start with ThreadPoolExecutor for almost everything. Only switch to ProcessPoolExecutor when you've profiled and confirmed your bottleneck is CPU-bound. The concurrent.futures module gives you a unified API that works the same way for both — making it easy to switch when needed.
