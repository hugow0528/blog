Git Basics for Beginners: Version Control, Commits, Branches & GitHub — Complete Guide

July 20, 2026 12 min read

Git is the version control system used by virtually every software project on the planet. It tracks changes to your code, lets you experiment safely with branches, collaborate with teammates, and never lose work. If you're just starting with Git, this guide will take you from zero to confident — with every command explained and demonstrated.

What Does Git Actually Do?

Think of Git as a "save system" for your code:

  • Track changes — See who changed what and when
  • Branch and experiment — Create parallel timelines without breaking anything
  • Collaborate — Multiple people working on the same project without stepping on each other
  • Never lose work — Every change is saved and can be recovered

Git works with three main areas:

  • Working Directory — Your actual files on disk (what you see and edit)
  • Staging Area (Index) — A preparation zone before committing
  • Repository (.git) — The permanent history of all your commits

Step 1: Install and Configure Git

Install Git for your platform:

# macOS (with Homebrew)
brew install git

# Ubuntu/Debian
sudo apt update && sudo apt install git

# Windows: download from https://git-scm.com/

# Verify installation
git --version  # Should show git version 2.x.x

Configure your identity (required before first commit):

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# Use a default editor for commit messages
git config --global core.editor "nano"

# Show your config
git config --list

Step 2: Create Your First Repository

A repository is a project directory that Git tracks:

# Create a project folder
mkdir my-first-project
cd my-first-project

# Initialize Git
git init
# Creates a hidden .git folder — this is where all history lives

# Check status
git status
# Shows: "On branch main" and "No commits yet"

Step 3: Your First Commit

A commit is a saved snapshot of your project at a point in time:

# Create a file
echo "Hello, Git!" > README.md

# Check what changed
git status
# Shows: "Untracked files: README.md"

# Stage the file (add to staging area)
git add README.md

# Check again — now it's staged
git status
# Shows: "Changes to be committed: new file: README.md"

# Commit (save to history)
git commit -m "Add README with project description"
# Output: "[main (root-commit) abc1234] Add README..."

# View history
git log
# Shows your commit with hash, author, date, and message

The workflow is always: edit → add → commit

Understanding the Three Stages

Git tracks files in three states:

# 1. Untracked — Git doesn't know about the file
touch new-feature.py
git status  # "Untracked files: new-feature.py"

# 2. Staged — Ready to commit
git add new-feature.py
git status  # "Changes to be committed: new-feature.py"

# 3. Committed — Saved in history
git commit -m "Add new feature module"
git status  # "nothing to commit, working tree clean"

The git add Command: Staging Files

You have flexibility in how you stage changes:

# Add a specific file
git add filename.py

# Add all files in a directory
git add src/

# Add ALL changes (new, modified, deleted)
git add -A

# Interactive mode — choose what to stage
git add -p

# Add only modified files (not new files)
git add -u

Viewing Changes: diff and status

Before committing, always review your changes:

# What has changed but not staged?
git diff

# What is staged but not committed?
git diff --staged

# What's the overall status?
git status

# Short, colored status
git status -sb

# Detailed file-by-file status
git status -v

Undoing Things (Don't Panic!)

Git has undo for every situation:

# Unstage a file (remove from staging area)
git reset HEAD filename.py

# Unstage ALL files
git reset

# Undo changes to a file (discard edits, restore last committed version)
git checkout -- filename.py

# Undo ALL uncommitted changes
git checkout -- .

# Amend the last commit (change message or add files)
git commit --amend -m "Better commit message"

# WARNING: Only use on commits NOT yet pushed to shared branches!

The .gitignore File

Some files should never be tracked — virtual environments, compiled files, secrets:

# Create .gitignore
cat > .gitignore << 'EOF'
# Python
__pycache__/
*.pyc
*.pyo
.env
venv/
.venv/

# IDE
.vscode/
.idea/
*.swp

# OS files
.DS_Store
Thumbs.db

# Secrets
*.pem
*.key
secrets.json
EOF

# Verify it works
echo "my-secret-key" > secrets.json
git add -A
git status  # secrets.json should NOT appear as staged!

Branching: Safe Experimentation

Branches let you work on features without affecting the main code:

# List branches (* = current branch)
git branch
# * main

# Create a new branch
git branch feature/login

# Switch to it
git checkout feature/login
# Or in one step:
git checkout -b feature/login

# (Modern Git 2.23+)
git switch feature/login
git switch -c feature/login

# Work and commit normally
echo "Login feature code" > login.py
git add login.py
git commit -m "Add login functionality"

# Verify the branch
git log --oneline
# Shows your commits, separate from main

Merging: Combining Branches

When your feature is ready, merge it back:

# Switch to main
git checkout main

# Merge the feature branch
git merge feature/login
# "Fast-forward" — if main hasn't changed, Git just moves the pointer

# Delete the feature branch (merged, no longer needed)
git branch -d feature/login

# Force delete if not merged (use carefully!)
git branch -D feature/login

Merge Conflicts

Conflicts happen when two branches edit the same lines:

# Git will tell you:
# "CONFLICT (content): Merge conflict in app.py"
# "Automatic merge failed; fix conflicts and then commit."

# Open the conflicted file — you'll see markers:
# <<<<<<< HEAD (your main branch changes)
# =======
# (feature branch changes)
# >>>>>>> feature/login

# Fix the conflict by editing the file, keeping what you want
# Then:
git add app.py
git commit -m "Resolve merge conflict in app.py"

Stashing: Temporary Pause

Need to switch branches but don't want to commit half-finished work?

# Save (stash) current changes
git stash

# List stashes
git stash list
# stash@{0}: WIP on main: abc1234

# Restore stashed changes
git stash pop

# Restore but keep the stash
git stash apply

# Apply a specific stash
git stash apply stash@{0}

# Drop (delete) a stash
git stash drop stash@{0}

# Delete all stashes
git stash clear

Working with GitHub

GitHub hosts Git repositories online. Here's the remote workflow:

Clone an Existing Repository

# Clone from GitHub
git clone https://github.com/username/repo.git
cd repo

# Clone into a specific directory
git clone https://github.com/username/repo.git my-folder

Set Up a Remote

# Add a remote repository
git remote add origin https://github.com/username/my-repo.git

# Verify
git remote -v
# origin  https://github.com/username/my-repo.git (fetch)
# origin  https://github.com/username/my-repo.git (push)

# Change remote URL
git remote set-url origin https://github.com/username/new-url.git

Push to GitHub

# Push for the first time
git push -u origin main
# -u sets upstream — future pushes just need `git push`

# Push after that
git push

# Push a specific branch
git push origin feature/login

Pull Updates from GitHub

# Get latest changes from remote
git pull

# Equivalent to:
git fetch origin
git merge origin/main

# Pull and rebase instead (cleaner history)
git pull --rebase

The Complete GitHub Workflow

Here's the typical daily workflow:

# 1. Start: update your local copy
git checkout main
git pull

# 2. Create a feature branch
git checkout -b feature/user-profile

# 3. Work, stage, commit
echo "# User Profile" > profile.py
git add profile.py
git commit -m "Add user profile module"

# 4. Push the branch
git push -u origin feature/user-profile

# 5. Create Pull Request on GitHub (in browser)
#    Go to github.com/username/repo → "Compare & pull request"

# 6. After review and merge, clean up
git checkout main
git pull
git branch -d feature/user-profile

Essential Shortcuts and Aliases

Save typing with these aliases:

# Add common aliases
git config --global alias.st "status -sb"
git config --global alias.co "checkout"
git config --global alias.br "branch -vv"
git config --global alias.ci "commit"
git config --global alias.lg "log --oneline --graph --decorate"

# Now use shortcuts:
git st      # instead of git status -sb
git co main # instead of git checkout main
git lg      # beautiful graph view of history

# View commit graph
git lg
# * abc1234 (HEAD -> main, origin/main) Add README
# * def5678 (origin/feature/login) Add login functionality
# * ghi9012 Initial commit

Interactive Git: The Visual Way

For visual learners, Git can run interactively:

# Interactive rebase (rewrite recent commit history)
git rebase -i HEAD~3

# You'll see a text editor with:
# pick abc1234 Add feature A
# pick def5678 Add feature B
# pick ghi9012 Fix typo

# Change 'pick' to:
#   reword — change commit message
#   squash — combine with previous commit
#   drop   — remove commit entirely
# Then save and exit

# Interactive staging — choose hunks
git add -p

# You'll be prompted for each change block:
# Stage this hunk [y,n,q,a,d,?]:
# y = yes, n = no, a = all, d = dismiss all, s = split

Git Log: Understanding History

Different ways to view your project's history:

# Basic log
git log

# One line per commit
git log --oneline

# Show who changed what and when
git log --oneline --author="Hugo" --since="2 weeks ago"

# Show a file's history
git log --oneline -- app.py

# Show the actual changes in each commit
git log -p -- app.py

# Compare two commits
git diff abc1234 def5678

# What changed between branch and main?
git diff main..feature/login

# Visual graph of branches
git log --oneline --graph --all --decorate

# Blame: who wrote each line?
git blame app.py

The git tag Command: Marking Releases

Tags mark important points in history — like version releases:

# Create a lightweight tag
git tag v1.0.0

# Create an annotated tag (with message)
git tag -a v1.0.0 -m "First stable release"

# List all tags
git tag

# Push tags to GitHub
git push origin --tags

# Check out a specific tag
git checkout v1.0.0
# Note: this puts you in "detached HEAD" state

Summary: The Git Command Cheat Sheet

# Setup
git init                        # Create new repository
git clone <url>                 # Copy remote repository

# Daily workflow
git status                      # Check file states
git add <file>                  # Stage changes
git commit -m "message"         # Save snapshot
git diff                        # View unstaged changes
git diff --staged               # View staged changes

# Branching
git branch                      # List branches
git branch <name>               # Create branch
git checkout <name>             # Switch branch
git checkout -b <name>          # Create + switch
git merge <name>                # Merge branch
git branch -d <name>            # Delete branch

# Remote
git remote add origin <url>     # Set remote
git push -u origin main         # Push to remote
git pull                        # Fetch + merge

# Undo
git reset HEAD <file>           # Unstage file
git checkout -- <file>          # Discard changes
git commit --amend              # Fix last commit

# History
git log --oneline               # Compact history
git blame <file>                # Who wrote each line
git diff <hash1>..<hash2>      # Compare commits

Next Steps

Once you're comfortable with these basics, explore:

  • Git rebasing — Create a cleaner, linear history
  • Git cherry-pick — Apply specific commits from one branch to another
  • Git bisect — Binary search for the commit that introduced a bug
  • Git hooks — Automate checks on every commit or push
  • GitHub Actions — Automate testing and deployment
  • SSH authentication — Push without passwords using SSH keys

The key to mastering Git is practice. Every time you feel nervous about running a command, remember: you can almost always undo it. Start using Git on every project, no matter how small, and it will become second nature.
