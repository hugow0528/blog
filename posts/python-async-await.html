Python Async Concurrency

Python Async/Await: Concurrency Made Simple

2026-06-27 10 min read New

You've learned Python functions, loops, and error handling. Now it's time to level up with async/await — Python's way of running multiple tasks at the same time without the complexity of threading or multiprocessing.

Think about it this way: when you're cooking dinner, you don't stand and stare at the boiling water. You set the pot, then chop vegetables while the water heats up. That's async programming — start a task, do something else, come back when it's ready.

Why Async? The Problem with Waiting

Most Python code runs sequentially — one line after another. This is fine for simple scripts, but when your code needs to wait for something (a web API response, reading a file, a database query), it just... sits there. Doing nothing. Wasting time.

Sequential code (slow):

# Each request waits for the previous one to finish
import time

def fetch_data(url):
    print(f"Fetching {url}...")
    time.sleep(2)  # Simulating network delay
    return f"Data from {url}"

start = time.time()

result1 = fetch_data("https://api.weather.com")
result2 = fetch_data("https://api.news.com")
result3 = fetch_data("https://api.prices.com")

elapsed = time.time() - start
print(f"Total time: {elapsed:.1f} seconds")
# Output: Total time: 6.0 seconds 😩

Three requests, each taking 2 seconds = 6 seconds total. But those requests don't actually depend on each other! We could do them all at once.

Async to the Rescue

Python's asyncio module lets us run multiple tasks concurrently using coroutines — special functions that can pause and resume:

import asyncio
import time

# Define an async function (coroutine)
async def fetch_data(url):
    print(f"Fetching {url}...")
    await asyncio.sleep(2)  # Non-blocking wait
    return f"Data from {url}"

async def main():
    start = time.time()
    
    # Run all three requests concurrently!
    results = await asyncio.gather(
        fetch_data("https://api.weather.com"),
        fetch_data("https://api.news.com"),
        fetch_data("https://api.prices.com")
    )
    
    elapsed = time.time() - start
    print(f"Results: {results}")
    print(f"Total time: {elapsed:.1f} seconds")

asyncio.run(main())
# Output: Total time: 2.0 seconds 🎉

Same three requests, but now they run concurrently — all at once. 6 seconds becomes 2 seconds. That's a 3x speedup with minimal code changes.

Key Concepts: async and await

1. async def — Declaring a Coroutine

The async def keyword tells Python this function is a coroutine. It doesn't execute immediately when called — it returns a coroutine object that needs to be awaited.

async def greet(name):
    await asyncio.sleep(1)  # Simulate work
    return f"Hello, {name}!"

# Calling it returns a coroutine, NOT the result
task = greet("Hugo")  # <coroutine object greet>
# Need to await it to get the actual result

2. await — Pausing Until Ready

The await keyword pauses the current coroutine until the awaited task completes, then returns the result. While paused, the event loop runs other coroutines.

async def main():
    # This PAUSES here, lets other tasks run
    greeting = await greet("Hugo")
    print(greeting)  # "Hello, Hugo!"

3. The Event Loop

The event loop is the engine that runs your coroutines. It manages all the tasks, switching between them as they pause and resume. You rarely need to manage it directly — asyncio.run() creates and runs it for you.

Running Tasks Concurrently

Method 1: asyncio.gather() — Run All Together

async def fetch_user(user_id):
    await asyncio.sleep(1)
    return {"id": user_id, "name": f"User {user_id}"}

async def fetch_orders(user_id):
    await asyncio.sleep(1)
    return [{"item": f"Order {i}"} for i in range(3)]

async def fetch_profile(user_id):
    await asyncio.sleep(1)
    return {"bio": f"Bio for user {user_id}", "avatar": "img.png"}

async def main():
    # All three fetch at the same time
    user, orders, profile = await asyncio.gather(
        fetch_user(42),
        fetch_orders(42),
        fetch_profile(42)
    )
    print(f"User: {user['name']}")
    print(f"Orders: {len(orders)} items")
    print(f"Profile: {profile['bio']}")

# Total time: ~1 second (not 3 seconds!)

Method 2: asyncio.create_task() — Fine Control

async def download_file(filename, size):
    """Simulate downloading files of different sizes"""
    print(f"Starting download: {filename}")
    await asyncio.sleep(size)  # Larger files take longer
    print(f"Downloaded: {filename}")
    return filename

async def main():
    # Create tasks immediately — they start running right away
    task1 = asyncio.create_task(download_file("image.png", 3))
    task2 = asyncio.create_task(download_file("video.mp4", 1))
    task3 = asyncio.create_task(download_file("audio.mp3", 2))
    
    # Wait for each to complete (video finishes first!)
    result2 = await task2  # 1 second
    result3 = await task3  # 1 more second  
    result1 = await task1  # 1 more second
    
    print("All downloads complete!")
    
# Output:
# Starting download: image.png
# Starting download: video.mp4
# Starting download: audio.mp3
# Downloaded: video.mp4
# Downloaded: audio.mp3
# Downloaded: image.png

Real-World Example: Concurrent API Client

Here's a practical async API client that fetches data from multiple endpoints simultaneously:

import asyncio
import aiohttp  # pip install aiohttp

async def fetch_with_session(session, url):
    """Fetch a single URL using a shared session"""
    try:
        async with session.get(url) as response:
            data = await response.json()
            return {"url": url, "status": response.status, "data": data}
    except Exception as e:
        return {"url": url, "status": "error", "error": str(e)}

async def fetch_multiple(urls):
    """Fetch multiple URLs concurrently"""
    async with aiohttp.ClientSession() as session:
        # Create a task for each URL
        tasks = [fetch_with_session(session, url) for url in urls]
        # Run all tasks concurrently
        results = await asyncio.gather(*tasks)
    return results

async def main():
    urls = [
        "https://jsonplaceholder.typicode.com/posts/1",
        "https://jsonplaceholder.typicode.com/users/1",
        "https://jsonplaceholder.typicode.com/comments/1",
    ]
    
    results = await fetch_multiple(urls)
    
    for result in results:
        if result["status"] == 200:
            print(f"✅ {result['url']}: {result['status']}")
        else:
            print(f"❌ {result['url']}: {result['error']}")

asyncio.run(main())

The key advantage: a ClientSession reuses TCP connections, and asyncio.gather() makes all requests simultaneously. For 3 endpoints, this might take 100ms instead of 300ms.

Error Handling in Async Code

Async code uses regular try/except blocks, just like synchronous code:

async def safe_fetch(session, url, timeout=10):
    try:
        async with session.get(url, timeout=timeout) as response:
            if response.status == 200:
                return await response.json()
            return {"error": f"HTTP {response.status}"}
    except asyncio.TimeoutError:
        return {"error": "Request timed out"}
    except Exception as e:
        return {"error": str(e)}

async def main():
    async with aiohttp.ClientSession() as session:
        result = await safe_fetch(session, "https://api.example.com")
        print(result)

You can also use asyncio.gather(..., return_exceptions=True) to prevent one failed task from cancelling all others:

async def main():
    results = await asyncio.gather(
        fetch_data("https://fast-api.com"),
        fetch_data("https://slow-api.com"),
        fetch_data("https://broken-api.com"),
        return_exceptions=True  # Don't crash on errors
    )
    
    for i, result in enumerate(results):
        if isinstance(result, Exception):
            print(f"Request {i} failed: {result}")
        else:
            print(f"Request {i} succeeded: {result}")

Async vs Threads: When to Use What

Use Async When... Use Threads When...
I/O-bound (network, files, APIs) CPU-bound (calculations, image processing)
Many concurrent connections Few heavy computations
You need lightweight concurrency You're using non-async libraries

Common Async Patterns

Rate Limiting with Semaphore

async def rate_limited_fetch(semaphore, session, url):
    async with semaphore:  # Only 5 requests at a time
        async with session.get(url) as response:
            return await response.json()

async def main():
    semaphore = asyncio.Semaphore(5)  # Max 5 concurrent
    urls = [f"https://api.example.com/data/{i}" for i in range(100)]
    
    async with aiohttp.ClientSession() as session:
        tasks = [rate_limited_fetch(semaphore, session, url) for url in urls]
        results = await asyncio.gather(*tasks)

Timeout Control

async def main():
    try:
        result = await asyncio.wait_for(
            some_slow_operation(),
            timeout=5.0  # Give up after 5 seconds
        )
    except asyncio.TimeoutError:
        print("Operation took too long!")

Common Mistakes to Avoid

❌ Forgetting await

# BUG: Returns a coroutine, not the result!
result = fetch_data(url)  # Missing await!

# FIX: Always await coroutines
result = await fetch_data(url)

❌ Using time.sleep() instead of asyncio.sleep()

# BUG: Blocks the entire event loop!
await time.sleep(2)

# FIX: Use async sleep
await asyncio.sleep(2)

❌ Mixing sync and async code

# BUG: Regular function in async context
async def main():
    data = regular_function()  # This is fine but blocks the loop

# Better: Use a thread pool for sync calls
import concurrent.futures
loop = asyncio.get_event_loop()
data = await loop.run_in_executor(None, regular_function)

Summary

Python async/await lets you write concurrent code that's:

  • ⚡ Faster — handle multiple I/O tasks simultaneously
  • 📖 Readable — looks like sequential code but runs concurrently
  • 🪶 Lightweight — thousands of coroutines vs dozens of threads
  • 🔧 Controlled — semaphores, timeouts, and error handling built-in

Start with asyncio.gather() for running independent tasks, use asyncio.create_task() when you need fine-grained control, and always use async-compatible libraries (aiohttp, httpx, asyncpg) to get the full benefit.
