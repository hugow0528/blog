Python subprocess Module: Run Shell Commands Safely — Complete Guide

July 8, 2026 · 10 min read

You've written Python scripts that manipulate files, process data, and call APIs. But what about running shell commands from Python? Maybe you need to run git, docker, ffmpeg, or any CLI tool as part of an automation pipeline.

The subprocess module is Python's built-in way to spawn new processes, connect to their input/output/error pipes, and obtain return codes. It replaces the older os.system(), os.popen(), and commands modules — and it's much safer and more powerful.

Why Not os.system()?

You might have seen os.system("ls -la") in old tutorials. Here's why you should avoid it:

  • No output capture — you can't read stdout or stderr
  • Shell injection risk — passing user input is dangerously easy
  • No error handling — return codes are lost unless you parse them
  • Platform-dependent — doesn't work the same on Windows

subprocess solves all of these. Let's dive in.

1. The Simple Way: subprocess.run()

For 90% of use cases, subprocess.run() is all you need. It runs a command, waits for it to finish, and returns a CompletedProcess object.

import subprocess

# Basic command — capture output
result = subprocess.run(
    ["ls", "-la"],
    capture_output=True,
    text=True
)

print("Exit code:", result.returncode)
print("Stdout:", result.stdout)
print("Stderr:", result.stderr)

Key parameters:

  • capture_output=True — captures both stdout and stderr (Python 3.7+)
  • text=True — returns strings instead of bytes (Python 3.7+)
  • check=True — raises CalledProcessError if exit code is non-zero
  • timeout=seconds — kills the process if it takes too long

2. Always Pass Arguments as a List

This is the most important security rule. Never pass a string with shell=True unless you absolutely must:

# ✅ SAFE — arguments are separate, no shell injection possible
subprocess.run(["git", "commit", "-m", "fix: bug in login"])

# ❌ DANGEROUS — user input could inject shell commands
username = "hugo; rm -rf /"
subprocess.run(f"git commit -m 'fix: {username}'", shell=True)

# ✅ SAFE VERSION — even with user input
subprocess.run(["git", "commit", "-m", f"fix: {username}"])

When you pass a list, each element is a separate argument. No shell interpretation happens, so ;, |, &, and backticks are treated as literal characters.

3. Error Handling with check=True

Use check=True to automatically raise an exception when a command fails:

import subprocess

try:
    result = subprocess.run(
        ["python", "script_that_crashes.py"],
        capture_output=True,
        text=True,
        check=True  # raises CalledProcessError on non-zero exit
    )
    print("Success:", result.stdout)
except subprocess.CalledProcessError as e:
    print(f"Command failed with exit code {e.returncode}")
    print(f"Error output:\n{e.stderr}")
except FileNotFoundError:
    print("Command not found — is it installed?")

This pattern is essential for scripts that depend on other tools. If docker or ffmpeg isn't installed, you'll get a clear error instead of silent failure.

4. Running Commands with a Timeout

Some commands can hang forever. Always set a timeout for external processes:

import subprocess

try:
    result = subprocess.run(
        ["docker", "pull", "nginx:latest"],
        capture_output=True,
        text=True,
        timeout=120  # 2 minutes max
    )
    print("Image pulled successfully!")
except subprocess.TimeoutExpired:
    print("Download took too long — maybe check your network?")

Tip: For long-running commands (deployments, migrations), set timeouts based on your service-level objectives. A database migration that takes 10 minutes might be fine during maintenance but not during a deploy.

5. Passing Input to Commands

Some commands read from stdin. Use the input parameter:

import subprocess

# Send data to a command's stdin
result = subprocess.run(
    ["python", "-c", "import sys; print(sys.stdin.read().upper())"],
    input="hello world\n",
    capture_output=True,
    text=True
)

print(result.stdout)  # HELLO WORLD\n

This is useful for password prompts, yes/no confirmations, or piping structured data between commands:

# Read environment variables from a file
result = subprocess.run(
    ["cat", ".env"],
    capture_output=True,
    text=True
)

# Parse them
env_vars = {}
for line in result.stdout.strip().split("\n"):
    if "=" in line and not line.startswith("#"):
        key, value = line.split("=", 1)
        env_vars[key.strip()] = value.strip()

print(env_vars)

6. Real-World: Git Automation

Here's a practical example — a Python script that automates a Git workflow:

import subprocess
import sys

def run_git(*args, check=True):
    """Run a git command and return stdout."""
    result = subprocess.run(
        ["git"] + list(args),
        capture_output=True,
        text=True,
        check=check
    )
    return result.stdout.strip()

def git_status_summary():
    """Print a summary of current git status."""
    # Get branch name
    branch = run_git("branch", "--show-current")
    
    # Check for changes
    changes = run_git("status", "--porcelain")
    
    # Count changes
    staged = sum(1 for line in changes if line.startswith(("M ", "A ", "R ")))
    unstaged = sum(1 for line in changes if line.startswith(" M") or line.startswith("??"))
    
    print(f"Branch: {branch}")
    print(f"Staged changes: {staged}")
    print(f"Unstaged changes: {unstaged}")
    
    if staged or unstaged:
        print("⚠️  You have uncommitted changes!")
    else:
        print("✅ Working tree is clean")

git_status_summary()

7. When You Need More Control: subprocess.Popen

subprocess.run() waits for the command to finish. But sometimes you need real-time output or want to interact with the process while it runs. That's where Popen comes in:

import subprocess

# Stream output in real-time
process = subprocess.Popen(
    ["tail", "-f", "/var/log/syslog"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True
)

# Read line by line as it's produced
for line in process.stdout:
    if "ERROR" in line:
        print(f"⚠️  {line.strip()}")
    if process.poll() is not None:
        break

process.wait()

When to use Popen:

  • Streaming live output (log monitoring, download progress)
  • Interactive commands that need input during execution
  • Running multiple processes and connecting their pipes

8. Environment Variables

Control the environment a subprocess runs in with the env parameter:

import subprocess
import os

# Get current environment and add/modify variables
env = os.environ.copy()
env["NODE_ENV"] = "production"
env["PORT"] = "8080"

result = subprocess.run(
    ["npm", "start"],
    env=env,
    capture_output=True,
    text=True
)

print(result.stdout)

Warning: Always start from os.environ.copy(). If you pass a new dict, the subprocess won't have PATH, HOME, or any other system variables — and most commands will fail silently.

9. Quick Reference: Common Patterns

Here's a cheat sheet for everyday subprocess use:

import subprocess

# Run and get output
output = subprocess.check_output(["git", "log", "--oneline", "-5"], text=True)

# Run and ignore output
subprocess.run(["docker", "prune", "-f"], check=True)

# Run with timeout
result = subprocess.run(
    ["curl", "-s", "https://api.example.com"],
    capture_output=True, text=True, timeout=30
)

# Run in a different directory
result = subprocess.run(
    ["python", "main.py"],
    capture_output=True, text=True,
    cwd="/path/to/project"
)

# Set working directory + environment
result = subprocess.run(
    ["npm", "test"],
    capture_output=True, text=True, check=True,
    cwd="./frontend",
    env={**os.environ.copy(), "CI": "true"}
)

Summary

The subprocess module is Python's workhorse for running external commands. Remember the golden rules:

  1. Use subprocess.run() — it handles 90% of cases
  2. Always pass arguments as a list — never shell=True with user input
  3. Use check=True — fail fast when commands error
  4. Set timeouts — prevent scripts from hanging forever
  5. Capture output — capture_output=True, text=True for debugging
  6. Use os.environ.copy() — preserve the parent environment
