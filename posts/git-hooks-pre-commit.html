Git Hooks & Pre-Commit: Automate Your Development Workflow

June 26, 2026 · 10 min read

Here's a scenario that's happened to every developer: you push code, the CI pipeline runs for 5 minutes, and then it fails because you forgot to format your Python file, or you committed a console.log statement, or worse — you accidentally included a .env file.

Git hooks let you catch these problems before they ever leave your machine. They run automatically when you commit, push, or perform other Git actions. Combined with the pre-commit framework, you get a bulletproof quality gate that runs locally for every developer on your team.

What Are Git Hooks?

Git hooks are scripts that Git executes automatically in response to specific events. They live in the .git/hooks/ directory of every repository. Git ships with sample hooks — rename pre-commit.sample to pre-commit and make it executable, and it runs every time you run git commit.

Common Hook Types

hook name       | when it runs
───────────────────────────────────────────────
pre-commit      | before commit, checks staged files
commit-msg      | after pre-commit, validates commit message
pre-push        | before push, runs before sending to remote
post-commit     | after commit succeeds
post-merge      | after a successful merge
pre-rebase      | before a rebase begins

The most useful hooks for daily development are pre-commit (runs before every commit) and pre-push (runs before every push).

Manual Git Hooks (The Basic Way)

Let's create a simple pre-commit hook that prevents committing Python files with syntax errors:

#!/bin/bash
# .git/hooks/pre-commit

# Check Python syntax on staged files
python_files=$(git diff --cached --name-only --diff-filter=ACM | grep '\.py$')

if [ -n "$python_files" ]; then
    for file in $python_files; do
        if ! python -m py_compile "$file" 2>/dev/null; then
            echo "❌ Syntax error in $file — commit aborted"
            exit 1
        fi
    done
    echo "✅ Python syntax check passed"
fi

# Prevent committing .env files
env_files=$(git diff --cached --name-only --diff-filter=ACM | grep '^\.(env|env\.)')

if [ -n "$env_files" ]; then
    echo "❌ Refusing to commit sensitive files: $env_files"
    exit 1
fi

# Prevent committing large files (>10MB)
large_files=$(git diff --cached --name-only --diff-filter=ACM | while read file; do
    if [ -f "$file" ]; then
        size=$(stat -f%z "$file" 2>/dev/null || stat -c%s "$file" 2>/dev/null || echo 0)
        if [ "$size" -gt 10485760 ]; then
            echo "$file"
        fi
    fi
done)

if [ -n "$large_files" ]; then
    echo "❌ Files over 10MB detected: $large_files"
    echo "Consider using Git LFS for large files"
    exit 1
fi

exit 0

Save this as .git/hooks/pre-commit and make it executable:

chmod +x .git/hooks/pre-commit

Now try committing a Python file with a syntax error:

# Create a file with a syntax error
echo "def hello(:" > broken.py
git add broken.py
git commit -m "test hook"

# Output:
# ❌ Syntax error in broken.py — commit aborted

The Problem With Manual Hooks

Manual hooks live in .git/hooks/, which is not tracked by Git (it's in .gitignore by design). This means:

  • 🚫 New team members don't get them automatically
  • 🚫 You can't share hooks across projects easily
  • 🚫 No version control for your hooks themselves
  • 🚫 Different team members have different hooks, leading to inconsistent quality

Enter the pre-commit framework.

Pre-Commit Framework: Shareable, Versioned Hooks

pre-commit.com solves all the manual hook problems. You define hooks in a YAML file that is committed to your repository. Every team member gets the same hooks automatically.

Step 1: Install pre-commit

# Install with pip
pip install pre-commit

# Or with Homebrew (macOS)
brew install pre-commit

Step 2: Create a Configuration File

# .pre-commit-config.yaml
repos:
  # Auto-format Python code
  - repo: https://github.com/psf/black
    rev: 24.4.2
    hooks:
      - id: black
        args: [--line-length=100]

  # Sort Python imports
  - repo: https://github.com/pycqa/isort
    rev: 5.13.2
    hooks:
      - id: isort
        args: ["--profile", "black"]

  # Check Python syntax and common errors
  - repo: https://github.com/pycqa/flake8
    rev: 7.1.0
    hooks:
      - id: flake8

  # Remove trailing whitespace
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-added-large-files
        args: ['--maxkb=5000']
      - id: check-merge-conflict
      - id: detect-private-key

  # Auto-fix common typos
  - repo: https://github.com/codespell-project/codespell
    rev: v2.3.0
    hooks:
      - id: codespell

  # Format JSON files
  - repo: https://github.com/pre-commit/mirrors-prettier
    rev: v4.0.0-alpha.8
    hooks:
      - id: prettier
        types_or: [json, yaml, markdown, javascript, css]

Step 3: Install the Git Hook

# Install hooks into .git/hooks/
pre-commit install

# Output: pre-commit installed at .git/hooks/pre-commit

# Run against ALL files (not just staged)
pre-commit run --all-files

Step 4: Watch It Work

Now every time you run git commit, pre-commit runs automatically:

git add my_script.py
git commit -m "add new feature"

# Output:
# [INFO] Installing hooks for the first time...
# trailing-whitespace....................Passed
# end-of-file-fixer......................Passed
# check-yaml.............................Passed
# black..................................Modifying fixable files
# isort..................................Modifying fixable files
# flake8.................................Passed
# codespell..............................Passed
# prettier...............................Passed

# Notice: black and isort modified your files!
# You need to `git add` the fixed files, then commit again:
git add my_script.py
git commit -m "add new feature"

# Now everything passes ✅

Hooking Into JavaScript Projects

Pre-commit works with any language. Here's a configuration for a JavaScript/Node.js project:

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/pre-commit/mirrors-eslint
    rev: v9.14.0
    hooks:
      - id: eslint
        args: [--fix]
        additional_dependencies:
          - eslint@9.14.0
          - eslint-plugin-react@7.35.0

  - repo: https://github.com/pre-commit/mirrors-prettier
    rev: v4.0.0-alpha.8
    hooks:
      - id: prettier
        types_or: [javascript, jsx, json, markdown, yaml]

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: no-commit-to-branch
        args: ['--branch', 'main']  # Don't commit directly to main
      - id: check-case-conflict

Advanced: Custom Hooks With Python

You can write your own hooks and define them locally in the same config file:

# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      # Custom hook: check that .gitignore exists
      - id: check-gitignore
        name: Check .gitignore
        entry: bash -c 'test -f .gitignore || { echo "❌ Missing .gitignore!"; exit 1; }'
        language: system
        pass_filenames: false
        always_run: true

      # Custom hook: run tests before committing
      - id: run-tests
        name: Run Python tests
        entry: python -m pytest tests/ -q
        language: system
        pass_filenames: false
        stages: [pre-push]  # Only run before push, not every commit
        verbose: true

      # Custom hook: check no TODOs in production code
      - id: no-todos
        name: Check for TODOs in source
        entry: bash -c 'grep -rn "TODO\|FIXME\|HACK" src/ || true'
        language: system
        pass_filenames: false
        always_run: true

Hook Stages: Control When Hooks Run

Pre-commit supports multiple stages. Assign hooks to stages for optimal performance:

repos:
  - repo: https://github.com/psf/black
    rev: 24.4.2
    hooks:
      - id: black
        stages: [commit]  # Run on every commit (fast auto-fix)

  - repo: local
    hooks:
      - id: run-integration-tests
        name: Integration Tests
        entry: pytest tests/integration/
        language: system
        stages: [pre-push]  # Only before push (slower, less frequent)
        pass_filenames: false

Available Stages

commit      = runs during `git commit` (most common)
merge-commit = runs during `git commit --no-verify` for merges
push        = runs during `git push`
post-checkout = runs after `git checkout`
post-commit = runs after a successful commit
manual      = runs only when called explicitly

Team Setup: Making It Work for Everyone

Commit the Config, Not the Hooks

The .pre-commit-config.yaml file is tracked in Git. The .git/hooks/pre-commit file is NOT tracked (it's a thin wrapper installed by pre-commit).

# What's in your repo:
✅ .pre-commit-config.yaml  (shared, versioned)
✅ .gitignore
❌ .git/hooks/pre-commit   (generated locally, not tracked)

Onboard New Team Members

# After cloning the repo, just run:
git clone https://github.com/your-org/project.git
cd project
pip install pre-commit
pre-commit install

# That's it. Hooks are active immediately.

Update Hooks for the Whole Team

# Auto-update all hook versions
pre-commit autoupdate

# Output:
# [https://github.com/psf/black] updating 24.4.2 -> 24.8.0
# [https://github.com/pycqa/isort] updating 5.13.2 -> 5.13.3
# ...

# Commit the updated config:
git add .pre-commit-config.yaml
git commit -m "chore: update pre-commit hooks"

Combining Pre-Commit With CI/CD

Pre-commit is a local safeguard. Always back it up with CI:

# .github/workflows/lint.yml
name: Lint & Format
on: [push, pull_request]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
      - uses: pre-commit/action@v3.0.1
        # This runs the SAME hooks as your local pre-commit

Now the quality gate exists both locally (fast feedback) and in CI (catches anyone who bypassed local hooks with --no-verify).

Common Pitfalls & Solutions

  • Hook too slow: Move heavy checks (full test suites) to pre-push stage instead of commit. Commit hooks should finish in under 10 seconds.
  • Auto-fixing hooks modify files: This is expected! black, isort, and prettier fix files automatically. Just git add the modified files and re-commit.
  • Skipping hooks: Use git commit --no-verify sparingly. Only for emergency fixes, and document why.
  • Language-specific hooks on wrong files: Use types: [python] or files: \.py$ to scope hooks to specific file types.

Summary

Git hooks and pre-commit transform your development workflow from "hope nobody forgets" to "it just works." The key takeaways:

  1. Git hooks run automatically at specific Git events (commit, push, merge)
  2. Manual hooks in .git/hooks/ work but aren't shareable
  3. pre-commit framework makes hooks shareable via a YAML config file in your repo
  4. Stages let you control when hooks run (commit vs push)
  5. Always pair local pre-commit with CI for a complete quality gate

Set this up on your next project. Your team will thank you when nobody ever commits a .env
