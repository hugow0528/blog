How HTTPS and TLS Work: Cybersecurity Basics

June 20, 2026 · 8 min read

That green padlock in your browser isn't just a design decoration — it's the result of a complex security handshake happening in milliseconds. Understanding how HTTPS and TLS work is essential for anyone who builds or uses websites. In this guide, we'll break down exactly what happens when you visit an HTTPS site.

The Problem: HTTP Is Insecure

HTTP (HyperText Transfer Protocol) sends data as plain text. Anyone on the same network can read it:

# What an attacker sees on HTTP:
GET /login HTTP/1.1
Host: example.com

username=john&password=mypassword123

That password just traveled across the internet in readable text. On a public WiFi network, someone sitting next to you could intercept it. HTTPS solves this by encrypting everything.

The Solution: HTTPS = HTTP + Encryption

HTTPS adds a secure layer called TLS (Transport Layer Security) between HTTP and the network. The data gets encrypted before leaving your browser and decrypted after reaching the server.

The flow looks like this:

Your Browser → [Encrypt] → Internet → [Decrypt] → Web Server
Web Server   → [Encrypt] → Internet → [Decrypt] → Your Browser

Think of it like putting a message in a locked briefcase before mailing it. Even if someone opens the mail, they can't read the contents without the key.

The TLS Handshake Step by Step

When you visit https://example.com, several things happen behind the scenes:

Step 1: Client Hello

Browser: "Hi! I support these encryption methods:
  - TLS 1.3 (preferred)
  - TLS 1.2
  These cipher suites: AES-256-GCM, ChaCha20-Poly1305, ..."
  Session ID: (random number)

Step 2: Server Hello + Certificate

Server: "I accept! Let's use TLS 1.3 with AES-256-GCM.
  Here's my certificate:" [certificate data]
  Server key share: [ephemeral key]

  Certificate chain:
  ├── example.com certificate
  ├── DigiCert intermediate CA
  └── Root CA (already in browser)

Step 3: Browser Verifies Certificate

The browser checks:

  • ✅ Is the certificate signed by a trusted Certificate Authority (CA)?
  • ✅ Is it valid for this domain (example.com)?
  • ✅ Has it expired?
  • ✅ Has it been revoked?

Step 4: Key Exchange

Browser generates a random session key, encrypts it
with the server's public key, and sends it.

Only the server can decrypt it with its private key.

Now both sides share the same secret key for encryption.

Step 5: Encrypted Communication

From now on, all data is encrypted with the shared session key:

Browser: [encrypted: GET /login HTTP/1.1]
Server:  [encrypted: 200 OK + HTML response]

Types of TLS Certificates

Domain Validated (DV)

Basic certificate. The CA just checks you own the domain. Fast and cheap. Cloudflare offers these for free.

# Cloudflare automatic HTTPS
# Enable in: SSL/TLS → Overview → Full (strict)

Organization Validated (OV)

The CA verifies your business exists. Shows company name in certificate details. Used by businesses.

Extended Validation (EV)

Rigorous verification. Shows the green company name in the address bar (in some browsers). Banks use these.

Free HTTPS with Cloudflare

You don't need to buy a certificate. Cloudflare provides free TLS/SSL for your domain:

Quick Setup

  1. Go to Cloudflare Dashboard → SSL/TLS → Overview
  2. Choose Full or Full (strict) mode
  3. Enable Always Use HTTPS in the Edge Certificates tab
  4. Done — Cloudflare handles certificate renewal automatically
# SSL/TLS modes explained:

# Off — No encryption (don't use)
# Flexible — Visitor to Cloudflare is HTTPS, Cloudflare to origin is HTTP
#   ⚠️ Not recommended — origin traffic is unencrypted
# Full — Both connections encrypted (works with self-signed certs)
# Full (strict) — Both encrypted, validates origin certificate (recommended)

How to Check Certificate Details

Using the Browser

  1. Click the padlock icon in the address bar
  2. Click "Connection is secure" or "Certificate is valid"
  3. View details: issuer, validity dates, domain coverage

Using OpenSSL Command Line

# Check a site's certificate
openssl s_client -connect example.com:443 -servername example.com

# Check certificate expiry
echo | openssl s_client -connect example.com:443 2>/dev/null \
    | openssl x509 -noout -dates

# Output:
# notBefore=Jan  1 00:00:00 2026 GMT
# notAfter=Mar 31 23:59:59 2027 GMT

Using Python

import ssl
import socket

def check_https(domain, port=443):
    """Check if a website has a valid HTTPS certificate"""
    context = ssl.create_default_context()
    
    try:
        with context.wrap_socket(
            socket.socket(),
            server_hostname=domain
        ) as s:
            s.settimeout(3)
            s.connect((domain, port))
            
            cert = s.getpeercert()
            
            print(f"✅ Valid certificate for {domain}")
            print(f"   Issuer: {cert['issuer'][1][1]}")
            print(f"   Valid until: {cert['notAfter']}")
            print(f"   TLS version: {s.version()}")
            
    except ssl.SSLCertVerificationError as e:
        print(f"❌ Certificate verification failed: {e}")
    except Exception as e:
        print(f"❌ Error: {e}")

# Test it
check_https("cloudflare.com")
check_https("google.com")
check_https("self-signed.example")  # This will fail

Common HTTPS Errors (And How to Fix Them)

Netscape_Invalid_Cert (Error 1015)

Cause: Your origin server doesn't have a valid certificate, but Cloudflare is set to "Full (strict)" mode.

Fix: Install a certificate on your server, or temporarily switch to "Full" mode while you set one up.

SSL Handshake Failed

Cause: Your server uses a protocol or cipher that Cloudflare doesn't support.

Fix: Enable TLS 1.2 or higher on your server. Disable SSLv3 and TLS 1.0/1.1.

Certificate Expired

Cause: The TLS certificate has passed its expiry date.

Fix: If using Cloudflare's free certificates, this shouldn't happen (they auto-renew). If using your own, renew it:

# With Let's Encrypt (Certbot)
sudo certbot renew --force-renewal

# Check when it expires
sudo certbot certificates

Security Best Practices

1. Always Use HTTPS

Redirect all HTTP traffic to HTTPS. In Cloudflare: SSL/TLS → Edge Certificates → Enable "Always Use HTTPS".

2. Use TLS 1.3

TLS 1.3 is faster and more secure than TLS 1.2. Enable it in Cloudflare → SSL/TLS → Edge Certificates → Minimum TLS Version → TLS 1.3.

3. Enable HSTS

HTTP Strict Transport Security tells browsers to always use HTTPS for your domain:

# HSTS header (add to your server)
Strict-Transport-Security: max-age=31536000; includeSubDomains

# Or enable in Cloudflare:
# SSL/TLS → Edge Certificates → HSTS → Enable

4. Use HSTS Preloading

Submit your domain to the HSTS preload list. Browsers will never load your site over HTTP:

# Requirements:
# - Valid HTTPS certificate
# - All subdomains must redirect to HTTPS
# - max-age >= 31536000 (1 year)
# - includeSubDomains directive

# Test at: https://hstspreload.org

5. Regular Certificate Monitoring

# Simple Python script to check cert expiry
import ssl
import socket
from datetime import datetime

def days_until_expiry(domain):
    context = ssl.create_default_context()
    with context.wrap_socket(
        socket.socket(), server_hostname=domain
    ) as s:
        cert = s.getpeercert()
        expiry = datetime.strptime(
            cert['notAfter'], '%b %d %H:%M:%S %Y %Z'
        )
        return (expiry - datetime.utcnow()).days

# Check multiple domains
for domain in ['blog.hugow.dev', 'api.hugow.dev']:
    days = days_until_expiry(domain)
    if days < 30:
        print(f"⚠️ {domain}: {days} days until expiry!")
    else:
        print(f"✅ {domain}: {days} days remaining")

Summary

HTTPS/TLS is the foundation of web security. Here's what you need to remember:

  • HTTP = plain text (anyone can read it), HTTPS = encrypted (only you and the server can read it)
  • TLS certificates prove a website's identity and enable encryption
  • Cloudflare provides free HTTPS — just enable it in the dashboard
  • Use Full (strict) mode for the best security
  • Enable HSTS to prevent downgrade attacks
  • Monitor certificate expiry before it's too late
