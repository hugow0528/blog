Python Classes & OOP: Objects, Methods, Inheritance — Complete Beginner's Guide

July 13, 2026 · 12 min read

You've written functions, loops, and scripts in Python. Now it's time to level up with object-oriented programming (OOP) — the paradigm that lets you organize code into reusable blueprints called classes. OOP is everywhere in Python: from the list you type daily to the open() function that returns file objects.

This guide walks you through classes, objects, __init__, methods, inheritance, and polymorphism with practical, beginner-friendly examples. By the end, you'll build a complete contact manager application.

What Is a Class?

A class is a blueprint for creating objects. Think of it like an architect's plan for a house — the plan itself isn't a house, but you can build many houses from it. In Python, you define a class with the class keyword:

class Dog:
    pass

# Create objects (instances) from the class
buddy = Dog()
max = Dog()

# Each object is independent
print(buddy)  # <__main__.Dog object at 0x...>
print(max)    # <__main__.Dog object at 0x...>

Here, Dog is the class and buddy / max are objects (or instances). The pass keyword means "do nothing for now" — our class is empty but valid.

The __init__ Method: Setting Up Objects

The __init__ method (called a constructor) runs automatically when you create a new object. It's where you set initial properties:

class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

# Create dogs with properties
buddy = Dog("Buddy", "Golden Retriever")
max = Dog("Max", "German Shepherd")

print(buddy.name)   # Buddy
print(buddy.breed)  # Golden Retriever
print(max.name)     # Max

Key concepts:

  • self refers to the current object. It's always the first parameter in instance methods.
  • self.name is an instance attribute — each object has its own copy.
  • The constructor runs automatically when you write Dog("Buddy", "Golden Retriever").

Methods: What Objects Can Do

Attributes describe what an object is. Methods describe what an object does. Define methods like functions, but inside a class with self as the first parameter:

class Dog:
    def __init__(self, name, energy=100):
        self.name = name
        self.energy = energy

    def bark(self):
        print(f"{self.name} says: Woof!")

    def walk(self, distance):
        self.energy -= distance * 2
        print(f"{self.name} walked {distance} blocks. Energy: {self.energy}")

    def rest(self):
        self.energy = 100
        print(f"{self.name} is fully rested!")

    def __str__(self):
        return f"Dog({self.name}, energy={self.energy})"

# Use methods
buddy = Dog("Buddy")
buddy.bark()     # Buddy says: Woof!
buddy.walk(5)    # Buddy walked 5 blocks. Energy: 90
buddy.rest()     # Buddy is fully rested!
print(buddy)     # Dog(Buddy, energy=100)

The __str__ method is special — it defines how the object looks when you print() it. Python has several such dunder methods (double-underscore methods) that change built-in behavior:

  • __str__ — string representation for users
  • __repr__ — string representation for developers
  • __len__ — what len(obj) returns
  • __eq__ — what obj1 == obj2 checks

Class Attributes vs Instance Attributes

Instance attributes belong to individual objects. Class attributes are shared across all instances:

class Dog:
    # Class attribute — shared by all dogs
    species = "Canis familiaris"
    total_dogs = 0

    def __init__(self, name):
        self.name = name           # Instance attribute
        Dog.total_dogs += 1       # Update class attribute

buddy = Dog("Buddy")
max = Dog("Max")

print(Dog.species)      # Canis familiaris
print(buddy.species)    # Canis familiaris (inherited)
print(Dog.total_dogs)   # 2

# Changing class attribute affects all instances
Dog.species = "Dog"
print(buddy.species)    # Dog

Inheritance: Build on Existing Classes

Inheritance lets a class inherit attributes and methods from another class. The inheriting class is a subclass (child), and the original is a parent class:

class Animal:
    def __init__(self, name, sound):
        self.name = name
        self.sound = sound

    def speak(self):
        return f"{self.name} says {self.sound}!"

    def __str__(self):
        return f"Animal({self.name})"

# Subclass inherits from Animal
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name, "Woof")  # Call parent constructor
        self.breed = breed               # Add new attribute

    def __str__(self):
        return f"Dog({self.name}, {self.breed})"

class Cat(Animal):
    def __init__(self, name, indoor=True):
        super().__init__(name, "Meow")
        self.indoor = indoor

    def scratch(self):
        return f"{self.name} scratches the furniture!"

# Use inherited and new methods
dog = Dog("Buddy", "Golden Retriever")
cat = Cat("Whiskers")

print(dog.speak())       # Buddy says Woof! (inherited)
print(dog)               # Dog(Buddy, Golden Retriever)
print(cat.speak())       # Whiskers says Meow! (inherited)
print(cat.scratch())     # Whiskers scratches the furniture! (new)

The super() function calls the parent class's method. This avoids code duplication — Dog and Cat reuse speak() from Animal.

Polymorphism: Same Name, Different Behavior

Polymorphism means "many forms." When different classes share a method name but behave differently, Python calls the right version automatically:

class Shape:
    def area(self):
        pass  # Abstract — to be overridden

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        import math
        return math.pi * self.radius ** 2

# Polymorphism in action
shapes = [Rectangle(5, 10), Circle(7), Rectangle(3, 8)]
for shape in shapes:
    print(f"Area: {shape.area():.2f}")

# Output:
# Area: 50.00
# Area: 153.94
# Area: 24.00

Notice we call shape.area() without checking the type. Each class defines its own version — Python figures it out.

Encapsulation: Protecting Your Data

Encapsulation hides internal details and provides controlled access. Python uses naming conventions:

  • public_name — accessible from anywhere
  • _protected_name — "don't touch this" (convention only)
  • __private_name — name-mangled, harder to access accidentally
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance  # Private attribute

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            return True
        return False

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            return True
        return False

    def get_balance(self):
        return self.__balance

account = BankAccount("Hugo", 1000)
account.deposit(500)
account.withdraw(200)
print(account.get_balance())  # 1300

# Can't directly access private attribute
# print(account.__balance)  # AttributeError!

# Workaround (not recommended)
print(account._BankAccount__balance)  # 1300

Using @property gives a cleaner interface:

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self._balance = balance

    @property
    def balance(self):
        """Read-only property"""
        return self._balance

    @balance.setter
    def balance(self, value):
        """Controlled write access"""
        if value >= 0:
            self._balance = value
        else:
            raise ValueError("Balance cannot be negative")

account = BankAccount("Hugo", 1000)
print(account.balance)      # 1000 (calls getter)
account.balance = 1500      # calls setter
# account.balance = -100    # ValueError!

Complete Project: Contact Manager

Let's put everything together into a practical application:

class Contact:
    """A simple contact with name, email, and phone."""

    def __init__(self, name, email="", phone=""):
        self.name = name
        self.email = email
        self.phone = phone
        self.tags = []

    def add_tag(self, tag):
        if tag not in self.tags:
            self.tags.append(tag)

    def __str__(self):
        info = f"{self.name}"
        if self.email:
            info += f" <{self.email}>"
        if self.phone:
            info += f" ({self.phone})"
        if self.tags:
            info += f" [{', '.join(self.tags)}]"
        return info

    def __eq__(self, other):
        if isinstance(other, Contact):
            return self.name.lower() == other.name.lower()
        return False


class ContactManager:
    """Manages a collection of contacts with CRUD operations."""

    def __init__(self):
        self.contacts = []

    def add(self, contact):
        if contact not in self.contacts:
            self.contacts.append(contact)
            print(f"✅ Added: {contact}")
        else:
            print(f"⚠️  {contact.name} already exists")

    def find(self, name):
        """Find contacts by partial name match."""
        results = [c for c in self.contacts
                   if name.lower() in c.name.lower()]
        return results

    def find_by_tag(self, tag):
        return [c for c in self.contacts if tag in c.tags]

    def delete(self, name):
        original_len = len(self.contacts)
        self.contacts = [c for c in self.contacts
                         if name.lower() not in c.name.lower()]
        if len(self.contacts) < original_len:
            print(f"🗑️  Deleted '{name}'")
        else:
            print(f"❌ Not found: '{name}'")

    def list_all(self):
        if not self.contacts:
            print("📭 No contacts yet.")
            return
        print(f"\n📇 Contacts ({len(self.contacts)}):")
        for i, c in enumerate(self.contacts, 1):
            print(f"  {i}. {c}")
        print()

    def count(self):
        return len(self.contacts)


# --- Demo ---
manager = ContactManager()

# Add contacts
hugo = Contact("Hugo Wong", "hugo@example.com", "555-0101")
hugo.add_tag("friend")
hugo.add_tag("developer")

alice = Contact("Alice Chen", "alice@example.com")
alice.add_tag("colleague")

bob = Contact("Bob Smith", phone="555-0103")
bob.add_tag("friend")

manager.add(hugo)
manager.add(alice)
manager.add(bob)

# Find by name
results = manager.find("hu")
print(f"Found {len(results)} match(es) for 'hu':")
for r in results:
    print(f"  → {r}")

# Find by tag
devs = manager.find_by_tag("developer")
print(f"\nDevelopers: {[str(d) for d in devs]}")

# List all
manager.list_all()
print(f"Total: {manager.count()} contacts")

This project demonstrates classes, instance attributes, methods, dunder methods (__str__, __eq__), encapsulation (tags managed through methods), and building a real application from OOP building blocks.

When to Use OOP (and When Not To)

OOP isn't always the right tool. Here's a quick guide:

Use OOP when... Use functions instead when...
You have state + behavior that belong together You're transforming data (input → output)
You need reusable, extensible types You're writing a quick script
You're modeling real-world entities Functions compose better than classes
You use libraries that expect objects Data flows in one direction (pipeline)

Python is a multi-paradigm language — you can mix OOP, functional, and procedural styles freely. The best code uses the right tool for each job.

Key Takeaways

  • Classes are blueprints; objects are instances created from them.
  • __init__ sets up new objects with initial state.
  • Methods define what objects can do. self refers to the current object.
  • Inheritance reuses code from parent classes with super().
  • Polymorphism lets different classes share method names with different implementations.
  • Encapsulation protects data using naming conventions and @property.
  • Use OOP for complex, stateful systems — simple scripts can stay procedural.

"Classes are like recipes. You write the recipe once, then bake many cakes. Each cake is different, but they all follow the same recipe."

Now you have the full OOP toolkit in Python. Start by wrapping related data and behavior into classes, then explore inheritance when you spot repetition between classes. Happy coding!
