How to Set Up Cloudflare Tunnel (Step by Step)

June 17, 2026 · 5 min read

Cloudflare Tunnel (cloudflared) lets you expose a local server to the internet without opening any ports on your firewall. No public IP needed. No router config. Just install, connect, and go live.

Why Use Cloudflare Tunnel?

  • No port forwarding — your server stays behind the firewall
  • Free SSL/TLS — automatic HTTPS on every domain
  • DDoS protection — Cloudflare absorbs the traffic
  • No public IP required — works on home networks with CGNAT

Step 1: Install cloudflared

Ubuntu / Debian

curl -fsSL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
chmod +x /usr/local/bin/cloudflared

macOS

brew install cloudflared

Step 2: Authenticate with Cloudflare

Run this command and follow the browser login:

cloudflared tunnel login

This creates a certificate at ~/.cloudflared/cert.pem. This cert proves you own the tunnel — it does not give Cloudflare access to your server.

Step 3: Create a Tunnel

cloudflared tunnel create my-tunnel

This gives you a tunnel ID (like 0e4fb61b-8dd0-421a-979f-43053f1a33b6) and saves credentials to ~/.cloudflared/credentials.json.

Step 4: Configure Routing

Create ~/.cloudflared/config.yaml:

tunnel: YOUR_TUNNEL_ID
credentials-file: ~/.cloudflared/credentials.json

ingress:
  - hostname: app.example.com
    service: http://localhost:8080
  - service: http_status:404

Key points:

  • hostname — the domain you want to expose
  • service — your local server (localhost port)
  • http_status:404 — catch-all for unmatched traffic

Step 5: Add DNS Records

cloudflared tunnel route dns my-tunnel app.example.com

This creates a CNAME record pointing to your tunnel. Make sure the orange cloud is ON (proxied) in Cloudflare dashboard.

Step 6: Start the Tunnel

cloudflared tunnel --config ~/.cloudflared/config.yaml run my-tunnel

For production, run it as a systemd service:

sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared

Common Issues

403 Managed Challenge

On the Free plan, Cloudflare shows a JS challenge to automated tools (curl, wget). Real browsers pass automatically. Not a bug — it's bot protection.

Multiple cloudflared Processes

If you see tunnel errors, check for duplicate processes:

ps aux | grep cloudflared
kill <duplicate-pid>

Tunnel Goes Down

Use systemctl status cloudflared to check. The tunnel auto-reconnects on restart.

Real World Example

Here's my setup with multiple services:

ingress:
  - hostname: weather.hugow.dev
    service: http://localhost:8080
  - hostname: deploy.hugow.dev
    service: http://localhost:8087
  - hostname: remote.hugow.dev
    service: http://localhost:6080
  - service: http_status:404

One tunnel, multiple subdomains. Each points to a different local port.

Tip: You can also tunnel SSH (ssh://localhost:22) so you can access your server from anywhere without a VPN.
