XSS and CSRF Protection in Python Web Apps: Secure Your Applications

July 4, 2026 · 10 min read

Cross-site scripting (XSS) and cross-site request forgery (CSRF) are two of the most common web vulnerabilities — and both are entirely preventable. In 2025, the OWASP Top 10 still lists them as critical risks. This guide shows you exactly how to defend against both attacks using Python frameworks like FastAPI, Flask, and Django, with working code examples you can copy and adapt.

Understanding the Threats

What is XSS? (Cross-Site Scripting)

XSS happens when an attacker injects malicious JavaScript into a page that other users see. The browser can't tell the difference between your legitimate HTML and the attacker's injected script — it just executes everything.

Types of XSS:

  • Reflected XSS — Malicious input in a URL is reflected back in the response (e.g., search results page). Most common in search boxes and error messages.
  • Stored XSS — Malicious input is saved to a database and served to all visitors (e.g., comment sections, profiles). Most dangerous because it persists.
  • DOM-based XSS — The vulnerability exists in client-side JavaScript that manipulates the DOM using unsanitized input. Server is never involved.

What is CSRF? (Cross-Site Request Forgery)

CSRF tricks an authenticated user into performing an action they didn't intend. The attacker creates a malicious site that sends requests to your app while the user is logged in. Since the browser automatically includes cookies, your app thinks the request is legitimate.

XSS vs CSRF: Key Difference

  • XSS = The attacker gets code to run in the victim's browser
  • CSRF = The attacker gets the victim's browser to send a request to the victim's account

Defending Against XSS

Rule #1: Escape All User Input in HTML Output

The single most important defense: never insert raw user input into HTML. Convert dangerous characters to their HTML entities:

# BAD — raw user input in HTML (vulnerable!)
html = f"<h1>{user_name}</h1>"

# GOOD — escape special characters
from html import escape
html = f"<h1>{escape(user_name)}</h1>"

The html.escape() function converts < > & " ' to safe HTML entities. An attacker inputting <script>alert('XSS')</script> becomes harmless text: &lt;script&gt;alert('XSS')&lt;/script&gt;.

FastAPI: Auto-Escaping with Jinja2 Templates

FastAPI doesn't auto-escape by default — it's a framework for APIs, not HTML rendering. But when you use Jinja2 templates (the standard approach), escaping is automatic:

from fastapi import FastAPI, Request
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates

app = FastAPI()
templates = Jinja2Templates(directory="templates")

@app.get("/user/{username}", response_class=HTMLResponse)
async def user_profile(request: Request, username: str):
    return templates.TemplateResponse("profile.html", {
        "request": request,
        "username": username  # Jinja2 auto-escapes this!
    })

In your profile.html template, this is safe:

<h1>{{ username }}</h1>

But this is NOT safe — you explicitly told Jinja2 to skip escaping:

<h1>{{ username | safe }}</h1>
