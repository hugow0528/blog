Python Async/Await Deep Dive: Write Concurrent Code Without Threads

July 6, 2026 11 min read

Python has a GIL (Global Interpreter Lock) that prevents true parallel execution of Python code across threads. So how do companies like Discord and FastAPI handle tens of thousands of simultaneous connections? The answer is async/await — a model of concurrency that doesn't fight the GIL but works around it by yielding control while waiting for I/O.

This guide takes you from zero to production-ready async Python. You'll learn coroutines, the event loop, running tasks concurrently, async generators, real-world patterns for APIs and databases, and the common pitfalls that trip up even experienced developers.

Async vs Threading: Why It Matters

Before writing any async code, understand when to use it:

Pattern Best For Example
Async/Await I/O-bound (network, disk, databases) API server, web scraper
Threads I/O-bound (legacy libraries) GUI apps, some DB drivers
Process (multiprocessing) CPU-bound (math, data processing) Image processing, ML inference

Async is the king of I/O-bound work. If your program spends most of its time waiting for network responses, disk reads, or database queries, async will let you handle many operations at once with a single thread.

Your First Async Function

An async function looks like a normal function, but you prefix it with async def and use await for operations that wait:

import asyncio
import time

# This is a regular (blocking) function
def slow_task_sync():
    time.sleep(2)  # Blocks the entire program for 2 seconds
    return "done"

# This is an async (non-blocking) function
async def slow_task_async():
    await asyncio.sleep(2)  # Yields control to the event loop
    return "done"

# ❌ WRONG: This just creates a coroutine object, doesn't run it
result = slow_task_async()
print(result)  # <coroutine object slow_task_async at 0x7f...>

# ✅ RIGHT: Run it with asyncio.run()
result = asyncio.run(slow_task_async())
print(result)  # "done"

The key insight: asyncio.sleep() doesn't actually stop your program — it tells the event loop "I'll wait 2 seconds, go run something else in the meantime."

Running Tasks Concurrently with asyncio.gather()

This is where async shines. Instead of waiting for each task sequentially, run them all at once:

import asyncio
import aiohttp
import time

async def fetch_url(session, url):
    """Fetch a URL and return its content length."""
    async with session.get(url) as response:
        text = await response.text()
        return (url, len(text))

async def main():
    urls = [
        "https://httpbin.org/delay/1",
        "https://httpbin.org/delay/2",
        "https://httpbin.org/delay/3",
    ]

    async with aiohttp.ClientSession() as session:
        # Sequential (slow): ~6 seconds total
        # results = []
        # for url in urls:
        #     result = await fetch_url(session, url)
        #     results.append(result)

        # Concurrent (fast): ~3 seconds (longest single request)
        tasks = [fetch_url(session, url) for url in urls]
        results = await asyncio.gather(*tasks)

    for url, length in results:
        print(f"{url}: {length} bytes")

# Run the async program
asyncio.run(main())

asyncio.gather() creates all coroutines simultaneously and waits for all of them to complete. The total time is roughly the longest individual request, not the sum of all requests.

Error Handling with asyncio.gather()

By default, if one task in gather() fails, all results are lost. Use return_exceptions=True to handle each independently:

async def main():
    urls = ["https://httpbin.org/delay/1", "https://invalid-url.example"]

    async with aiohttp.ClientSession() as session:
        tasks = [fetch_url(session, url) for url in urls]
        results = await asyncio.gather(*tasks, return_exceptions=True)

    for result in results:
        if isinstance(result, Exception):
            print(f"Error: {result}")
        else:
            url, length = result
            print(f"{url}: {length} bytes")

Async Generators: Lazy, Non-Blocking Iteration

Just as regular generators use yield, async generators use async def with yield:

async def count_down(n):
    """Async generator that counts down."""
    while n > 0:
        await asyncio.sleep(0.5)  # Non-blocking delay
        yield n
        n -= 1

async def main():
    async for number in count_down(5):
        print(f"{number}...")
    print("Liftoff!")

asyncio.run(main())
# Output:
# 5...
# 4...
# 3...
# 2...
# 1...
# Liftoff!

Real-world use case: reading a large stream of data from an API without loading everything into memory:

async def fetch_stock_ticks(ticker):
    """Simulate streaming stock price updates."""
    import random
    price = 150.0
    while True:
        price += random.uniform(-0.5, 0.5)
        await asyncio.sleep(1)
        yield {"ticker": ticker, "price": round(price, 2)}

async def main():
    async for tick in fetch_stock_ticks("AAPL"):
        print(f"AAPL: ${tick['price']}")
        if tick["price"] < 148:
            print("⚠️ Price dropped below $148!")
            break

asyncio.run(main())

Async Context Managers

Just like regular context managers use with, async context managers use async with:

from contextlib import asynccontextmanager

@asynccontextmanager
async def managed_connection():
    """Async context manager for a simulated database connection."""
    print("Connecting to database...")
    # Simulate async connection
    await asyncio.sleep(0.1)
    connection = {"status": "open"}

    try:
        yield connection
    finally:
        print("Closing connection...")
        connection["status"] = "closed"

async def query_database():
    async with managed_connection() as conn:
        print(f"Connection status: {conn['status']}")
        # Simulate a query
        await asyncio.sleep(0.5)
        return {"users": 42}

result = asyncio.run(query_database())
# Output:
# Connecting to database...
# Connection status: open
# Closing connection...
# Returns: {'users': 42}

Real-World Pattern: Concurrent Web Scraper

Let's build something practical — a web scraper that fetches multiple pages concurrently:

import asyncio
import aiohttp
from bs4 import BeautifulSoup

async def scrape_page(session: aiohttp.ClientSession, url: str) -> dict:
    """Scrape a single page and extract title + links."""
    try:
        async with session.get(url, timeout=aiohttp.ClientTimeout(total=10)) as resp:
            html = await resp.text()
            soup = BeautifulSoup(html, "html.parser")
            return {
                "url": url,
                "title": soup.title.string if soup.title else "No title",
                "links": len(soup.find_all("a")),
                "status": resp.status,
            }
    except Exception as e:
        return {"url": url, "error": str(e), "status": 0}

async def scrape_many(urls: list[str], max_concurrent: int = 5) -> list[dict]:
    """Scrape multiple URLs with a concurrency limit."""
    # Semaphore limits concurrent requests
    semaphore = asyncio.Semaphore(max_concurrent)

    async def bounded_scrape(session, url):
        async with semaphore:
            return await scrape_page(session, url)

    async with aiohttp.ClientSession() as session:
        tasks = [bounded_scrape(session, url) for url in urls]
        return await asyncio.gather(*tasks, return_exceptions=True)

# Usage
if __name__ == "__main__":
    urls = [
        "https://example.com",
        "https://httpbin.org/html",
        "https://python.org",
        "https://news.ycombinator.com",
        "https://github.com",
    ]
    results = asyncio.run(scrape_many(urls))

    for result in results:
        if isinstance(result, Exception):
            print(f"Error: {result}")
        else:
            print(f"{result['url']}: {result['title']} ({result['links']} links)")

The Semaphore is crucial — without it, you'd open hundreds of connections simultaneously and get blocked or rate-limited. A limit of 5-10 concurrent requests is a good starting point.

Real-World Pattern: API Rate Limiter

Many APIs limit how fast you can call them. Here's a reusable rate limiter:

import asyncio
import time

class RateLimiter:
    """Async rate limiter using the token bucket algorithm."""

    def __init__(self, max_tokens: int, refill_rate: float):
        """
        Args:
            max_tokens: Maximum requests allowed in a burst
            refill_rate: Tokens added per second
        """
        self.max_tokens = max_tokens
        self.tokens = max_tokens
        self.refill_rate = refill_rate
        self.last_refill = time.monotonic()
        self._lock = asyncio.Lock()

    async def acquire(self):
        """Wait until a token is available."""
        while True:
            async with self._lock:
                now = time.monotonic()
                # Refill tokens based on elapsed time
                elapsed = now - self.last_refill
                self.tokens = min(
                    self.max_tokens,
                    self.tokens + elapsed * self.refill_rate
                )
                self.last_refill = now

                if self.tokens >= 1:
                    self.tokens -= 1
                    return  # Token acquired!

            # No token available — wait a bit and retry
            await asyncio.sleep(1.0 / self.refill_rate)

# Usage: 5 requests per second, burst of 10
limiter = RateLimiter(max_tokens=10, refill_rate=5.0)

async def make_api_call(url):
    await limiter.acquire()  # Rate limiting happens here
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as resp:
            return await resp.json()

# Run 20 calls — will automatically pace to 5/sec
tasks = [make_api_call("https://httpbin.org/get") for _ in range(20)]
results = asyncio.run(asyncio.gather(*tasks))

Common Pitfalls and How to Avoid Them

Pitfall 1: Mixing Blocking and Async Code

# ❌ WRONG: time.sleep() blocks the entire event loop
async def bad():
    await fetch_data()
    time.sleep(1)  # Everything else stops for 1 second
    await process_data()

# ✅ RIGHT: Use asyncio.sleep()
async def good():
    await fetch_data()
    await asyncio.sleep(1)  # Other tasks can run
    await process_data()

Common blocking functions to watch out for: time.sleep(), open()/read(), requests.get() (use aiohttp instead), and any library that doesn't have an async version.

Pitfall 2: Forgetting to Await

# ❌ This creates the coroutine but never runs it
async def main():
    result = slow_task()  # Forgot await!

# ✅ Always await async functions
async def main():
    result = await slow_task()

Use ruff or flake8-async to catch this at lint time — they flag missing await automatically.

Pitfall 3: Creating Tasks Without Tracking Them

# ❌ Fire-and-forget — task might fail silently
async def main():
    asyncio.create_task(fire_and_forget())
    await asyncio.sleep(0.1)
    # Task might not have finished!

# ✅ Track your tasks
async def main():
    task = asyncio.create_task(fire_and_forget())
    try:
        await task
    except Exception as e:
        print(f"Task failed: {e}")

Pitfall 4: Deadlocks with Locks

# ❌ Deadlock: acquire lock, then await while holding it
lock = asyncio.Lock()
async def deadlock():
    async with lock:
        await some_slow_operation()  # If this raises, lock never releases

# ✅ Use a try/finally or set a timeout
async def safe():
    async with asyncio.timeout(5):
        async with lock:
            await some_slow_operation()

Async with FastAPI

FastAPI is built on async. Here's how it works in practice:

from fastapi import FastAPI
import httpx

app = FastAPI()

@app.get("/weather/{city}")
async def get_weather(city: str):
    """Fetch weather from multiple APIs concurrently."""
    async with httpx.AsyncClient() as client:
        # Run two API calls at the same time
        response1, response2 = await asyncio.gather(
            client.get(f"https://api.openweathermap.org/data/2.5/weather?q={city}"),
            client.get(f"https://api.weatherapi.com/v1/current.json?q={city}"),
        )
        return {
            "openweather": response1.json(),
            "weatherapi": response2.json(),
        }

Each request to /weather/{city} handles both API calls concurrently instead of sequentially, cutting response time roughly in half.

When NOT to Use Async

Async is not always the right tool:

  • CPU-bound tasks: Use multiprocessing or concurrent.futures.ProcessPoolExecutor
  • Simple scripts: If your script fetches one URL and prints the result, async adds complexity for zero benefit
  • Libraries without async support: If every library you need is synchronous, wrapping them in loop.run_in_executor() defeats the purpose
  • Small teams, simple apps: Flask with synchronous code is simpler and faster to develop for most use cases

Start with synchronous Python. Add async when you measure a real bottleneck — typically when your server needs to handle more concurrent connections than threads can efficiently manage.

Summary Cheat Sheet

# Core syntax
async def my_coroutine(): ...
result = await my_coroutine()

# Running an async program
asyncio.run(main())

# Concurrent execution
results = await asyncio.gather(task1(), task2(), task3())

# Limit concurrency
semaphore = asyncio.Semaphore(5)
async with semaphore:
    await rate_limited_operation()

# Async generator
async def my_generator():
    for item in items:
        await asyncio.sleep(0.1)
        yield item

# Async context manager
async with managed_resource() as resource:
    await resource.do_something()

Async/await turns Python from a language that waits for one thing at a time into one that can juggle hundreds of I/O operations simultaneously — all on a single thread. Master it, and you'll write servers, scrapers, and data pipelines that scale without adding infrastructure complexity.
