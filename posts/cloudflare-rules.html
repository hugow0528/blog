Cloudflare Rules: Page Rules, Transform Rules & WAF for Beginners

June 24, 2026 · 10 min read

Cloudflare sits between your visitors and your server. But what if you want more control? What if you want to cache specific pages, redirect old URLs, block malicious traffic, or transform responses before they reach the browser? That's where Cloudflare Rules come in.

Rules let you define conditions and actions — like an "if this, then that" system for your website traffic. In this guide, you'll learn the different types of rules Cloudflare offers and how to use them, even if you've never touched Cloudflare before.

How Cloudflare Rules Work

Every rule has three parts:

  • Match Condition — When should this rule apply? (e.g., specific URL, country, user agent)
  • Action — What should happen? (e.g., cache, redirect, block, transform)
  • Priority — If multiple rules match, which one wins?

Think of it like traffic signs on a highway. A "Speed Limit 60" sign applies to all cars. But a "Trucks Turn Right" sign only applies to trucks — that's a condition-based rule.

1. Page Rules (Classic, Still Useful)

Page Rules are Cloudflare's original rule system. They're simple but limited to 3 rules on the free plan. Despite newer alternatives, they're still widely used for basic tasks.

Creating a Page Rule

Go to your Cloudflare dashboard → Rules → Page Rules. Enter a URL pattern and select actions:

# Example 1: Force HTTPS on all pages
URL: example.com/*
Actions: Always Use HTTPS

# Example 2: Cache a static asset for 30 days
URL: example.com/images/*
Actions: Cache Level: Cache Everything, Edge Cache TTL: 30 days

# Example 3: Redirect old blog to new blog
URL: example.com/old-blog/*
Actions: Forwarding URL (301) → https://example.com/new-blog/$1

Common Page Rule use cases:

  • Force HTTPS across your entire site
  • Set longer cache times for static assets (images, CSS, JS)
  • Redirect old URLs to new ones (301 permanent redirects)
  • Disable performance features for specific subdomains
  • Set custom cache statuses per path
Pro tip: If you only need HTTPS enforcement, use SSL/TLS → Edge Certificates → Always Use HTTPS instead. Page Rules are better for more specific needs.

2. Cloudflare Rules (The New System)

Cloudflare is transitioning away from Page Rules to Cloudflare Rules — a more powerful, unified system. Each type of rule has its own dashboard:

A. Cache Rules

Control what Cloudflare caches and for how long. The free plan includes cache rules, so you can fine-tune performance without upgrading.

# Rule: Cache API responses for 1 hour
Match: Hostname is example.com AND URI path matches /api/weather/*
Then: Set cache TTL = 3600 seconds

# Rule: Never cache user-specific pages
Match: URI path matches /account/* OR /dashboard/*
Then: Bypass cache (TTL = 0)

When to use Cache Rules:

  • Your homepage doesn't change often — cache it for 1–4 hours
  • Blog posts are static — cache for days or weeks
  • User dashboards change frequently — bypass the cache
  • API responses have a known freshness window — set specific TTLs

B. Transform Rules

Modify responses before they reach the browser — no server code changes needed.

# Rule: Rewrite hostname in responses
Match: Hostname is oldsite.com
Then: Rewrite hostname to → newsite.com

# Rule: Add a security header to all responses
Match: Hostname is example.com
Then: Add response header: Strict-Transport-Security → max-age=31536000

# Rule: Change content type for a specific endpoint
Match: URI path is /feed
Then: Set response content-type → application/rss+xml

When to use Transform Rules:

  • Adding security headers (HSTS, X-Frame-Options) without touching server config
  • Fixing broken links that reference an old domain
  • Injecting a small JavaScript snippet for analytics
  • Changing response content types for compatibility

C. Redirect Rules

More powerful than Page Rule redirects — supports regex and complex conditions.

# Rule: Redirect mobile users to mobile site
Match: User agent contains "Mobile"
Then: Redirect (302) → https://m.example.com$dst

# Rule: Redirect all .htm pages to .html
Match: URI path ends with ".htm"
Then: Redirect (301) → {uri_path:r/\.htm$/, .html}

# Rule: Send /blog/* to a different subdomain
Match: URI path matches /blog/*
Then: Redirect (301) → https://blog.example.com/$1

3. WAF Rules (Web Application Firewall)

A WAF (Web Application Firewall) blocks malicious traffic before it reaches your server. Cloudflare provides managed rules and lets you create custom rules.

Managed Rules (Built-In)

Cloudflare maintains rule sets that block common attacks:

  • OWASP Core Ruleset — Blocks SQL injection, XSS, and other OWASP Top 10 attacks
  • Bot Fight Mode — Challenges known malicious bots
  • Security Level — Low, Medium, High, I'm Under Attack

On the free plan, you get Security Level and Bot Fight Mode. Managed Rulesets require Cloudflare Pro ($20/month).

Custom WAF Rules

You can create your own rules even on the free plan:

# Rule: Block requests with a suspicious user agent
Expression: http.user_agent contains "sqlmap"
Action: Block

# Rule: Block traffic from a specific country
Expression: cf.ip_geo.country eq "XX"
Action: Block

# Rule: Challenge requests to a specific path
Expression: cf.zone.name eq "example.com" AND http.request.uri.path contains "/wp-admin"
Action: Challenge

# Rule: Log suspicious requests (don't block, just track)
Expression: http.request.uri.path contains ".env" OR http.request.uri.path contains "/wp-login.php"
Action: Log

Action types:

  • Block — Return 403 Forbidden
  • Challenge — Show a Cloudflare verification page (JS Challenge or CAPTCHA)
  • Log — Record the request for analysis, allow it through
  • Bypass — Skip security checks (use sparingly!)

Building a Real Ruleset for a Blog

Let's put it all together. Here's a practical ruleset for a blog site:

Cache Rules

Rule 1: Cache blog posts for 4 hours
  Match: URI path matches /posts/*
  Action: Set cache TTL = 14400 seconds

Rule 2: Never cache homepage (updates frequently)
  Match: URI path equals "/"
  Action: Bypass cache (TTL = 0)

Rule 3: Cache static assets for 1 week
  Match: URI path matches /css/* OR /js/* OR /images/*
  Action: Set cache TTL = 604800 seconds

Redirect Rules

Rule 1: Redirect www to non-www
  Match: Hostname is www.example.com
  Action: Redirect (301) → https://example.com$uri_path$uri_query

WAF Rules

Rule 1: Block common hacking tools
  Match: http.user_agent contains "sqlmap" OR http.user_agent contains "nikto"
  Action: Block

Rule 2: Protect .env and config files
  Match: http.request.uri.path contains ".env" OR http.request.uri.path contains ".git"
  Action: Block

Transform Rules

Rule 1: Add security headers
  Match: Always true
  Action: Add header: X-Frame-Options → DENY
  Action: Add header: X-Content-Type-Options → nosniff

Rule Priority and Testing

When multiple rules could match a single request, Cloudflare evaluates them in priority order. Higher priority rules (lower number) are evaluated first. By default, rules created earlier get higher priority.

Always test your rules! Cloudflare provides a rule builder that shows estimated matches. For production:

  1. Create rules with Log action first
  2. Check the Analytics dashboard for logged matches
  3. Verify no legitimate traffic was affected
  4. Switch the action to Block/Challenge when confident

Common Mistakes to Avoid

  • Overlapping rules: Two rules matching the same URL with different actions. Set clear priorities.
  • Blocking yourself: Before blocking by IP or country, verify you're not in the blocked range.
  • Caching user data: Never cache pages with personalized content. Always bypass cache for /account/*, /profile/*, etc.
  • Forgetting about mobile: Mobile sites may need different cache rules or redirects.
  • Too broad WAF rules: A rule blocking all requests to /* with a certain header might block legitimate browsers. Test in Log mode first.

Summary

Cloudflare Rules give you powerful, serverless control over your website traffic:

  • Cache Rules — Control what and how long to cache
  • Transform Rules — Modify responses without server changes
  • Redirect Rules — Powerful URL redirection with regex
  • WAF Rules — Block malicious traffic with custom conditions
  • Page Rules — Legacy but still useful for simple cases

Start with simple rules, test in Log mode, and gradually build up your ruleset. The key is matching the right condition to the right action — just like good programming logic, but with a GUI instead of code.
