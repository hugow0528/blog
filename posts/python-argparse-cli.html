Python argparse: Build Professional CLI Tools — Complete Beginner's Guide

July 20, 2026 10 min read

Command-line interfaces (CLIs) are one of the most practical ways to build tools that other developers (and your future self) will actually use. Python's built-in argparse module makes it easy to create professional-grade CLIs with automatic help text, type validation, and subcommands — all without installing any third-party packages.

In this guide, you'll learn everything from your first positional argument to building a complete multi-command tool with subcommands, custom types, and configuration file support.

Why argparse Over sys.argv?

Before argparse existed, developers parsed command-line arguments manually using sys.argv. This approach quickly becomes messy:

import sys

# Manual parsing — fragile and error-prone
args = sys.argv
if len(args) < 2:
    print("Usage: mytool.py <filename>")
    sys.exit(1)

filename = args[1]
verbose = "--verbose" in args
output = None
for i, arg in enumerate(args):
    if arg == "--output" and i + 1 < len(args):
        output = args[i + 1]

This approach has no validation, no help text, no type conversion, and no handling of flags in different orders. argparse solves all of these problems:

import argparse

parser = argparse.ArgumentParser(
    description="Process a file and generate a report."
)
parser.add_argument("filename", help="Input file to process")
parser.add_argument("--verbose", "-v", action="store_true",
                    help="Enable verbose output")
parser.add_argument("--output", "-o", default="report.txt",
                    help="Output file path (default: report.txt)")

args = parser.parse_args()
print(f"Processing: {args.filename}")
print(f"Output: {args.output}")
print(f"Verbose: {args.verbose}")

Run python mytool.py --help and you get beautifully formatted help text automatically. Try passing invalid arguments and argparse handles the error messages for you.

Positional vs Optional Arguments

There are two types of arguments in argparse: positional (required, order matters) and optional (start with -- or -, order doesn't matter).

Positional Arguments

Positional arguments are required by default. They must be provided in the order they're defined:

import argparse

parser = argparse.ArgumentParser(description="Convert between units")
parser.add_argument("value", type=float, help="The numeric value to convert")
parser.add_argument("from_unit", choices=["cm", "m", "ft", "in"],
                    help="Source unit")
parser.add_argument("to_unit", choices=["cm", "m", "ft", "in"],
                    help="Target unit")

args = parser.parse_args()

# Conversion logic
conversion = {
    "cm": 1, "m": 100, "ft": 30.48, "in": 2.54
}

result = args.value * conversion[args.from_unit] / conversion[args.to_unit]
print(f"{args.value} {args.from_unit} = {result:.4f} {args.to_unit}")

Try running this:

$ python converter.py 5 ft cm
5 ft = 152.4000 cm

$ python converter.py 100 inches
# Error: too few arguments

$ python converter.py 5 ft km
# Error: invalid choice: 'km'

The choices parameter validates input against a predefined set. The type=float parameter ensures the value is converted from string to float automatically.

Optional Arguments (Flags and Values)

Optional arguments start with -- (long form) or - (short form). They can be provided in any order:

import argparse

parser = argparse.ArgumentParser(description="Download files from URLs")
parser.add_argument("url", help="URL to download from")
parser.add_argument("-o", "--output", default=None,
                    help="Output filename (default: from URL)")
parser.add_argument("-r", "--retries", type=int, default=3,
                    help="Number of retries on failure (default: 3)")
parser.add_argument("--timeout", type=int, default=30,
                    help="Request timeout in seconds (default: 30)")
parser.add_argument("--verbose", "-v", action="store_true",
                    help="Print detailed progress")
parser.add_argument("--format", "-f", choices=["json", "csv", "txt"],
                    default="json", help="Output format (default: json)")

args = parser.parse_args()

Key parameter types:

  • type=int — automatically converts the string to an integer
  • default=3 — value used when the flag is not provided
  • action="store_true" — turns the flag into a boolean (True if present, False otherwise)
  • choices=["json", "csv"] — validates against a set of allowed values
  • nargs="?" — makes the argument optional even without default

Required Optional Arguments

Some optional arguments should be mandatory — for example, an API key. Use required=True:

parser.add_argument("--api-key", required=True,
                    help="Your API key (env: MY_API_KEY)")

# Better pattern: check environment first
import os
default_key = os.environ.get("MY_API_KEY")
parser.add_argument("--api-key", required=not default_key,
                    default=default_key,
                    help="API key (or set MY_API_KEY env var)")

Custom Type Validation

You can define custom validation functions with the type parameter:

def positive_int(value):
    """Validate that the value is a positive integer."""
    ivalue = int(value)
    if ivalue <= 0:
        raise argparse.ArgumentTypeError(f"{value} is not a positive integer")
    return ivalue

def port_number(value):
    """Validate a TCP port number (1-65535)."""
    port = int(value)
    if not 1 <= port <= 65535:
        raise argparse.ArgumentTypeError(
            f"{port} is not a valid port number (1-65535)"
        )
    return port

parser.add_argument("--count", type=positive_int, help="Number of items")
parser.add_argument("--port", type=port_number, default=8080, help="Port number")

When validation fails, argparse prints a clear error message and exits with code 2:

$ python tool.py --port 0
error: argument --port: 0 is not a valid port number (1-65535)

Subcommands

Many real-world CLIs have subcommands (like git commit, docker build). argparse supports this with add_subparsers():

import argparse

def cmd_create(args):
    """Handle the 'create' subcommand."""
    print(f"Creating user: {args.name}")
    print(f"  Email: {args.email}")
    if args.admin:
        print("  Role: admin")

def cmd_list(args):
    """Handle the 'list' subcommand."""
    print(f"Listing users...")
    if args.active_only:
        print("  Filter: active only")

def cmd_delete(args):
    """Handle the 'delete' subcommand."""
    print(f"Deleting user ID: {args.user_id}")
    if args.force:
        print("  Force delete: yes")
    else:
        print("  Confirm before deleting...")

# Main parser
parser = argparse.ArgumentParser(
    prog="user-manager",
    description="Manage user accounts in the system."
)
subparsers = parser.add_subparsers(dest="command", help="Available commands")

# 'create' subcommand
create_parser = subparsers.add_parser("create", help="Create a new user")
create_parser.add_argument("--name", "-n", required=True, help="User's full name")
create_parser.add_argument("--email", "-e", required=True, help="User's email address")
create_parser.add_argument("--admin", "-a", action="store_true", help="Make admin user")
create_parser.set_defaults(func=cmd_create)

# 'list' subcommand
list_parser = subparsers.add_parser("list", help="List all users")
list_parser.add_argument("--active-only", action="store_true", help="Show only active users")
list_parser.add_argument("--limit", type=int, default=50, help="Max results (default: 50)")
list_parser.set_defaults(func=cmd_list)

# 'delete' subcommand
delete_parser = subparsers.add_parser("delete", help="Delete a user")
delete_parser.add_argument("user_id", type=int, help="ID of user to delete")
delete_parser.add_argument("--force", "-f", action="store_true", help="Skip confirmation")
delete_parser.set_defaults(func=cmd_delete)

# Parse and dispatch
args = parser.parse_args()
if args.command is None:
    parser.print_help()
else:
    args.func(args)

Now you get a rich CLI experience:

$ python user-manager.py --help
usage: user-manager [-h] {create,list,delete} ...

Manage user accounts in the system.

positional arguments:
  {create,list,delete}  Available commands
    create              Create a new user
    list                List all users
    delete              Delete a user

$ python user-manager.py create -n "Alice" -e "alice@example.com"
Creating user: Alice
  Email: alice@example.com

Complete Real-World Example: Log File Analyzer

Let's put everything together into a practical CLI tool that analyzes log files:

#!/usr/bin/env python3
"""Log file analyzer — search, filter, and summarize log files."""

import argparse
import sys
from datetime import datetime

def parse_log_line(line):
    """Parse a single log line into components."""
    # Expected format: [2026-07-20 10:30:00] LEVEL: message
    parts = line.strip().split("] ", 1)
    if len(parts) != 2:
        return None
    timestamp_str = parts[0].strip("[")
    rest = parts[1]
    level_msg = rest.split(": ", 1)
    if len(level_msg) != 2:
        return None
    return {
        "timestamp": timestamp_str,
        "level": level_msg[0].strip(),
        "message": level_msg[1].strip()
    }

def cmd_analyze(args):
    """Analyze and summarize a log file."""
    try:
        with open(args.file, "r") as f:
            lines = f.readlines()
    except FileNotFoundError:
        print(f"Error: File '{args.file}' not found.", file=sys.stderr)
        sys.exit(1)

    levels = {"INFO": 0, "WARNING": 0, "ERROR": 0, "DEBUG": 0}
    errors = []

    for line in lines:
        parsed = parse_log_line(line)
        if parsed:
            level = parsed["level"]
            if level in levels:
                levels[level] += 1
            if level == "ERROR" and not args.exclude_errors:
                errors.append(parsed["message"])

    print(f"\n📊 Log Analysis: {args.file}")
    print(f"   Total lines: {len(lines)}")
    for level, count in levels.items():
        print(f"   {level}: {count}")

    if errors and args.show_errors:
        print(f"\n   Recent errors:")
        for err in errors[-5:]:
            print(f"     - {err}")

def cmd_search(args):
    """Search for text in a log file."""
    try:
        with open(args.file, "r") as f:
            lines = f.readlines()
    except FileNotFoundError:
        print(f"Error: File '{args.file}' not found.", file=sys.stderr)
        sys.exit(1)

    results = []
    for i, line in enumerate(lines):
        if args.pattern.lower() in line.lower():
            results.append((i + 1, line.strip()))

    print(f"Found {len(results)} matches for '{args.pattern}':")
    for num, match in results[:args.max_results]:
        print(f"  Line {num}: {match}")
    if len(results) > args.max_results:
        print(f"  ... and {len(results) - args.max_results} more")

def main():
    parser = argparse.ArgumentParser(
        prog="log-analyzer",
        description="Analyze and search through log files.",
        formatter_class=argparse.RawDescriptionHelpFormatter,
        epilog="""
Examples:
  %(prog)s analyze app.log
  %(prog)s analyze app.log --show-errors
  %(prog)s search app.log "connection timeout"
  %(prog)s search app.log "error" --max 20
"""
    )
    subparsers = parser.add_subparsers(dest="command", help="Commands")

    analyze = subparsers.add_parser("analyze", help="Analyze a log file")
    analyze.add_argument("file", help="Path to the log file")
    analyze.add_argument("--show-errors", action="store_true",
                        help="Display recent error messages")
    analyze.add_argument("--exclude-errors", action="store_true",
                        help="Don't count errors in analysis")
    analyze.set_defaults(func=cmd_analyze)

    search = subparsers.add_parser("search", help="Search log file")
    search.add_argument("file", help="Path to the log file")
    search.add_argument("pattern", help="Text to search for")
    search.add_argument("--max", type=int, default=10,
                       help="Max results to show (default: 10)")
    search.set_defaults(func=cmd_search)

    args = parser.parse_args()
    if args.command is None:
        parser.print_help()
        sys.exit(1)
    args.func(args)

if __name__ == "__main__":
    main()

Pro Tips

  • Use __main__.py — package your tool so users can run it with python -m mytool
  • Group related arguments — use parser.add_argument_group("Network options") to organize help output
  • Read defaults from config files — merge a YAML/JSON config with CLI args using set_defaults(**config)
  • Use nargs="*" for arguments that accept zero or more values (like a list of filenames)
  • Consider typer or click for more complex CLIs — they build on argparse ideas with cleaner syntax

Summary

argparse is Python's built-in answer to building command-line tools. It handles help text, validation, type conversion, subcommands, and error messages — all automatically. Start with simple positional and optional arguments, then add subcommands as your tool grows. The key pattern is set_defaults(func=handler) to dispatch to the right handler function based on which subcommand the user called.
