Python Pydantic: Data Validation That Just Works — Complete Guide

July 7, 2026 · 10 min read

Every Python application that accepts data from outside — user input, API responses, config files, database rows — needs validation. Without it, a single wrong data type can crash your entire application. Pydantic makes validation declarative, type-driven, and incredibly fast. It's the backbone of FastAPI and one of the most popular Python packages with over 200 million monthly downloads.

In this guide, you'll learn everything from basic models to advanced custom validators, nested schemas, serialization, and real-world patterns you'll use in production.

What is Pydantic?

Pydantic is a data validation library for Python. You define a model — essentially a class with type annotations — and Pydantic automatically validates any data you pass into it. If the data is wrong, you get a clear error message. If it's correct, you get a fully typed, validated object.

Here's the core idea in 3 lines:

from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

user = User(name="Hugo", age=28)
print(user.name)  # Hugo
print(user.age)   # 28

Now try passing invalid data:

User(name="Hugo", age="not a number")
# pydantic.ValidationError: 1 validation error for User
# age
#   Input should be a valid integer, unable to parse string as an integer [type=int_parsing]

That's it. No custom error checking code, no try/except blocks — Pydantic handles it automatically.

Why Pydantic Over Manual Validation?

Without Pydantic, your validation code looks like this:

def validate_user(data):
    if "name" not in data:
        raise ValueError("name is required")
    if not isinstance(data["name"], str):
        raise ValueError("name must be a string")
    if "age" not in data:
        raise ValueError("age is required")
    if not isinstance(data["age"], int):
        raise ValueError("age must be an integer")
    if data["age"] < 0:
        raise ValueError("age must be positive")
    return data

data = validate_user({"name": "Hugo", "age": 28})

With Pydantic, that entire function collapses into a model definition. The model is self-documenting, reusable, and integrates with IDEs, type checkers, and OpenAPI generators.

Installation

pip install pydantic

Pydantic v2 is the current version (released 2023). It's significantly faster than v1 and uses a different internal engine (Rust-based). Most examples online still show v1 syntax — make sure you're reading v2 documentation.

Basic Model Types

Pydantic understands all standard Python types plus many extras from the typing module:

from pydantic import BaseModel, EmailStr
from typing import Optional, List
from datetime import datetime
from decimal import Decimal

class Product(BaseModel):
    # Basic types
    name: str
    price: Decimal          # Use Decimal for money, never float!
    in_stock: bool = True   # Default value

    # Optional fields
    description: Optional[str] = None
    created_at: datetime = datetime.now()

    # Collections
    tags: List[str] = []
    ratings: list[float] = []  # Python 3.9+ syntax works too

    # Email validation (requires email-validator package)
    contact_email: EmailStr

# Valid product
product = Product(
    name="Mechanical Keyboard",
    price=Decimal("89.99"),
    contact_email="hugo@example.com",
    tags=["peripherals", "mechanical"],
    ratings=[4.5, 4.0, 5.0]
)

print(product.price)        # 89.99
print(product.tags)         # ['peripherals', 'mechanical']
print(product.in_stock)     # True (default)

Field Configuration with Field()

The Field() function lets you add constraints, defaults, and metadata to individual fields:

from pydantic import BaseModel, Field
from typing import List

class UserProfile(BaseModel):
    username: str = Field(
        min_length=3,
        max_length=30,
        description="Unique username for login",
        examples=["hugo_w", "dev_guru"]
    )
    age: int = Field(ge=0, le=150)  # ge=greater or equal, le=less or equal
    bio: str = Field(default="", max_length=500)
    interests: List[str] = Field(default_factory=list, max_length=10)

# Valid
profile = UserProfile(username="hugo_w", age=28, bio="Developer")

# Too short username
UserProfile(username="hi", age=28)
# ValidationError: 1 validation error for UserProfile
# username
#   String should have at least 3 characters [type=string_too_short]

# Age out of range
UserProfile(username="hugo_w", age=200)
# ValidationError: 1 validation error for UserProfile
# age
#   Input should be less than or equal to 150 [type=less_than_equal]

Tip: Always use default_factory=list instead of default=[] for mutable defaults. Using default=[] creates a single shared list instance across all model objects — a common Python gotcha.

Custom Validators

When built-in constraints aren't enough, use the @field_validator decorator to write custom validation logic:

from pydantic import BaseModel, Field, field_validator
import re

class UserRegistration(BaseModel):
    username: str
    email: str
    password: str

    @field_validator("username")
    @classmethod
    def username_alphanumeric(cls, v):
        if not re.match(r"^[a-zA-Z0-9_]+$", v):
            raise ValueError("Username must be alphanumeric or underscores")
        return v

    @field_validator("email")
    @classmethod
    def email_lowercase(cls, v):
        return v.lower().strip()

    @field_validator("password")
    @classmethod
    def password_strength(cls, v):
        if len(v) < 8:
            raise ValueError("Password must be at least 8 characters")
        if not any(c.isupper() for c in v):
            raise ValueError("Password must contain an uppercase letter")
        if not any(c.isdigit() for c in v):
            raise ValueError("Password must contain a digit")
        return v

# Valid registration
user = UserRegistration(
    username="hugo_dev",
    email="Hugo@Example.COM",  # Gets normalized to lowercase
    password="Secure1Pass"
)
print(user.email)  # hugo@example.com

# Invalid password
UserRegistration(username="hugo", email="a@b.com", password="weak")
# ValidationError: Password must be at least 8 characters

Validators can also access other field values using @model_validator:

from pydantic import BaseModel, model_validator

class DateRange(BaseModel):
    start_date: str
    end_date: str

    @model_validator(mode="after")
    def check_dates(self):
        if self.start_date > self.end_date:
            raise ValueError("start_date must be before end_date")
        return self

DateRange(start_date="2026-01-01", end_date="2026-12-31")  # OK
DateRange(start_date="2026-12-31", end_date="2026-01-01")  # ValidationError

Nested Models

Models can contain other models, creating complex nested structures:

from pydantic import BaseModel, Field
from typing import List, Optional
from datetime import datetime

class Address(BaseModel):
    street: str
    city: str
    country: str = "US"
    zip_code: str = Field(pattern=r"^\d{5}(-\d{4})?$")

class Company(BaseModel):
    name: str
    founded: int = Field(ge=1800, le=datetime.now().year)

class Employee(BaseModel):
    name: str
    email: str
    address: Address
    company: Company
    skills: List[str] = []
    manager: Optional["Employee"] = None

# Create nested data
employee = Employee(
    name="Hugo Wong",
    email="hugo@example.com",
    address=Address(
        street="123 Dev Lane",
        city="San Francisco",
        zip_code="94102"
    ),
    company=Company(name="TechCorp", founded=2020),
    skills=["Python", "Docker", "Cloudflare"]
)

print(employee.company.name)    # TechCorp
print(employee.address.city)    # San Francisco

Serialization: dict(), JSON, and More

Pydantic models can be converted to dictionaries and JSON effortlessly:

from pydantic import BaseModel
from datetime import datetime

class Post(BaseModel):
    title: str
    body: str
    published_at: datetime = datetime.now()
    draft: bool = False

post = Post(title="Hello World", body="My first post")

# To dictionary
print(post.model_dump())
# {'title': 'Hello World', 'body': 'My first post',
#  'published_at': datetime(2026, 7, 7, ...), 'draft': False}

# To JSON string
print(post.model_dump_json())
# {"title":"Hello World","body":"My first post",
#  "published_at":"2026-07-07T12:00:00","draft":false}

# Exclude fields
print(post.model_dump(exclude={"body"}))
# {'title': 'Hello World', 'published_at': ..., 'draft': False}

# Include only certain fields
print(post.model_dump(include={"title", "published_at"}))
# {'title': 'Hello World', 'published_at': ...}

Config Classes and Settings

One of Pydantic's killer features is BaseSettings for reading configuration from environment variables:

from pydantic import BaseModel, Field
from pydantic_settings import BaseSettings

# pip install pydantic-settings

class AppSettings(BaseSettings):
    app_name: str = "MyApp"
    debug: bool = False
    database_url: str
    api_key: str = Field(exclude=True)  # Don't include in dumps

    # Read from .env file automatically
    model_config = {"env_file": ".env", "env_file_encoding": "utf-8"}

# Creates settings from environment variables
settings = AppSettings()
print(settings.app_name)    # MyApp (or value from env)
print(settings.database_url) # From DATABASE_URL env var

# .env file contents:
# DATABASE_URL=postgresql://user:pass@localhost:5432/mydb
# API_KEY=secret-key-123
# DEBUG=true

Real-World Pattern: API Request/Response Models

Here's how Pydantic models are used in production APIs:

from pydantic import BaseModel, Field, field_validator
from typing import List, Optional
from enum import Enum

class SortOrder(str, Enum):
    ASC = "asc"
    DESC = "desc"

# Request model
class ListProductsRequest(BaseModel):
    page: int = Field(default=1, ge=1)
    per_page: int = Field(default=20, ge=1, le=100)
    search: Optional[str] = None
    min_price: Optional[float] = Field(default=None, ge=0)
    sort_by: str = "name"
    sort_order: SortOrder = SortOrder.ASC

# Response model
class ProductResponse(BaseModel):
    id: int
    name: str
    price: float
    in_stock: bool

class ProductsResponse(BaseModel):
    products: List[ProductResponse]
    total: int
    page: int
    per_page: int

# Validate incoming request data
request_data = {"search": "keyboard", "per_page": 50, "sort_order": "desc"}
request = ListProductsRequest(**request_data)
print(request.search)      # keyboard
print(request.per_page)    # 50
print(request.sort_order)  # SortOrder.DESC

# Build response
response = ProductsResponse(
    products=[
        ProductResponse(id=1, name="Mech Keyboard", price=89.99, in_stock=True)
    ],
    total=1,
    page=1,
    per_page=50
)
print(response.model_dump_json(indent=2))

Dataclass Compatibility

Pydantic works with Python's built-in dataclass decorator:

from pydantic.dataclasses import dataclass
from pydantic import Field, ValidationError

@dataclass
class Product:
    name: str
    price: float = Field(ge=0)
    category: str = "general"

# Auto-validated!
product = Product(name="Keyboard", price=89.99)

# Invalid data raises error
try:
    Product(name="Keyboard", price=-10)
except ValidationError as e:
    print(e)
    # 1 validation error for Product
    # price
    #   Input should be greater than or equal to 0

Common Pitfalls

  • Floats for money: Always use Decimal, never float. Floating point arithmetic causes precision errors: 0.1 + 0.2 != 0.3.
  • Mutable defaults: Use default_factory=list or default_factory=dict instead of default=[] or default={}.
  • Coercion: Pydantic v2 coerces types by default. age: int accepts the string "28" and converts it. Use StrictInt if you want to reject type mismatches.
  • Optional vs default: Optional[str] = None means the field can be omitted or set to None. str = "default" means the field is required but has a fallback.
  • model_dump vs model_dump_json: Use model_dump() for Python dictionaries and model_dump_json() for JSON strings. Don't use json.dumps(model.dict()) — it will fail on datetime objects.
