Python Debugging and Profiling: pdb, print() Tricks & Performance Tools

July 10, 2026 12 min read New

Master Python debugging and profiling from scratch — the built-in pdb debugger, smart print() debugging tricks, logging-based debugging, cProfile for performance analysis, line_profiler for line-by-line profiling, and finding memory leaks with tracemalloc. Real code examples for every concept.

Every Python developer spends more time debugging than writing new code. It's not glamorous, but it's essential. This guide covers the complete toolkit for finding and fixing bugs in Python, from the simplest print statement to professional profiling tools.

Whether you're a beginner confused by a TypeError or a developer tracking down a performance bottleneck, you'll learn practical techniques you can use immediately.

1. print() Debugging — Don't Underestimate the Basics

Before reaching for fancy tools, master the humble print(). Yes, print debugging works — and it works fast when done right.

Basic Print Debugging

# Basic: print variable values
def calculate_total(items, tax_rate):
    print(f"items: {items}")
    print(f"tax_rate: {tax_rate}")

    subtotal = sum(item["price"] * item["qty"] for item in items)
    print(f"subtotal: {subtotal}")

    total = subtotal * (1 + tax_rate)
    print(f"total: {total}")
    return total

The print(f"DEBUG: {var=}") Trick (Python 3.8+)

Python 3.8 introduced a killer feature: self-documenting print statements.

x = 42
name = "hugo"
items = [1, 2, 3]

print(f"{x=}")           # Output: x=42
print(f"{name=}")        # Output: name='hugo'
print(f"{items=}")       # Output: items=[1, 2, 3]

# Combine with expressions
print(f"{x=}, {x*2=}")   # Output: x=42, x*2=84

# This is HUGE for debugging — you see both name and value

Print with Line Numbers

import inspect

def debug_print(msg):
    frame = inspect.currentframe().f_back
    print(f"[L{frame.f_lineno}] {msg}")

def example():
    x = 1
    debug_print(f"before calc, x={x}")  # [L10] before calc, x=1
    x += 5
    debug_print(f"after calc, x={x}")   # [L12] after calc, x=6

example()

Print Only When Debugging

import os

def debug(msg):
    if os.environ.get("DEBUG") == "1":
        print(f"DEBUG: {msg}")

# Usage: only prints when DEBUG=1
DEBUG=1 python myscript.py

2. The pdb Interactive Debugger

pdb is Python's built-in interactive debugger. It lets you pause execution, inspect variables, step through code, and evaluate expressions — all without modifying your code permanently.

Setting a Breakpoint

def process_orders(orders):
    total = 0
    for order in orders:
        # Drop into debugger here
        breakpoint()  # Python 3.7+ (same as import pdb; pdb.set_trace())
        total += order["amount"]
    return total

When you run this, execution pauses at breakpoint() and drops you into the pdb prompt:

--Return--
> myscript.py(5)process_orders()
        total += order["amount"]
(Pdb)

Essential pdb Commands

# Command    Shortcut    What it does

pdb in Action

def find_duplicate(numbers):
    """Find the first duplicate in a list"""
    seen = set()
    for i, num in enumerate(numbers):
        breakpoint()
        if num in seen:
            return num
        seen.add(num)
    return None

# Run: python myscript.py
# Then at the (Pdb) prompt:

(Pdb) p numbers      # [1, 2, 3, 2, 4]
(Pdb) p i            # 0
(Pdb) p num          # 1
(Pdb) p seen         # set()
(Pdb) n              # (go to next line)
(Pdb) p seen         # {1}
(Pdb) c              # (continue to next breakpoint, i=1)
(Pdb) c              # (i=2)
(Pdb) c              # (i=3, num=2)
(Pdb) p num in seen  # True! Found our duplicate
(Pdb) c              # returns 2

Conditional Breakpoints

# Break only when a condition is met
def process_items(items):
    for i, item in enumerate(items):
        breakpoint()  # Will stop every iteration

# BETTER: Use a conditional expression
def process_items(items):
    for i, item in enumerate(items):
        if i == 5: breakpoint()  # Only break on 6th item
        process(item)

Running pdb from the Command Line

# Start script in debugger immediately
python -m pdb myscript.py

(Pdb) b 10            # Set breakpoint on line 10
(Pdb) b process_orders  # Set breakpoint on function
(Pdb) c               # Run to first breakpoint
(Pdb) continue
(Pdb) n               # Step through

3. Logging-Based Debugging (The Professional Approach)

For production code, replace print() with the logging module. It gives you levels, formatting, timestamps, and file output.

import logging

# Configure once (usually in your main module)
logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s | %(name)s | %(levelname)s | %(message)s',
    handlers=[
        logging.FileHandler("app.log"),
        logging.StreamHandler()  # Also print to console
    ]
)

logger = logging.getLogger(__name__)

def calculate_shipping(weight, distance):
    logger.debug(f"Calculating shipping: weight={weight}kg, distance={distance}km")

    if weight <= 0:
        logger.error(f"Invalid weight: {weight}")
        raise ValueError("Weight must be positive")

    base_rate = 5.0
    per_km = 0.5
    per_kg = 0.1
    cost = base_rate + (distance * per_km) + (weight * per_kg)

    logger.info(f"Shipping cost calculated: ${cost:.2f}")
    return cost

# Output:
# 2026-07-10 10:00:00,123 | __main__ | DEBUG | Calculating shipping: weight=2.5kg, distance=100km
# 2026-07-10 10:00:00,124 | __main__ | INFO | Shipping cost calculated: $57.50

Logging levels from lowest to highest:

DEBUG    → Detailed diagnostic info
INFO     → Confirmation things work normally
WARNING  → Something unexpected happened
ERROR    → Something failed but program continues
CRITICAL → Severe error, program might stop

4. cProfile: Find What's Slow

When your Python code is slow, don't guess — profile it. cProfile tells you exactly which functions consume the most time.

Basic cProfile Usage

import cProfile

def slow_function():
    """Simulate a slow function with nested work"""
    results = []
    for i in range(10000):
        results.append(sorted(range(i, 0, -1)))
    return len(results)

# Run with profiler
cProfile.run('slow_function()')

# Output:
#    10002 function calls in 0.152 seconds
#
#    Ordered by: standard name
#
#    ncalls  tottime  percall  cumtime  percall filename:lineno(function)
#       10000    0.089    0.000    0.142    0.000 {built-in method builtins.sorted}
#       10000    0.033    0.000    0.033    0.000 {method 'append' of 'list' objects}
#           1    0.001    0.001    0.152    0.152 myscript.py:4(slow_function)

Profile with a Script

# From command line (easiest way)
python -m cProfile -s cumtime myscript.py

# -s cumtime : sort by cumulative time (slowest overall)
# -s tottime : sort by total time in function itself
# -s calls   : sort by number of calls
# -o profile.out : save to file instead of printing

Pretty Print with pstats

import cProfile
import pstats

profile = cProfile.Profile()
profile.enable()

# Your code here
slow_function()

profile.disable()

stats = pstats.Stats(profile)
stats.strip_dirs()
stats.sort_stats('cumulative')
stats.print_stats(10)  # Top 10 slowest functions

5. line_profiler: See Time Per Line

cProfile tells you which functions are slow. line_profiler tells you which lines are slow within a function.

# Install first: pip install line_profiler

# myscript.py
import line_profiler

@profile  # Special decorator for line_profiler
def build_report(data):
    # Line 1: Sort the data
    sorted_data = sorted(data, key=lambda x: x["value"])

    # Line 2: Calculate totals
    totals = {}
    for item in sorted_data:
        category = item["category"]
        if category not in totals:
            totals[category] = 0
        totals[category] += item["value"]

    # Line 3: Build output
    report_lines = []
    for cat, total in totals.items():
        report_lines.append(f"{cat}: ${total:.2f}")

    return "\n".join(report_lines)

# Run: kernprof -l -v myscript.py
# This shows time spent on EACH line of the @profile function

6. Finding Memory Leaks with tracemalloc

Memory leaks in Python happen when objects aren't garbage collected — often from circular references, caches that grow forever, or holding onto data you don't need.

import tracemalloc

# Start tracking memory
tracemalloc.start()

# Simulate a memory leak
cache = {}
def leaky_function():
    for i in range(100000):
        cache[i] = "x" * 1000  # Each entry = 1KB, never freed

leaky_function()

# Take a snapshot and compare
snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics('lineno')

print("[ Top 10 memory allocations ]")
for stat in top_stats[:10]:
    print(stat)

# Output:
# myscript.py:10: size=97.7 MiB, count=100000, average=1000 B
#   (showing the exact line allocating the most memory)

# Compare two snapshots (before and after)
snapshot1 = tracemalloc.take_snapshot()
leaky_function()
snapshot2 = tracemalloc.take_snapshot()

top_stats = snapshot2.compare_to(snapshot1, 'lineno')
for stat in top_stats[:5]:
    print(stat)
    # Shows: myscript.py:10: +97.7 MiB

7. Building a Complete Debugging Workflow

Here's a production-ready debugging setup combining everything we've learned:

# debug_utils.py — Add this to any project
import os
import sys
import logging
import tracemalloc

# --- Debug flag ---
DEBUG = os.environ.get("DEBUG") == "1"
PROFILE = os.environ.get("PROFILE") == "1"

# --- Smart logger ---
logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG if DEBUG else logging.INFO)
handler = logging.StreamHandler(sys.stderr)
handler.setFormatter(logging.Formatter(
    '%(asctime)s | %(levelname)-8s | %(name)s | %(message)s'
))
logger.addHandler(handler)

# --- Debug print helper ---
def dprint(*args, **kwargs):
    """Only prints when DEBUG=1"""
    if DEBUG:
        print(*args, **kwargs, file=sys.stderr)

# --- Memory tracker ---
if PROFILE:
    tracemalloc.start()
    logger.info("Memory tracking enabled")

def get_memory_report():
    """Print top memory allocations"""
    if not tracemalloc.is_tracing():
        return
    snapshot = tracemalloc.take_snapshot()
    top = snapshot.statistics('lineno')[:10]
    logger.info("=== Top memory allocations ===")
    for stat in top:
        logger.info(f"  {stat}")

# --- Usage in your app ---
def main():
    logger.info("Application starting")

    items = [{"name": f"item_{i}", "value": i} for i in range(100)]
    dprint(f"Loaded {len(items)} items")

    # Process...
    total = sum(item["value"] for item in items)
    logger.debug(f"Calculated total: {total}")

    get_memory_report()
    logger.info("Application complete")

if __name__ == "__main__":
    main()
