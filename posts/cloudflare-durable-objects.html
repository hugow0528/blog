Cloudflare Durable Objects: Shared State at the Edge — Complete Guide

July 10, 2026 10 min read New

Master Cloudflare Durable Objects — persistent state at the edge without traditional databases. Build real-time counters, leaderboards, chat rooms, and rate limiters. Step-by-step code examples from basic to advanced patterns.

Cloudflare Workers are incredibly fast — they run at the edge, closest to your users. But there's one limitation: they're stateless. Every request is independent, and you can't share data between them without an external database.

Enter Durable Objects — a feature that gives you a persistent, colocated storage and compute environment at the edge. Think of it as a serverless database with zero cold starts, single-digit millisecond latency, and a generous free tier.

What Are Durable Objects?

A Durable Object is a single-threaded actor that lives at a specific location in Cloudflare's global network. Every request routed to the same Durable Object ID is guaranteed to hit the same instance, giving you:

  • Colocated storage — key-value store with atomic operations
  • Strong consistency — no eventual consistency headaches
  • Networking — WebSocket support for real-time apps
  • Automatic failover — if an instance crashes, data survives

1. Set Up Your First Durable Object

First, define your Durable Object in wrangler.toml:

# wrangler.toml
name = "my-app"
main = "src/index.js"
compatibility_date = "2025-01-01"

[[durable_objects.bindings]]
name = "MY_DO"
class_name = "MyCounter"

Then implement the Durable Object class:

// src/counter.js
export class MyCounter {
    constructor(state, env) {
        this.state = state;
        this.env = env;
        this.count = 0;
    }

    async fetch(request) {
        // Increment the counter
        this.count += 1;
        
        // Persist to storage
        await this.state.storage.put("count", this.count);
        
        return new Response(
            JSON.stringify({ count: this.count }),
            { headers: { "Content-Type": "application/json" } }
        );
    }
}

2. Routing Requests to Your Durable Object

Durable Objects are accessed via unique IDs. You derive these IDs from your application data — like a room ID, user ID, or rate-limit bucket:

// src/index.js
export default {
    async fetch(request, env) {
        const url = new URL(request.url);
        
        // Use the path as our Durable Object ID
        const roomId = url.pathname.slice(1) || "default";
        const id = env.MY_DO.idFromName(roomId);
        const stub = env.MY_DO.get(id);
        
        return stub.fetch(request);
    }
};

Now http://your-app.dev/room1 and http://your-app.dev/room1 will always hit the same Durable Object instance, while /room2 hits a different one.

3. Persistent Storage API

Durable Objects include a built-in transactional key-value store:

// Key-value operations
await storage.put("key", "value");           // Save
const value = await storage.get("key");      // Read (null if missing)
await storage.delete("key");                  // Delete

// Lists
await storage.list({ prefix: "user_" });      // Filtered list
await storage.list();                          // All keys

// Batch operations (atomic)
await storage.transaction(async tx => {
    const a = await tx.get("a") || 0;
    const b = await tx.get("b") || 0;
    await tx.put("a", a - 10);
    await tx.put("b", b + 10);
});

// Get all keys
const all = await storage.list();
const keys = all.keys.map(k => k.name);

4. Real-World Example: Global Leaderboard

Let's build a real-time leaderboard that works across all edge locations:

// src/leaderboard.js
export class Leaderboard {
    constructor(state, env) {
        this.state = state;
        this.state.blockConcurrencyWhile(async () => {
            this.scores = await state.storage.get("scores") || {};
        });
    }

    async fetch(request) {
        const url = new URL(request.url);
        
        switch (url.pathname) {
            case "/score": {
                const data = await request.json();
                this.scores[data.player] = Math.max(
                    this.scores[data.player] || 0,
                    data.score
                );
                await this.state.storage.put("scores", this.scores);
                return new Response(JSON.stringify({ ok: true }));
            }
            
            case "/top": {
                const sorted = Object.entries(this.scores)
                    .sort((a, b) => b[1] - a[1])
                    .slice(0, 10);
                return new Response(JSON.stringify(sorted));
            }
            
            default:
                return new Response("Not found", { status: 404 });
        }
    }
}

5. WebSocket Support for Real-Time Apps

Durable Objects can hold persistent WebSocket connections — making them perfect for chat rooms, live notifications, and collaborative editing:

// src/chat.js
export class ChatRoom {
    constructor(state, env) {
        this.state = state;
        this.connections = new Map();
        this.messages = [];
        
        // Handle WebSocket upgrades
        state.ephemeralKey = "ws-room-" + Math.random();
    }

    async fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/ws") {
            const { 0: client, 1: server } = new WebSocketPair();
            server.accept();
            
            const id = this.connections.size + 1;
            this.connections.set(id, server);
            
            server.addEventListener("message", (event) => {
                const msg = JSON.parse(event.data);
                msg.id = Date.now();
                
                // Save to storage
                this.messages.push(msg);
                if (this.messages.length > 100) {
                    this.messages = this.messages.slice(-100);
                    this.state.storage.put("messages", this.messages);
                }
                
                // Broadcast to all connected clients
                for (const [, conn] of this.connections) {
                    conn.send(JSON.stringify(msg));
                }
            });
            
            server.addEventListener("close", () => {
                this.connections.delete(id);
            });
            
            return new Response(null, { status: 101, webSocket: client });
        }
        
        // Get recent messages (non-WebSocket)
        if (url.pathname === "/messages") {
            return new Response(JSON.stringify(this.messages.slice(-50)));
        }
    }
}

When to Use Durable Objects

Durable Objects shine for:

  • Real-time apps — chat rooms, live dashboards, collaborative editing
  • Rate limiting — per-user or per-IP counters with exact accuracy
  • Session storage — user sessions that need fast reads/writes
  • Distributed locks — coordinate actions across requests
  • Counters & leaderboards — atomic increments at the edge

Use D1 when you need SQL queries, joins, or complex filtering. Use Worker KV for simple caching where eventual consistency is acceptable. Use Durable Objects when you need strong consistency, compute, or real-time networking at the edge.

Summary

Cloudflare Durable Objects are a powerful tool for building stateful, real-time applications at the edge. They combine persistent storage, compute, and networking into a single primitive — eliminating the need for separate databases and WebSocket servers for many use cases.

Start with simple counters and leaderboards, then graduate to real-time chat and collaborative apps. The free tier is generous enough to prototype and even run small production services.

Key takeaway: Durable Objects give you strong consistency and colocated compute at the edge — the perfect balance between a key-value store and a full database. When your app needs state + logic at the same location, Durable Objects are your answer.
