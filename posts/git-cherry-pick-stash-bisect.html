Git Cherry-Pick, Stash, and Bisect: Power Tools Every Developer Needs — Complete Guide

July 13, 2026 10 min read New

Master three essential Git commands that separate beginners from power users — cherry-pick to selectively merge commits, stash to temporarily save work without committing, and bisect to find bugs using binary search. Real-world scenarios and working examples for each tool.

You've learned git add, git commit, and git push. Now it's time for the tools that make Git truly powerful. Cherry-pick, stash, and bisect solve three everyday problems: "I need just this one commit," "I need to switch branches but my work isn't ready," and "something broke — when did it happen?"

Let's set up a demo repo first, then dive into each command with real scenarios.

Setup: Demo Repository

# Create a demo repo
mkdir git-power-tools && cd git-power-tools
git init

# Create some initial commits on main
echo "v1.0 - initial version" > app.py
git add app.py && git commit -m "feat: initial version"

echo "v1.1 - added logging" > app.py
git add app.py && git commit -m "feat: add logging"

echo "v1.2 - added config" > app.py
git add app.py && git commit -m "feat: add config system"

# Create a feature branch with multiple commits
git checkout -b feature/dashboard
echo "dash v1" > dashboard.py
git add dashboard.py && git commit -m "feat: create dashboard layout"

echo "dash v2 - with charts" > dashboard.py
git add dashboard.py && git commit -m "feat: add charts to dashboard"

echo "bugfix in dashboard" > dashboard.py
git add dashboard.py && git commit -m "fix: resolve chart rendering bug"

# Switch back to main
git checkout main

1. git cherry-pick: Selectively Apply Commits

Problem: Your feature branch has 10 commits. You only need that one bug fix on main right now — the rest of the feature isn't ready.

Basic Cherry-Pick

# Find the commit hash you want
git log feature/dashboard --oneline
# abc1234 fix: resolve chart rendering bug
# def5678 feat: add charts to dashboard
# 901abcd feat: create dashboard layout

# Apply just the bug fix to main
git cherry-pick abc1234

# main now has the fix, without the other feature commits
git log --oneline
# abc1234 fix: resolve chart rendering bug
# ... (other main commits)

Cherry-Pick a Range of Commits

# Apply multiple commits at once
git cherry-pick abc1234^..def5678

# The ^.. syntax means "from the parent of abc1234 through def5678"
# This applies both the bug fix AND the chart commit

Handle Conflicts During Cherry-Pick

# If the cherry-picked commit conflicts with your current branch:
git cherry-pick abc1234
# CONFLICT (content): Merge conflict in dashboard.py

# Option 1: Fix the conflict manually, then continue
vim dashboard.py          # Resolve the conflict
git add dashboard.py
git cherry-pick --continue

# Option 2: Abort if you change your mind
git cherry-pick --abort

# Option 3: Skip this commit, continue with the next
git cherry-pick --skip

Real-World Scenario: Hotfix from Feature Branch

A bug was found in production. Your team member already fixed it on their feature branch. Instead of merging the whole branch:

# On production branch
git checkout main

# Get the fix commit hash from colleague's branch
git log colleague/feature-branch --oneline | head -5
# 7a3b2c1 fix: null pointer in payment module
# ...

# Apply just that fix
git cherry-pick 7a3b2c1

# Deploy the fix without the unfinished feature
git push origin main

# Later, when the feature is ready, merge the whole branch
git merge colleague/feature-branch

Cherry-Pick Without Committing

# Apply the changes but don't commit — useful for reviewing
git cherry-pick -n abc1234

# Check what changed
git diff --staged

# If it looks good, commit manually
git commit -m "fix: backport chart rendering fix from feature branch"

2. git stash: Save Work-In-Progress

Problem: You're in the middle of a feature when your manager says "we have a production issue, fix it now." Your current work is half-done — committing it would pollute the history.

Basic Stash and Pop

# You're working on a feature
echo "WIP: new feature code" > feature.py
git add feature.py

# Need to switch branches urgently!
git stash
# Saved working directory and index state WIP on main: a1b2c3d

# Your working directory is now clean
git status
# On branch main
# nothing to commit, working tree clean

# Switch to fix the production issue
git checkout hotfix/production-bug
# ... fix the bug ...
git commit -m "fix: critical production issue"
git push

# Go back to your feature and restore your work
git checkout feature/my-feature
git stash pop
# Dropped refs/stash@{0} (d4e5f6a)

# Your changes are back!
git status
# Changes to be committed:
#   new file:   feature.py

Stash with a Message

# Name your stash so you remember what it is
git stash save "WIP: dashboard chart component - need to finish tooltip"

# List all stashes
git stash list
# stash@{0}: WIP: dashboard chart component - need to finish tooltip
# stash@{1}: WIP: experiment with new color scheme
# stash@{2}: On main: testing API integration

Apply Without Deleting

# Apply a stash but keep it in the list (use stash apply, not pop)
git stash apply stash@{0}

# Check if it applied correctly
git status

# If good, drop it manually
git stash drop stash@{0}

# Or combine apply + drop
git stash pop stash@{0}

Stash Untracked and Ignored Files

# By default, stash only includes tracked files
# Include untracked files too
git stash -u
# or: git stash --include-untracked

# Include even .gitignore files (careful!)
git stash -a
# or: git stash --all

# Stash only specific files
git stash push -m "just the config" config.py settings.py

Create a Branch from a Stash

# Turn a stash into its own branch (great for isolating experiments)
git stash branch new-feature-name stash@{0}
# Switched to a new branch "new-feature-name"

# Now you have a clean branch with your stashed work
git log --oneline
# Your stashed changes are now proper commits

Clean Up Old Stashes

# Drop a specific stash
git stash drop stash@{1}

# Drop all stashes
git stash clear

# View stash contents before deleting
git stash show -p stash@{0}
# diff --git a/feature.py b/feature.py
# new file mode 100644
# --- /dev/null
# +++ b/feature.py
# @@ -0,0 +1 @@
# +WIP: new feature code

3. git bisect: Find the Bug-Introducing Commit

Problem: Your application worked 100 commits ago but is broken now. Manually checking each commit would take forever. Binary search finds the culprit in ~7 steps.

Manual Bisect

# Start bisect — tell Git where it was good and bad
git bisect start

# Mark the current (broken) commit as bad
git bisect bad
# We are currently bisecting, include all parents.

# Mark a known-good commit as good
git bisect good v1.0
# Bisecting: 7 revisions left to test after this

# Git checks out a middle commit. Test your app.
# If it works → good, if broken → bad

# Repeat telling Git the result
git bisect good   # This commit works
# Bisecting: 3 revisions left to test after this

git bisect bad    # This one's broken
# Bisecting: 1 revision left to test after this

git bisect bad    # Found it!
# a1b2c3d4e5 is the first bad commit
# commit a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8
# Author: Someone
# Date:   Mon Jul 6 14:23:00 2026 +0000
#
#     feat: refactor user authentication module
#
# :0000000000000... 1234567890abc.. M src/auth.py
# src/auth.py | 45 ++++++++++++++++++++++++++++++-------------
# 1 file changed, 32 insertions(+), 13 deletions(-)

# Done! Reset bisect
git bisect reset
# Previous HEAD was on branch 'main'

Automated Bisect with a Test Script

If you have a test that passes/fails, Git can automate the entire search:

# Create a test script
cat > test.sh << 'EOF'
#!/bin/bash
# Exit 0 = good (bug not present), exit 1 = bad (bug present)
python3 -c "
try:
    from app import main
    result = main()
    if result == expected_output:
        exit(0)
    exit(1)
except Exception:
    exit(1)
"
EOF

chmod +x test.sh

# Run automated bisect
git bisect start
git bisect bad          # Current HEAD is bad
git bisect good v1.0    # v1.0 was good
git bisect run ./test.sh

# Git automatically finds the first bad commit!
# a1b2c3d4e5 is the first bad commit

# Clean up
git bisect reset

Real-World Bisect Example

Imagine your test suite started failing. Here's the full workflow:

# 1. Make sure your working tree is clean
git stash

# 2. Start bisect
git bisect start

# 3. Mark current HEAD as bad
git bisect bad HEAD

# 4. Find a known-good tag or commit
git tag -l
# v2.0
# v1.5
# v1.0

git bisect good v1.5

# 5. Git checks out a middle point. Run tests:
git checkout $(git rev-parse HEAD)  # Already checked out
pytest tests/ -x
# FAILURES: 3 tests failed

# 6. Mark as bad and repeat
git bisect bad

# Git jumps to a new point. Test again.
pytest tests/ -x
# ====================== 42 passed in 3.2s ======================

git bisect good

# Continue until Git finds the culprit...
# f3a8b2c1 is the first bad commit
# commit f3a8b2c1d2e3
# Author: dev@example.com
# Date:   Thu Jul 10 09:15:00 2026
#
#     refactor: simplify database connection pooling
#
# :040000 040000 abc..def M src/db.py

# 7. Investigate the change
git show f3a8b2c1

# 8. Fix the issue, then reset
git bisect reset

4. Bonus: Combining These Tools

These tools are even more powerful together:

Scenario: Find and Fix a Regression

# Step 1: Use bisect to find when things broke
git bisect start
git bisect bad
git bisect good v2.0
# ... (bisect process) ...
# abc1234 is the first bad commit
git bisect reset

# Step 2: Create a fix branch
git checkout -b fix/regression-from-abc1234

# Step 3: Fix the issue and test
# ... (write the fix) ...
pytest tests/  # ✓ all pass

# Step 4: Commit the fix
git commit -m "fix: regression from commit abc1234"

# Step 5: Cherry-pick the fix back to the affected branch
git checkout main
git cherry-pick fix/regression-from-abc1234

# Step 6: Push and create PR
git push -u origin fix/regression-from-abc1234

Scenario: Stash Experiment, Test, Then Decide

# You have an idea but don't want to commit yet
echo "# Experimental feature" > experimental.py
git stash push -m "experiment: new algorithm" experimental.py

# Switch to another branch, do other work
git checkout feature/other
# ... work work work ...

# Come back and test your experiment
git checkout main
git stash apply stash@{0}

# Try it out
python3 experimental.py
# Works! Let's commit it.

git add experimental.py
git commit -m "feat: add experimental algorithm"
git stash drop stash@{0}

Quick Reference Cheat Sheet

CHERRY-PICK (selectively apply commits):
  git cherry-pick <hash>              Apply one commit
  git cherry-pick <hash>..<hash>     Apply a range
  git cherry-pick -n <hash>           Apply without committing
  git cherry-pick --continue           After resolving conflict
  git cherry-pick --abort             Cancel the cherry-pick
  git cherry-pick --skip               Skip conflicting commit

STASH (save work-in-progress):
  git stash                            Save + clean working tree
  git stash save "message"             Named stash
  git stash -u                         Include untracked files
  git stash push -m "msg" file.py     Stash specific files
  git stash list                       List all stashes
  git stash pop                        Apply + delete top stash
  git stash apply stash@{0}           Apply without deleting
  git stash branch <name>             Create branch from stash
  git stash clear                      Delete all stashes

BISECT (binary search for bugs):
  git bisect start                     Begin bisecting
  git bisect bad                       Mark as bad
  git bisect good <commit>            Mark as good
  git bisect good/bad                 Current revision status
  git bisect run ./test.sh            Automated testing
  git bisect reset                    End bisect, return to start

Summary

Cherry-pick lets you transplant individual commits between branches — essential for hotfixes and selective backports. Stash gives you a clean escape hatch when you need to switch context without committing incomplete work. Bisect uses binary search to find bug-introducing commits in logarithmic time instead of linear time.

Together, these three commands cover the "selective," "temporary," and "investigative" gaps that basic Git operations leave open. Master them and you'll navigate any Git situation with confidence. 🚀
