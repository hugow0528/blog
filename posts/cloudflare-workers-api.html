Cloudflare Workers: Build a Serverless REST API

July 1, 2026 10 min read New

Cloudflare Workers let you run code at the edge — in 300+ data centers worldwide — without provisioning a single server. In this guide, we'll build a complete REST API from scratch using the Workers platform. No AWS, no Docker, no servers to patch. Just code that runs instantly.

Our API will manage a simple todo list with full CRUD operations (Create, Read, Update, Delete). We'll use Workers KV as our datastore and the Wrangler CLI for local development and deployment.

Why Cloudflare Workers for an API?

Traditional APIs need a server. Cloudflare Workers APIs don't:

  • 100K free requests per day — plenty for small projects
  • Sub-millisecond cold starts — Workers never "spin up"
  • Global edge execution — your code runs closest to the user
  • No infrastructure to manage — no servers, no load balancers, no auto-scaling config
  • Built-in HTTPS and DDoS protection — automatic, no configuration

Prerequisites

You need three things:

  1. A free Cloudflare account
  2. Node.js 18+ installed
  3. The Wrangler CLI: npm install -g wrangler

Log in to Wrangler:

wrangler login

Step 1: Create a New Worker Project

Wrangler scaffolds a new project with a single command:

wrangler init my-api --site
cd my-api

This creates a project directory with a wrangler.toml configuration file and a src/ folder containing your Worker code.

Step 2: Set Up Workers KV

We need a database. Workers KV is a globally distributed key-value store that's free to use (100K reads/day, 1K writes/day on the free tier). Create a namespace:

wrangler kv:namespace create "TODOS"

Wrangler outputs an ID like abcd1234.... Add it to your wrangler.toml:

[kv_namespaces]
binding = "TODOS"
id = "abcd1234..."
preview_id = "abcd1234..."

Step 3: Build the API Router

Create src/index.js. We'll implement a simple router that handles different HTTP methods and paths:

export default {
    async fetch(request, env) {
        const url = new URL(request.url);
        const path = url.pathname;
        const method = request.method;

        try {
            // Health check
            if (path === "/" && method === "GET") {
                return json({ status: "ok", api: "Todos API v1" });
            }

            // GET /todos — List all todos
            if (path === "/todos" && method === "GET") {
                return listTodos(env);
            }

            // POST /todos — Create a todo
            if (path === "/todos" && method === "POST") {
                return createTodo(request, env);
            }

            // GET /todos/:id — Get a single todo
            const getMatch = path.match(/^\/todos\/([a-z0-9-]+)$/);
            if (getMatch && method === "GET") {
                return getTodo(getMatch[1], env);
            }

            // PUT /todos/:id — Update a todo
            if (getMatch && method === "PUT") {
                return updateTodo(getMatch[1], request, env);
            }

            // DELETE /todos/:id — Delete a todo
            if (getMatch && method === "DELETE") {
                return deleteTodo(getMatch[1], env);
            }

            return json({ error: "Not found" }, 404);

        } catch (error) {
            return json({ error: error.message }, 500);
        }
    }
};

// Helper: Return JSON response
function json(data, status = 200) {
    return new Response(JSON.stringify(data), {
        status,
        headers: {
            "Content-Type": "application/json",
            "Access-Control-Allow-Origin": "*",
            "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
            "Access-Control-Allow-Headers": "Content-Type"
        }
    });
}

The router checks the URL path and HTTP method, then dispatches to the right handler. We also add CORS headers to every response so your API works with browser-based clients.

Step 4: Implement CRUD Operations

Add these functions to your src/index.js file:

List all todos:

async function listTodos(env) {
    const { keys } = await env.TODOS.list();
    const todos = [];
    for (const key of keys) {
        const todo = await env.TODOS.get(key.name, { type: "json" });
        if (todo) todos.push(todo);
    }
    return json(todos);
}

Create a new todo:

async function createTodo(request, env) {
    const body = await request.json();
    const { task, completed = false } = body;

    if (!task || typeof task !== "string") {
        return json({ error: "task (string) is required" }, 400);
    }

    const id = crypto.randomUUID();
    const todo = {
        id,
        task: task.trim(),
        completed,
        createdAt: new Date().toISOString(),
        updatedAt: new Date().toISOString()
    };

    await env.TODOS.put(`todo:${id}`, JSON.stringify(todo));
    return json(todo, 201);
}

Get a single todo:

async function getTodo(id, env) {
    const todo = await env.TODOS.get(`todo:${id}`, { type: "json" });
    if (!todo) return json({ error: "Todo not found" }, 404);
    return json(todo);
}

Update a todo:

async function updateTodo(id, request, env) {
    const existing = await env.TODOS.get(`todo:${id}`, { type: "json" });
    if (!existing) return json({ error: "Todo not found" }, 404);

    const body = await request.json();
    const updated = {
        ...existing,
        task: body.task ?? existing.task,
        completed: body.completed ?? existing.completed,
        updatedAt: new Date().toISOString()
    };

    await env.TODOS.put(`todo:${id}`, JSON.stringify(updated));
    return json(updated);
}

Delete a todo:

async function deleteTodo(id, env) {
    const existing = await env.TODOS.get(`todo:${id}`);
    if (!existing) return json({ error: "Todo not found" }, 404);

    await env.TODOS.delete(`todo:${id}`);
    return json({ message: "Todo deleted", id });
}

Step 5: Handle CORS Preflight Requests

Browsers send OPTIONS requests before any cross-origin PUT, DELETE, or POST request. Add this to your router, before the method checks:

// Handle CORS preflight
if (method === "OPTIONS") {
    return new Response(null, {
        headers: {
            "Access-Control-Allow-Origin": "*",
            "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
            "Access-Control-Allow-Headers": "Content-Type",
        }
    });
}

Step 6: Test Locally

Wrangler includes a local development server that simulates the edge environment:

wrangler dev

This starts http://localhost:8787. Test with curl:

# Create a todo
curl -X POST http://localhost:8787/todos \
  -H "Content-Type: application/json" \
  -d '{"task": "Learn Cloudflare Workers"}'

# List todos
curl http://localhost:8787/todos

# Update a todo (replace the UUID)
curl -X PUT http://localhost:8787/todos/<id> \
  -H "Content-Type: application/json" \
  -d '{"completed": true}'

# Delete a todo
curl -X DELETE http://localhost:8787/todos/<id>

Step 7: Deploy

When you're ready, deploy to the edge with a single command:

wrangler deploy

Wrangler publishes your Worker and gives you a *.workers.dev URL. You can also bind a custom domain from your Cloudflare dashboard.

Add Input Validation

Production APIs need validation. Here's a simple approach:

async function createTodo(request, env) {
    let body;
    try {
        body = await request.json();
    } catch {
        return json({ error: "Invalid JSON body" }, 400);
    }

    const { task, completed } = body;

    if (!task || typeof task !== "string") {
        return json({ error: "'task' must be a non-empty string" }, 400);
    }

    if (task.trim().length > 500) {
        return json({ error: "'task' must be 500 characters or less" }, 400);
    }

    if (completed !== undefined && typeof completed !== "boolean") {
        return json({ error: "'completed' must be a boolean" }, 400);
    }

    // ... rest of the function
}

Next Steps

Here are ways to extend this API:

  • Add authentication — use a simple API key header check or Cloudflare Access
  • Use D1 instead of KV — D1 gives you full SQL if you need relationships and queries
  • Add pagination — KV's list() supports limit and cursor for large datasets
  • Add search — store tasks in a separate KV key for fast lookups
  • Add a Workers Cron trigger — auto-delete todos older than 30 days
  • Connect to a frontend — pair with Cloudflare Pages for a full-stack app

Summary

We built a complete REST API in under 200 lines of code:

  • GET / — Health check
  • GET /todos — List all todos
  • POST /todos — Create a todo
  • GET /todos/:id — Get a single todo
  • PUT /todos/:id — Update a todo
  • DELETE /todos/:id — Delete a todo

No server to provision, no database to manage, no DevOps to worry about. Your code runs on Cloudflare's global network, serving requests from the data center closest to each user. And the first 100K requests per day are free.
