JSON Schema: Validate Your Data Like a Pro — Complete Beginner's Guide

July 16, 2026 10 min read New

Every application receives data from somewhere — user input, APIs, configuration files, webhooks, message queues. Without validation, that data can crash your program, corrupt your database, or introduce security vulnerabilities. JSON Schema is a vocabulary for describing the structure, constraints, and types of JSON data. It's used everywhere: OpenAPI specs, Terraform modules, CI/CD configs, and as a validation layer in applications.

In this guide, you'll learn to write JSON schemas from scratch, validate data in Python and JavaScript, and apply schemas to real-world scenarios like API contracts, configuration validation, and webhook processing.

What Is JSON Schema?

JSON Schema is itself a JSON document. You describe what valid data looks like, and validators check if a piece of data matches. Think of it like a type system for JSON — but with rich constraints like minimum/maximum values, regex patterns, and required fields.

Here's the simplest schema: "this data must be a string"

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "string"
}

Valid data: "hello". Invalid data: 42, true, null.

Step 1: Basic Types and Constraints

JSON Schema supports these types: string, number, integer, boolean, object, array, and null. Each has constraints:

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "UserProfile",
  "type": "object",
  "properties": {
    "username": {
      "type": "string",
      "minLength": 3,
      "maxLength": 30,
      "pattern": "^[a-zA-Z0-9_]+$",
      "description": "Alphanumeric username, 3-30 characters"
    },
    "email": {
      "type": "string",
      "format": "email",
      "description": "User's email address"
    },
    "age": {
      "type": "integer",
      "minimum": 13,
      "maximum": 120,
      "description": "User's age in years"
    },
    "score": {
      "type": "number",
      "minimum": 0,
      "maximum": 100,
      "multipleOf": 0.5,
      "description": "Game score (0-100, in half-point increments)"
    },
    "is_active": {
      "type": "boolean",
      "description": "Whether the account is active"
    }
  },
  "required": ["username", "email"],
  "additionalProperties": false
}

Key concepts:

  • properties — defines each field and its rules
  • required — lists fields that must be present
  • additionalProperties: false — rejects any fields not defined in the schema
  • pattern — regex validation (Perl-compatible)
  • format — built-in checks like "email", "uri", "date-time", "uuid"

Step 2: Validate with Python

The jsonschema package is the standard Python validator:

pip install jsonschema

import json
import jsonschema
from jsonschema import validate, ValidationError, Draft202012Validator

# Your schema (as a Python dict)
schema = {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object",
    "properties": {
        "username": {"type": "string", "minLength": 3, "maxLength": 30},
        "email": {"type": "string", "format": "email"},
        "age": {"type": "integer", "minimum": 13, "maximum": 120},
    },
    "required": ["username", "email"],
}

# Load schema from a JSON file instead (recommended for larger schemas)
# with open("schema.json") as f:
#     schema = json.load(f)

# Valid data — passes silently
data = {"username": "hugo_dev", "email": "hugo@example.com", "age": 28}
validate(instance=data, schema=schema)
print("✅ Valid!")

# Invalid data — raises ValidationError
bad_data = {"username": "hi", "email": "not-an-email"}
try:
    validate(instance=bad_data, schema=schema)
except ValidationError as e:
    print(f"❌ {e.message}")
    # Output: ❌ 'hi' is too short (3 characters minimum)

# Get ALL errors at once (not just the first one)
validator = Draft202012Validator(schema)
errors = list(validator.iter_errors(bad_data))
for error in errors:
    print(f"  Field: {'.'.join(str(p) for p in error.path)}")
    print(f"  Error: {error.message}")

Step 3: Validate with JavaScript (Node.js)

Use ajv (Another JSON Schema Validator) — the most popular JS validator:

npm install ajv

const Ajv = require('ajv');
const ajv = new Ajv({ allErrors: true });

const schema = {
  type: "object",
  properties: {
    username: { type: "string", minLength: 3, maxLength: 30 },
    email: { type: "string", format: "email" },
    age: { type: "integer", minimum: 13, maximum: 120 },
  },
  required: ["username", "email"],
};

const validate = ajv.compile(schema);

// Valid data
const validData = { username: "hugo_dev", email: "hugo@example.com", age: 28 };
if (validate(validData)) {
    console.log("✅ Valid!");
} else {
    console.log("Errors:", validate.errors);
}

// Invalid data
const badData = { username: "hi", email: "not-email" };
const valid = validate(badData);
if (!valid) {
    console.log("❌ Validation failed:");
    validate.errors.forEach(e => {
        console.log(`  ${e.instancePath || '/'}: ${e.message}`);
    });
}
// Output:
//   /username: should be longer than or equal to 3 characters
//   /email: should match format "email"

Step 4: Arrays and Nested Objects

Real-world data is rarely flat. Schemas handle nested structures naturally:

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "order_id": {
      "type": "string",
      "pattern": "^ORD-[0-9]{8}$"
    },
    "customer": {
      "type": "object",
      "properties": {
        "name": { "type": "string", "minLength": 1 },
        "email": { "type": "string", "format": "email" },
        "address": {
          "type": "object",
          "properties": {
            "street": { "type": "string" },
            "city": { "type": "string" },
            "zip": { "type": "string", "pattern": "^[0-9]{5}(-[0-9]{4})?$" },
            "country": { "type": "string", "minLength": 2, "maxLength": 2, "pattern": "^[A-Z]{2}$" }
          },
          "required": ["street", "city", "zip", "country"]
        }
      },
      "required": ["name", "email", "address"]
    },
    "items": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "properties": {
          "product_id": { "type": "string" },
          "name": { "type": "string", "minLength": 1 },
          "quantity": { "type": "integer", "minimum": 1 },
          "price": { "type": "number", "minimum": 0 }
        },
        "required": ["product_id", "name", "quantity", "price"]
      }
    },
    "status": {
      "type": "string",
      "enum": ["pending", "processing", "shipped", "delivered", "cancelled"]
    }
  },
  "required": ["order_id", "customer", "items", "status"]
}

Step 5: Advanced Patterns

JSON Schema has powerful keywords for complex validation:

OneOf — Exactly One Schema Must Match

{
  "oneOf": [
    { "type": "object", "properties": { "type": { "const": "circle" }, "radius": { "type": "number" } }, "required": ["type", "radius"] },
    { "type": "object", "properties": { "type": { "const": "rectangle" }, "width": { "type": "number" }, "height": { "type": "number" } }, "required": ["type", "width", "height"] }
  ]
}

Dependencies — Fields That Require Other Fields

{
  "properties": {
    "payment_type": { "type": "string", "enum": ["credit_card", "paypal"] },
    "credit_card_number": { "type": "string" },
    "paypal_email": { "type": "string", "format": "email" }
  },
  "dependentRequired": {
    "credit_card_number": ["payment_type"],
    "paypal_email": ["payment_type"]
  }
}

PrefixItems — Typed Tuples

{
  "type": "array",
  "prefixItems": [
    { "type": "string" },  // First element: string
    { "type": "integer" }, // Second element: integer
    { "type": "boolean" }  // Third element: boolean
  ],
  "items": { "type": "string" } // Any additional elements must be strings
}

// Valid: ["hello", 42, true, "extra"]
// Invalid: [42, "hello", true]  ← first element must be string

Step 6: Real-World Example — Webhook Validator

Here's a practical Python script that validates incoming webhook payloads:

import json
import jsonschema
from jsonschema import validate, ValidationError
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()

# GitHub webhook schema (simplified)
GITHUB_WEBHOOK_SCHEMA = {
    "type": "object",
    "required": ["action", "repository", "sender"],
    "properties": {
        "action": { "type": "string", "enum": ["opened", "closed", "synchronized"] },
        "repository": {
            "type": "object",
            "required": ["name", "full_name", "html_url"],
            "properties": {
                "name": { "type": "string" },
                "full_name": { "type": "string" },
                "html_url": { "type": "string", "format": "uri" },
            }
        },
        "sender": {
            "type": "object",
            "required": ["login", "id"],
            "properties": {
                "login": { "type": "string" },
                "id": { "type": "integer", "minimum": 1 },
            }
        },
        "pull_request": {
            "type": "object",
            "properties": {
                "number": { "type": "integer" },
                "title": { "type": "string" },
                "state": { "type": "string", "enum": ["open", "closed"] },
            }
        }
    }
}

@app.post("/webhooks/github")
async def github_webhook(request: Request):
    """Validate and process GitHub webhook payloads."""
    payload = await request.json()
    
    try:
        validate(instance=payload, schema=GITHUB_WEBHOOK_SCHEMA)
    except ValidationError as e:
        raise HTTPException(
            status_code=400,
            detail={
                "message": "Invalid webhook payload",
                "field": ".".join(str(p) for p in e.path),
                "error": e.message,
            }
        )
    
    # Process the valid webhook
    action = payload["action"]
    repo = payload["repository"]["full_name"]
    print(f"✅ Webhook: {action} on {repo}")
    
    return {"status": "received"}

Step 7: Schema Best Practices

  1. Store schemas as JSON files — not inline in code. This lets non-developers update validation rules, and tools can consume them directly.
  2. Use $id for schema naming — gives each schema a unique URI for $ref references across files.
  3. Keep schemas focused — one schema per data type. Compose complex schemas with $ref.
  4. Set additionalProperties: false — catch typos in field names early.
  5. Test your schemas — write test cases for valid and invalid data. Edge cases trip up even experienced schema writers.
  6. Use $defs for reusable definitions — define a Address schema once, reference it everywhere.

Schema with Definitions ($defs and $ref)

Reuse common patterns instead of repeating them:

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$defs": {
    "Address": {
      "type": "object",
      "properties": {
        "street": { "type": "string" },
        "city": { "type": "string" },
        "state": { "type": "string", "pattern": "^[A-Z]{2}$" },
        "zip": { "type": "string" }
      },
      "required": ["street", "city", "state", "zip"]
    },
    "User": {
      "type": "object",
      "properties": {
        "id": { "type": "integer", "minimum": 1 },
        "name": { "type": "string", "minLength": 1 },
        "email": { "type": "string", "format": "email" }
      },
      "required": ["id", "name", "email"]
    }
  },
  "type": "object",
  "properties": {
    "author": { "$ref": "#/$defs/User" },
    "billing_address": { "$ref": "#/$defs/Address" },
    "shipping_address": { "$ref": "#/$defs/Address" }
  },
  "required": ["author", "billing_address"]
}
