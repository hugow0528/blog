HTTP Status Codes & REST API Basics: A Beginner's Guide with Python Examples

July 3, 2026 · 10 min read

If you've ever used the internet, you've interacted with HTTP — the Hypertext Transfer Protocol. It's the foundation of every website, every API call, and every time you load a page. Understanding HTTP status codes and REST API principles is essential for any developer, whether you're building web apps, writing Python scripts that talk to APIs, or just debugging why a request failed.

In this guide, we'll cover the most important HTTP status codes, the core principles of REST APIs, and how to interact with APIs using Python's requests library. You'll walk away with working examples you can run immediately.

What Are HTTP Status Codes?

Every time your browser or a Python script makes an HTTP request, the server responds with a status code — a three-digit number that tells you what happened. Think of it as the server's way of communicating success, errors, or special instructions.

Status codes are grouped into five categories:

Range Category Meaning
1xx Informational Request received, continue
2xx Success Request succeeded
3xx Redirection Take further action
4xx Client Error Something's wrong with your request
5xx Server Error Something's wrong on the server

The Most Common Status Codes You'll See

2xx — Success

200 OK — The golden standard. Your request was received, understood, and processed successfully. This is what you want to see 99% of the time.

201 Created — A new resource was successfully created. You'll see this when you POST data to create a new user, blog post, or database entry.

204 No Content — The request succeeded, but there's nothing to return in the body. Common when you delete a resource or update something that doesn't need a response body.

3xx — Redirection

301 Moved Permanently — The resource has moved to a new URL forever. Search engines use this for permanent redirects. Your browser will automatically follow it.

302 Found — The resource is temporarily at a different URL. Common for login redirects or A/B testing.

304 Not Modified — Your browser already has a cached version, and it hasn't changed. The server is telling you to use your local copy instead of downloading again. This is a performance optimization.

4xx — Client Errors

400 Bad Request — The server couldn't understand your request. Maybe you sent malformed JSON, a missing required field, or invalid parameters. Fix your request and try again.

401 Unauthorized — You need to authenticate. Missing or invalid API key? Not logged in? That's a 401. The server is asking "Who are you?"

403 Forbidden — You're authenticated, but you don't have permission. Maybe you're trying to access an admin endpoint as a regular user. The server knows who you are but says "You can't go there."

404 Not Found — The classic "page not found." The resource doesn't exist at the URL you requested. Typo in the endpoint? Deleted resource? Either way, it's not here.

405 Method Not Allowed — You used the wrong HTTP method. Maybe you tried DELETE on an endpoint that only accepts GET and POST.

409 Conflict — Your request conflicts with the current state of the server. For example, trying to create a user with an email that already exists.

422 Unprocessable Entity — The request was well-formed but contained semantic errors. The server understood what you asked but couldn't do it. Common in APIs for validation errors.

429 Too Many Requests — You're being rate-limited. You've made too many requests in a short time. Back off and try again later — usually the response includes a Retry-After header telling you when.

5xx — Server Errors

500 Internal Server Error — Something went wrong on the server side. This is a catch-all error. The application crashed, an unhandled exception occurred, or the database is down.

502 Bad Gateway — A server acting as a gateway or proxy received an invalid response from an upstream server. If you're behind Cloudflare, you might see this when your origin server is broken.

503 Service Unavailable — The server is temporarily overloaded or undergoing maintenance. Usually transient — retry after a short delay.

504 Gateway Timeout — The server acting as a gateway didn't get a timely response from the upstream server. Your origin server is too slow or not responding.

REST API Fundamentals

REST (Representational State Transfer) is an architectural style for building web APIs. It uses HTTP methods to perform operations on resources. Here's how it maps:

HTTP Method CRUD Operation Example Expected Response
GET Read GET /api/users 200 OK
POST Create POST /api/users 201 Created
PUT Update (full) PUT /api/users/123 200 OK
PATCH Update (partial) PATCH /api/users/123 200 OK
DELETE Delete DELETE /api/users/123 204 No Content

REST APIs typically return data in JSON format. A well-designed API follows conventions like using plural nouns for resources (/users, not /getUser), using status codes appropriately, and including pagination for large lists.

Making API Calls with Python

The requests library is the most popular way to make HTTP requests in Python. Install it with pip install requests.

GET Request — Fetching Data

import requests
import json

# Simple GET request
response = requests.get("https://jsonplaceholder.typicode.com/posts/1")

# Check status code
print(f"Status: {response.status_code}")  # 200

# Parse JSON response
data = response.json()
print(json.dumps(data, indent=2))

# Output:
# {
#   "userId": 1,
#   "id": 1,
#   "title": "sunt aut facere repellat provident occaecati...",
#   "body": "quia et suscipit..."
# }

POST Request — Creating Data

import requests
import json

# POST request with JSON body
url = "https://jsonplaceholder.typicode.com/posts"
payload = {
    "title": "My First Post",
    "body": "Hello, REST API!",
    "userId": 1
}

response = requests.post(url, json=payload)
print(f"Status: {response.status_code}")  # 201

# The API echoes back your data with a new ID
print(json.dumps(response.json(), indent=2))
# Output:
# {
#   "title": "My First Post",
#   "body": "Hello, REST API!",
#   "userId": 1,
#   "id": 101
# }

PUT Request — Full Update

import requests

# PUT replaces the entire resource
url = "https://jsonplaceholder.typicode.com/posts/1"
payload = {
    "id": 1,
    "title": "Updated Title",
    "body": "This is the updated content.",
    "userId": 1
}

response = requests.put(url, json=payload)
print(f"Status: {response.status_code}")  # 200

PATCH Request — Partial Update

import requests

# PATCH updates only specified fields
url = "https://jsonplaceholder.typicode.com/posts/1"
payload = {"title": "Only this changes"}

response = requests.patch(url, json=payload)
print(f"Status: {response.status_code}")  # 200

# The 'body' field stays the same — only 'title' changed

DELETE Request — Removing Data

import requests

url = "https://jsonplaceholder.typicode.com/posts/1"
response = requests.delete(url)
print(f"Status: {response.status_code}")  # 200

# Response body is usually empty for DELETE

Error Handling Best Practices

Always handle HTTP errors gracefully. Here's a production-ready pattern:

import requests

def fetch_user(user_id):
    """Fetch user data with proper error handling."""
    url = f"https://jsonplaceholder.typicode.com/users/{user_id}"

    try:
        response = requests.get(url, timeout=10)
        response.raise_for_status()  # Raises exception for 4xx/5xx
        return response.json()

    except requests.HTTPError as e:
        if response.status_code == 404:
            print(f"User {user_id} not found.")
        elif response.status_code == 429:
            print("Rate limited. Try again later.")
        else:
            print(f"HTTP error: {e}")

    except requests.Timeout:
        print("Request timed out. Server is slow.")

    except requests.RequestException as e:
        print(f"Network error: {e}")

    return None

# Usage
user = fetch_user(1)    # Works — returns user data
user = fetch_user(999)   # 404 — prints "not found"
user = fetch_user(1)     # Returns the user dict

Working with API Authentication

Most real APIs require authentication. Here's how to handle common auth methods:

import requests

# 1. API Key in headers
response = requests.get(
    "https://api.example.com/data",
    headers={"Authorization": "Bearer YOUR_API_KEY"}
)

# 2. API Key as query parameter
response = requests.get(
    "https://api.example.com/data",
    params={"api_key": "YOUR_API_KEY"}
)

# 3. Basic Authentication
response = requests.get(
    "https://api.example.com/data",
    auth=("username", "password")
)

# 4. API Key in custom header (Cloudflare style)
response = requests.get(
    "https://api.cloudflare.com/client/v4/zones",
    headers={
        "X-Auth-Email": "you@example.com",
        "X-Auth-Key": "YOUR_GLOBAL_API_KEY"
    }
)

Pagination — Getting All Results

Most APIs paginate large result sets. Here's how to handle it:

import requests

def fetch_all_posts():
    """Fetch all posts handling pagination."""
    all_posts = []
    page = 1

    while True:
        response = requests.get(
            "https://jsonplaceholder.typicode.com/posts",
            params={"_page": page, "_limit": 10},
            timeout=10
        )

        if response.status_code != 200:
            break

        posts = response.json()
        if not posts:
            break

        all_posts.extend(posts)
        print(f"Fetched page {page}: {len(posts)} posts")

        if len(posts) < 10:
            break  # Last page

        page += 1

    return all_posts

posts = fetch_all_posts()
print(f"Total posts: {len(posts)}")  # 100 posts

Quick Reference: Status Code Cheatsheet

Save this mental model for debugging:

  • 200 — Everything is fine
  • 201 — Something new was created
  • 301/302 — Go look somewhere else
  • 400 — Fix your request
  • 401 — Log in / provide credentials
  • 403 — You don't have permission
  • 404 — Resource doesn't exist
  • 429 — Slow down, you're too fast
  • 500 — Server crashed, try again later
  • 502/504 — Backend is broken or slow

Building Your Own Simple API with FastAPI

Now that you know how to consume APIs, let's build one. Install FastAPI: pip install fastapi uvicorn

# main.py
from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel

app = FastAPI()

# In-memory "database"
items = {
    1: {"id": 1, "name": "Widget", "price": 9.99},
    2: {"id": 2, "name": "Gadget", "price": 24.99}
}

class ItemCreate(BaseModel):
    name: str
    price: float

# GET — list all items
@app.get("/items", status_code=status.HTTP_200_OK)
def list_items():
    return list(items.values())

# GET — single item
@app.get("/items/{item_id}", status_code=status.HTTP_200_OK)
def get_item(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return items[item_id]

# POST — create item
@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item(item: ItemCreate):
    new_id = max(items.keys()) + 1
    new_item = {"id": new_id, **item.model_dump()}
    items[new_id] = new_item
    return new_item

# PUT — update item
@app.put("/items/{item_id}", status_code=status.HTTP_200_OK)
def update_item(item_id: int, item: ItemCreate):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    items[item_id] = {"id": item_id, **item.model_dump()}
    return items[item_id]

# DELETE — remove item
@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    del items[item_id]
    return None

Run it with uvicorn main:app --reload, then test with curl:

# Get one item
curl http://localhost:8000/items/1

# Create an item
curl -X POST http://localhost:8000/items \

# Update an item

# Delete an item (returns 204 — no body)
curl -X DELETE http://localhost:8000/items/1 -v

# Try to get a deleted item (returns 404)
curl http://localhost:8000/items/1

Common API Mistakes to Avoid

  1. Not checking status codes — Don't just assume a request worked. Always check response.status_code or use raise_for_status().
  2. No timeouts — Always set a timeout parameter. Without it, your program could hang indefinitely on a slow server.
  3. Hardcoding API keys — Use environment variables. Never commit secrets to version control.
  4. Ignoring rate limits — Check response headers for X-RateLimit-Remaining and handle 429 responses gracefully.
  5. Not using HTTPS — Always use https:// for API calls to prevent man-in-the-middle attacks.

Pro tip: Use response.raise_for_status() instead of manually checking status codes. It converts any 4xx/5xx response into a Python exception you can catch with a try/except block — clean and consistent.

Summary

HTTP status codes are your API's communication tool. 2xx means success, 4xx means you need to fix your request, and 5xx means the server had a problem. REST APIs use HTTP methods (GET, POST, PUT, PATCH, DELETE) to map to CRUD operations, and the Python requests library makes it trivial to interact with any API.

Remember the three pillars of good API code: always handle errors, always set timeouts, and never hardcode secrets. Master these fundamentals and you'll be ready for any API you encounter.
