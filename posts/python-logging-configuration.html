Python Logging & Configuration Management: Build Production-Ready Apps

Python DevOps 2026-06-27 11 min read

print() is great for learning. It's terrible for production. When your application runs on a server processing thousands of requests, you need structured logging and proper configuration to understand what's happening, debug issues, and keep things running smoothly.

This guide covers Python's built-in logging module (which is more powerful than you think), log rotation, configuration management following the 12-factor app methodology, and practical patterns you can use in any project.

Why Not Just Use print()?

Let's be honest about why print() fails in production:

  • No severity levels — is it an error, a warning, or just informational?
  • No timestamps — when did this happen?
  • No structure — can't filter or search programmatically
  • Blocks output — print writes to stdout, which can slow down your app
  • No file output — logs disappear when the process restarts
  • No log rotation — one big log file until your disk fills up

Python's built-in logging module solves all of these problems. And the best part? It's in the standard library — no pip install needed.

Part 1: The Logging Module Basics

Log Levels

Python logging has 5 standard levels, from least to most severe:

import logging

# Log levels (with numeric values)
# DEBUG    = 10   — Detailed diagnostic info
# INFO     = 20   — Normal operation messages
# WARNING  = 30   — Something unexpected happened
# ERROR    = 40   — Something failed but the app keeps running
# CRITICAL = 50   — The app might crash or stop working

logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)

logger.debug("Loading configuration file")
logger.info("Server started on port 8080")
logger.warning("Config file not found, using defaults")
logger.error("Failed to connect to database")
logger.critical("System running out of disk space")

Basic Configuration with basicConfig()

The quickest way to get logging working:

import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s [%(levelname)s] %(name)s: %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)

logger = logging.getLogger("myapp")
logger.info("Application started")
# Output: 2026-06-27 10:30:00 [INFO] myapp: Application started

Understanding the Format String

These are the most useful format specifiers:

# Common format pattern
'%(asctime)s [%(levelname)s] %(name)s (%(filename)s:%(lineno)d): %(message)s'

# asctime  — human-readable timestamp
# levelname — DEBUG, INFO, WARNING, ERROR, CRITICAL
# name    — logger name (great for filtering)
# filename — which .py file the log came from
# lineno  — line number in the file
# message — the actual log message
# exc_info — include traceback when present

Part 2: Handlers and Formatters

Handlers control where logs go. Formatters control how they look. You can have multiple handlers with different formatters — that's the power of the logging system.

import logging

def setup_logger(name: str) -> logging.Logger:
    """Create a logger that writes to both console and file."""
    logger = logging.getLogger(name)
    logger.setLevel(logging.DEBUG)

    # Prevent duplicate handlers on repeated calls
    if logger.handlers:
        return logger

    # Shared formatter
    fmt = logging.Formatter(
        '%(asctime)s [%(levelname)s] %(name)s: %(message)s',
        datefmt='%Y-%m-%d %H:%M:%S'
    )

    # Console handler — shows INFO and above
    console = logging.StreamHandler()
    console.setLevel(logging.INFO)
    console.setFormatter(fmt)
    logger.addHandler(console)

    # File handler — captures everything including DEBUG
    file_handler = logging.FileHandler("app.log", encoding="utf-8")
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(fmt)
    logger.addHandler(file_handler)

    # Error-only file handler
    error_fmt = logging.Formatter(
        '=== ERROR ===\n%(asctime)s | %(name)s | %(levelname)s\n%(message)s\n'
        '%(filename)s:%(lineno)d\n'
        '%(exc_info)s',
        datefmt='%Y-%m-%d %H:%M:%S'
    )
    error_handler = logging.FileHandler("errors.log", encoding="utf-8")
    error_handler.setLevel(logging.ERROR)
    error_handler.setFormatter(error_fmt)
    logger.addHandler(error_handler)

    return logger

# Usage
logger = setup_logger("myapp")
logger.debug("This goes to app.log only")
logger.info("This goes to console + app.log")
logger.error("This goes everywhere + errors.log", exc_info=True)

Part 3: Log Rotation — Don't Fill Your Disk

Without rotation, your log files grow forever. Python provides RotatingFileHandler and TimedRotatingFileHandler:

from logging.handlers import RotatingFileHandler, TimedRotatingFileHandler

logger = logging.getLogger("myapp")

# Rotate by SIZE — max 5MB per file, keep 3 backups
size_handler = RotatingFileHandler(
    "app.log",
    maxBytes=5 * 1024 * 1024,  # 5 MB
    backupCount=3,              # Keep app.log.1, .2, .3
    encoding="utf-8"
)
logger.addHandler(size_handler)

# Rotate by TIME — new file every midnight
time_handler = TimedRotatingFileHandler(
    "daily_app.log",
    when="midnight",             # Rotate at midnight
    interval=1,                 # Every 1 period
    backupCount=30,             # Keep 30 days of logs
    encoding="utf-8"
)
logger.addHandler(time_handler)

Part 4: JSON Logging for Structured Data

In production environments (especially with log aggregators like Datadog, ELK, or Cloudflare Workers), JSON logs are the standard. Here's how to create a JSON formatter:

import json
import logging
import traceback

class JsonFormatter(logging.Formatter):
    """Format log records as JSON for easy parsing."""

    def format(self, record: logging.LogRecord) -> str:
        log_data = {
            "timestamp": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }

        # Add exception info if present
        if record.exc_info:
            log_data["exception"] = traceback.format_exception(*record.exc_info)

        # Add any extra fields passed in
        if hasattr(record, "user_id"):
            log_data["user_id"] = record.user_id
        if hasattr(record, "request_id"):
            log_data["request_id"] = record.request_id

        return json.dumps(log_data)

# Usage
logger = logging.getLogger("myapp")
handler = logging.StreamHandler()
handler.setFormatter(JsonFormatter())
logger.addHandler(handler)
logger.setLevel(logging.INFO)

logger.info("User logged in", extra={"user_id": "12345"})
# Output: {"timestamp": "2026-06-27 10:30:00", "level": "INFO",
#          "logger": "myapp", "message": "User logged in",
#          "module": "app", "function": "login", "line": 42,
#          "user_id": "12345"}

# With an exception
try:
    1 / 0
except ZeroDivisionError:
    logger.error("Calculation failed", exc_info=True)

Part 5: Configuration Management

Hardcoding values like database URLs, API keys, and server ports is a recipe for deployment failures. The 12-factor app methodology says: store config in the environment.

Method 1: Environment Variables (Recommended)

import os
from pathlib import Path

class Settings:
    """Application settings loaded from environment variables."""

    # Server
    HOST: str = os.getenv("APP_HOST", "0.0.0.0")
    PORT: int = int(os.getenv("APP_PORT", "8000"))
    DEBUG: bool = os.getenv("APP_DEBUG", "false").lower() == "true"

    # Database
    DB_HOST: str = os.getenv("DB_HOST", "localhost")
    DB_PORT: int = int(os.getenv("DB_PORT", "5432"))
    DB_NAME: str = os.getenv("DB_NAME", "myapp")
    DB_USER: str = os.getenv("DB_USER", "postgres")
    DB_PASSWORD: str = os.getenv("DB_PASSWORD", "")

    @property
    def database_url(self) -> str:
        return f"postgresql://{self.DB_USER}:{self.DB_PASSWORD}@{self.DB_HOST}:{self.DB_PORT}/{self.DB_NAME}"

    # API Keys
    CLOUDFLARE_TOKEN: str = os.getenv("CLOUDFLARE_API_TOKEN", "")
    SECRET_KEY: str = os.getenv("SECRET_KEY", "change-me-in-production!")

    def validate(self) -> bool:
        """Check required settings are present."""
        if not self.SECRET_KEY or self.SECRET_KEY == "change-me-in-production!":
            raise ValueError("SECRET_KEY must be set in production")
        return True

# Usage
settings = Settings()
settings.validate()
print(f"Database: {settings.database_url}")
print(f"Server: {settings.HOST}:{settings.PORT}")

Method 2: .env Files with python-dotenv

For local development, use a .env file. Never commit this to Git.

# .env (NEVER commit to Git!)
APP_DEBUG=true
APP_PORT=8000
DB_HOST=localhost
DB_PASSWORD=mysecret123
CLOUDFLARE_API_TOKEN=eyJh...
SECRET_KEY=dev-key-not-for-production

# .gitignore
# Add this line:
# .env
# pip install python-dotenv
from dotenv import load_dotenv

# Load from .env file (only in development)
load_dotenv()  # Reads .env from current directory

# Now os.getenv() uses values from .env as fallbacks
import os
db_password = os.getenv("DB_PASSWORD")  # Gets value from .env

Method 3: YAML Configuration Files

For complex configurations (like microservices), YAML files work well:

# config/production.yaml
server:
  host: 0.0.0.0
  port: 8000
  workers: 4

database:
  host: db.production.internal
  port: 5432
  name: myapp_prod
  pool_size: 20

logging:
  level: INFO
  format: json
  file: /var/log/myapp/app.log
  max_size_mb: 100
  backup_count: 7

cache:
  redis_url: redis://cache.internal:6379/0
  ttl_seconds: 300
# pip install pyyaml
import yaml
from pathlib import Path

def load_config(env: str = "development") -> dict:
    """Load configuration from YAML files."""
    config_path = Path(f"config/{env}.yaml")

    if not config_path.exists():
        raise FileNotFoundError(f"Config not found: {config_path}")

    with open(config_path) as f:
        config = yaml.safe_load(f)

    return config

# Usage
config = load_config("production")
print(config["server"]["host"])   # 0.0.0.0
print(config["database"]["host"])  # db.production.internal

Part 6: Putting It All Together — A Real Project

Here's a complete example combining logging and configuration in a Flask app:

# project/app.py
import os
import logging
from logging.handlers import RotatingFileHandler
from flask import Flask

def create_app() -> Flask:
    app = Flask(__name__)

    # Configuration from environment
    app.config["SECRET_KEY"] = os.getenv("SECRET_KEY", "dev-key")
    app.config["DEBUG"] = os.getenv("APP_DEBUG", "false").lower() == "true"
    app.config["DATABASE_URL"] = os.getenv(
        "DATABASE_URL",
        "postgresql://localhost:5432/myapp"
    )

    # Setup logging
    setup_logging(app)

    # Register routes
    @app.route("/")
    def index():
        app.logger.info("Home page accessed")
        return "Hello, World!"

    @app.route("/api/data")
    def get_data():
        try:
            result = fetch_data()
            app.logger.info("Data fetched successfully")
            return result
        except Exception as e:
            app.logger.error("Failed to fetch data", exc_info=True)
            return {"error": "Service unavailable"}, 503

    return app

def setup_logging(app: Flask) -> None:
    """Configure application logging."""
    if app.config["DEBUG"]:
        level = logging.DEBUG
    else:
        level = logging.INFO

    app.logger.setLevel(level)

    # Console handler
    console = logging.StreamHandler()
    console.setLevel(level)
    console.setFormatter(logging.Formatter(
        '%(asctime)s [%(levelname)s] %(message)s',
        datefmt='%Y-%m-%d %H:%M:%S'
    ))
    app.logger.addHandler(console)

    # File handler (production only)
    if not app.config["DEBUG"]:
        file_handler = RotatingFileHandler(
            "app.log", maxBytes=10*1024*1024, backupCount=5
        )
        file_handler.setLevel(logging.WARNING)
        file_handler.setFormatter(logging.Formatter(
            '%(asctime)s [%(levelname)s] %(name)s: %(message)s'
        ))
        app.logger.addHandler(file_handler)

    # Log startup
    app.logger.info(f"App starting in {'DEBUG' if app.config['DEBUG'] else 'PRODUCTION'} mode")

if __name__ == "__main__":
    app = create_app()
    app.run(host="0.0.0.0", port=8000)

Part 7: Common Logging Anti-Patterns

Avoid these mistakes:

# ❌ BAD: Creating a new logger everywhere
logger = logging.getLogger(__name__)
# ... somewhere else
logger2 = logging.getLogger(__name__)  # Same logger, but confusing

# ✅ GOOD: Use __name__ consistently, import the logger
# In logging.py
import logging
logger = logging.getLogger(__name__)

# In other_file.py
from logging import getLogger
logger = getLogger(__name__)  # Gets child logger automatically

# ❌ BAD: Logging sensitive data
logger.info(f"User password is: {password}")

# ✅ GOOD: Never log secrets
logger.info(f"User {user_id} authenticated successfully")

# ❌ BAD: Using print in production code
print("Error connecting to database")

# ✅ GOOD: Use proper log levels
logger.error("Failed to connect to database: %s", str(e))

# ❌ BAD: String concatenation (evaluates even if log level is too low)
logger.debug("User " + user.id + " loaded " + str(data))

# ✅ GOOD: Lazy evaluation with % formatting
logger.debug("User %s loaded %d items", user.id, len(data))

Summary

Logging and configuration are foundational skills that separate hobby code from production systems:

  • Use the built-in logging module — it's more powerful than you think and requires no dependencies.
  • Set proper log levels — DEBUG for development, INFO/WARNING for production.
  • Use multiple handlers — console for real-time monitoring, files for history, error logs for incident response.
  • Implement log rotation — either by size (RotatingFileHandler) or time (TimedRotatingFileHandler).
  • Use JSON logging in production — structured logs are essential for log aggregation tools.
  • Store config in environment variables — follow the 12-factor methodology.
  • Use .env files for local development — never commit secrets to Git.
  • Validate your configuration at startup — fail fast with clear error messages.

With these patterns, your Python applications will be observable, configurable, and production-ready from day one.
