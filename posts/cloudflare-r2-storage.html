Cloudflare R2 Storage: Serverless Object Storage Without Egress Fees

2026-06-24 9 min read New

Cloudflare R2 is serverless object storage that eliminates egress fees — the hidden cost that makes AWS S3 expensive when you download or serve a lot of data. If you're storing images, backups, videos, or any files that users download, R2 can save you a fortune.

In this guide, you'll learn how to create an R2 bucket, upload and download files using the S3-compatible API, serve files publicly, and automate everything with Python.

What Is Cloudflare R2?

R2 is Cloudflare's answer to AWS S3. It stores objects (files) in buckets (containers) and provides an S3-compatible API, so most tools and libraries that work with S3 work with R2 too. The killer feature: zero egress fees. With AWS S3, you pay $0.09 per GB downloaded. With R2, downloads are free.

Pricing at a Glance

  • Storage: $0.015/GB/month (same as S3 Infrequent Access)
  • Class A operations (upload/delete): $4.50 per million
  • Class B operations (list/read): $0.36 per million
  • Egress (downloads): FREE

For a project storing 100 GB with 500 GB of monthly downloads, S3 costs roughly $65/month. R2 costs about $2.50/month.

Setting Up R2

Step 1: Create a Bucket

Go to the Cloudflare Dashboard, navigate to R2, and click "Create Bucket." Give it a name like my-files.

Step 2: Create API Tokens

You need an Account ID and API Token (Access Key ID + Secret Access Key) to use the S3-compatible API.

  1. Go to R2 → R2 API Tokens
  2. Click "Create API Token"
  3. Choose "Admin Read Write" policy for full access
  4. Copy the Access Key ID and Secret Access Key immediately

Store these securely:

# Create a credentials file
cat > ~/.r2-credentials << EOF
R2_ACCOUNT_ID=your_account_id_here
R2_ACCESS_KEY_ID=your_access_key_here
R2_SECRET_ACCESS_KEY=your_secret_key_here
EOF

chmod 600 ~/.r2-credentials

Using R2 with curl

The easiest way to test R2 is with curl. Here's how to list objects in your bucket:

export R2_ENDPOINT="https://<account-id>.r2.cloudflarestorage.com"
export AWS_ACCESS_KEY_ID="your_access_key"
export AWS_SECRET_ACCESS_KEY="your_secret_key"

# List bucket contents
aws s3 ls s3://my-files --endpoint-url=$R2_ENDPOINT

# Upload a file
aws s3 cp report.pdf s3://my-files/documents/ \
  --endpoint-url=$R2_ENDPOINT

# Download a file
aws s3 cp s3://my-files/documents/report.pdf ./ \
  --endpoint-url=$R2_ENDPOINT

Using R2 with Python (boto3)

Since R2 is S3-compatible, you can use boto3 — the AWS SDK for Python — to interact with it.

# Install boto3
pip install boto3

# Connect to R2
import boto3
import os

r2 = boto3.client(
    "s3",
    endpoint_url="https://<account-id>.r2.cloudflarestorage.com",
    aws_access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    aws_secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
    region_name="auto",
)

# Upload a file
r2.upload_file("report.pdf", "my-files", "documents/report.pdf")

# List all objects
for obj in r2.list_objects_v2(Bucket="my-files")["Contents"]:
    print(f"{obj['Key']} — {obj['Size']} bytes")

# Download a file
r2.download_file("my-files", "documents/report.pdf", "./report.pdf")

# Set a public URL (optional — needs bucket settings enabled)
r2.put_object_acl(
    Bucket="my-files",
    Key="documents/report.pdf",
    ACL="public-read"
)

Serving Files Publicly with R2

By default, R2 objects are private. To serve files publicly, you have two options:

Option 1: R2 Public Access

Enable public access on your bucket in the dashboard, then set objects to public-read. Files become available at:

https://pub-<hash>.r2.dev/my-files/documents/report.pdf

Option 2: Signed URLs (Temporary Access)

For private files, generate a temporary URL that expires after a set time:

from botocore.client import Config
from datetime import datetime, timedelta
import boto3

r2 = boto3.client(
    "s3",
    endpoint_url="https://<account-id>.r2.cloudflarestorage.com",
    aws_access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    aws_secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
)

# Generate a presigned URL valid for 1 hour
url = r2.generate_presigned_url(
    "get_object",
    Params={
        "Bucket": "my-files",
        "Key": "private/secret.pdf"
    },
    ExpiresIn=3600  # 1 hour in seconds
)

print(f"Download link: {url}")

Option 3: Cloudflare Tunnel for Static Hosting

You can also pair R2 with a Cloudflare Worker or Tunnel to serve files behind your own domain with custom authentication, rate limiting, or transformations.

Automated Backups with Python

Here's a practical script that backs up a directory to R2 daily:

import boto3
import os
import tarfile
from datetime import datetime

r2 = boto3.client(
    "s3",
    endpoint_url="https://<account-id>.r2.cloudflarestorage.com",
    aws_access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    aws_secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
    region_name="auto",
)

def backup_directory(source_dir, bucket_name="backups"):
    timestamp = datetime.now().strftime("%Y-%m-%d_%H%M%S")
    archive_name = f"backup_{timestamp}.tar.gz"

    # Create compressed archive
    with tarfile.open(archive_name, "w:gz") as tar:
        tar.add(source_dir, arcname=os.path.basename(source_dir))

    # Upload to R2
    r2.upload_file(
        archive_name,
        bucket_name,
        f"daily/{archive_name}"
    )
    print(f"✅ Uploaded {archive_name} to R2")

    # Clean up local archive
    os.remove(archive_name)

    # Delete backups older than 30 days
    response = r2.list_objects_v2(Bucket=bucket_name, Prefix="daily/")
    cutoff = datetime.now().timestamp() - (30 * 86400)

    for obj in response.get("Contents", []):
        if obj["LastModified"].timestamp() < cutoff:
            r2.delete_object(Bucket=bucket_name, Key=obj["Key"])
            print(f"🗑️ Deleted old backup: {obj['Key']}")

# Run backup
backup_directory("/home/user/my-data")

Best Practices

  1. Use environment variables — never hardcode credentials in your code
  2. Enable lifecycle rules — auto-delete or tier old objects to save money
  3. Use presigned URLs for temporary, secure file sharing
  4. Pair with Workers — serve files through a Cloudflare Worker for authentication, image resizing, or caching headers
  5. Monitor usage — check the R2 dashboard weekly for storage and operation counts

Summary

Cloudflare R2 is a powerful, cost-effective alternative to AWS S3. The zero egress fee alone makes it worth switching if you serve a lot of downloads. The S3-compatible API means you can migrate with minimal code changes. Try it for file storage, backups, static assets, or any use case where you want to store data without surprise bills.
