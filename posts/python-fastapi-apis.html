Python APIs with FastAPI: Build Your First REST API — Complete Beginner's Guide

July 16, 2026 11 min read New

You've learned Python basics — variables, loops, functions, classes. Now it's time to build something that other programs can talk to. An API (Application Programming Interface) is exactly that: a set of endpoints that accept requests and return responses, usually as JSON. FastAPI is the fastest-growing Python web framework, and for good reason: it's fast (pun intended), auto-generates documentation, validates your data automatically, and supports async natively.

In this guide, you'll build a complete Task Management API from scratch — from a single endpoint to a production-ready service with validation, error handling, middleware, and deployment with Docker. Every code example is complete and runnable.

Why FastAPI?

Before we dive in, let's compare FastAPI with other Python web frameworks:

  • Flask — Simple, but you need extra packages for validation and async support
  • Django — Full-featured but heavy; overkill for simple APIs
  • FastAPI — Modern, fast, auto-docs, built-in validation, async-ready

FastAPI uses Python type hints to define what data your endpoints expect and return. It validates incoming data, generates OpenAPI documentation, and returns proper HTTP errors — all automatically.

Step 1: Install and Your First Endpoint

Create a project directory and install FastAPI with Uvicorn (the ASGI server that runs it):

# Create and enter project directory
mkdir my-api && cd my-api

# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install fastapi uvicorn

# Create the main file
touch main.py

Now write your first API in main.py:

from fastapi import FastAPI

app = FastAPI(title="Task Manager API", version="1.0.0")

@app.get("/")
def read_root():
    return {"message": "Welcome to the Task Manager API", "version": "1.0.0"}

@app.get("/health")
def health_check():
    return {"status": "ok"}

Run it with:

uvicorn main:app --reload

The --reload flag restarts the server when you edit files (dev only). Visit http://localhost:8000 to see your JSON response. Visit http://localhost:8000/docs to see the auto-generated Swagger UI — try it!

Step 2: Path Parameters and Query Parameters

APIs need to accept data. Path parameters are part of the URL; query parameters come after a ?. Let's add routes to list and get tasks:

from fastapi import FastAPI, Query, Path

app = FastAPI()

# In-memory "database" for this tutorial
tasks = [
    {"id": 1, "title": "Learn FastAPI", "completed": False},
    {"id": 2, "title": "Build an API", "completed": True},
]

@app.get("/tasks")
def list_tasks(completed: bool | None = None):
    """List all tasks, optionally filtered by completion status."""
    if completed is not None:
        return [t for t in tasks if t["completed"] == completed]
    return tasks

@app.get("/tasks/{task_id}")
def get_task(task_id: int = Path(ge=1)):
    """Get a single task by ID."""
    for task in tasks:
        if task["id"] == task_id:
            return task
    return {"error": "Task not found"}, 404

# Test in browser:
# GET /tasks                → all tasks
# GET /tasks?completed=true → only completed tasks
# GET /tasks/1              → task with id=1
# GET /tasks/999            → 404 error

Notice how we used Path(ge=1) to validate that task_id is at least 1. FastAPI rejects invalid requests with a 422 error before your code even runs.

Step 3: Pydantic Models for Request Validation

Pydantic models define the shape of your data. They handle type conversion, validation, and serialization. This is where FastAPI shines:

from pydantic import BaseModel, Field
from typing import Optional
from datetime import datetime

class TaskCreate(BaseModel):
    """Model for creating a new task."""
    title: str = Field(min_length=1, max_length=200, description="Task title")
    description: Optional[str] = Field(None, max_length=1000)
    priority: int = Field(default=3, ge=1, le=5, description="1=urgent, 5=low")

class TaskUpdate(BaseModel):
    """Model for updating an existing task — all fields optional."""
    title: Optional[str] = Field(None, min_length=1, max_length=200)
    description: Optional[str] = Field(None, max_length=1000)
    completed: Optional[bool] = None
    priority: Optional[int] = Field(None, ge=1, le=5)

class TaskResponse(BaseModel):
    """Model for the API response — adds server-side fields."""
    id: int
    title: str
    description: Optional[str]
    completed: bool
    priority: int
    created_at: str

    class Config:
        from_attributes = True

Now use these models in your endpoint:

@app.post("/tasks", status_code=201)
def create_task(task: TaskCreate):
    """Create a new task. Returns 201 with the created task."""
    new_id = max((t["id"] for t in tasks), default=0) + 1
    new_task = {
        "id": new_id,
        "title": task.title,
        "description": task.description,
        "completed": False,
        "priority": task.priority,
        "created_at": datetime.utcnow().isoformat(),
    }
    tasks.append(new_task)
    return new_task

Test with curl:

curl -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \

Step 4: Full CRUD — Update and Delete

Complete the API with PUT and DELETE endpoints:

@app.put("/tasks/{task_id}")
def update_task(task_id: int, updates: TaskUpdate):
    """Update a task. Only provided fields are changed."""
    for task in tasks:
        if task["id"] == task_id:
            # Update only fields that were provided
            update_data = updates.model_dump(exclude_unset=True)
            task.update(update_data)
            return task
    raise HTTPException(status_code=404, detail="Task not found")

@app.delete("/tasks/{task_id}", status_code=204)
def delete_task(task_id: int):
    """Delete a task. Returns 204 No Content on success."""
    for i, task in enumerate(tasks):
        if task["id"] == task_id:
            tasks.pop(i)
            return None  # 204 No Content
    raise HTTPException(status_code=404, detail="Task not found")

Key concepts here:

  • model_dump(exclude_unset=True) — only updates fields the client actually sent
  • HTTPException — raises proper HTTP errors with status codes
  • status_code=204 — delete returns no body on success (REST best practice)

Step 5: Middleware and Error Handling

Middleware runs on every request. Let's add request logging and timing:

import time
import logging
from fastapi import Request, Response

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("api")

@app.middleware("http")
async def add_process_time(request: Request, call_next):
    """Middleware: log every request and measure response time."""
    start = time.time()
    
    response = await call_next(request)
    
    duration = time.time() - start
    logger.info(f"{request.method} {request.url.path} — {response.status_code} — {duration:.3f}s")
    
    # Add custom header to every response
    response.headers["X-Process-Time"] = f"{duration:.3f}s"
    
    return response

Customize the default error response:

from fastapi.exceptions import RequestValidationError

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    """Custom 422 error responses."""
    errors = []
    for error in exc.errors():
        errors.append({
            "field": ".".join(str(loc) for loc in error["loc"]),
            "message": error["msg"],
        })
    return JSONResponse(
        status_code=422,
        content={"error": "Validation failed", "details": errors},
    )

Step 6: Dependency Injection

FastAPI's dependency injection system lets you share logic across endpoints:

from fastapi import Depends

def get_db():
    """Simulated database connection. Replace with real DB in production."""
    return tasks

@app.get("/tasks/count")
def task_count(db: list = Depends(get_db)):
    """Count tasks by status."""
    return {
        "total": len(db),
        "completed": sum(1 for t in db if t["completed"]),
        "pending": sum(1 for t in db if not t["completed"]),
    }

Step 7: Async Endpoints

FastAPI supports async natively. For I/O-bound operations (database queries, HTTP calls), use async def:

import httpx

@app.get("/weather/{city}")
async def get_weather(city: str):
    """Fetch weather data from an external API using async."""
    async with httpx.AsyncClient() as client:
        response = await client.get(
            f"https://api.openweathermap.org/data/2.5/weather",
            params={"q": city, "appid": "your_api_key", "units": "metric"},
        )
        return response.json()

# Without async, each request blocks the thread.
# With async, the server handles other requests while waiting for the HTTP call.

Step 8: Deployment with Docker

Containerize your API with a multi-stage Dockerfile:

# Dockerfile
FROM python:3.12-slim AS builder

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

FROM python:3.12-slim

WORKDIR /app
COPY --from=builder /install /usr/local
COPY main.py .

# Run as non-root user for security
RUN useradd -m appuser && chown -R appuser /app
USER appuser

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

Your requirements.txt:

fastapi>=0.110.0
uvicorn>=0.27.0
httpx>=0.27.0

Build and run:

docker build -t my-api .
docker run -p 8000:8000 my-api

Next Steps

You've built a working REST API. Here's where to go next:

  1. Add a real database — SQLite for dev, PostgreSQL for production (see SQLAlchemy or Tortoise ORM)
  2. Add authentication — JWT tokens, OAuth2, or API keys
  3. Add rate limiting — protect against abuse with slowapi
  4. Add background tasks — use FastAPI BackgroundTasks for email sending, cleanup
  5. Add CORS — enable frontend access with CORSMiddleware
  6. Add health checks — probe endpoints for load balancers
  7. Write tests — use TestClient with pytest

FastAPI's auto-generated docs at /docs (Swagger) and /redoc (ReDoc) are invaluable for API consumers. They update automatically when you change your code — no manual documentation needed.
