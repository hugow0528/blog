Cloudflare Cache Rules & Caching Strategy: Speed Up Your Site 10x

Cloudflare DevOps June 29, 2026

Cloudflare's edge network caches your content in 300+ cities worldwide, serving users from the closest location. But the default caching isn't always optimal — and with Cache Rules, you can take full control. In this guide, you'll learn how to configure caching for static assets, API responses, and dynamic pages to dramatically reduce load times and bandwidth costs.

How Cloudflare Caching Works

Before configuring rules, understand the flow:

  1. First request: Cloudflare checks its edge cache. If the content isn't there (a cache miss), it fetches from your origin server and stores a copy.
  2. Subsequent requests: If the content is cached (a cache hit), Cloudflare serves it directly from the edge — no origin server needed.
  3. Cache expiration: Cached content expires based on the Cache-Control header from your origin, or Cloudflare's default (2 hours for assets, 4 hours for HTML).
Key insight: A cache hit means your origin server handles ZERO requests. For a popular site, this can mean 80-95% fewer origin requests.

Default Cache Behavior

Cloudflare caches these file types by default (when your site is proxied through Cloudflare):

# File types cached by default
.jpg, .jpeg, .png, .gif, .svg, .webp      # Images
.css, .js                                   # Stylesheets & scripts
.pdf, .doc, .xls, .ppt                     # Documents
.mp3, .mp4, .webm, .ogg                    # Media files
.html                                       # HTML (4-hour edge TTL by default)

Cloudflare respects your origin's Cache-Control headers. If your server sends Cache-Control: no-store, Cloudflare won't cache the content regardless of file type.

Cache Rules: Take Full Control

Cache Rules (available on Free plan) let you override default behavior with custom conditions. Navigate to Caching → Configuration → Cache Rules in the Cloudflare dashboard.

Rule #1: Cache Static Assets Aggressively

For images, CSS, and JS that rarely change, set a long cache duration:

# Cache Rule: Static assets for 30 days
IF: Request is for file extension = .css, .js, .png, .jpg, .webp
THEN: Cache Level = Maximum, Edge TTL = 30 days, Browser TTL = Respect Origin

This tells Cloudflare to cache these files for 30 days at the edge, and let the browser cache them according to your origin's Cache-Control headers. For a site with 10,000 page views, this could save ~95% of image requests to your origin.

Rule #2: Cache API Responses for Short Durations

API endpoints that return semi-static data (product listings, blog posts, settings) can be cached:

# Cache Rule: Cache API responses for 5 minutes
IF: Request URI contains "/api/products" OR "/api/blog"
THEN: Cache Level = Maximum, Edge TTL = 5 minutes

Even 5 minutes of caching for API endpoints can dramatically reduce origin load during traffic spikes.

Rule #3: Don't Cache Admin Pages

Some pages should NEVER be cached:

# Cache Rule: Bypass cache for admin pages
IF: Request URI contains "/admin" OR "/dashboard" OR "/login"
THEN: Cache Level = Bypass Cache

Rule #4: Cache HTML Pages with a Short TTL

For blog posts and static pages, a moderate cache time works well:

# Cache Rule: Cache HTML pages for 1 hour
IF: Request is for file extension = .html AND Request URI not contains "/admin"
THEN: Cache Level = Maximum, Edge TTL = 1 hour, Respect Strong Origin ETags = On

Respect Strong Origin ETags means Cloudflare will revalidate with your origin using ETags before serving stale content — the best of both worlds.

Cache-Control Headers: The Origin Side

Cloudflare respects these headers from your origin server. Here's how to set them in different web servers:

Nginx Configuration

# nginx.conf - Cache headers for static assets
location ~* \.(css|js|png|jpg|jpeg|gif|svg|webp|ico)$ {
    expires 30d;
    add_header Cache-Control "public, no-transform";
    add_header Vary "Accept-Encoding";
}

# HTML pages - cache with revalidation
location ~* \.html$ {
    expires 1h;
    add_header Cache-Control "public, must-revalidate";
    etag on;
}

Apache (.htaccess)

# .htaccess - Cache headers
<FilesMatch "\.(css|js|png|jpg|jpeg|gif|svg|webp)$">
    Header set Cache-Control "public, max-age=2592000, no-transform"
    Header set Vary "Accept-Encoding"
</FilesMatch>

<FilesMatch "\.(html|htm)$">
    Header set Cache-Control "public, max-age=3600, must-revalidate"
</FilesMatch>

Python (Flask/FastAPI)

from flask import Flask, make_response
from functools import wraps

app = Flask(__name__)

def cached(minutes=60):
    """Cache decorator for Flask routes"""
    def decorator(f):
        @wraps(f)
        def decorated_function(*args, **kwargs):
            response = make_response(f(*args, **kwargs))
            response.headers['Cache-Control'] = f'public, max-age={minutes * 60}'
            response.headers['Vary'] = 'Accept-Encoding'
            return response
        return decorated_function
    return decorator

@app.route('/api/products')
@cached(minutes=5)
def get_products():
    return {"products": [...]}

Cache Purging: Updating Stale Content

When you update your site, you need to purge cached content. Cloudflare offers three purge levels:

  1. Soft Purge: Forces revalidation with origin. Cloudflare checks if the content changed before updating the cache. Recommended for most cases.
  2. Hard Purge: Removes the content entirely. Next request is a full cache miss. Use for emergencies or when origin is down.
  3. Everything Purge: Clears the entire cache. Use sparingly — causes a cache stampede.

Purge via Dashboard: Caching → Configuration → Purge Cache

Purge via API (Python):

import requests

ZONE_ID = "your-zone-id"
API_TOKEN = "your-api-token"

def purge_url(urls):
    """Purge specific URLs from Cloudflare cache"""
    headers = {
        "Authorization": f"Bearer {API_TOKEN}",
        "Content-Type": "application/json"
    }
    data = {"files": urls}
    response = requests.post(
        f"https://api.cloudflare.com/client/v4/zones/{ZONE_ID}/purge_cache",
        headers=headers,
        json=data
    )
    return response.json()

# Purge specific files
purge_url([
    "https://blog.hugow.dev/styles/main.css",
    "https://blog.hugow.dev/index.html"
])

Purge via CLI (wrangler):

# Purge a specific URL
cf purge --url https://blog.hugow.dev/styles/main.css

# Purge everything
cf purge --all

Cache Analytics: Monitor Your Savings

Track your cache performance at Analytics → Speed in the Cloudflare dashboard. Key metrics:

  • Cache Hit Ratio: Percentage of requests served from cache. Aim for 80%+ for content sites.
  • Cached Bandwidth: Data served from edge vs origin. Your savings in GB.
  • First Byte Time: Time to first byte. Caching should reduce this dramatically.
  • Load Reduction: Percentage of requests that didn't reach your origin.
# Check cache status with curl
curl -I https://blog.hugow.dev/styles/main.css

# Look for these headers:
# cf-cache-status: HIT  (served from edge cache!)
# cf-cache-status: MISS (fetched from origin)
# cf-cache-status: EXPIRED (cache expired, revalidated)
# cf-cache-status: DYNAMIC (not cached)

Common Caching Mistakes

  1. Not using the proxy (orange cloud): Caching only works when your DNS record is proxied (orange cloud ON in Cloudflare DNS).
  2. Forgetting Vary headers: If you serve different content for different user agents or languages, set Vary: Accept-Encoding, Accept-Language so Cloudflare caches the right variant.
  3. Caching authenticated content: Never cache pages behind login. Always bypass cache for authenticated routes.
  4. Ignoring browser cache: Cloudflare edge cache and browser cache are separate. Set Cache-Control headers for both.
  5. Over-purging: Purging everything on every deploy defeats the purpose. Purge only changed files.

Cache Rules Priority & Ordering

Cache Rules are evaluated in order — first match wins. Place your most specific rules at the top:

# Rule 1 (highest priority): Bypass admin
IF: URI contains "/admin" → Bypass Cache

# Rule 2: Cache API for 5 min
IF: URI contains "/api/" → Cache 5 min

# Rule 3: Cache static assets for 30 days
IF: Extension = .css, .js, .png... → Cache 30 days

# Rule 4 (lowest priority): Cache HTML for 1 hour
IF: Extension = .html → Cache 1 hour

Complete Caching Strategy Summary

Content Type Edge TTL Reason
Images (.png, .jpg, .webp) 30 days Rarely change, big savings
CSS / JavaScript 30 days Versioned filenames
HTML pages 1 hour Balance freshness & speed
API responses 5 minutes Reduce origin load
Admin / Authenticated Bypass Always fresh, security
