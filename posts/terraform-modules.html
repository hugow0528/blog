Terraform Modules: Reusable Infrastructure Code — Complete Beginner's Guide

July 17, 2026 · 11 min read

You've written your first Terraform configuration and deployed a few servers. It works, but your main.tf file is growing. You're copying the same VPC and subnet configuration across dev, staging, and production. Every environment update means changing three files. Sound familiar?

Terraform modules are the solution. A module is a self-contained package of Terraform configurations that you can reuse across projects — like functions in Python, but for infrastructure. This guide takes you from your first module { } block to building a complete modular infrastructure library.

Why Use Modules?

Without modules, your infrastructure code looks like this:

# ❌ main.tf — 400 lines, repeated 3 times per environment
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  tags = {
    Name        = "dev-vpc"
    Environment = "dev"
  }
}

resource "aws_subnet" "public_a" {
  vpc_id     = aws_vpc.main.id
  cidr_block = "10.0.1.0/24"
  # ... 30 more resources, all duplicated per environment
}

With modules, you write the VPC once and call it everywhere:

# ✅ main.tf — 10 lines, clean and readable
module "vpc" {
  source = "./modules/vpc"

  environment = "dev"
  cidr        = "10.0.0.0/16"
}

Anatomy of a Module

A Terraform module is just a directory containing .tf files. Three key concepts make a directory a proper module:

  • Variables (inputs): Configurable parameters that customize the module
  • Resources (body): The infrastructure the module creates
  • Outputs (returns): Values the module exposes to callers

Let's build a complete VPC module from scratch.

Building Your First Module: VPC

Start with the directory structure:

infrastructure/
├── main.tf              # Root — calls modules
├── variables.tf         # Root variables
├── outputs.tf           # Root outputs
└── modules/
    └── vpc/
        ├── main.tf      # Module resources
        ├── variables.tf # Module inputs
        └── outputs.tf   # Module outputs

Step 1: Module Variables (Inputs)

# modules/vpc/variables.tf

variable "environment" {
  description = "Environment name (dev, staging, prod)"
  type        = string

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

variable "cidr" {
  description = "CIDR block for the VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "public_subnet_count" {
  description = "Number of public subnets to create"
  type        = number
  default     = 2
}

variable "tags" {
  description = "Additional tags to apply to all resources"
  type        = map(string)
  default     = {}
}

Notice the validation block — this catches invalid inputs before Terraform tries to create anything. Always validate early.

Step 2: Module Resources (Body)

# modules/vpc/main.tf

locals {
  common_tags = merge(var.tags, {
    Environment = var.environment
    ManagedBy   = "terraform"
    Module      = "vpc"
  })
}

resource "aws_vpc" "this" {
  cidr_block           = var.cidr
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = merge(local.common_tags, {
    Name = "${var.environment}-vpc"
  })
}

resource "aws_subnet" "public" {
  count = var.public_subnet_count

  vpc_id            = aws_vpc.this.id
  cidr_block        = cidrsubnet(var.cidr, 8, count.index)
  availability_zone = data.aws_availability_zones.available.names[count.index % length(data.aws_availability_zones.available.names)]

  map_public_ip_on_launch = true

  tags = merge(local.common_tags, {
    Name = "${var.environment}-public-${count.index + 1}"
    Tier = "public"
  })
}

data "aws_availability_zones" "available" {
  state = "available"
}

The locals block merges default tags with user-provided tags, so every resource gets consistent labeling. The count met-argument creates multiple subnets without duplicating code.

Step 3: Module Outputs (Returns)

# modules/vpc/outputs.tf

output "vpc_id" {
  description = "ID of the VPC"
  value       = aws_vpc.this.id
}

output "vpc_cidr" {
  description = "CIDR block of the VPC"
  value       = aws_vpc.this.cidr_block
}

output "public_subnet_ids" {
  description = "List of public subnet IDs"
  value       = aws_subnet.public[*].id
}

output "public_subnet_cidrs" {
  description = "List of public subnet CIDR blocks"
  value       = aws_subnet.public[*].cidr_block
}

Calling the Module

Now use the module from your root configuration:

# main.tf

terraform {
  required_version = ">= 1.5.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}

variable "aws_region" {
  default = "us-east-1"
}

variable "environment" {
  default = "dev"
}

module "vpc" {
  source = "./modules/vpc"

  environment           = var.environment
  cidr                  = "10.0.0.0/16"
  public_subnet_count   = 3

  tags = {
    Project = "myapp"
    Team    = "platform"
  }
}

# Use the module outputs
output "vpc_id" {
  value = module.vpc.vpc_id
}

output "public_subnets" {
  value = module.vpc.public_subnet_ids
}

Building a Second Module: EC2 Instance

Modules become powerful when you chain them. Create an EC2 module that depends on your VPC module's outputs:

# modules/ec2/variables.tf

variable "instance_name" {
  type        = string
  description = "Name of the EC2 instance"
}

variable "instance_type" {
  type    = string
  default = "t3.micro"
}

variable "subnet_id" {
  type        = string
  description = "Subnet ID to launch the instance in"
}

variable "vpc_id" {
  type        = string
  description = "VPC ID (for security group creation)"
}

variable "environment" {
  type = string
}
# modules/ec2/main.tf

resource "aws_security_group" "this" {
  name_prefix = "${var.instance_name}-sg"
  vpc_id      = var.vpc_id

  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name        = "${var.instance_name}-sg"
    Environment = var.environment
  }
}

resource "aws_instance" "this" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type
  subnet_id     = var.subnet_id

  vpc_security_group_ids = [aws_security_group.this.id]

  tags = {
    Name        = var.instance_name
    Environment = var.environment
  }
}

data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }
}
# modules/ec2/outputs.tf

output "instance_id" {
  description = "ID of the EC2 instance"
  value       = aws_instance.this.id
}

output "public_ip" {
  description = "Public IP of the EC2 instance"
  value       = aws_instance.this.public_ip
}

Call it from the root alongside the VPC module:

# main.tf (continued)

module "web_server" {
  source = "./modules/ec2"

  instance_name = "${var.environment}-web-01"
  instance_type = var.environment == "prod" ? "t3.medium" : "t3.micro"
  subnet_id     = module.vpc.public_subnet_ids[0]
  vpc_id        = module.vpc.vpc_id
  environment   = var.environment
}

Notice how module.vpc.public_subnet_ids[0] chains the output from one module as input to another. This is the core pattern of modular infrastructure.

Using Remote Modules (Terraform Registry)

You don't always need to build your own modules. The Terraform Registry hosts thousands of community modules:

# Use a module from the registry
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"

  name = "my-app-vpc"
  cidr = "10.0.0.0/16"

  azs             = ["us-east-1a", "us-east-1b", "us-east-1c"]
  public_subnets  = ["10.0.1.0/24", "10.0.2.0/24", "10.0.3.0/24"]
  private_subnets = ["10.0.10.0/24", "10.0.20.0/24", "10.0.30.0/24"]

  enable_nat_gateway = true
  single_nat_gateway = true
}

# Or use a GitHub URL
module "custom_vpc" {
  source = "git::https://github.com/myorg/terraform-modules.git//vpc?ref=v1.0.0"
  # ...
}

Python Helper: Validate Module Outputs

Write a quick Python script to validate that your Terraform outputs match expected types:

#!/usr/bin/env python3
"""validate-tf-outputs.py — Validate Terraform state against expected schema."""

import json
import subprocess
import sys

EXPECTED_OUTPUTS = {
    "vpc_id": str,
    "vpc_cidr": str,
    "public_subnet_ids": list,
    "public_subnet_cidrs": list,
    "instance_id": str,
    "public_ip": str,
}

def get_terraform_outputs():
    """Pull outputs from Terraform state."""
    result = subprocess.run(
        ["terraform", "output", "-json"],
        capture_output=True, text=True, check=True
    )
    return json.loads(result.stdout)

def validate_outputs():
    """Check outputs exist and have correct types."""
    try:
        outputs = get_terraform_outputs()
    except subprocess.CalledProcessError:
        print("❌ No Terraform state found. Run 'terraform apply' first.")
        return False

    errors = []
    for name, expected_type in EXPECTED_OUTPUTS.items():
        if name not in outputs:
            errors.append(f"  ❌ Missing: {name}")
            continue

        value = outputs[name]["value"]
        if not isinstance(value, expected_type):
            errors.append(
                f"  ❌ Wrong type: {name} "
                f"expected {expected_type.__name__}, "
                f"got {type(value).__name__}"
            )
        else:
            print(f"  ✅ {name}: {str(value)[:60]}")

    if errors:
        print("\nValidation failed:")
        for error in errors:
            print(error)
        return False

    print(f"\n✅ All {len(EXPECTED_OUTPUTS)} outputs validated!")
    return True

if __name__ == "__main__":
    if not validate_outputs():
        sys.exit(1)

Best Practices for Module Design

  • Single responsibility: Each module should do one thing well. A VPC module creates a VPC, not a VPC + RDS + Lambda.
  • Sensible defaults: Provide reasonable defaults so calling a module requires minimal configuration for common cases.
  • Version your modules: Use Git tags for local modules and version constraints for registry modules.
  • Document inputs: Every variable should have a description. Future you will thank present you.
  • Use locals for shared values: Compute derived values once and reuse them. Don't repeat var.environment in every tag block.
  • Avoid exposing everything: Only output values that callers actually need. Internal IDs should stay internal.
  • Test modules independently: Use terraform validate and tools like Terratest to test modules before using them in production.

Rule of thumb: If you copy-paste a Terraform resource block more than twice, extract it into a module. If a module grows beyond 100 lines of resources, consider splitting it into smaller modules.

Quick Reference

# Initialize (downloads modules)
terraform init

# Validate syntax
terraform validate

# Plan changes
terraform plan

# Apply changes
terraform apply

# Show module outputs
terraform output

# List all modules in config
terraform providers

# Initialize a specific directory
terraform -chdir=modules/vpc init

# Force re-download modules
terraform init -upgrade

Summary

Terraform modules turn repetitive infrastructure code into reusable, testable, versioned packages. The key concepts:

  1. Define variables for inputs, resources for infrastructure, outputs for returns
  2. Call modules with module "name" { source = "..." }
  3. Chain modules: one module's output becomes another's input
  4. Use the Terraform Registry for battle-tested modules
  5. Keep modules small, focused, and well-documented

Start by modularizing your most repeated resource — usually a VPC or subnet. Once you see how clean your root configuration becomes, you'll want to module-ize everything.
