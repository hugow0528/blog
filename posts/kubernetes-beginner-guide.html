Kubernetes for Beginners: Deploy Your First App — Complete Guide

July 15, 2026 11 min read

Docker lets you run a single container. But in production you need multiple containers — web servers, databases, caches — that talk to each other, restart when they crash, scale when traffic spikes, and receive zero-downtime updates. That's what Kubernetes (often shortened to K8s) does: it's the operating system for containers. This guide takes you from zero to deploying a live Python app, one concept at a time.

What Is Kubernetes, Really?

Kubernetes is an orchestration platform. Instead of manually starting, monitoring, and restarting Docker containers, you declare the desired state in YAML files, and Kubernetes makes it happen. If you say "I want 3 copies of my app running," and one crashes, Kubernetes starts a replacement automatically.

It was created by Google from 15 years of running containers at scale, and donated to the Cloud Native Computing Foundation in 2014. Today it runs on every major cloud (AWS EKS, Google GKE, Azure AKS) and locally with tools like Minikube and k3s.

Core Concepts: The Kubernetes Vocabulary

Pods: The Smallest Unit

A Pod is the smallest deployable unit in Kubernetes. It wraps one or more containers that share networking (same IP), storage, and lifecycle. In most cases, one Pod = one container. Think of a Pod as the "lifecycle wrapper" around your container.

Deployments: Managing Pod Lifecycles

You rarely create Pods directly. Instead, you create a Deployment, which manages a set of identical Pods (called replicas). Deployments handle rolling updates, rollbacks, and self-healing automatically.

Services: Stable Networking

Pods are ephemeral — they get new IP addresses when recreated. A Service provides a stable network endpoint that routes traffic to your Pods. Think of it as a DNS name + load balancer combined.

Setting Up a Local Cluster with Minikube

You don't need a cloud provider to learn Kubernetes. Minikube runs a single-node cluster on your machine. Install it with:

# macOS with Homebrew
brew install minikube kubectl

# Or using the official script (Linux/macOS)
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl

# Start a local cluster
minikube start --driver=docker

Verify it's running:

# Check cluster health
kubectl cluster-info

# Verify nodes
kubectl get nodes
# NAME       STATUS   ROLES           AGE   VERSION
# minikube   Ready    control-plane   2m    v1.31.0

Deploying Your First Python App

Let's create a simple Flask app and deploy it. First, the application code:

# app.py
from flask import Flask, jsonify
from datetime import datetime

app = Flask(__name__)

@app.route("/")
def home():
    return jsonify({
        "message": "Hello from Kubernetes!",
        "time": datetime.utcnow().isoformat()
    })

@app.route("/health")
def health():
    return jsonify({"status": "healthy"}), 200

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

And the Dockerfile:

# Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
RUN pip install --no-cache-dir flask
EXPOSE 5000
CMD ["python", "app.py"]

Build and load the image into Minikube:

# Build using Minikube's Docker daemon
minikube docker-env
# Run the output eval command, then:
docker build -t myapp:v1 .

Writing the Deployment YAML

Kubernetes uses YAML files to define resources. Create deployment.yaml:

# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  labels:
    app: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: myapp:v1
        ports:
        - containerPort: 5000
        resources:
          requests:
            memory: "64Mi"
            cpu: "50m"
          limits:
            memory: "128Mi"
            cpu: "100m"
        livenessProbe:
          httpGet:
            path: /health
            port: 5000
          initialDelaySeconds: 5
          periodSeconds: 10

Key sections explained:

  • replicas: 3 — run 3 copies of the app for redundancy
  • selector.matchLabels — how the Deployment finds its Pods
  • resources — CPU/memory limits prevent one container from starving others
  • livenessProbe — Kubernetes checks /health every 10 seconds and restarts unhealthy Pods

Apply it:

kubectl apply -f deployment.yaml
deployment.apps/myapp created

# Watch pods start up
kubectl get pods -l app=myapp -w
# NAME                    READY   STATUS    RESTARTS   AGE
# myapp-5d4f7b8c9-abc12  1/1     Running   0          10s
# myapp-5d4f7b8c9-def34  1/1     Running   0          10s
# myapp-5d4f7b8c9-ghi56  1/1     Running   0          10s

Exposing the App with a Service

Your Pods are running but not accessible. Create service.yaml:

# service.yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  type: ClusterIP
  selector:
    app: myapp
  ports:
    - protocol: TCP
      port: 80
      targetPort: 5000

ClusterIP creates an internal IP accessible within the cluster. To access it from your browser, use minikube service:

kubectl apply -f service.yaml
minikube service myapp-service
# Opening service default/myapp-service in default browser...
# 🎉  http://192.168.49.2:30080

# Or use kubectl port-forward for direct access:
kubectl port-forward service/myapp-service 8080:80
# Now visit http://localhost:8080

Scaling and Rolling Updates

Need more capacity? Scale with a single command:

# Scale to 5 replicas
kubectl scale deployment myapp --replicas=5

# Check the result
kubectl get pods -l app=myapp
# 5 pods running

To update the app, build a new image tagged myapp:v2 and run:

# Update the image in the deployment
kubectl set image deployment/myapp myapp=myapp:v2

# Watch the rolling update in real time
kubectl rollout status deployment/myapp
# Waiting for deployment "myapp" rollout to finish: 2 out of 3 new replicas have been updated...
# Waiting for deployment "myapp" rollout to finish: 2 out of 3 new replicas have been updated...
# deployment "myapp" successfully rolled out

Rolling updates replace old Pods one at a time, so your app stays available throughout. If something goes wrong, rollback instantly:

# Undo the last update
kubectl rollout undo deployment/myapp

# Check rollout history
kubectl rollout history deployment/myapp

Namespaces: Organizing Your Resources

Namespaces let you partition your cluster. Create one and deploy into it:

# Create a namespace
kubectl create namespace staging

# Deploy into it
kubectl apply -f deployment.yaml -n staging
kubectl apply -f service.yaml -n staging

# Check resources in a specific namespace
kubectl get all -n staging

Essential kubectl Commands

Command What It Does
kubectl get pods List all running pods
kubectl describe pod <name> Detailed info about a pod
kubectl logs <pod-name> View pod container logs
kubectl exec -it <pod> -- /bin/sh Open a shell inside a pod
kubectl apply -f <file> Create or update resources
kubectl delete -f <file> Remove resources
kubectl cluster-info View cluster details
minikube dashboard Open the web UI

Debugging Common Issues

ImagePullBackOff

Kubernetes can't find your image. Make sure you built it with minikube docker-env loaded, or pushed it to a registry.

CrashLoopBackOff

Your container keeps crashing. Check the logs:

kubectl logs myapp-5d4f7b8c9-abc12
# or, if there are multiple containers in the pod:
kubectl logs myapp-5d4f7b8c9-abc12 -c myapp

Pending Pods

Not enough resources on the node. Check with kubectl describe pod <name> — it usually says "Insufficient cpu" or "Insufficient memory". Reduce your resource requests or add nodes.

Where to Go From Here

  • ConfigMaps and Secrets — externalize configuration and sensitive data from your images
  • Ingress — route external HTTP traffic to your services with path-based routing
  • Persistent Volumes — attach storage that survives Pod restarts
  • Helm — package and manage complex Kubernetes applications as reusable charts
  • k3s — lightweight Kubernetes for production on low-resource servers

Summary

  • Pods are the smallest unit; Deployments manage groups of Pods
  • Services provide stable networking to ephemeral Pods
  • Use kubectl apply with YAML manifests for declarative, version-controlled infrastructure
  • Minikube gives you a local cluster for learning and testing
  • Rolling updates keep your app available during deployments
  • Resource limits and health probes are essential for production stability

Kubernetes has a steep learning curve, but the mental model is simple: declare what you want, Kubernetes makes it happen. Start with local deployments using Minikube, master the core resource types (Pod, Deployment, Service), and gradually explore ConfigMaps, Ingress, and persistent storage as your applications grow.
