Python Logging: Beyond print() — Complete Beginner's Guide

July 12, 2026 10 min read

Every Python developer starts with print() for debugging. It works for small scripts, but as your applications grow, print() becomes unmanageable. You can't filter output, route it to files, or control verbosity. Python's built-in logging module solves all of these problems — and it's already installed with Python.

Why Not Just Use print()?

Consider these problems with print():

  • No levels: Can't distinguish errors from info messages
  • No filtering: Can't disable debug output in production
  • No timestamps: You don't know when things happened
  • No file output: Everything goes to stdout, lost after the script ends
  • No formatting: Hard to read in a wall of text

The logging module handles all of this automatically.

Quick Start: Your First Logger

Replace your print() calls with logging in three lines:

import logging

# Configure the root logger
logging.basicConfig(level=logging.DEBUG)

# Now log instead of print
logging.debug("This is a debug message")
logging.info("Application started successfully")
logging.warning("Low disk space: 10% remaining")
logging.error("Failed to connect to database")
logging.critical("System shutdown initiated")

Output:

DEBUG:root:This is a debug message
INFO:root:Application started successfully
WARNING:root:Low disk space: 10% remaining
ERROR:root:Failed to connect to database
CRITICAL:System shutdown initiated

Log Levels Explained

Logging has five standard levels, from lowest to highest severity:

Level Number When to Use
DEBUG 10 Detailed diagnostics during development
INFO 20 Confirmation that things are working as expected
WARNING 30 Something unexpected happened, but the app continues
ERROR 40 A function or feature failed, but the app keeps running
CRITICAL 50 The application itself may be unable to continue

When you set level=logging.WARNING, only WARNING, ERROR, and CRITICAL messages are shown. DEBUG and INFO are silently filtered out. This is perfect for production — you see problems without noise.

# Production: only warnings and above
logging.basicConfig(level=logging.WARNING)

logging.debug("Processing item...")      # NOT shown
logging.info("Request received")          # NOT shown
logging.warning("Slow response: 3.2s")   # SHOWN
logging.error("Connection timeout")       # SHOWN

Customizing Log Format

The default format is minimal. Let's add timestamps, log levels, and module names:

import logging

logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s | %(levelname)-8s | %(name)s | %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)

logging.info("Server starting on port 8080")
logging.error("Failed to bind to port 8080")

Output:

2026-07-12 14:30:00 | INFO     | root | Server starting on port 8080
2026-07-12 14:30:01 | ERROR    | root | Failed to bind to port 8080

Common format specifiers:

  • %(asctime)s — human-readable timestamp
  • %(levelname)s — DEBUG, INFO, WARNING, etc.
  • %(name)s — the logger's name
  • %(message)s — your log message
  • %(filename)s — source file name
  • %(lineno)d — line number
  • %(funcName)s — function name
  • %(threadName)s — thread name

Named Loggers for Different Modules

Instead of using the root logger, create named loggers for each module. This lets you control logging per-module:

# In database.py
import logging
logger = logging.getLogger(__name__)  # __name__ = "database"

def connect():
    logger.debug("Attempting database connection...")
    try:
        # connect logic here
        logger.info("Connected to database successfully")
    except Exception as e:
        logger.error(f"Database connection failed: {e}")
        raise

# In api.py
import logging
logger = logging.getLogger(__name__)  # __name__ = "api"

def handle_request(request):
    logger.info(f"Received request: {request.path}")
    logger.debug(f"Headers: {request.headers}")

Now you can configure logging per module:

# Only show database logs, silence API debug
logging.getLogger("database").setLevel(logging.DEBUG)
logging.getLogger("api").setLevel(logging.WARNING)

Logging to Files

In production, you need logs to persist. The FileHandler writes logs to a file:

import logging

# Create a logger
logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)

# Create a file handler
file_handler = logging.FileHandler("app.log")
file_handler.setLevel(logging.DEBUG)

# Create a console handler
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.INFO)

# Create a formatter
formatter = logging.Formatter(
    '%(asctime)s | %(levelname)-8s | %(name)s | %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)

# Attach formatter to handlers
file_handler.setFormatter(formatter)
console_handler.setFormatter(formatter)

# Add handlers to logger
logger.addHandler(file_handler)
logger.addHandler(console_handler)

# Now this logs to BOTH file and console
logger.info("Application started")
logger.error("Something went wrong")

This pattern — debug to file, info to console — is a common production setup. You get detailed logs for later analysis while the terminal stays clean.

Rotating Log Files

Without rotation, log files grow forever and fill your disk. RotatingFileHandler automatically manages file size and number of backups:

import logging
from logging.handlers import RotatingFileHandler

logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)

# Rotate when file reaches 5MB, keep 3 backup files
handler = RotatingFileHandler(
    "app.log",
    maxBytes=5 * 1024 * 1024,  # 5 MB
    backupCount=3               # Keep app.log.1, .2, .3
)

handler.setFormatter(logging.Formatter(
    '%(asctime)s | %(levelname)-8s | %(message)s'
))
logger.addHandler(handler)

# Files created automatically:
# app.log      (current)
# app.log.1    (previous)
# app.log.2    (older)
# app.log.3    (oldest)

There's also TimedRotatingFileHandler for time-based rotation:

from logging.handlers import TimedRotatingFileHandler

# New file every midnight
handler = TimedRotatingFileHandler(
    "app.log",
    when="midnight",
    interval=1,
    backupCount=30   # Keep 30 days of logs
)

Logging Exceptions with Tracebacks

Use logger.exception() inside except blocks to automatically include the full traceback:

import logging
logger = logging.getLogger(__name__)

def divide(a, b):
    try:
        result = a / b
        return result
    except ZeroDivisionError:
        # exception() logs at ERROR level + full traceback
        logger.exception("Division by zero attempted: %d / %d", a, b)
        return None

divide(10, 0)
# Output:
# ERROR:__main__:Division by zero attempted: 10 / 0
# Traceback (most recent call last):
#   File "app.py", line 5, in divide
#     result = a / b
# ZeroDivisionError: division by zero

Structured Logging with JSON

For production systems, parseable log formats like JSON are essential. Here's how to create a simple JSON formatter:

import json
import logging

class JSONFormatter(logging.Formatter):
    def format(self, record):
        log_entry = {
            "timestamp": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }
        if record.exc_info:
            log_entry["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

# Use it
handler = logging.StreamHandler()
handler.setFormatter(JSONFormatter())
logger = logging.getLogger("myapp")
logger.addHandler(handler)
logger.setLevel(logging.DEBUG)

logger.info("User logged in", extra={"user_id": 42})
# Output: {"timestamp": "...", "level": "INFO", "message": "User logged in", ...}

For production use, consider libraries like python-json-logger or structlog which handle edge cases and extra fields automatically.

Complete Production Example

Here's a production-ready logging setup you can copy into any project:

import logging
import logging.handlers
import os
import sys

def setup_logging(app_name="myapp", log_dir="logs", level=None):
    """Set up production-grade logging."""
    # Use environment variable for level, default to WARNING
    log_level = level or os.environ.get("LOG_LEVEL", "WARNING").upper()
    numeric_level = getattr(logging, log_level, logging.WARNING)

    # Create log directory
    os.makedirs(log_dir, exist_ok=True)

    # Root logger
    logger = logging.getLogger(app_name)
    logger.setLevel(logging.DEBUG)  # Capture everything

    # Formatter
    fmt = '%(asctime)s | %(levelname)-8s | %(name)s | %(message)s'
    formatter = logging.Formatter(fmt, datefmt='%Y-%m-%d %H:%M:%S')

    # Console handler — always show at least WARNING
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(logging.INFO)
    console.setFormatter(formatter)
    logger.addHandler(console)

    # File handler — all debug info
    file_handler = logging.handlers.RotatingFileHandler(
        os.path.join(log_dir, f"{app_name}.log"),
        maxBytes=10 * 1024 * 1024,  # 10 MB
        backupCount=5
    )
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(formatter)
    logger.addHandler(file_handler)

    # Error-only file — separate file for errors
    error_handler = logging.handlers.RotatingFileHandler(
        os.path.join(log_dir, f"{app_name}_error.log"),
        maxBytes=5 * 1024 * 1024,
        backupCount=3
    )
    error_handler.setLevel(logging.ERROR)
    error_handler.setFormatter(formatter)
    logger.addHandler(error_handler)

    return logger

# Usage
logger = setup_logging("myapp", level="DEBUG")
logger.info("App initialized")

Common Mistakes to Avoid

  • Using print() in production: Remove all print statements before deploying. Use logger.debug() instead.
  • Logging sensitive data: Never log passwords, API keys, tokens, or PII. Mask or omit sensitive fields.
  • Over-logging at DEBUG: Don't log every variable. Focus on state transitions, decisions, and external interactions.
  • Forgetting to propagate: Named loggers propagate to the root logger by default. If you've configured the root logger, child loggers inherit its handlers.
  • Logging inside tight loops: Logging has overhead. In a loop processing millions of items, log a summary instead of every iteration.
# ❌ Bad: logging in a tight loop
for item in items:  # 1,000,000 items
    logger.debug(f"Processing {item}")  # Too slow!

# ✅ Good: log summaries
processed = 0
for i, item in enumerate(items):
    process(item)
    processed += 1
    if (i + 1) % 10000 == 0:  # Log every 10,000
        logger.info(f"Processed {processed} items so far")

logger.info(f"Completed: {processed} items processed")

Summary

Python's logging module is your go-to tool for any application beyond a quick script. Use DEBUG for development diagnostics, INFO for important events, and WARNING/ERROR for problems. Add file handlers with rotation for production, format your logs with timestamps and levels, and never log secrets. The setup_logging() function above gives you a solid starting point for any project.

Good logging is like insurance — you hope you never need it, but when things break in production, it's the difference between a 5-minute fix and a 5-hour investigation.
