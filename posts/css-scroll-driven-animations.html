CSS Scroll-Driven Animations: Animate on Scroll Without JavaScript — Complete Guide

July 12, 2026 · 10 min read

Remember when animating elements on scroll meant hundreds of lines of JavaScript — intersection observers, scroll event listeners, animation frame loops, and cleanup code? That era is over. CSS Scroll-Driven Animations let you tie animations directly to scroll position using pure CSS.

Browsers now support this feature natively — no libraries, no JavaScript, and buttery smooth performance because the browser optimizes scroll-linked animations at the compositor level. This guide covers everything from basic scroll-timeline to advanced view-timeline ranges and real-world hero section patterns.

Why CSS Scroll Animations Over JavaScript?

The traditional JavaScript approach to scroll animations has several problems:

  • Performance: Scroll events fire at 60fps — any heavy computation blocks the main thread
  • Jank: JavaScript animations compete with scroll handling, causing stutter
  • Complexity: IntersectionObserver + requestAnimationFrame + cleanup = lots of boilerplate
  • Accessibility: JS animations are harder to pause for users who prefer reduced motion

CSS scroll-driven animations solve all of these. The browser's rendering engine handles the animation at the compositor level, completely off the main thread. Zero JavaScript, zero boilerplate, perfect performance.

The Two Timeline Types

CSS scroll-driven animations use timelines instead of time. There are two types:

  1. scroll-timeline: Animates based on the scroll position of a scroll container (e.g., the page)
  2. view-timeline: Animates based on an element's position within the viewport (e.g., when it enters/exits the visible area)

Both replace the implicit time-based animation of standard CSS with a scroll-linked progression from 0% (start) to 100% (end).

Basic Scroll Timeline

A scroll-timeline animates an element as the page (or any scroll container) scrolls. The animation progresses from 0% to 100% as the scroll position moves from the start to the end:

/* A progress bar that fills as you scroll down the page */
.progress-bar {
    position: fixed;
    top: 0;
    left: 0;
    height: 4px;
    background: #5e6ad2;
    width: 100%;
    transform-origin: left;
    transform: scaleX(0);
    animation: fill linear forwards;
    animation-timeline: scroll(root);
}

@keyframes fill {
    to { transform: scaleX(1); }
}

The animation-timeline: scroll(root) declaration ties the animation to the root scrolling element (the page). As you scroll from the top to the bottom, the bar goes from scaleX(0) to scaleX(1).

Key concepts:

  • scroll(root) — the document's main scroll container
  • scroll(y) — vertical scroll of the nearest scroll ancestor
  • scroll(x) — horizontal scroll
  • The animation's 0% = scroll position at the top, 100% = scroll position at the bottom

Scroll Timeline with Named Containers

You can also use named scroll containers for more control:

.scroll-container {
    height: 400px;
    overflow-y: scroll;
    scroll-timeline-axis: y;
    scroll-timeline: --my-scroll;
}

.animated-element {
    animation: slide-in linear;
    animation-timeline: --my-scroll;
}

@keyframes slide-in {
    from { transform: translateX(-100%); opacity: 0; }
    to   { transform: translateX(0);    opacity: 1; }
}

The scroll-timeline: --my-scroll property on the container creates a named timeline. The child element references it with animation-timeline: --my-scroll. This decouples the animation from the page scroll — it only responds to scrolling inside that specific container.

View Timeline: The Powerhouse

View timelines are more powerful because they animate based on an element's visibility in the viewport, not just page scroll position. The animation triggers when the element enters or leaves the viewport:

/* An element fades in and scales up as it enters the viewport */
.hero-card {
    opacity: 0;
    transform: scale(0.8) translateY(40px);
    animation: appear linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 40%;
}

@keyframes appear {
    to {
        opacity: 1;
        transform: scale(1) translateY(0);
    }
}

Here's what's happening:

  • animation-timeline: view() — the animation is driven by this element's position in the viewport
  • animation-range: entry 0% entry 40% — the animation starts when the element first enters the viewport (entry 0%) and completes when 40% of the element is visible (entry 40%)
  • both fill mode — the element retains its initial state before animation starts and final state after it ends

View Progress Keywords

The animation-range property uses special keywords to define when animation phases occur:

  • entry — when the element enters the viewport (from bottom)
  • exit — when the element leaves the viewport (from top)
  • cover — the combined entry and exit phases
  • contain — when the element is fully inside the viewport

Each keyword has start, end, and percentage offsets:

/* Complex range: start animating when 20% visible, finish when 80% visible */
.fade-in {
    animation-timeline: view();
    animation-range: entry 20% entry 80%;
}

/* Start on entry, end on exit (full viewport traversal) */
.parallax-element {
    animation-timeline: view();
    animation-range: entry exit;
}

/* Only animate while fully in the viewport */
.highlight {
    animation-timeline: view();
    animation-range: contain;
}

Building a Scroll-Driven Hero Section

Let's combine these concepts into a real hero section that animates as the user scrolls:

<section class="hero">
    <h1 class="hero-title">Welcome to the Future</h1>
    <p class="hero-subtitle">CSS animations driven by scroll</p>
    <div class="hero-image">✦</div>
</section>

<main>
    <section>More content here...</section>
</main>

<style>
.hero {
    height: 100vh;
    display: flex;
    flex-direction: column;
    align-items: center;
    justify-content: center;
    background: #0a0a0a;
}

.hero-title {
    font-size: clamp(2rem, 8vw, 6rem);
    font-weight: 700;
    opacity: 1;
    transform: translateY(0);
    animation: hero-title linear both;
    animation-timeline: view();
    animation-range: entry 0% cover 30%;
}

@keyframes hero-title {
    to {
        opacity: 0;
        transform: translateY(-80px);
    }
}

.hero-subtitle {
    font-size: clamp(1rem, 3vw, 1.5rem);
    opacity: 0;
    animation: hero-sub linear both;
    animation-timeline: view();
    animation-range: entry 20% cover 40%;
}

@keyframes hero-sub {
    to {
        opacity: 1;
    }
}

.hero-image {
    font-size: 8rem;
    transform: scale(0.5) rotate(0deg);
    animation: hero-img ease-out both;
    animation-timeline: view();
    animation-range: entry 10% cover 50%;
}

@keyframes hero-img {
    to {
        transform: scale(1.5) rotate(180deg);
    }
}
</style>

This hero section creates a cinematic effect:

  1. The title starts fully visible and fades up as you scroll
  2. The subtitle fades in as the title fades out (staggered timing)
  3. The decorative element grows and rotates throughout the scroll

All of this is pure CSS — zero JavaScript, zero dependencies, and the browser handles the animation at 60fps with no jank.

Parallax with View Timeline

Create smooth parallax effects by moving elements at different speeds relative to the scroll:

.parallax-layer {
    animation: parallax linear;
    animation-timeline: view();
    animation-range: cover;
}

.parallax-slow {
    --speed: 0.3;
}

.parallax-fast {
    --speed: 0.8;
}

@keyframes parallax {
    from {
        transform: translateY(calc(-100px * var(--speed)));
    }
    to {
        transform: translateY(calc(100px * var(--speed)));
    }
}

Each layer moves at a different speed based on the CSS custom property --speed, creating a depth effect. Since the browser composites transforms, this runs on the GPU with no layout recalculation.

Scroll-Driven Progress Indicators

Build a section progress indicator without JavaScript:

.section {
    scroll-timeline: --section-scroll;
    scroll-timeline-axis: block;
}

.section-progress {
    position: absolute;
    bottom: 0;
    left: 0;
    height: 3px;
    width: 100%;
    background: #333;
}

.section-progress::after {
    content: "";
    position: absolute;
    left: 0;
    top: 0;
    height: 100%;
    width: 100%;
    background: #5e6ad2;
    transform-origin: left;
    transform: scaleX(0);
    animation: progress-fill linear forwards;
    animation-timeline: --section-scroll;
}

@keyframes progress-fill {
    to { transform: scaleX(1); }
}

This creates a progress bar at the bottom of each scrollable section that fills as the user scrolls through that section. Each section gets its own progress indicator.

Animation Range with Multiple Values

You can define complex animation ranges with multiple start and end points:

/* Animate in on entry, hold, then animate out on exit */
.reveal-card {
    animation: reveal linear both;
    animation-timeline: view();
    /*
     * entry 0%  → animation starts (element just visible)
     * entry 50% → animation completes (halfway into viewport)
     * exit 0%   → animation restarts (element leaving viewport)
     * exit 100% → animation completes (element fully gone)
     */
    animation-range: entry 0% entry 50% exit 0% exit 100%;
}

@keyframes reveal {
    0%   { opacity: 0; transform: translateY(30px) scale(0.95); }
    25%  { opacity: 1; transform: translateY(0) scale(1); }
    75%  { opacity: 1; transform: translateY(0) scale(1); }
    100% { opacity: 0; transform: translateY(-30px) scale(0.95); }
}

The element smoothly fades in as it enters, stays visible while in the viewport, then fades out as it scrolls away — all defined in CSS.

Respecting User Preferences

Always respect the prefers-reduced-motion preference for users who prefer minimal animation:

@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
        scroll-behavior: auto !important;
    }
}

For scroll-driven animations specifically, you can disable the timeline entirely:

@media (prefers-reduced-motion: reduce) {
    .animated {
        animation-timeline: none !important;
        opacity: 1;
        transform: none;
    }
}

Browser Support and Fallbacks

CSS scroll-driven animations are widely supported as of 2026 in Chrome, Edge, and Safari. For browsers that don't support it, the element simply shows its initial/final CSS state — graceful degradation built in:

.animated-element {
    /* Fallback state — visible in old browsers */
    opacity: 1;
    transform: none;

    /* Enhanced for modern browsers */
    animation: fade-in linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 50%;
}

/* Browsers without support see opacity: 1, no animation */

The key principle: define your fallback state in the base styles, then enhance with scroll-driven animations. Old browsers see a perfectly usable page.

Common Patterns and Recipes

Staggered Card Entrance

.card {
    opacity: 0;
    transform: translateY(20px);
    animation: card-in ease-out both;
    animation-timeline: view();
    animation-range: entry 0% entry 40%;
}

/* Each card staggers based on its index */
.card:nth-child(1) { animation-range: entry 0% entry 30%; }
.card:nth-child(2) { animation-range: entry 10% entry 40%; }
.card:nth-child(3) { animation-range: entry 20% entry 50%; }
.card:nth-child(4) { animation-range: entry 30% entry 60%; }

@keyframes card-in {
    to { opacity: 1; transform: translateY(0); }
}

Horizontal Scroll Section

.horizontal-section {
    height: 100vh;
    overflow-x: auto;
    overflow-y: hidden;
    scroll-snap-type: x mandatory;
    scroll-timeline: --horizontal-scroll x;
}

.slide {
    animation: slide-x linear;
    animation-timeline: --horizontal-scroll;
}

@keyframes slide-x {
    from { transform: translateX(0); }
    to   { transform: translateX(calc(-100vw)); }
}

Summary

CSS scroll-driven animations eliminate the need for JavaScript scroll listeners:

  • animation-timeline: scroll() — animate based on page/container scroll position
  • animation-timeline: view() — animate based on element's viewport position
  • animation-range — control exactly when animation phases trigger
  • View progress keywords: entry, exit, cover, contain — with percentage offsets
  • Always provide fallback states — old browsers see a static version
  • Respect prefers-reduced-motion — disable animations for users who need it

With scroll-driven animations, you get smooth, performant, declarative animations that work entirely in CSS. No more scroll event handlers, no more IntersectionObserver boilerplate, no more requestAnimationFrame loops. Just clean CSS that the browser optimizes automatically.
