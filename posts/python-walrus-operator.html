Python Walrus Operator (:=): Assign Inside Expressions

July 3, 2026 8 min read New

Python 3.8 introduced the walrus operator (:=) — named for its resemblance to a walrus's eyes and tusks. It lets you assign values to variables within an expression, not as a separate statement. This might sound like a small change, but it opens up genuinely useful patterns that make your code cleaner and sometimes faster.

Before walrus, you had to write:

data = get_data()
if data:
    process(data)

With the walrus operator:

if data := get_data():
    process(data)

Two lines become one. Let's explore where this actually helps, where it doesn't, and the patterns you'll use in real code.

Basic Syntax

The walrus operator follows the pattern (variable := expression). The parentheses are required except at the start of a compound statement.

# Assign and check in one step
if (length := len(my_list)) > 10:
    print(f"List is too long: {length} items")

# Without walrus (3 lines):
length = len(my_list)
if length > 10:
    print(f"List is too long: {length} items")

The key insight: := evaluates the expression, assigns the result to the variable, and returns the value so it can be used in the surrounding expression.

Pattern 1: Reading from Files or Streams

This is the canonical use case from PEP 572. Reading chunks from a file or network stream until you get empty data:

# Without walrus — awkward repetition
chunk = file.read(8192)
while chunk:
    process(chunk)
    chunk = file.read(8192)

# With walrus — clean and readable
while chunk := file.read(8192):
    process(chunk)

No repeated variable name. No duplicated file.read(8192) call. The assignment happens once per iteration, and the loop condition checks the result.

Pattern 2: Regular Expression Matching

Extracting data from regex matches is another common pattern:

import re

# Without walrus
text = "Order #12345 placed on 2026-07-03"
match = re.search(r"Order #(\d+)", text)
if match:
    order_id = match.group(1)
    print(f"Found order: {order_id}")

# With walrus — match and extract in one line
if (match := re.search(r"Order #(\d+)", text)):
    print(f"Found order: {match.group(1)}")

# Or extract directly into a variable
if (order_id := re.search(r"Order #(\d+)", text).group(1)):
    print(f"Order ID: {order_id}")

Pattern 3: List Comprehensions with Filtering

When you need to compute a value for filtering and use it in the output:

import re

# Data: list of strings containing user info
entries = [
    "hugo:admin:25",
    "alice:viewer:30",
    "bob:admin:45",
    "carol:editor:22",
]

# Without walrus — compute role twice
admins = [
    entry.split(":")[1]
    for entry in entries
    if entry.split(":")[1] == "admin"
]

# With walrus — compute once, use twice
admins = [
    role for entry in entries
    if (role := entry.split(":")[1]) == "admin"
]
# Result: ['admin', 'admin']

The walrus operator saves computing entry.split(":")[1] twice per entry. For simple cases this doesn't matter, but for expensive computations (database lookups, API calls, complex calculations), the savings are real.

Pattern 4: Interactive Input Loops

Build a simple REPL or command prompt that runs until the user types "quit":

# Without walrus
command = input(">>> ")
while command != "quit":
    print(f"Running: {command}")
    command = input(">>> ")

# With walrus
while (command := input(">>> ")) != "quit":
    print(f"Running: {command}")

Pattern 5: Caching Expensive Function Results

When a function is expensive and you need the result in multiple places:

import time

def expensive_computation(x):
    time.sleep(0.1)  # Simulate heavy work
    return x * 2

# Without walrus — call twice (0.2 seconds total)
x = 42
if expensive_computation(x) > 50:
    print(f"Result: {expensive_computation(x)}")

# With walrus — call once (0.1 seconds)
if (result := expensive_computation(x)) > 50:
    print(f"Result: {result}")

When NOT to Use the Walrus Operator

The walrus operator is powerful, but more power doesn't always mean better code. Avoid it when:

1. It Makes Code Harder to Read

# Don't do this — too clever
if (result := complex_function(a, b, c)) and (other := another_function(result)) > 0:
    do_something(result, other)

# This is clearer:
result = complex_function(a, b, c)
if result:
    other = another_function(result)
    if other > 0:
        do_something(result, other)

2. The Variable Is Used Only Once

# Walrus adds no value here
print((total := sum(numbers)))

# Just assign normally
total = sum(numbers)
print(total)

3. In Function Arguments (Not Allowed!)

# SyntaxError! Walrus not allowed in default arguments
def process(data, result := None):
    ...

# Use None as default instead
def process(data, result=None):
    ...

Real-World Example: Log File Parser

Let's combine several walrus patterns into a practical tool:

import re
from datetime import datetime

def parse_log_file(filepath):
    """Parse a log file and extract error entries with timestamps."""
    errors = []
    pattern = re.compile(
        r"(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) \[(ERROR)\] (.+)"
    )

    with open(filepath) as f:
        while line := f.readline():
            if match := pattern.match(line):
                timestamp_str, _, message = match.groups()
                timestamp = datetime.strptime(timestamp_str, "%Y-%m-%d %H:%M:%S")
                errors.append({
                    "timestamp": timestamp,
                    "message": message.strip(),
                })

    return errors

# Usage
errors = parse_log_file("app.log")
for error in errors:
    print(f"[{error['timestamp']}] {error['message']}")

Two walrus operators in the loop: one for reading lines (the classic file-reading pattern), one for regex matching (the extraction pattern). The code reads naturally — process each line, skip it if it doesn't match the error pattern.

Scope Behavior

Important: the walrus operator leaks the variable into the enclosing scope. Be careful with comprehensions:

# WARNING: i leaks into the outer scope!
result = [i for item in items if (i := process(item)) > 0]
print(i)  # This works — i is the last assigned value

# Use a regular loop if you don't want this
results = []
for item in items:
    i = process(item)
    if i > 0:
        results.append(i)
# i still leaks, but at least the logic is clearer

Summary

The walrus operator shines in these situations:

  • Loop conditions where you need to read/assign then check
  • Regex matching where you need the match object
  • Comprehensions where a computed value is used for both filtering and output
  • Expensive computations where you want to evaluate once but check the result

Use it when it reduces repetition. Avoid it when it makes code harder to understand. The best Python code is clear first, clever second.
