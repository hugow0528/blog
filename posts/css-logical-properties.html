CSS Logical Properties: Modern Layout Without Direction-Specific Code — Complete Guide

Stop writing separate padding-left and padding-right rules for RTL support. Learn CSS logical properties — padding-inline, margin-block, start/end sizing — that automatically adapt to any writing direction. Modern, clean, bidirectional-ready layouts.

July 10, 2026 10 min read

The Problem with Physical Properties

Traditional CSS uses physical properties that refer to specific sides of an element: margin-left, padding-top, border-right. This works perfectly for left-to-right languages like English. But when your site needs to support right-to-left languages (Arabic, Hebrew) or top-to-bottom writing (classical Chinese, Mongolian), every directional property needs a manual override:

/* Physical properties — breaks with RTL */
.card {
    margin-left: 20px;    /* Has to become margin-right in RTL */
    padding-right: 16px;  /* Has to become padding-left in RTL */
    text-align: left;     /* Has to become text-align: right in RTL */
}

/* The old way to fix it: separate RTL styles */
[dir="rtl"] .card {
    margin-left: 0;
    margin-right: 20px;
    padding-right: 0;
    padding-left: 16px;
    text-align: right;
}

This duplication is error-prone, verbose, and easy to forget. CSS logical properties solve this by referencing logical sides (inline/block, start/end) instead of physical directions.

Inline vs Block: The Logical Axes

CSS logical properties define two axes based on the writing direction:

  • Inline axis: The direction text flows. In LTR languages, this is left-to-right. In RTL languages, this is right-to-left. Think of it as the "reading direction."
  • Block axis: The perpendicular direction. In horizontal writing, this is top-to-bottom. In vertical writing, this becomes left-to-right.

Here's how physical properties map to their logical equivalents:

/* Physical        →  Logical (shorthand)   */
padding-left       →  padding-inline-start
padding-right      →  padding-inline-end
padding-top        →  padding-block-start
padding-bottom     →  padding-block-end

margin-left        →  margin-inline-start
margin-right       →  margin-inline-end
margin-top         →  margin-block-start
margin-bottom      →  margin-block-end

/* Shorthand versions for both sides */
padding-left/right →  padding-inline
padding-top/bottom →  padding-block
margin-left/right  →  margin-inline
margin-top/bottom  →  margin-block

Using padding-inline and padding-block

The most common use case is replacing directional padding. Instead of specifying left and right separately:

/* Before: physical properties */
.card {
    padding: 16px 24px;        /* top/bottom = 16px, left/right = 24px */
    margin-bottom: 24px;
    margin-left: 12px;
}

/* After: logical properties */
.card {
    padding-block: 16px;       /* top AND bottom */
    padding-inline: 24px;      /* left AND right in LTR, right AND left in RTL */
    margin-block-end: 24px;    /* bottom in horizontal writing */
    margin-inline-start: 12px; /* left in LTR, right in RTL */
}

With logical properties, the same CSS works for both LTR and RTL languages. The browser automatically maps "inline-start" to the correct physical side based on the writing direction. Zero RTL-specific code needed.

Border and Background Logical Properties

Logical properties extend to borders and backgrounds too. This is especially useful for cards, dividers, and content separation:

.card {
    /* Logical borders */
    border-inline-start: 4px solid #5e6ad2;  /* left border in LTR */
    border-block-end: 1px solid #eee;         /* bottom border */
    
    /* Logical background positioning */
    background-position: left center;    /* physical — won't adapt */
    background-position: start center;   /* logical — adapts to direction */
    
    /* Logical border-radius */
    border-start-start-radius: 12px;   /* top-left in LTR */
    border-start-end-radius: 12px;     /* top-right in LTR */
    border-end-start-radius: 0;        /* bottom-left in LTR */
    border-end-end-radius: 0;          /* bottom-right in LTR */
}

The border-radius logical properties are verbose but incredibly powerful for complex designs. The naming follows the pattern border-{block-side}-{inline-side}-radius, where each side is either start or end.

Intrinsic Sizing: min() and max() Functions

CSS also introduces logical keywords for sizing elements based on their content's natural dimensions, rather than fixed pixel values:

.responsive-container {
    /* Use minimum of viewport width and 800px */
    width: min(100vw, 800px);
    
    /* Minimum size based on content, maximum based on viewport */
    min-width: min(50ch, 100%);   /* 50 characters or full width */
    max-width: min(80ch, 100%);   /* 80 characters or full width */
    
    /* Clamp for fluid typography */
    font-size: clamp(1rem, 2.5vw, 1.5rem);
    
    /* Intrinsic sizing keywords */
    min-width: min-content;  /* Shrink to smallest content */
    min-width: max-content;  /* Expand to largest content */
    min-width: fit-content;  /* Best fit between min and max */
}

The ch unit (width of the character "0") is perfect for text containers. A max-width of 80ch ensures lines stay around 80 characters — the optimal reading length for most languages. Combined with min(), it creates fluid containers that never overflow their parent.

start and end Keywords for Positioning

Logical start and end keywords work across many CSS properties beyond padding and margin:

.icon-button {
    /* Position icon on the "start" side (left in LTR, right in RTL) */
    display: flex;
    align-items: center;
    justify-content: space-between;
    
    /* Logical float */
    float: inline-start;  /* float: left in LTR */
    
    /* Logical text alignment */
    text-align: start;    /* text-align: left in LTR */
    
    /* Logical absolute positioning */
    position: absolute;
    inset-inline-start: 16px;   /* left: 16px in LTR */
    inset-block-end: 16px;      /* bottom: 16px */
    
    /* Logical overflow */
    overflow-x: clip;
    overflow-y: auto;
    
    /* Logical scroll behavior */
    scroll-margin-inline-start: 24px;
}

/* Logical inset shorthand */
.modal {
    inset: 2rem;           /* top/right/bottom/left = 2rem */
    inset-inline: 4rem;    /* left AND right = 4rem */
    inset-block: 2rem;     /* top AND bottom = 2rem */
}

The inset-inline and inset-block shorthands are particularly powerful for modal dialogs, overlays, and sticky elements. They replace the need for separate top/bottom/left/right declarations.

Complete Real-World Example: Blog Card Component

Here's a complete card component built entirely with logical properties. It works flawlessly in both LTR and RTL:

.blog-card {
    /* Layout */
    display: flex;
    flex-direction: column;
    
    /* Spacing with logical properties */
    padding-block: 24px;          /* top + bottom padding */
    padding-inline: 24px;         /* left + right padding */
    margin-block-end: 16px;       /* bottom margin */
    
    /* Borders */
    border-radius: 12px;
    border: 1px solid #222;
    border-inline-start: 4px solid #5e6ad2;
    
    /* Typography */
    text-align: start;            /* left in LTR, right in RTL */
    
    /* Content spacing */
    .card-title {
        margin-block-end: 8px;
    }
    
    .card-excerpt {
        margin-block-end: 16px;
        color: #888;
        font-size: 0.95rem;
    }
    
    /* Button alignment */
    .card-footer {
        display: flex;
        justify-content: space-between;
        align-items: center;
        padding-block-start: 16px;
        border-block-start: 1px solid #333;
    }
    
    /* Arrow icon direction */
    .read-more {
        display: inline-flex;
        align-items: center;
        gap: 4px;
    }
    
    .read-more::after {
        content: '→';
        transition: transform 0.2s;
    }
    
    /* Arrow flips in RTL */
    [dir="rtl"] .read-more::after {
        transform: scaleX(-1);
    }
    
    .read-more:hover::after {
        transform: translateX(4px);
    }
    
    [dir="rtl"] .read-more:hover::after {
        transform: scaleX(-1) translateX(4px);
    }
}

Notice how only the icon arrow needs an explicit RTL override. Every padding, margin, border, and alignment property automatically adapts through logical properties. That's a 90% reduction in RTL-specific CSS.

Browser Support

CSS logical properties have excellent browser support in 2026. All major browsers (Chrome, Firefox, Safari, Edge) fully support the core logical properties:

  • margin-inline, margin-block — 100% support
  • padding-inline, padding-block — 100% support
  • border-inline, border-block — 100% support
  • inset-inline, inset-block — 100% support
  • text-align: start/end — 100% support
  • min(), max(), clamp() — 100% support

There's no reason not to use logical properties in new projects. For legacy code, gradually replace physical properties one component at a time — they can coexist without conflicts.

Migration Strategy

Converting existing projects to logical properties is straightforward:

  1. Audit: Search your CSS for margin-left, margin-right, padding-left, padding-right — these are the most common targets.
  2. Pair replacements: When both left and right have the same value, combine them: padding-left: 16px; padding-right: 16px → padding-inline: 16px.
  3. Asymmetric pairs: When left and right differ, use start/end: margin-left: 20px; margin-right: 8px → margin-inline: 20px 8px (start end).
  4. Test both directions: Add dir="rtl" to your <html> tag temporarily and verify the layout flips correctly.

Summary

CSS logical properties eliminate the need for direction-specific stylesheets and reduce code duplication by 50-90%. They future-proof your layouts for any writing direction, from Arabic and Hebrew to vertical Japanese text. Start using padding-inline, margin-block, text-align: start, and inset-inline in every new project. Your CSS will be cleaner, more maintainable, and automatically internationalized.
