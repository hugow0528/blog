Cloudflare Workers Assets: Serve Static Files from Your Edge Functions

July 9, 2026 · 9 min read

Cloudflare Workers Assets is a feature that lets you bundle static files — HTML, CSS, JavaScript, images, fonts — directly with your Worker. Instead of deploying your API to Workers and your frontend to a separate static host (S3, Vercel, Netlify), everything lives in one deployment. Your static assets get served from Cloudflare's 300+ edge locations with the same low latency as your Worker code.

In this guide, we'll walk through setting up Workers Assets, configuring the manifest, handling routing between static files and API endpoints, and building a complete single-page application (SPA) served entirely from a Worker.

What Is Workers Assets?

Workers Assets solves a common problem: you need both a frontend (static files) and a backend (API endpoints), but managing two separate deployments adds complexity. With Workers Assets:

  • Single deployment: One wrangler deploy command pushes everything
  • Same origin: Frontend and API share the same domain — no CORS issues
  • Edge caching: Static assets are automatically cached at the edge with smart cache-control headers
  • Worker as fallback: Your Worker code can intercept requests and serve API responses or dynamic content
  • Free tier included: Assets count toward your storage limits but are free on the Workers plan

Project Structure

A typical Workers Assets project looks like this:

my-app/

Step 1: Initialize and Configure

Start by creating a new Workers project and configuring the assets directory in your wrangler.jsonc file:

# Create a new project
npm create cloudflare@latest my-app
cd my-app

# Or if you already have a Worker, just add the configuration

Then update your wrangler.jsonc to specify the assets directory:

{
  "name": "my-app",
  "main": "src/index.js",
  "compatibility_date": "2026-07-09",
  "assets": {
    "directory": "./assets",
    "binding": "ASSETS",
    "html_handling": "html",
    "not_found_handling": "single-page-application"
  }
}

The key options explained:

Option Description
directory Path to your static files folder
binding Environment variable name for accessing assets programmatically
html_handling "html" sets proper Content-Type; "binary" treats HTML as binary
not_found_handling "single-page-application" serves index.html for unmatched routes (SPA); "404" returns a 404

Step 3: Write the Worker Code

Your Worker handles API routes and falls through to serve static assets for everything else:

// src/index.js

export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        // API routes — handle /api/* yourself
        if (url.pathname.startsWith('/api/')) {
            return handleApi(request);
        }
        
        // Everything else — serve from assets (automatic fallback)
        // Workers Assets automatically serves static files for non-matching routes
        // So we can just return the assets response for non-API requests
        return env.ASSETS.fetch(request);
    }
};

async function handleApi(request) {
    const url = new URL(request.url);
    
    if (url.pathname === '/api/greeting') {
        return Response.json({
            message: `Hello! You visited at ${new Date().toLocaleString()}`,
            server: 'Cloudflare Workers'
        });
    }
    
    if (url.pathname === '/api/hello') {
        return Response.json({
            name: 'Workers Assets App',
            status: 'running',
            timestamp: Date.now(),
            visitorIp: request.headers.get('CF-Connecting-IP')
        });
    }
    
    if (url.pathname === '/api/health') {
        return Response.json({ status: 'ok' }, { status: 200 });
    }
    
    // Unknown API route
    return Response.json(
        { error: 'API endpoint not found' },
        { status: 404 }
    );
}

The key insight: when a request doesn't match your /api/ prefix, env.ASSETS.fetch(request) serves the static files. Workers Assets automatically picks the right file based on the URL path.

SPA Routing: Serving index.html for All Paths

If you're building a React, Vue, or Svelte SPA, you want every route (except /api/) to serve index.html so the client-side router handles navigation:

// src/index.js — SPA version

export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        // API routes
        if (url.pathname.startsWith('/api/')) {
            return handleApi(request);
        }
        
        // Static asset routes (CSS, JS, images)
        // These have file extensions, so serve them directly
        if (url.pathname.match(/\.(css|js|png|jpg|svg|ico|woff2)$/)) {
            return env.ASSETS.fetch(request);
        }
        
        // Everything else — serve index.html for client-side routing
        const assetRequest = new Request(
            new URL('/index.html', request.url),
            { headers: request.headers }
        );
        return env.ASSETS.fetch(assetRequest);
    }
};

Alternatively, set "not_found_handling": "single-page-application" in your wrangler.jsonc and Workers Assets will automatically serve index.html for any path that doesn't match an existing file or your Worker's routes.

Setting Cache-Control Headers

Workers Assets sets sensible defaults (cache static assets aggressively), but you can customize headers in your Worker:

export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        if (url.pathname.startsWith('/api/')) {
            return handleApi(request);
        }
        
        // Let Assets serve the file
        let response = await env.ASSETS.fetch(request);
        
        // Add custom cache headers
        if (url.pathname.match(/\.(css|js)$/)) {
            // Cache JS/CSS for 1 year (they should be versioned)
            response = new Response(response.body, response);
            response.headers.set('Cache-Control', 'public, max-age=31536000, immutable');
        } else if (url.pathname.match(/\.(png|jpg|svg|woff2)$/)) {
            // Cache images and fonts for 30 days
            response = new Response(response.body, response);
            response.headers.set('Cache-Control', 'public, max-age=2592000');
        } else if (url.pathname.match(/\.html$/)) {
            // Don't cache HTML — always get fresh version
            response = new Response(response.body, response);
            response.headers.set('Cache-Control', 'no-cache, no-store, must-revalidate');
        }
        
        return response;
    }
};

    <h1>404 — Page Not Found</h1>
    <p>The page you're looking for doesn't exist.</p>
    <a href="/>Go home</a>
</body>
</html>

# assets/500.html
<!DOCTYPE html>
<html lang="en">
<head>
    <title>Server Error</title>
</head>
<body>
    <h1>500 — Something went wrong</h1>
    <p>Please try again later.</p>
</body>
</html>

Workers Assets automatically serves these when your Worker throws an error or returns a 404/500 status.

Deploying

Everything deploys with one command:

# Deploy to your Cloudflare Workers subdomain
npx wrangler deploy

# Deploy to a custom domain (after setting up in wrangler.jsonc)
npx wrangler deploy --var NAME=production

# Preview locally with hot-reload
npx wrangler dev

That's it. Your HTML, CSS, JavaScript, images, and Worker code all deploy together. Your visitors get static files from the edge cache and API responses from your Worker — all from the same URL.

Workers Assets vs Cloudflare Pages

When should you use Workers Assets vs Cloudflare Pages?

Feature Workers Assets Cloudflare Pages
Static file serving ✅ Yes ✅ Yes (optimized)
Edge functions (API) ✅ Full Workers runtime ✅ Pages Functions (subset)
Build process Manual / npm scripts ✅ Built-in build steps
Git integration Manual ✅ Automatic deploys from git
Preview deployments Manual ✅ Per-PR previews
Complex Worker logic ✅ Full Workers API ⚠️ Limited to Pages Functions
Bundles Worker + assets = 1 deploy Pages + Functions = 1 deploy

Choose Workers Assets when you have significant Worker logic (databases, D1, KV, API complexity) that needs to run alongside your frontend.

Choose Cloudflare Pages when your app is mostly static content with light serverless functions, or when you want automatic Git-based CI/CD with preview deployments.

Common Gotchas

  • Asset size limit: Individual files are limited to 25 MB. Total assets are limited by your plan (100 GB on Workers Paid, lower on Free).
  • Build output: Workers Assets expects ready-to-serve files. Make sure your build step (Vite, Webpack, etc.) outputs to the assets/ directory before deploying.
  • Trailing slashes: /about won't match about.html by default. Use html_handling: "html" in your config to enable HTML file matching.
  • Subdirectories: If you have assets/docs/index.html, the Worker serves it at /docs/. The directory name becomes part of the URL path.
  • Environment variables: Set them in wrangler.jsonc or the Cloudflare dashboard. They're available in your Worker via env, but NOT in your static HTML/JS files.

Building a Full-Stack SPA with Vite

Here's how to integrate Workers Assets with a Vite build pipeline:

# wrangler.jsonc
{
  "name": "my-spa",
  "main": "src/index.js",
  "compatibility_date": "2026-07-09",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "not_found_handling": "single-page-application"
  },
  "build": {
    "command": "npm run build"
  }
}

# package.json scripts
{
  "scripts": {
    "dev": "vite",
    "build": "vite build --outDir dist",
    "deploy": "npm run build && npx wrangler deploy",
    "preview": "npx wrangler dev"
  }
}

# vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  base: '/',
  build: {
    outDir: 'dist',
    sourcemap: true
  }
});

Now npm run deploy builds your React app into dist/ and deploys both the build output and your Worker together.
