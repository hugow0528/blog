Python Logging: Professional Debugging Without print() — Complete Guide

July 6, 2026 10 min read

Every Python developer starts with print() to debug their code. It works — until you're debugging a server that processes 10,000 requests per minute and needs to log to a file, filter messages by severity, and format timestamps. That's when the logging module becomes essential.

This guide takes you from your first print() statement to production-grade logging with levels, formatting, file rotation, and structured output.

Why Not Just Use print()?

print() works for quick scripts, but it has serious limitations:

# print() limitations
print("Starting server...")        # No timestamp
print("Request received")          # No severity level
print("Error: connection refused") # No source file info
print("User logged in")            # Goes to stdout — no file output

# You can't:
# • Filter "debug" messages in production
# • Write logs to a file
# • Add timestamps automatically
# • Format messages consistently
# • Log from multiple modules without confusion

The logging module solves every one of these problems and it's built into Python — no install required.

Getting Started: Basic Setup

Replace print() with logging in three lines:

import logging

# One-time setup (put this in your main script or config file)
logging.basicConfig(
    level=logging.DEBUG,          # Show all messages from DEBUG upward
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s"
)

logger = logging.getLogger(__name__)

# Now use logger instead of print
logger.debug("This is a debug message")
logger.info("Server started on port 8080")
logger.warning("Config file not found, using defaults")
logger.error("Failed to connect to database")
logger.critical("System is out of memory!")

Output looks like this:

2026-07-06 14:23:01,123 - main - DEBUG - This is a debug message
2026-07-06 14:23:01,123 - main - INFO - Server started on port 8080
2026-07-06 14:23:01,124 - main - WARNING - Config file not found, using defaults
2026-07-06 14:23:01,124 - main - ERROR - Failed to connect to database
2026-07-06 14:23:01,124 - main - CRITICAL - System is out of memory!

Log Levels: Choosing the Right Severity

Python defines five standard levels, ordered from least to most severe:

Level Numeric When to Use Example
DEBUG 10 Detailed diagnostics, variable values logger.debug(f"Processing item {i}")
INFO 20 Normal operation milestones logger.info("User registered")
WARNING 30 Unexpected but handled situations logger.warning("Retrying connection")
ERROR 40 Operations failed but app continues logger.error("API returned 500")
CRITICAL 50 System cannot continue logger.critical("Disk full")

Setting the root level to INFO automatically filters out DEBUG messages:

logging.basicConfig(level=logging.INFO)  # DEBUG messages are suppressed

logger.debug("This won't appear")   # Filtered out
logger.info("This appears")         # Shown
logger.error("This also appears")   # Shown

Logging from Multiple Modules

Each module gets its own logger named after the module. This lets you filter by module:

# database.py
import logging
logger = logging.getLogger(__name__)  # Name: "database"

def connect():
    logger.info("Connecting to database...")
    # ... connection code ...

# api.py
import logging
logger = logging.getLogger(__name__)  # Name: "api"

def handle_request():

Now you can configure different log levels per module:

import logging

logging.basicConfig(level=logging.WARNING)          # Root: only WARNING+
logging.getLogger("database").setLevel(logging.INFO) # database: INFO+
logging.getLogger("api").setLevel(logging.DEBUG)     # api: DEBUG+

# Result:
# • database module shows INFO, WARNING, ERROR, CRITICAL
# • api module shows everything
# • all other modules show only WARNING and above

Log to a File

Use FileHandler to write logs to disk while keeping console output:

import logging

logger = logging.getLogger(__name__)
logger.setLevel(logging.DEBUG)

# Console handler — warnings and above
console = logging.StreamHandler()
console.setLevel(logging.WARNING)
console.setFormatter(logging.Formatter("%(levelname)s: %(message)s"))

# File handler — all messages
file_handler = logging.FileHandler("app.log")
file_handler.setLevel(logging.DEBUG)
file_handler.setFormatter(logging.Formatter(
    "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
))

logger.addHandler(console)
logger.addHandler(file_handler)

logger.debug("Only in file")           # File only
logger.info("Server started")          # File only
logger.warning("Config missing")       # Both file and console
logger.error("Connection failed")      # Both file and console

Rotating Log Files

Without rotation, your log file grows forever. RotatingFileHandler automatically splits logs by size:

from logging.handlers import RotatingFileHandler

logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)

# Rotate at 5MB, keep 5 backup files
handler = RotatingFileHandler(
    "app.log",
    maxBytes=5 * 1024 * 1024,  # 5 MB
    backupCount=5               # Keep app.log.1 through app.log.5
)
handler.setFormatter(logging.Formatter(
    "%(asctime)s - %(levelname)s - %(message)s"
))
logger.addHandler(handler)

Use TimedRotatingFileHandler to rotate by time instead:

from logging.handlers import TimedRotatingHandler

handler = TimedRotatingHandler(
    "app.log",
    when="midnight",      # Rotate every day at midnight
    backupCount=30        # Keep 30 days of logs
)
logger.addHandler(handler)

Structured Logging with JSON

For production systems, structured (JSON) logs are easier to search and analyze:

import logging
import json

class JsonFormatter(logging.Formatter):
    """Format log records as JSON for easy parsing"""
    def format(self, record):
        log_entry = {
            "timestamp": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }
        if record.exc_info and record.exc_info[0] is not None:
            log_entry["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

# Use it
logger = logging.getLogger(__name__)
handler = logging.StreamHandler()
handler.setFormatter(JsonFormatter())
logger.addHandler(handler)

logger.info("User logged in", extra={"user_id": 42})
# Output: {"timestamp": "...", "level": "INFO", "logger": "__main__", ...}

Capturing Exceptions with Tracebacks

Logging automatically captures tracebacks when you use exc_info=True or the exception() method:

import logging
logger = logging.getLogger(__name__)

def process_payment(amount):
    if amount <= 0:
        logger.error("Invalid payment amount: %s", amount)
        raise ValueError(f"Amount must be positive, got {amount}")

try:
    process_payment(-50)
except ValueError:
    # Captures the full traceback
    logger.exception("Payment processing failed")
    # OR equivalently: logger.error("Payment failed", exc_info=True)
2026-07-06 14:30:00 - ERROR - Payment processing failed
Traceback (most recent call last):
  File "app.py", line 10, in main
    process_payment(-50)
  File "app.py", line 5, in process_payment
    raise ValueError(...)
ValueError: Amount must be positive, got -50

Configuration from a Dictionary

For larger apps, configure logging from a dictionary (or YAML/JSON file):

import logging
import logging.config

LOGGING_CONFIG = {
    "version": 1,
    "disable_existing_loggers": False,
    "formatters": {
        "standard": {
            "format": "%(asctime)s [%(levelname)s] %(name)s: %(message)s"
        },
        "detailed": {
            "format": "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d: %(message)s"
        },
    },
    "handlers": {
        "console": {
            "class": "logging.StreamHandler",
            "level": "WARNING",
            "formatter": "standard",
        },
        "file": {
            "class": "logging.handlers.RotatingFileHandler",
            "filename": "app.log",
            "maxBytes": 10485760,  # 10 MB
            "backupCount": 5,
            "level": "DEBUG",
            "formatter": "detailed",
        },
    },
    "root": {
        "level": "DEBUG",
        "handlers": ["console", "file"],
    },
    "loggers": {
        "database": {
            "level": "INFO",
            "handlers": ["console", "file"],
            "propagate": False,
        },
        "api": {
            "level": "DEBUG",
            "handlers": ["console", "file"],
            "propagate": False,
        },
    },
}

# Apply configuration
logging.config.dictConfig(LOGGING_CONFIG)
logger = logging.getLogger(__name__)

Best Practices Summary

  • Never use print() in production code — it's impossible to filter or redirect
  • Use logger = logging.getLogger(__name__) in every module for proper namespace tracking
  • Set log levels per environment — DEBUG in development, WARNING in production
  • Always use lazy formatting — logger.debug("Value: %s", expensive_call()) avoids calling expensive functions when debug is disabled
  • Use logger.exception() in except blocks to capture full tracebacks
  • Rotate your log files — never let them grow unbounded
  • Consider JSON formatting for production systems where logs are parsed by tools like ELK, Datadog, or Grafana

The logging module is one of Python's most powerful standard library tools. Investing 30 minutes to set it up properly will save you hours of debugging time later. Start with basicConfig and getLogger(__name__), then add file handlers and rotation as your app grows.
