Python *args and **kwargs: Flexible Function Parameters

July 1, 2026 7 min read New

Have you ever looked at a Python function definition and wondered what those mysterious asterisks mean?

def my_function(*args, **kwargs):
    pass

You've probably seen *args and **kwargs in tutorials, library documentation, and even in frameworks like Flask or FastAPI. They look intimidating but are actually one of Python's most practical features. Once you understand them, you'll use them constantly.

The Problem: What If You Don't Know How Many Arguments?

Regular functions take a fixed number of parameters:

def greet(name):
    print(f"Hello, {name}!")

greet("Alice")   # ✅ Works
greet("Alice", "Bob")  # ❌ TypeError: too many arguments

What if you want to greet one person, five people, or fifty — without knowing the count ahead of time? That's where *args comes in.

Understanding *args (Positional Arguments)

The *args parameter collects extra positional arguments into a tuple. Think of it as a catch-all bucket for all the values that don't fit into your named parameters.

def greet_all(*args):
    for name in args:
        print(f"Hello, {name}!")

greet_all("Alice")
# Output: Hello, Alice!

greet_all("Alice", "Bob", "Charlie")
# Output:
# Hello, Alice!
# Hello, Bob!
# Hello, Charlie!

# args is just a tuple:
print(type(args))  # <class 'tuple'>

Key insight: *args is not special syntax inside the function. It's just a tuple. The asterisk packs the arguments into a tuple when the function is called.

Mixing *args with Regular Parameters

You can combine regular parameters with *args. Regular parameters come first, then *args catches the rest:

def build_profile(title, *skills):
    profile = {"title": title, "skills": list(skills)}
    return profile

result = build_profile("Developer", "Python", "Docker", "Git")
print(result)
# {'title': 'Developer', 'skills': ['Python', 'Docker', 'Git']}

Understanding **kwargs (Keyword Arguments)

While *args collects positional arguments into a tuple, **kwargs collects keyword arguments (name=value pairs) into a dictionary.

def create_user(**kwargs):
    print(kwargs)
    print(type(kwargs))

create_user(name="Alice", age=30, role="admin")
# Output:
# {'name': 'Alice', 'age': 30, 'role': 'admin'}
# <class 'dict'>

This is incredibly useful for configuration, options, or any scenario where you have many optional parameters.

Unpacking: The Reverse Operation

The asterisks work in reverse too. You can unpack a list or dictionary into a function call:

def add(a, b, c):
    return a + b + c

# Unpacking a list with *
numbers = [1, 2, 3]
print(add(*numbers))  # 6 (same as add(1, 2, 3))

# Unpacking a dict with **
def introduce(name, age, city):
    return f"{name} is {age} years old, lives in {city}."

info = {"name": "Hugo", "age": 28, "city": "Toronto"}
print(introduce(**info))
# Hugo is 28 years old, lives in Toronto.

Real-World Example: A Flexible Logger

Let's build something practical — a logging function that accepts any number of messages with optional formatting:

def log(level, *messages, **options):
    """Log messages with flexible formatting."""
    timestamp = options.get("timestamp", True)
    prefix = options.get("prefix", "APP")
    separator = options.get("separator", " | ")

    parts = []
    if timestamp:
        parts.append("[2026-07-01]")
    parts.append(f"[{prefix}]")
    parts.append(f"[{level}]")
    parts.append(separator.join(messages))

    print(" ".join(parts))

# Use it flexibly:
log("INFO", "Server started")
# [2026-07-01] [APP] [INFO] Server started

log("ERROR", "Connection failed", "Retrying...", prefix="DB")
# [2026-07-01] [DB] [ERROR] Connection failed | Retrying...

log("DEBUG", "Payload:", "{'key': 'value'}", timestamp=False)
# [APP] [DEBUG] Payload: | {'key': 'value'}

Real-World Example: API Wrapper

API wrappers often need to pass through arbitrary parameters. **kwargs shines here:

import requests

def fetch(url, method="GET", **params):
    """Fetch data from any API with flexible parameters."""
    headers = params.pop("headers", {"Accept": "application/json"})
    timeout = params.pop("timeout", 10)

    response = requests.request(
        method, url, params=params, headers=headers, timeout=timeout
    )
    return response.json()

# Pass any query parameters you need:
data = fetch(
    "https://jsonplaceholder.typicode.com/posts",
    userId=1,
    _limit=3
)

print(f"Found {len(data)} posts")

Real-World Example: Function Decorator with *args and **kwargs

Decorators almost always use *args and **kwargs because they don't know what the wrapped function accepts:

import time
import functools

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)  # Pass everything through
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f} seconds")
        return result
    return wrapper

# Works with ANY function signature:
@timer
def slow_operation(x, y, label="default"):
    time.sleep(0.1)
    return x + y

slow_operation(3, 4)           # slow_operation took 0.1001 seconds
slow_operation(10, 20, label="test")  # slow_operation took 0.1001 seconds

Parameter Order Rules

When you combine everything in one function, the order matters. Python enforces this strict order:

def example(positional, *args, keyword="default", **kwargs):
    pass
    #  ^^^^^^^^^^  ^^^^  ^^^^^^^  ^^^^^^
    #  Regular    Variable   Keyword  Variable
    #  params     positional params    keyword

Here's the working example:

def full_example(name, *skills, role="developer", **details):
    print(f"Name: {name}")
    print(f"Skills: {skills}")
    print(f"Role: {role}")
    print(f"Details: {details}")

full_example("Hugo", "Python", "Docker", role="Senior", location="Toronto", years=5)

# Output:
# Name: Hugo
# Skills: ('Python', 'Docker')
# Role: Senior
# Details: {'location': 'Toronto', 'years': 5}

Common Pitfalls to Avoid

1. Forgetting that *args is a tuple (immutable):

def collect(*args):
    args.append("new")  # ❌ AttributeError: 'tuple' has no attribute 'append'

def collect_fixed(*args):
    args = list(args)  # Convert to list first
    args.append("new")
    return args

2. Name conflicts with **kwargs:

def configure(host, port=8080, **kwargs):
    # If caller passes host or port in kwargs, you get a conflict:
    pass

configure("localhost", host="remote")  # ❌ TypeError: multiple values for 'host'

3. Confusing *args in definition vs. calling:

def func(*args):    # Packing: collects arguments into a tuple
    print(args)

values = [1, 2, 3]
func(*values)       # Unpacking: spreads the list into individual arguments
# Output: (1, 2, 3)

When NOT to Use *args / **kwargs

Despite their flexibility, don't overuse them:

  • Prefer explicit parameters when you know what arguments a function needs — it makes the API self-documenting
  • Avoid **kwargs as a catch-all for hiding too many parameters — it makes debugging harder
  • Use dataclasses or dictionaries instead of **kwargs when the config has many known fields
# ❌ Don't do this
def create_product(**kwargs):
    pass

# ✅ Do this instead
def create_product(name: str, price: float, category: str = "general"):
    pass

Summary

*args and **kwargs are Python's way of making functions accept a variable number of arguments:

  • *args — collects extra positional arguments into a tuple
  • **kwargs — collects extra keyword arguments into a dictionary
  • Use * and ** to unpack iterables and dictionaries when calling functions
  • Essential for decorators, wrappers, and any API that needs flexibility

The next time you see a function with asterisks, you'll know exactly what's happening under the hood.
