JavaScript Promises and Async/Await: A Complete Beginner's Guide

June 22, 2026 · 11 min read

If you've been learning JavaScript, you've probably hit a wall when trying to fetch data from an API, read a file, or do anything that takes time. JavaScript is single-threaded — it can only do one thing at a time. So how does it handle tasks that need to wait? The answer: asynchronous programming, powered by Promises and async/await.

This guide takes you from callbacks to modern async/await, with clear examples you can run right in your browser's developer console.

The Problem: Blocking Code

Imagine you're at a coffee shop. If the barista makes each order one at a time and waits for it to finish before accepting the next one, the line moves slowly. That's blocking (synchronous) code:

// Blocking — each step waits for the previous one
console.log("1. Accept order");
console.log("2. Grind beans");
console.log("3. Brew coffee");   // takes 30 seconds... line is stuck
console.log("4. Accept next order");  // can't happen until #3 finishes

In JavaScript, heavy computation or network requests would freeze your entire page. The solution is to let the browser handle time-consuming tasks in the background, then respond when they're done.

Step 1: Callbacks

The original way to handle async in JavaScript was callbacks — passing a function to another function to be called "later".

// Simulating a 2-second delay with setTimeout
console.log("1. Start coffee");

setTimeout(function() {
    console.log("3. Coffee is ready!");
}, 2000);

console.log("2. Do something else while waiting...");

// Output:
// 1. Start coffee
// 2. Do something else while waiting...
// (2 seconds pass)
// 3. Coffee is ready!

But callbacks have a major problem called "callback hell" when you chain multiple async operations:

// Callback hell — hard to read and debug
fetchUsers(function(users) {
    fetchPosts(users[0].id, function(posts) {
        fetchComments(posts[0].id, function(comments) {
            fetchAuthor(comments[0].authorId, function(author) {
                console.log(author.name);
                // Nesting gets deeper and deeper...
            });
        });
    });
});

Each level of nesting makes the code harder to read, harder to debug, and harder to handle errors. Enter Promises.

Step 2: Promises

A Promise represents a value that may not be available yet, but will be resolved (or rejected) at some point. Think of it like ordering food delivery: you get a receipt (the Promise) immediately, and the food arrives later (resolved) or is cancelled (rejected).

Creating a Promise

const coffeeReady = new Promise((resolve, reject) => {
    const brewing = true;

    if (brewing) {
        resolve("☕ Coffee is ready!");
    } else {
        reject("❌ Out of coffee beans!");
    }
});

coffeeReady
    .then(message => console.log(message))
    .catch(error => console.error(error));

A Promise has three states:

  • Pending — the operation is in progress
  • Fulfilled — the operation completed successfully
  • Rejected — the operation failed

Chaining Promises with .then()

The beauty of Promises is that you can chain them linearly, avoiding callback hell:

// Chaining — flat and readable
fetchUsers()
    .then(users => fetchPosts(users[0].id))
    .then(posts => fetchComments(posts[0].id))
    .then(comments => fetchAuthor(comments[0].authorId))
    .then(author => console.log(author.name))
    .catch(error => console.error("Something failed:", error));

Real Example: Fetching from an API

The built-in fetch() API returns a Promise. Here's how to use it:

// Fetch data from a public API
fetch('https://jsonplaceholder.typicode.com/users/1')
    .then(response => response.json())
    .then(data => {
        console.log("Name:", data.name);
        console.log("Email:", data.email);
        console.log("City:", data.address.city);
    })
    .catch(error => {
        console.error("Fetch failed:", error);
    });

// Output:
// Name: Leanne Graham
// Email: Sincere@april.biz
// City: Gwenborough

Notice the two .then() calls — the first converts the raw HTTP response to JSON, and the second processes the parsed data. Each .then() receives the return value of the previous one.

Parallel Execution with Promise.all()

What if you need to fetch multiple independent resources? You don't want to wait for one to finish before starting the next. Promise.all() runs them in parallel:

// Run these simultaneously, wait for all to finish
Promise.all([
    fetch('https://jsonplaceholder.typicode.com/users/1').then(r => r.json()),
    fetch('https://jsonplaceholder.typicode.com/posts/1').then(r => r.json()),
    fetch('https://jsonplaceholder.typicode.com/todos/1').then(r => r.json())
])
    .then(([user, post, todo]) => {
        console.log("User:", user.name);
        console.log("Post:", post.title);
        console.log("Todo:", todo.title);
    })
    .catch(error => console.error("One of the fetches failed:", error));

Related methods:

  • Promise.all() — waits for ALL to succeed (fails fast on first rejection)
  • Promise.allSettled() — waits for ALL, returns results regardless of success/failure
  • Promise.race() — returns the first one that settles (success or failure)
  • Promise.any() — returns the first successful one (ignores failures)

Step 3: Async/Await

Async/await is syntactic sugar built on top of Promises. It makes async code look and behave like synchronous code, dramatically improving readability.

Basic Syntax

// async function always returns a Promise
async function getCoffee() {
    return "☕ Coffee ready!";
}

// Using await to pause until the Promise resolves
async function orderCoffee() {
    console.log("Placing order...");
    const coffee = await getCoffee();
    console.log(coffee);
}

orderCoffee();

// Output:
// Placing order...
// ☕ Coffee ready!

Refactoring Our API Example

Let's rewrite the fetch example using async/await:

// Before: Promises with .then()
fetch('https://jsonplaceholder.typicode.com/users/1')
    .then(res => res.json())
    .then(data => console.log(data.name));

// After: async/await — reads top to bottom
async function getUser() {
    try {
        const response = await fetch('https://jsonplaceholder.typicode.com/users/1');
        const data = await response.json();
        console.log(data.name);
    } catch (error) {
        console.error("Failed:", error);
    }
}

getUser();

See the difference? No chaining, no callbacks. It reads like normal, sequential code. And the try/catch block handles errors the same way you'd handle any other exception.

Error Handling with Try/Catch

This is one of the biggest advantages of async/await:

async function fetchUserProfile(userId) {
    try {
        // Step 1: Fetch user
        const userRes = await fetch(
            `https://jsonplaceholder.typicode.com/users/${userId}`
        );
        
        if (!userRes.ok) {
            throw new Error(`HTTP ${userRes.status}: ${userRes.statusText}`);
        }
        
        const user = await userRes.json();

        // Step 2: Fetch their posts
        const postsRes = await fetch(
            `https://jsonplaceholder.typicode.com/posts?userId=${userId}`
        );
        
        const posts = await postsRes.json();

        // Step 3: Display results
        return {
            name: user.name,
            email: user.email,
            postCount: posts.length,
            posts: posts.map(p => p.title)
        };

    } catch (error) {
        console.error("Error fetching profile:", error.message);
        return null;
    }
}

// Usage
const profile = await fetchUserProfile(1);
console.log(profile);
// { name: "Leanne Graham", email: "Sincere@april.biz", postCount: 10, posts: [...] }

Mixing Sequential and Parallel

async/await doesn't mean everything must run one at a time. Use Promise.all() within async functions for parallel execution:

async function loadDashboard() {
    try {
        // These run IN PARALLEL (not one after another!)
        const [users, posts, comments] = await Promise.all([
            fetch('/api/users').then(r => r.json()),
            fetch('/api/posts').then(r => r.json()),
            fetch('/api/comments').then(r => r.json())
        ]);

        console.log(`Loaded ${users.length} users, ${posts.length} posts`);
        return { users, posts, comments };
    } catch (error) {
        console.error("Dashboard load failed:", error);
    }
}

Common Patterns and Gotchas

Async IIFE (Immediately Invoked Function Expression)

You can't use await at the top level of a regular script (outside an async function). Use an async IIFE:

(async () => {
    const data = await fetch('/api/data').then(r => r.json());
    console.log(data);
})();

Common Mistake: Forgetting await

// BUG: This logs a Promise, not the actual data
const data = fetch('/api/data');
console.log(data); // Promise {<pending>}

// FIX: Add await
const response = await fetch('/api/data');
const data = await response.json();
console.log(data); // { "message": "Hello" }

Common Mistake: Using await in a forEach

// BUG: forEach doesn't wait for async callbacks
users.forEach(async (user) => {
    const profile = await fetch(`/api/${user.id}`);
    // This fires BEFORE all fetches complete!
});

// FIX: Use for...of loop instead
for (const user of users) {
    const profile = await fetch(`/api/${user.id}`);
    // This waits for each fetch before continuing
}

// BETTER FIX: Use Promise.all for parallel execution
const profiles = await Promise.all(
    users.map(user => fetch(`/api/${user.id}`))
);

Real-World Project: Mini Dashboard

Let's build a simple dashboard that loads data from multiple endpoints:

// dashboard.js
async function renderDashboard() {
    const container = document.getElementById('dashboard');
    container.innerHTML = '
⏳ Loading...
';

    try {
        // Load all data in parallel
        const [users, posts, todos] = await Promise.all([
            fetch('https://jsonplaceholder.typicode.com/users').then(r => r.json()),
            fetch('https://jsonplaceholder.typicode.com/posts').then(r => r.json()),
            fetch('https://jsonplaceholder.typicode.com/todos').then(r => r.json())
        ]);

        // Render summary cards
        container.innerHTML = `
            

                
👥 Users

                
${users.length} total

                
    
                    ${users.slice(0, 5).map(u => `
  • ${u.name}
    • `).join('')}
                

            

            

                
📝 Posts

                
${posts.length} total

            

            

                
✅ Todos

                
${todos.filter(t => t.completed).length} completed

                
${todos.filter(t => !t.completed).length} pending

            

        `;
    } catch (error) {
        container.innerHTML = `
❌ Failed to load: ${error.message}
`;
    }
}

// Load dashboard when page is ready
document.addEventListener('DOMContentLoaded', renderDashboard);

Promise vs Async/Await — When to Use Which

Use Promises (.then/.catch) when:
  ✓ You're chaining a few operations
  ✓ You need Promise.all/allSettled/race/any
  ✓ Working with older codebases

Use async/await when:
  ✓ Operations are sequential (one depends on another)
  ✓ You need clean error handling with try/catch
  ✓ Writing new, modern code
  ✓ Debugging is important (stack traces are cleaner)

Summary

JavaScript async programming has evolved from callbacks to Promises to async/await, each step making code more readable and maintainable:

  • Callbacks — the original approach, leads to callback hell
  • Promises — chainable, linear, better error handling with .catch()
  • async/await — looks like synchronous code, uses try/catch for errors
  • Promise.all() — run independent tasks in parallel regardless of syntax
The key insight: await pauses the function, not the browser. Your page stays responsive while waiting for data.
