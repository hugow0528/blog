Docker for Beginners: Containers, Images & Docker Compose

June 21, 2026 · 9 min read

Docker lets you package an application and everything it needs into a lightweight container that runs the same way on your laptop, your server, or in the cloud. No more "it works on my machine" excuses. This guide takes you from zero to running multi-container apps.

What Problem Does Docker Solve?

Imagine you built a Python web app. It uses Python 3.11, specific libraries (Flask, PostgreSQL driver), and a particular configuration. You hand it to a friend, and it crashes because they have Python 3.9 installed.

Docker solves this by bundling your code, its dependencies, and the operating system environment into a container image. That image runs identically everywhere — macOS, Windows, Linux, or any cloud provider.

Key idea: A container is like a pre-configured server that takes up megabytes instead of gigabytes. Think of it as a portable, lightweight virtual machine.

Docker vs Virtual Machines

  • Virtual Machines (VMs) run a full operating system inside another OS. Heavy, slow to start, resource-hungry.
  • Docker Containers share the host OS kernel. Lightweight, starts in seconds, uses minimal resources.

Install Docker

macOS / Windows

Download Docker Desktop and follow the installer. It includes Docker Engine, CLI, and a GUI.

Linux (Ubuntu/Debian)

# Install Docker's official repository
sudo apt update
sudo apt install docker.io docker-compose

# Start the service
sudo systemctl start docker
sudo systemctl enable docker

# Verify installation
docker --version
docker compose version

Core Concepts: Images, Containers, and Registries

Three terms you'll hear constantly:

  • Image — A read-only template. Think of it as a software installation package.
  • Container — A running instance of an image. Like a program running from that package.
  • Registry — A storage place for images. Docker Hub (hub.docker.com) is the default, public registry.

Analogy: An image is like a class in Python. A container is like an object instantiated from that class. A registry is like PyPI — where you find and share images.

Your First Container

Let's run a simple web server. No installation needed — Docker pulls it automatically:

# Run an Nginx web server in a container
docker run -d --name my-web -p 8080:80 nginx:latest

What each flag does:

  • -d — Run in detached (background) mode
  • --name my-web — Give the container a friendly name
  • -p 8080:80 — Map host port 8080 to container port 80
  • nginx:latest — Use the latest Nginx image from Docker Hub

Open http://localhost:8080 in your browser. You'll see the Nginx welcome page.

Useful Container Commands

# List running containers
docker ps

# List ALL containers (including stopped ones)
docker ps -a

# Stop a container
docker stop my-web

# Remove a container
docker rm my-web

# View container logs
docker logs my-web

# Execute a command inside a running container
docker exec -it my-web bash

# Remove all stopped containers
docker container prune

Build Your Own Image with a Dockerfile

A Dockerfile is a text file that tells Docker how to build an image. Let's create one for a simple Python web app.

Step 1: Create the App

Make a project folder with these files:

# app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello from Docker! 🐳"

@app.route("/health")
def health():
    return "OK"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
# requirements.txt
flask==3.1.0

Step 2: Write the Dockerfile

# Dockerfile
# Use an official Python runtime as the base image
FROM python:3.12-slim

# Set the working directory inside the container
WORKDIR /app

# Copy dependency file first (better for caching)
COPY requirements.txt .

# Install dependencies
RUN pip install --no-cache-dir -r requirements.txt

# Copy the rest of the application
COPY . .

# Expose port 5000 to the outside world
EXPOSE 5000

# Run the application
CMD ["python", "app.py"]

Each instruction builds a layer in the final image. Docker caches layers — so if you only change app.py, Docker reuses the cached layer for installing dependencies, making rebuilds fast.

Step 3: Build and Run

# Build the image (the . means "current directory")
docker build -t my-python-app .

# Run it with port mapping
docker run -d --name my-app -p 5000:5000 my-python-app

# Check it's working
curl http://localhost:5000
# Output: Hello from Docker! 🐳

# Check the health endpoint
curl http://localhost:5000/health
# Output: OK

Step 4: Push to Docker Hub (Optional)

# Tag your image with your Docker Hub username
docker tag my-python-app yourusername/my-python-app:1.0

# Log in to Docker Hub
docker login

# Push the image
docker push yourusername/my-python-app:1.0

Now anyone can run your app with docker run yourusername/my-python-app:1.0.

Multi-Container Apps with Docker Compose

Real apps need databases, caches, message queues. Docker Compose lets you define and run multiple containers together.

Let's build a full-stack app: a Flask API + PostgreSQL database.

docker-compose.yml

# docker-compose.yml
version: "3.9"

services:
  web:
    build: .
    ports:
      - "5000:5000"
    environment:
      - DATABASE_URL=postgresql://appuser:secretpass@db:5432/appdb
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: postgres:16
    environment:
      - POSTGRES_USER=appuser
      - POSTGRES_PASSWORD=secretpass
      - POSTGRES_DB=appdb
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  pgdata:

Updated app.py to connect to the database:

# app.py
import os
from flask import Flask, jsonify

app = Flask(__name__)

DATABASE_URL = os.environ.get("DATABASE_URL")

@app.route("/")
def hello():
    return "Hello from Docker! 🐳"

@app.route("/config")
def config():
    return jsonify({
        "database": "connected" if DATABASE_URL else "not configured",
        "host": os.environ.get("HOST", "localhost")
    })

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Run the Stack

# Start all services
docker compose up -d

# Check running containers
docker compose ps
# Name          Command          State          Ports
# -----------------------------------------------------------------
# app-db-1      docker-entrypoint.sh ...  Up      5432/tcp
# app-web-1     python app.py             Up      0.0.0.0:5000->5000/tcp

# View logs from all services
docker compose logs -f

# Stop and remove everything
docker compose down

# Stop and also remove data volumes (WARNING: deletes database!)
docker compose down -v

Docker Networking Explained

Containers in the same Docker Compose file can talk to each other using service names as hostnames. That's why our app uses db as the hostname in DATABASE_URL — Docker's internal DNS resolves db to the PostgreSQL container's IP.

Key networking concepts:

  • Bridge network (default) — Containers can communicate but the host cannot see them unless you publish ports with -p
  • Port publishing (-p) — Maps a host port to a container port. -p 5000:5000 means "host:5000 → container:5000"
  • Docker Compose DNS — Each service name is a hostname other services can use

Common Dockerfile Best Practices

  • Use specific tags — Avoid latest in production. Use python:3.12-slim instead of python:latest
  • Use .dockerignore — Skip node_modules, __pycache__, .git to keep images small
  • Multi-stage builds — Build dependencies in one stage, copy only what you need in the next
  • Copy requirements before code — Leverage Docker's layer cache for faster rebuilds
  • Use non-root users — Add USER nonroot for better security
  • Keep images small — Use slim or alpine variants of base images

Example .dockerignore

# .dockerignore
__pycache__
*.pyc
.git
.env
*.md
tests/

Quick Reference Cheat Sheet

# Run a one-off command
docker run --rm python:3.12 python -c "print('Hello')""

# Interactive shell
docker run -it --rm python:3.12 bash

# Inspect image layers
docker history my-python-app

# Check disk usage
docker system df

# Clean up unused images, containers, and volumes
docker system prune -a

# Run in background, auto-restart, name it
docker run -d --name my-app --restart unless-stopped -p 5000:5000 my-python-app

# Build and push in one command
docker compose build && docker compose push
