Vibe Coding: Build a Full Web App from Scratch with AI

2026-06-27 12 min read

Watch an AI coding assistant take a project description and turn it into a working full-stack application. We'll walk through the entire process — from the first prompt to a deployed app — using Cursor, Claude Code, and GitHub Copilot.

The Project: A Task Manager with Priority Levels

We're building a task management app with these features:

  • Create, read, update, and delete tasks (CRUD)
  • Priority levels: low, medium, high, urgent
  • Search and filter by priority
  • Clean, modern UI
  • SQLite backend with Python FastAPI

No boilerplate. No scaffolding tools. Just us, the AI, and a clear prompt. Let's go.

Phase 1: The Setup Prompt

Open your AI coding tool (we'll use Cursor for this example) and start with a project-level prompt. This is the most important prompt you'll write — it sets the foundation for everything that follows.

# Paste this into Cursor's Chat (Cmd+L) or Claude Code

Build a task manager web application with:

BACKEND:
- Python FastAPI
- SQLite database with SQLAlchemy ORM
- RESTful API endpoints for CRUD operations
- Pydantic models for request/response validation
- SQLite database file: tasks.db

FRONTEND:
- Plain HTML/CSS/JavaScript (no framework)
- Fetch API for backend communication
- Clean, modern card-based design
- Responsive layout

DATA MODEL:
- Task: id (int), title (str), description (str), priority (enum: low, medium, high, urgent), status (enum: pending, in_progress, done), created_at (datetime), updated_at (datetime)

FOLDER STRUCTURE:
- app/
  - main.py        (FastAPI app)
  - models.py      (SQLAlchemy models)
  - schemas.py     (Pydantic schemas)
  - database.py    (DB setup)
  - api/
    - tasks.py     (API routes)
- static/
  - index.html
  - style.css
  - app.js
- requirements.txt

Generate all files with full, working code.

Key tip: The more specific your prompt, the better the output. Notice we specified folder structure, data models, technologies, and even the database filename. Vague prompts get vague results.

Phase 2: Reviewing the AI Output

The AI generates all the files. Here's what you should check before running anything:

1. Database Models Look Correct

# models.py — verify this matches your requirements
from sqlalchemy import Column, Integer, String, Enum, DateTime
from sqlalchemy.orm import declarative_base
from datetime import datetime
import enum

Base = declarative_base()

class Priority(str, enum.Enum):
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    URGENT = "urgent"

class Status(str, enum.Enum):
    PENDING = "pending"
    IN_PROGRESS = "in_progress"
    DONE = "done"

class Task(Base):
    __tablename__ = "tasks"

    id = Column(Integer, primary_key=True, index=True)
    title = Column(String(200), nullable=False)
    description = Column(String(1000), default="")
    priority = Column(Enum(Priority), default=Priority.MEDIUM)
    status = Column(Enum(Status), default=Status.PENDING)
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

2. API Routes Handle Edge Cases

Check that the generated API handles missing tasks, validation errors, and returns proper HTTP status codes:

# api/tasks.py — verify error handling
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy.orm import Session
from .. import models, schemas
from ..database import get_db
from typing import List

router = APIRouter()

@router.get("/", response_model=List[schemas.TaskRead])
def list_tasks(
    search: str = None,
    priority: str = None,
    status: str = None,
    db: Session = Depends(get_db)
):
    """List tasks with optional search and filters."""
    query = db.query(models.Task)

    if search:
        query = query.filter(
            models.Task.title.ilike(f"%{search}%") |
            models.Task.description.ilike(f"%{search}%")
        )
    if priority:
        query = query.filter(models.Task.priority == priority)
    if status:
        query = query.filter(models.Task.status == status)

    # Sort by priority (urgent first) then creation date
    return query.order_by(
        models.Task.priority.desc(),
        models.Task.created_at.desc()
    ).all()

@router.post("/", response_model=schemas.TaskRead, status_code=201)
def create_task(task: schemas.TaskCreate, db: Session = Depends(get_db)):
    """Create a new task."""
    db_task = models.Task(**task.model_dump())
    db.add(db_task)
    db.commit()
    db.refresh(db_task)
    return db_task

@router.get("/{task_id}", response_model=schemas.TaskRead)
def get_task(task_id: int, db: Session = Depends(get_db)):
    """Get a single task by ID."""
    task = db.query(models.Task).filter(models.Task.id == task_id).first()
    if not task:
        raise HTTPException(status_code=404, detail="Task not found")
    return task

@router.put("/{task_id}", response_model=schemas.TaskRead)
def update_task(task_id: int, task_update: schemas.TaskUpdate, db: Session = Depends(get_db)):
    """Update a task."""
    db_task = db.query(models.Task).filter(models.Task.id == task_id).first()
    if not db_task:
        raise HTTPException(status_code=404, detail="Task not found")

    for key, value in task_update.model_dump(exclude_unset=True).items():
        setattr(db_task, key, value)

    db.commit()
    db.refresh(db_task)
    return db_task

@router.delete("/{task_id}", status_code=204)
def delete_task(task_id: int, db: Session = Depends(get_db)):
    """Delete a task."""
    db_task = db.query(models.Task).filter(models.Task.id == task_id).first()
    if not db_task:
        raise HTTPException(status_code=404, detail="Task not found")
    db.delete(db_task)
    db.commit()

Phase 3: The Frontend Iteration

The AI's initial HTML is usually functional but rarely polished. This is where you iterate with targeted prompts instead of rewriting everything:

# Iteration 1 — Fix the layout
"The task cards are stacked vertically. Make them a responsive grid 
with 3 columns on desktop, 2 on tablet, 1 on mobile. Add a subtle 
shadow and rounded corners to each card."

# Iteration 2 — Improve colors
"Update the priority badges: urgent = red (#ef4444), high = orange 
(#f97316), medium = yellow (#eab308), low = green (#22c55e). 
Use pill-shaped badges with matching borders."

# Iteration 3 — Add animations
"Add a smooth fade-in animation when new tasks appear. When a task 
is deleted, slide it out to the right before removing it. Keep it 
subtle — nothing distracting."

Key insight: Small, specific iterations produce better results than one massive "make it pretty" prompt. The AI works like a junior developer — give it clear, actionable instructions.

Phase 4: Testing with the AI

Don't just run the app and hope. Ask the AI to write tests:

# Prompt for the AI:
"Write pytest tests for the task API endpoints. Test:
1. Creating a task returns 201 and the correct data
2. Listing tasks returns all tasks
3. Filtering by priority works correctly
4. Searching finds tasks by title
5. Updating a task changes the specified fields
6. Deleting a task removes it and returns 204
7. Getting a non-existent task returns 404
8. Updating a non-existent task returns 404

Use test client and an in-memory SQLite database."

The AI generates tests like this:

# tests/test_tasks.py
import pytest
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.main import app
from app.database import Base, get_db
from fastapi.testclient import TestClient

SQLALCHEMY_DATABASE_URL = "sqlite:///./test.db"
engine = create_engine(SQLALCHEMY_DATABASE_URL, connect_args={"check_same_thread": False})
TestingSessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

def override_get_db():
    try:
        db = TestingSessionLocal()
        yield db
    finally:
        db.close()

app.dependency_overrides[get_db] = override_get_db
client = TestClient(app)

@pytest.fixture(autouse=True)
def setup_database():
    """Create tables before each test, drop after."""
    Base.metadata.create_all(bind=engine)
    yield
    Base.metadata.drop_all(bind=engine)

def test_create_task():
    response = client.post("/tasks/", json={
        "title": "Test task",
        "description": "Testing task creation",
        "priority": "high"
    })
    assert response.status_code == 201
    data = response.json()
    assert data["title"] == "Test task"
    assert data["priority"] == "high"
    assert data["status"] == "pending"
    assert "id" in data

def test_list_tasks():
    # Create two tasks first
    client.post("/tasks/", json={"title": "Task 1", "priority": "high"})
    client.post("/tasks/", json={"title": "Task 2", "priority": "low"})

    response = client.get("/tasks/")
    assert response.status_code == 200
    tasks = response.json()
    assert len(tasks) == 2

def test_filter_by_priority():
    client.post("/tasks/", json={"title": "Urgent thing", "priority": "urgent"})
    client.post("/tasks/", json={"title": "Chill thing", "priority": "low"})

    response = client.get("/tasks/?priority=urgent")
    tasks = response.json()
    assert len(tasks) == 1
    assert tasks[0]["priority"] == "urgent"

def test_search_tasks():
    client.post("/tasks/", json={"title": "Buy groceries"})
    client.post("/tasks/", json={"title": "Write report"})

    response = client.get("/tasks/?search=groceries")
    tasks = response.json()
    assert len(tasks) == 1
    assert tasks[0]["title"] == "Buy groceries"

def test_get_task_not_found():
    response = client.get("/tasks/99999")
    assert response.status_code == 404

def test_update_task():
    create_resp = client.post("/tasks/", json={"title": "Original"})
    task_id = create_resp.json()["id"]

    update_resp = client.put(f"/tasks/{task_id}", json={"status": "done"})
    assert update_resp.status_code == 200
    assert update_resp.json()["status"] == "done"

def test_delete_task():
    create_resp = client.post("/tasks/", json={"title": "To delete"})
    task_id = create_resp.json()["id"]

    delete_resp = client.delete(f"/tasks/{task_id}")
    assert delete_resp.status_code == 204

    # Verify it's gone
    get_resp = client.get(f"/tasks/{task_id}")
    assert get_resp.status_code == 404

Phase 6: Bug Fixing with AI

Something almost always goes wrong. That's fine — the AI excels at debugging when you give it the error message:

# Copy the error and paste it into the AI:

"Getting this error when I try to create a task:

pydantic_core._pydantic_core.ValidationError: 1 validation error for TaskCreate
description
  Field required [type=missing, input={'title': 'My task'}, ...]

The description field should be optional with a default empty string. Fix the 
Pydantic schema."

The AI will spot the issue in schemas.py:

# Before (broken — description required):
class TaskCreate(BaseModel):
    title: str
    description: str  # ← this makes it required
    priority: Priority = Priority.MEDIUM

# After (fixed — description optional):
class TaskCreate(BaseModel):
    title: str
    description: str = ""  # ← default value makes it optional
    priority: Priority = Priority.MEDIUM

Choosing Your AI Tool

Each tool has different strengths for vibe coding:

Cursor (Editor-based)

Best for: Full project scaffolding, multi-file generation, iterative design.
Superpower: Cmd+K for inline edits, Cmd+L for chat, Composer for multi-file changes.
Cost: $20/month for Pro tier.

Claude Code (Terminal-based)

Best for: Code reviews, refactoring, understanding existing codebases.
Superpower: Can read, edit, and create files directly from terminal. Great for CI/CD integration.
Cost: Uses Claude API credits.

GitHub Copilot (IDE-integrated)

Best for: Line-by-line autocomplete, filling in boilerplate, quick fixes.
Superpower: Works in any IDE with Copilot extension. Tab to accept suggestions.
Cost: $10/month.

My Recommended Stack

  1. Cursor for the initial build and UI work
  2. Claude Code for code review and security checks
  3. GitHub Copilot for day-to-day autocomplete while writing tests

Vibe Coding Principles

After building dozens of projects with AI, here are the principles that actually matter:

1. You Are Still the Engineer

AI writes code. You decide what code to write, how to architect it, and whether it's correct. The AI is a force multiplier, not a replacement. Always review every line before accepting it into production.

2. Iterate in Small Steps

"Build me a full e-commerce site" gets you 20 files of mediocre code. "Build me a product listing page with this exact data model" gets you something you can actually use. Break projects into small, verifiable steps.

3. Context Is Everything

The AI only knows what you tell it. Include:

  • Technology choices and versions
  • Folder structure expectations
  • Code style preferences (naming, formatting)
  • Existing code that the new code needs to integrate with
  • Known constraints (performance, security, compliance)

4. Test What Matters

AI-generated code can look correct while being wrong. Write tests for:

  • API endpoints (especially error handling)
  • Database operations (especially edge cases)
  • User input validation
  • Authentication and authorization flows

5. Security Review Is Non-Negotiable

AI doesn't think about security unless you tell it to. Always ask:

  • "Review this code for security vulnerabilities"
  • "Are there any injection risks in these endpoints?"
  • "Is sensitive data properly handled?"

Deploying with AI

Even deployment gets the vibe coding treatment. Here's a prompt to generate a Docker setup:

"Create a Dockerfile and docker-compose.yml for this FastAPI app.
Requirements:
- Multi-stage build for smallest image
- Non-root user for security
- Health check endpoint at /health
- docker-compose includes the FastAPI service only (SQLite is file-based)
- Port mapping: 8000:8000
- Volume mount for the SQLite database
- Restart policy: unless-stopped"

What Vibe Coding Is NOT

It's important to be realistic:

  • Not magic: You still need to understand what the code does. If you can't explain it, don't merge it.
  • Not free: Time spent reviewing, testing, and debugging AI output is real time.
  • Not always right: AI confidently writes wrong code. Tests catch this — always write tests.
  • Not a learning replacement: Use AI to accelerate what you know. Learn the fundamentals first, then use AI to go further.

Final Thoughts

Vibe coding changes the development workflow from "writing every line" to "specifying, reviewing, and iterating." You become an architect and reviewer rather than a typist. The projects you can build in a day now take minutes of focused prompting and review.

Start small. Build a single API endpoint. Then a full CRUD app. Then a real project. With each step, your prompting skills improve and the AI becomes more valuable.
