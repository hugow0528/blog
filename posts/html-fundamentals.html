HTML Fundamentals: Structure Your Web Pages — Complete Beginner's Guide

July 9, 2026 · 12 min read

HTML (HyperText Markup Language) is the skeleton of every website. It tells the browser what content to show and how it's organized. Unlike CSS (styling) or JavaScript (behavior), HTML is purely about structure — headings, paragraphs, images, links, and the semantic meaning behind them.

If you want to build anything on the web, HTML is your first step. Let's go from zero to a complete webpage.

The Basic Document Structure

Every HTML page follows this template. Save it as index.html and open it in your browser:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My First Webpage</title>
</head>
<body>
    <h1>Hello, World!</h1>
    <p>This is my first webpage.</p>
</body>
</html>

Breaking it down:

  • <!DOCTYPE html> — tells the browser this is HTML5
  • <html> — root element, wrap everything inside it
  • <head> — metadata (title, character encoding, links to CSS/JS)
  • <body> — visible content the user sees
  • lang="en" — tells screen readers and search engines the language

The meta charset="UTF-8" line is essential — it lets you use any character (emojis, accented letters, CJK, etc.). The meta viewport line makes your page responsive on mobile devices. Always include both.

Headings: h1 Through h6

HTML provides six heading levels. Use them to create a logical hierarchy:

<h1>Main Page Title</h1>         <!-- Only ONE per page -->
<h2>Section Title</h2>
<h3>Subsection</h3>
<h4>Sub-subsection</h4>
<h5>Minor heading</h5>
<h6>Smallest heading</h6>

Golden rules for headings:

  • Use exactly one <h1> per page — it's the main topic
  • Never skip levels (don't go from h2 to h4)
  • Use headings for structure, not to make text bigger. That's CSS's job
  • Screen readers use headings to navigate — good heading structure = better accessibility

Paragraphs and Text Formatting

The <p> tag creates paragraphs. The browser automatically adds space between them:

<p>This is the first paragraph. It contains some text
that wraps to multiple lines in the source code,
but the browser treats it as one block.</p>

<p>This is the second paragraph.</p>

For inline text formatting, use semantic tags that convey meaning:

<p>This text is <strong>important</strong> and this is <em>emphasized</em>.</p>
<p>This is <abbr title="HyperText Markup Language">HTML</abbr> code.</p>
<p>Water is H<sub>2</sub>O and E = mc<sup>2</sup>.</p>
<p>Use <code>print("hello")</code> to output text in Python.</p>
<p>The price was <del>$100</del> <ins>$80</ins> on sale.</p>

Avoid <b> and <i> — they're purely visual. Use <strong> (important) and <em> (emphasized) instead, which convey meaning to assistive technologies.

Links: Connecting the Web

The <a> (anchor) tag creates hyperlinks — the backbone of the web:

<!-- Open in same tab (default) -->
<a href="https://blog.hugow.dev">Visit Hugo's Blog</a>

<!-- Open in new tab -->
<a href="https://docs.python.org" target="_blank" rel="noopener">Python Docs</a>

<!-- Internal page link -->
<a href="about.html">About Me</a>

<!-- Email link -->
<a href="mailto:hugo@example.com">Email Me</a>

<!-- Phone link (works on mobile) -->
<a href="tel:+1234567890">Call Me</a>

<!-- Jump to section on same page -->
<a href="#installation">Skip to Installation</a>

Always include rel="noopener" when using target="_blank" — it's a security and performance best practice that prevents the new page from accessing your page's window object.

Images

Images use the self-closing <img> tag. The alt attribute is required — it describes the image for screen readers and shows when the image fails to load:

<!-- Basic image -->
<img src="photo.jpg" alt="A sunset over Victoria Harbour in Hong Kong">

<!-- Image with specific dimensions (prevents layout shifts) -->
<img src="logo.png" alt="Company logo" width="200" height="80">

<!-- Image as a clickable link -->
<a href="gallery.html">
    <img src="preview.jpg" alt="Click to view the photo gallery">
</a>

Tip: Always specify width and height to prevent "layout shift" — when the page jumps around as images load. For responsive images that adapt to screen size, use the srcset attribute:

<img src="photo.jpg"
     srcset="photo-small.jpg 480w,
             photo-medium.jpg 768w,
             photo-large.jpg 1200w"
     sizes="(max-width: 480px) 100vw,
            (max-width: 768px) 50vw,
            33vw"
     alt="Descriptive text">

Semantic HTML: Meaningful Structure

HTML5 introduced semantic elements that describe what the content is, not just how it looks. These improve SEO, accessibility, and code readability:

<header>
    <nav>
        <a href="/">Home</a>
        <a href="/blog">Blog</a>
        <a href="/about">About</a>
    </nav>
</header>

<main>
    <article>
        <h1>Blog Post Title</h1>
        <time datetime="2026-07-09">July 9, 2026</time>
        <p>Blog post content goes here...</p>
    </article>

    <aside>
        <h2>Related Posts</h2>
        <ul>
            <li><a href="/post1">Related Post 1</a></li>
        </ul>
    </aside>
</main>

<footer>
    <p>&copy; 2026 Hugo's Dev Notes</p>
</footer>

Semantic element cheat sheet:

  • <header> — page or section header
  • <nav> — navigation links
  • <main> — primary content (only one per page)
  • <article> — self-contained content (blog post, news article)
  • <section> — thematic grouping of content
  • <aside> — sidebar or tangential content
  • <footer> — page or section footer
  • <figure> — image or diagram with optional caption
  • <time> — machine-readable date/time

Lists

Three types of lists for different situations:

<!-- Unordered list (bullet points) -->
<ul>
    <li>Python</li>
    <li>JavaScript</li>
    <li>Go</li>
</ul>

<!-- Ordered list (numbered) -->
<ol>
    <li>Install Python</li>
    <li>Create a virtual environment</li>
    <li>Install dependencies with pip</li>
    <li>Run your script</li>
</ol>

<!-- Description list (terms and definitions) -->
<dl>
    <dt>HTML</dt>
    <dd>HyperText Markup Language — structures web content</dd>
    <dt>CSS</dt>
    <dd>Cascading Style Sheets — styles web content</dd>
    <dt>JS</dt>
    <dd>JavaScript — adds interactivity to web pages</dd>
</dl>

Tables: Display Tabular Data

Tables are for tabular data only — never use them for page layout:

<table>
    <caption>Popular Programming Languages</caption>
    <thead>
        <tr>
            <th>Language</th>
            <th>Year</th>
            <th>Creator</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Python</td>
            <td>1991</td>
            <td>Guido van Rossum</td>
        </tr>
        <tr>
            <td>JavaScript</td>
            <td>1995</td>
            <td>Brendan Eich</td>
        </tr>
        <tr>
            <td>Go</td>
            <td>2009</td>
            <td>Google Team</td>
        </tr>
    </tbody>
</table>

Always use <thead> for headers and <tbody> for data rows. The <caption> provides a table description for screen readers.

Divs, Spans, and Inline vs Block

When semantic tags don't fit, use generic containers:

<!-- Block-level: takes full width, starts on new line -->
<div class="card">
    <h2>Card Title</h2>
    <p>Card content</p>
</div>

<!-- Inline: flows with text, only as wide as content -->
<p>The price is <span class="discount">$80</span> on sale.</p>

Key difference: <div> is for grouping block elements, <span> is for styling small pieces of text within a line. Use semantic elements whenever possible — <div> and <span> are fallbacks, not defaults.

Attributes: Adding Extra Information

Attributes provide additional info about elements. Key attributes you'll use daily:

<!-- class: for CSS styling (can reuse) -->
<p class="highlight">Important text</p>

<!-- id: unique identifier (use once per page) -->
<div id="main-content">...</div>

<!-- data-*: store custom data for JavaScript -->
<button data-user-id="42">Delete User</button>

<!-- style: inline CSS (avoid in production) -->
<p style="color: red;">Don't do this</p>

<!-- aria: accessibility attributes -->
<button aria-label="Close menu">✕</button>

Use class for styling (an element can have multiple: class="btn btn-primary"). Use id sparingly — for anchors and JavaScript hooks. Never use id for styling if class works.

Special Characters and HTML Entities

Some characters are reserved in HTML. Use entities to display them:

&lt;   → <     (less than)
&gt;   → >     (greater than)
&amp;  → &     (ampersand)
&quot; → "     (double quote)
&nbsp; →        (non-breaking space)
&copy; → ©     (copyright)
&mdash; → —    (em dash)
&euro;  → €     (euro sign)

In practice, UTF-8 encoding handles most special characters directly. You mainly need entities for <, >, &, and " when they appear in content.

Build a Complete Webpage: Step by Step

Let's put everything together into a real blog-style page:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Blog — Python Tips</title>
</head>
<body>
    <header>
        <h1>My Dev Blog</h1>
        <nav>
            <a href="index.html">Home</a> |
            <a href="about.html">About</a> |
            <a href="contact.html">Contact</a>
        </nav>
    </header>

    <main>
        <article>
            <h2>Python List Comprehensions</h2>
            <p>List comprehensions are a Python feature that lets you
            create lists in a single, readable line of code.</p>

            <figure>
                <img src="screenshot.png" alt="Code editor showing a list comprehension"
                     width="600" height="300">
                <figcaption>Figure 1: A list comprehension in action</figcaption>
            </figure>

            <p>Here's a simple example:</p>

            <pre><code>squares = [x ** 2 for x in range(10)]
print(squares)  # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]</code></pre>

            <p>They're <strong>faster</strong> and more <em>Pythonic</em> than
            equivalent for-loops.</p>
        </article>

        <aside>
            <h3>Related Posts</h3>
            <ul>
                <li><a href="python-loops.html">Python Loops</a></li>
                <li><a href="python-functions.html">Python Functions</a></li>
            </ul>
        </aside>
    </main>

    <footer>
        <p>&copy; 2026 My Blog. All rights reserved.</p>
    </footer>
</body>
</html>

Common Mistakes to Avoid

Forgetting to close tags

<!-- Wrong: missing closing tag -->
<p>This paragraph never ends...

<!-- Right -->
<p>This paragraph is complete.</p>

Using divs for everything

<!-- Wrong -->
<div class="nav">...</div>

<!-- Right -->
<nav>...</nav>

Nesting block elements inside inline elements

<!-- Wrong: p inside a span -->
<span><p>This breaks layout</p></span>

<!-- Right: span inside a p -->
<p>This is <span>correct</span> nesting.</p>

Next Steps

  • Explore JavaScript — make your pages interactive
  • Practice building real pages — a portfolio, blog, or documentation site
Practice tip: Open your browser's developer tools (F12), go to any website, and inspect the HTML. See how real sites use semantic elements, classes, and structure. It's the fastest way to learn from production code.
