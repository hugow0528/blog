JavaScript Event Handling & Event Delegation — Complete Beginner's Guide

July 7, 2026 11 min read

Every interactive website relies on events. A user clicks a button, types in a search box, scrolls down a page — JavaScript responds to these actions through event handling. But as your app grows, attaching individual event listeners to every element becomes slow, messy, and hard to maintain.

In this guide, you'll learn the complete picture: event types, event bubbling and capturing, the golden pattern called event delegation, and real-world implementations you can copy into your projects today.

Common Event Types

JavaScript supports dozens of event types. Here are the ones you'll use 95% of the time:

// Mouse events
element.addEventListener('click', handler);
element.addEventListener('dblclick', handler);
element.addEventListener('mouseenter', handler);
element.addEventListener('mouseleave', handler);
element.addEventListener('mousemove', handler);

// Keyboard events
element.addEventListener('keydown', handler);
element.addEventListener('keyup', handler);

// Form events
element.addEventListener('submit', handler);
element.addEventListener('change', handler);
element.addEventListener('input', handler);

// Window/document events
window.addEventListener('load', handler);
window.addEventListener('scroll', handler);
window.addEventListener('resize', handler);

// DOM events
element.addEventListener('focus', handler);
element.addEventListener('blur', handler);

The input event fires on every keystroke, while change fires when the element loses focus. Use input for live search and change for form validation.

Three Ways to Attach Event Listeners

Method 1: Inline HTML (Avoid)

<button onclick="handleClick()">Click</button>

Never use inline handlers in real projects. They mix HTML and JavaScript, pollute the global scope, and are impossible to remove or modify dynamically.

Method 2: Property Assignment (Limited)

const button = document.querySelector('.btn');
button.onclick = function(event) {
    console.log('Clicked!', event.target);
};

// Problem: only ONE handler can be assigned
button.onclick = function() {
    console.log('This replaces the previous handler');
};

You can only assign one handler per event type. The second assignment overwrites the first.

Method 3: addEventListener (Recommended)

const button = document.querySelector('.btn');

// Multiple handlers on the same event
button.addEventListener('click', function(e) {
    console.log('Handler 1');
});

button.addEventListener('click', function(e) {
    console.log('Handler 2');
});

// Both fire when clicked!

// Remove a handler (must use named function)
function myHandler(e) {
    console.log('Will be removed');
}
button.addEventListener('click', myHandler);
button.removeEventListener('click', myHandler);

addEventListener lets you attach multiple handlers, remove them later, and control event flow. This is the standard approach for all modern JavaScript.

The Event Object

Every event handler receives an Event object with useful properties:

document.querySelector('.btn').addEventListener('click', function(event) {
    console.log(event.type);       // 'click'
    console.log(event.target);     // The element that was clicked
    console.log(event.currentTarget); // The element the listener is on
    console.log(event.clientX);    // Mouse X position (window-relative)
    console.log(event.clientY);    // Mouse Y position (window-relative)
    console.log(event.offsetX);    // Mouse X position (element-relative)
    console.log(event.preventDefault()); // Stop default action
    console.log(event.stopPropagation()); // Stop bubbling
});

// Keyboard event properties
document.addEventListener('keydown', function(event) {
    console.log(event.key);       // 'a', 'Enter', 'Escape', etc.
    console.log(event.code);      // 'KeyA', 'Enter', 'Escape'
    console.log(event.ctrlKey);   // true/false
    console.log(event.shiftKey);  // true/false
    console.log(event.altKey);    // true/false
});

Event Bubbling and Capturing

When you click a nested element, the event travels through the DOM tree. There are two phases:

// HTML: <div id="parent"><button id="child">Click</button></div>

const parent = document.getElementById('parent');
const child = document.getElementById('child');

// By default, event listeners use "bubbling" (capture = false)
parent.addEventListener('click', () => {
    console.log('Parent handler fires SECOND (bubbling up)');
});

child.addEventListener('click', () => {
    console.log('Child handler fires FIRST');
});

// Click the button → "Child" prints, then "Parent"

// Use capture phase to intercept BEFORE the target
parent.addEventListener('click', () => {
    console.log('This fires FIRST during capture phase');
}, true); // true = capture phase

Event flow summary:

  1. Capture phase: Event travels from <html> down to the target (rarely used)
  2. Target phase: Event reaches the actual clicked element
  3. Bubbling phase: Event travels back up to <html> (default behavior)

Event Delegation: The Game Changer

This is the most important pattern in this guide. Instead of attaching a listener to every single element, attach ONE listener to a parent and use event.target to figure out which child was clicked.

Without Event Delegation (Bad)

// Imagine 1,000 todo items
const todos = document.querySelectorAll('.todo-item');

// 1,000 event listeners — memory hog!
todos.forEach(todo => {
    todo.addEventListener('click', function() {
        this.classList.toggle('completed');
    });
});

// Adding a new todo? You forgot to add the listener!
const newTodo = document.createElement('div');
newTodo.className = 'todo-item';
newTodo.textContent = 'New task';
document.querySelector('.todo-list').appendChild(newTodo);
// Click handler doesn't work on this new item!

With Event Delegation (Good)

// ONE listener on the parent
const todoList = document.querySelector('.todo-list');

todoList.addEventListener('click', function(event) {
    // Find the closest .todo-item ancestor
    const todo = event.target.closest('.todo-item');

    if (todo) {
        todo.classList.toggle('completed');
    }
});

// New todos automatically work! No extra code needed.
const newTodo = document.createElement('div');
newTodo.className = 'todo-item';
newTodo.textContent = 'New task';
todoList.appendChild(newTodo);

Real-World Examples

Example 1: Dynamic Navigation with Active State

const nav = document.querySelector('.main-nav');

nav.addEventListener('click', function(event) {
    const link = event.target.closest('a.nav-link');

    if (link) {
        event.preventDefault();

        // Remove active class from all links
        nav.querySelectorAll('.nav-link').forEach(l => {
            l.classList.remove('active');
        });

        // Add active class to clicked link
        link.classList.add('active');

        // Navigate (or in a SPA, render the page)
        console.log('Navigating to:', link.getAttribute('href'));
    }
});

Example 2: Delete Button in a Dynamic List

const container = document.getElementById('app-container');

container.addEventListener('click', function(event) {
    // Check if a delete button was clicked
    if (event.target.classList.contains('delete-btn')) {
        const item = event.target.closest('.list-item');
        if (item && confirm('Delete this item?')) {
            item.remove();
        }
    }

    // Check if an edit button was clicked
    if (event.target.classList.contains('edit-btn')) {
        const item = event.target.closest('.list-item');
        if (item) {
            openEditor(item);
        }
    }

    // Check if an increment button was clicked
    if (event.target.classList.contains('increment')) {
        const counter = event.target.closest('.counter-item');
        if (counter) {
            const display = counter.querySelector('.count');
            display.textContent = parseInt(display.textContent) + 1;
        }
    }
});

One handler, multiple actions. Adding new button types means adding one more if block — no need to touch event registration code.

Example 3: Live Search with Debouncing

// Debounce: wait until user stops typing for 300ms
function debounce(func, delay) {
    let timeout;
    return function(...args) {
        clearTimeout(timeout);
        timeout = setTimeout(() => func.apply(this, args), delay);
    };
}

const searchInput = document.getElementById('search');

const performSearch = function(event) {
    const query = event.target.value.trim();
    if (query.length < 2) return;

    fetch(`/api/search?q=${encodeURIComponent(query)}`)
        .then(res => res.json())
        .then(data => {
            renderResults(data);
        })
        .catch(err => console.error('Search failed:', err));
};

searchInput.addEventListener('input', debounce(performSearch, 300));

Without debouncing, every keystroke triggers a network request. With debouncing, the request fires only after the user pauses for 300 milliseconds.

Example 4: Keyboard Shortcuts

document.addEventListener('keydown', function(event) {
    // Ctrl/Cmd + K for search
    if ((event.ctrlKey || event.metaKey) && event.key === 'k') {
        event.preventDefault();
        document.getElementById('search-modal').showModal();
    }

    // Escape to close modals
    if (event.key === 'Escape') {
        const modal = document.querySelector('dialog[open]');
        if (modal) modal.close();
    }

    // Enter to submit forms
    if (event.key === 'Enter' && !event.shiftKey) {
        const active = document.activeElement;
        if (active && active.form) {
            active.form.requestSubmit();
        }
    }
});

Best Practices Summary

  1. Always use addEventListener — never inline handlers or property assignment
  2. Use event delegation for dynamic lists — one listener beats hundreds
  3. Use event.target.closest() to find the right element
  4. Debounce scroll and input events — they fire very frequently
  5. Clean up listeners when removing elements — use removeEventListener or rely on garbage collection for detached DOM nodes
  6. Use event.preventDefault() sparingly — only when you truly need to override default behavior
  7. Name your handler functions — you need named references to remove listeners later

Quick Reference

// The pattern to remember
parentElement.addEventListener('click', function(event) {
    const target = event.target.closest('.selector');
    if (target) {
        // Do something with target
    }
});

// Keyboard shortcut pattern
document.addEventListener('keydown', function(event) {
    if (event.key === 'Escape') {
        // Handle escape
    }
});

// Debounced input pattern
input.addEventListener('input', debounce(handler, 300));

// Stop default form submission
form.addEventListener('submit', function(event) {
    event.preventDefault();
    // Handle with fetch/AJAX instead
});

Master these patterns and you'll write cleaner, faster, more maintainable JavaScript. Event delegation alone will save you from dozens of future headaches when your UI becomes dynamic.
