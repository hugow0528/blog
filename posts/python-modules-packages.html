Python Modules & Packages: Organize Your Code Like a Pro

2026-06-25 9 min read New

If your Python script has grown past 100 lines, it's probably time to organize it. Modules and packages are how Python developers split code into manageable, reusable pieces — just like chapters in a book.

Whether you're importing math for calculations or building your own library to share with the world, understanding modules and packages is essential. This guide walks you through everything from basic imports to publishing a package on PyPI.

What Is a Module?

A module is simply a Python file with a .py extension. Every Python file you create is a module. When you write import math, Python looks for a file called math.py and loads its contents.

Here's a simple example. Create a file called utils.py:

# utils.py — a custom module
def greet(name):
    return f"Hello, {name}! Welcome aboard."

def calculate_age(birth_year):
    current_year = 2026
    return current_year - birth_year

PI = 3.14159

Now import and use it in another file:

# main.py
import utils

print(utils.greet("Hugo"))           # Hello, Hugo! Welcome aboard.
print(utils.calculate_age(1995))     # 31
print(utils.PI)                      # 3.14159

The utils module gives us access to all functions and variables defined inside it. We use the dot notation module_name.function_name to call them.

Import Styles

Python supports several import styles. Choose the right one for readability:

# Full module import (recommended)
import utils
result = utils.greet("Hugo")

# Import specific items (cleaner when you use many things)
from utils import greet, calculate_age
result = greet("Hugo")          # No dot notation needed
age = calculate_age(1995)

# Rename with alias (useful for long names)
import utils as u
result = u.greet("Hugo")

# Import everything (avoid in production)
from utils import *
result = greet("Hugo")

Best practice: Use full module imports (import utils) for most cases. It makes it clear where each function comes from, especially when your project grows.

Built-in Modules You Should Know

Python ships with dozens of modules you can use without installing anything:

import os           # File system, environment variables
import sys           # Python interpreter info and arguments
import json          # Parse and create JSON data
import datetime      # Work with dates and times
import math          # Math functions (sqrt, pi, factorial)
import random        # Random number generation
import pathlib       # Modern file path handling
import collections   # Specialized container datatypes

Here's a practical example using multiple built-in modules:

import json
import datetime
import os

# Create a JSON config file
config = {
    "app_name": "MyApp",
    "version": "1.0.0",
    "created": datetime.datetime.now().isoformat(),
    "debug": False
}

# Write to file
with open("config.json", "w") as f:
    json.dump(config, f, indent=2)

# Read it back
with open("config.json", "r") as f:
    loaded = json.load(f)

print(loaded["app_name"])     # MyApp
print(os.path.exists("config.json"))  # True

What Is a Package?

A package is a directory of modules grouped together. It lets you organize related modules under a single namespace. Think of it as a folder for your modules.

Here's a project structure for a package called myapp:

myapp/
├── __init__.py      # Makes this directory a package
├── models.py        # Database models
├── views.py         # Web views / UI functions
├── utils.py         # Utility functions
└── tests/
    ├── __init__.py
    └── test_models.py

The __init__.py file is crucial — it tells Python "this directory is a package." In Python 3.3+, it can be empty, but it's commonly used to expose specific items:

# myapp/__init__.py
"""My Application Package"""

__version__ = "1.0.0"
__author__ = "Hugo Wong"

# Expose commonly used items at the package level
from .models import User, Product
from .utils import send_email, format_date

Now you can import like this:

# Import the whole package
import myapp
print(myapp.__version__)       # 1.0.0

# Import specific items from a submodule
from myapp.utils import send_email
send_email("user@example.com", "Hello!")

# Import exposed items directly
from myapp import User, send_email

The __init__.py File Explained

The __init__.py file serves three purposes:

  1. Package marker: Tells Python the directory is a package (less critical in Python 3.3+)
  2. Initialization code: Runs when the package is first imported — good for setup logic
  3. Public API: Controls what gets imported with from package import *

You can use __all__ to explicitly define the public API:

# myapp/__init__.py
__all__ = ["User", "Product", "send_email"]

from .models import User, Product, _internal_func
from .utils import send_email

# Only User, Product, and send_email are exported with "from myapp import *"

Installing Third-Party Packages with pip

The Python Package Index (PyPI) hosts over 500,000 packages. Install them with pip:

# Install a single package
pip install requests

# Install a specific version
pip install flask==3.0.0

# Install from a requirements file
pip install -r requirements.txt

# Install in development mode (editable)
pip install -e .

# Uninstall a package
pip uninstall requests

Always use a virtual environment for your projects:

# Create a virtual environment
python -m venv venv

# Activate it (Linux/macOS)
source venv/bin/activate

# Activate it (Windows)
venv\Scripts\activate

# Install packages into the virtual environment
pip install requests beautifulsoup4

# Save requirements
pip freeze > requirements.txt

Creating a Package You Can Install

Want to turn your code into an installable package? Create a pyproject.toml:

# pyproject.toml
[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "my-toolkit"
version = "0.1.0"
description = "A useful toolkit for everyday tasks"
readme = "README.md"
requires-python = ">=3.8"
authors = [
    {name = "Hugo Wong", email = "hugo@example.com"}
]
license = {text = "MIT"}
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
]

[project.scripts]
my-toolkit = "my_toolkit.cli:main"

Build and install it locally:

# Build the package
pip install build
python -m build

# Install it in development mode
pip install -e .

Best Practices Summary

  • 📁 Keep related functions in the same module
  • 📦 Group related modules into packages with __init__.py
  • 🔒 Use __all__ to define your public API
  • 🐍 Always use virtual environments for projects
  • 📋 Maintain a requirements.txt or pyproject.toml
  • 📝 Write docstrings for every module, function, and class
  • 🧪 Include a tests/ directory in your package

Quick Exercise

Create your own package called calculator with basic math operations:

calculator/
├── __init__.py
├── basic.py       # add, subtract, multiply, divide
├── advanced.py    # power, sqrt, factorial
└── __main__.py    # CLI entry point
# calculator/basic.py
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

def multiply(a, b):
    return a * b

def divide(a, b):
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a / b
# calculator/__init__.py
from .basic import add, subtract, multiply, divide

Now you can use it anywhere:

from calculator import add, divide

print(add(10, 5))        # 15
print(divide(10, 3))     # 3.333...

Modules and packages are the backbone of Python development. Master these, and you'll write cleaner, more maintainable code that scales from scripts to full applications.
