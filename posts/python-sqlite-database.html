Python SQLite Database: Store and Query Data Like a Pro — Complete Beginner's Guide

July 20, 2026 10 min read

SQLite is the most deployed database engine in the world, and Python includes built-in support through the sqlite3 module. No installation needed, no server to configure — just import and go. This guide covers everything from creating your first table to building a complete data layer with parameterized queries, transactions, indexes, and a reusable database class.

Why SQLite for Python Projects?

SQLite is a file-based database — your entire database lives in a single .db file. This makes it perfect for local applications, prototypes, mobile apps, embedded systems, and small-to-medium projects where a full database server (PostgreSQL, MySQL) would be overkill. It supports almost all standard SQL features: transactions, indexes, joins, views, and triggers.

Connecting to a Database

Import the built-in sqlite3 module and create a connection. If the file doesn't exist, SQLite creates it automatically:

import sqlite3

# Connect to a database (creates file if it doesn't exist)
conn = sqlite3.connect("app.db")

# Use an in-memory database for testing (faster, ephemeral)
test_conn = sqlite3.connect(":memory:")

# Create a cursor to execute SQL
cursor = conn.cursor()

The cursor object is your interface to the database. You use it to execute SQL statements and fetch results. The connection manages transactions, so always remember to commit() your changes and close() the connection when done.

Creating Tables

Let's create a table for storing user accounts. SQLite supports INTEGER, TEXT, REAL, BLOB, and NUMERIC types, plus the special INTEGER PRIMARY KEY for auto-incrementing IDs:

cursor.execute("""
    CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        username TEXT NOT NULL UNIQUE,
        email TEXT NOT NULL UNIQUE,
        age INTEGER,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    )
""")
conn.commit()

The IF NOT EXISTS clause prevents errors if the table already exists. The UNIQUE constraint ensures no duplicate usernames or emails. The DEFAULT CURRENT_TIMESTAMP automatically records when each row was inserted.

INSERT — Adding Data with Parameterized Queries

Never concatenate user input into SQL strings — that's how SQL injection attacks happen. Instead, use ? placeholders (parameterized queries), which safely escape all values:

# ✅ Safe — parameterized query
cursor.execute(
    "INSERT INTO users (username, email, age) VALUES (?, ?, ?)",
    ("alice", "alice@example.com", 28)
)

# Insert multiple rows at once
new_users = [
    ("bob", "bob@example.com", 34),
    ("carol", "carol@example.com", 22),
    ("dave", "dave@example.com", 41),
]
cursor.executemany(
    "INSERT INTO users (username, email, age) VALUES (?, ?, ?)",
    new_users
)
conn.commit()

# Get the ID of the last inserted row
last_id = cursor.lastrowid
print(f"Inserted user ID: {last_id}")

The executemany() method is much faster than calling execute() in a loop because it batches the inserts into a single transaction.

SELECT — Reading Data

Use execute() to run a SELECT query, then fetch results with fetchone(), fetchall(), or by iterating the cursor directly:

# Fetch all rows
cursor.execute("SELECT * FROM users")
all_users = cursor.fetchall()
for user in all_users:
    print(user)  # (1, 'alice', 'alice@example.com', 28, '2026-07-20 10:00:00')

# Fetch one row
cursor.execute("SELECT username, email FROM users WHERE age > 30")
senior_user = cursor.fetchone()
print(senior_user)  # ('bob', 'bob@example.com')

# Iterate results directly (memory efficient)
cursor.execute("SELECT username FROM users ORDER BY username")
for row in cursor:
    print(row[0])

# Filter with parameters
cursor.execute("SELECT * FROM users WHERE age > ?", (25,))
adults = cursor.fetchall()

Row Factory: Access Columns by Name

By default, rows are tuples indexed by position. Use the Row factory to access columns by name instead:

conn.row_factory = sqlite3.Row

cursor.execute("SELECT * FROM users WHERE id = 1")
user = cursor.fetchone()

# Access by column name (like a dictionary)
print(user["username"])   # alice
print(user["email"])      # alice@example.com
print(user.keys())        # ['id', 'username', 'email', 'age', 'created_at']

UPDATE and DELETE — Modifying Data

UPDATE and DELETE also use parameterized queries to prevent injection:

# Update a row
cursor.execute(
    "UPDATE users SET email = ? WHERE username = ?",
    ("alice.new@example.com", "alice")
)
print(f"Rows changed: {cursor.rowcount}")  # Rows changed: 1

# Delete a row
cursor.execute("DELETE FROM users WHERE username = ?", ("dave",))
print(f"Rows deleted: {cursor.rowcount}")  # Rows deleted: 1

conn.commit()

The rowcount attribute tells you how many rows were affected. Always include a WHERE clause on UPDATE and DELETE — otherwise you'll modify or delete every row in the table.

Transactions and Rollbacks

SQLite wraps operations in transactions. Call conn.commit() to save changes, or conn.rollback() to discard them:

try:
    # Start a transaction (automatic)
    cursor.execute("INSERT INTO users (username, email) VALUES (?, ?)",
                   ("eve", "eve@example.com"))
    cursor.execute("INSERT INTO users (username, email) VALUES (?, ?)",
                   ("frank", "frank@example.com"))
    conn.commit()  # Save both inserts
except sqlite3.IntegrityError:
    conn.rollback()  # Undo everything if something failed
    print("Insert failed — rolled back")

You can also use the connection as a context manager for automatic transaction handling:

with conn:  # Auto-commits on success, auto-rolls-back on exception
    cursor.execute("INSERT INTO users (username, email) VALUES (?, ?)",
                   ("grace", "grace@example.com"))

Indexes for Performance

As your table grows, queries slow down. Indexes speed up lookups on specific columns. Create them when you frequently filter or sort by a column:

# Speed up queries filtering by age
cursor.execute("CREATE INDEX idx_users_age ON users(age)")

# Speed up lookups by email (also helps UNIQUE enforcement)
cursor.execute("CREATE INDEX idx_users_email ON users(email)")

# Composite index for multi-column queries
cursor.execute("CREATE INDEX idx_users_age_email ON users(age, email)")

conn.commit()

Don't over-index — every index slows down INSERT, UPDATE, and DELETE operations. Only index columns you query frequently.

JOINs — Combining Multiple Tables

Relational databases shine when you split data across related tables. Here's a user-posts example:

# Create a related table
cursor.execute("""
    CREATE TABLE IF NOT EXISTS posts (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        user_id INTEGER NOT NULL,
        title TEXT NOT NULL,
        body TEXT,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        FOREIGN KEY (user_id) REFERENCES users(id)
    )
""")

# Insert posts
cursor.executemany(
    "INSERT INTO posts (user_id, title, body) VALUES (?, ?, ?)",
    [
        (1, "Hello World", "My first post"),
        (1, "SQLite Tips", "Using Python with databases"),
        (2, "Bob's Post", "Learning databases"),
    ]
)

# JOIN users with their posts
cursor.execute("""
    SELECT u.username, p.title, p.created_at
    FROM posts p
    JOIN users u ON p.user_id = u.id
    ORDER BY p.created_at DESC
""")

for row in cursor.fetchall():
    print(f"{row[0]}: {row[1]}")
# alice: SQLite Tips
# alice: Hello World
# bob: Bob's Post

Building a Reusable Database Class

Wrap everything in a class for clean, reusable code:

import sqlite3
from pathlib import Path

class Database:
    def __init__(self, db_path: str = "app.db"):
        self.path = Path(db_path)
        self.conn = sqlite3.connect(self.path)
        self.conn.row_factory = sqlite3.Row
        self.conn.execute("PRAGMA foreign_keys = ON")

    def init_tables(self):
        with self.conn:
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS users (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    username TEXT NOT NULL UNIQUE,
                    email TEXT NOT NULL UNIQUE,
                    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
                )
            """)

    def add_user(self, username: str, email: str) -> int:
        with self.conn:
            cursor = self.conn.execute(
                "INSERT INTO users (username, email) VALUES (?, ?)",
                (username, email)
            )
            return cursor.lastrowid

    def get_user(self, user_id: int) -> dict | None:
        cursor = self.conn.execute(
            "SELECT * FROM users WHERE id = ?", (user_id,)
        )
        row = cursor.fetchone()
        return dict(row) if row else None

    def get_all_users(self) -> list[dict]:
        cursor = self.conn.execute("SELECT * FROM users ORDER BY created_at DESC")
        return [dict(row) for row in cursor.fetchall()]

    def close(self):
        self.conn.close()

# Usage
db = Database("myapp.db")
db.init_tables()
user_id = db.add_user("alice", "alice@example.com")
print(db.get_user(user_id))
# {'id': 1, 'username': 'alice', 'email': 'alice@example.com', ...}
print(db.get_all_users())
db.close()

Common Pitfalls to Avoid

SQL Injection: Always use ? placeholders — never f-strings or .format() for SQL values. Forgetting commit(): Without it, your INSERT/UPDATE/DELETE changes are lost when the connection closes. Not closing connections: Always conn.close() or use a context manager. Blocking on long queries: SQLite doesn't handle concurrent writes well — use a single connection per thread and PRAGMA journal_mode=WAL for better concurrency.

Summary

SQLite gives you a full relational database with zero setup. The sqlite3 module in Python's standard library lets you create tables, run parameterized queries, manage transactions, and build clean data layers — all without installing anything. For local apps, prototypes, and small projects, it's the perfect starting point before graduating to PostgreSQL or MySQL.
