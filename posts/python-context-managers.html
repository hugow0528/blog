Python Context Managers: The with Statement Explained — Complete Beginner's Guide

July 13, 2026 10 min read

You've probably seen the with statement in Python and thought it was just a shortcut for opening files. It's so much more. Context managers are one of Python's most elegant features — they handle setup and cleanup automatically, even when errors occur. Let's master them from the ground up.

Why Context Managers Matter

Imagine you're opening a file, processing data, and need to close it afterward. Without context managers, you'd write something like this:

# ❌ The old way — error-prone
f = open("data.txt", "r")
try:
    data = f.read()
    process(data)
finally:
    f.close()  # What if process() raises an exception?

With context managers, the cleanup happens automatically:

# ✅ The Pythonic way — automatic cleanup
with open("data.txt", "r") as f:
    data = f.read()
    process(data)
# File is closed here, even if process() crashes

The with statement guarantees that cleanup code runs no matter what — exceptions, returns, or normal completion. This pattern applies to any resource: database connections, network sockets, locks, timers, temporary directories, and more.

How Context Managers Work

A context manager is any object that implements two special methods:

  • __enter__() — runs when you enter the with block. Its return value is assigned to the as variable.
  • __exit__() — runs when you leave the with block. Receives exception info if one occurred.

Example 1: A Timer Context Manager

Let's build something practical — a timer that measures how long a block of code takes:

import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self  # 'as t' gets this

    def __exit__(self, exc_type, exc_val, exc_tb):
        elapsed = time.perf_counter() - self.start
        print(f"⏱ Elapsed: {elapsed:.4f} seconds")
        return False  # Don't suppress exceptions

# Usage:
with Timer() as t:
    total = sum(range(1_000_000))
    print(f"Sum: {total}")

Output:

Sum: 499999500000
⏱ Elapsed: 0.0342 seconds

Notice the three parameters in __exit__: exc_type, exc_val, and exc_tb. These contain the exception details if one was raised. Return True to suppress the exception, or False to let it propagate.

Example 2: A Database Connection Manager

Database connections are a classic use case — you always want to ensure they're closed:

import sqlite3

class Database:
    def __init__(self, db_path):
        self.db_path = db_path
        self.connection = None

    def __enter__(self):
        self.connection = sqlite3.connect(self.db_path)
        self.connection.row_factory = sqlite3.Row
        print(f"Connected to {self.db_path}")
        return self.connection

    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.connection:
            if exc_type is not None:
                self.connection.rollback()
                print("⚠️ Transaction rolled back")
            else:
                self.connection.commit()
                print("✅ Transaction committed")
            self.connection.close()
            print("Connection closed")
        return False

# Usage:
with Database(":memory:") as db:
    db.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)")
    db.execute("INSERT INTO users VALUES (1, 'Alice')")
    db.execute("INSERT INTO users VALUES (2, 'Bob')")
    rows = db.execute("SELECT * FROM users").fetchall()
    for row in rows:
        print(f"  User: {row['name']}")

The magic here: if an error occurs inside the with block, the transaction is rolled back. If everything succeeds, it's committed. No manual try/finally needed.

Using contextlib for Simplicity

Writing __enter__ and __exit__ every time is tedious. Python's built-in contextlib module provides easier alternatives.

Method 1: @contextmanager Decorator

Use a generator function with a single yield:

from contextlib import contextmanager

@contextmanager
def temporary_file(name):
    import os
    path = f"/tmp/{name}"
    with open(path, "w") as f:
        f.write("temporary data")
    try:
        yield path  # Code between 'with' and 'exit' runs here
    finally:
        if os.path.exists(path):
            os.remove(path)
            print(f"Cleaned up {path}")

# Usage:
with temporary_file("example.txt") as filepath:
    with open(filepath) as f:
        print(f"Contents: {f.read()}")
# File is automatically deleted after the block

Everything before the yield is the setup (__enter__). Everything after is the cleanup (__exit__).

Method 2: ExitStack for Dynamic Resources

Sometimes you need to manage a variable number of resources:

from contextlib import ExitStack

def open_multiple_files(*filenames):
    """Open any number of files safely."""
    stack = ExitStack()
    files = []
    for name in filenames:
        f = stack.enter_context(open(name))
        files.append(f)
    return stack, files

# Open 3 files at once — all closed automatically:
filenames = ["a.txt", "b.txt", "c.txt"]
stack, files = open_multiple_files(*filenames)
with stack:
    for i, f in enumerate(files):
        print(f"File {i}: {len(f.read())} bytes")

Chaining and Nesting Context Managers

You can chain multiple context managers on a single line with commas:

# Chain with commas:
with open("input.txt") as src, open("output.txt", "w") as dst:
    dst.write(src.read().upper())

# Or nest them (more readable for complex cases):
with open("input.txt") as src:
    with open("output.txt", "w") as dst:
        dst.write(src.read().upper())

Suppressing Specific Exceptions

Sometimes you want to silently handle certain errors. The contextlib.suppress function makes this clean:

from contextlib import suppress
import os

# Don't raise FileExistsError if directory exists
with suppress(FileExistsError):
    os.mkdir("my_project")

# Don't raise KeyError if setting is missing
with suppress(KeyError):
    value = config["nonexistent_key"]
    print(value)

Built-in Context Managers You Already Know

Python includes many built-in context managers beyond file operations:

# Threading lock — prevents concurrent access
import threading
lock = threading.Lock()
with lock:
    # Only one thread can be here at a time
    shared_counter += 1

# Decimal precision context
from decimal import Decimal, localcontext
with localcontext():
    localcontext().prec = 4
    print(Decimal(1) / Decimal(3))  # 0.3333

# Suppressing warnings temporarily
import warnings
with warnings.catch_warnings():
    warnings.simplefilter("ignore")
    old_function()  # Warnings silenced here

Project: A Complete Retry Context Manager

Let's combine everything into a production-ready retry mechanism:

from contextlib import contextmanager
import time
import logging

logger = logging.getLogger(__name__)

class RetryState:
    """Holds retry attempts and results for a context."""
    def __init__(self, max_retries=3, delay=1.0, exceptions=(Exception,)):
        self.max_retries = max_retries
        self.delay = delay
        self.exceptions = exceptions
        self.attempt = 0
        self.result = None
        self._raised = None

    def execute(self, func, *args, **kwargs):
        """Run a function with retry logic."""
        for attempt in range(1, self.max_retries + 1):
            try:
                logger.info(f"Attempt {attempt}/{self.max_retries}")
                self.result = func(*args, **kwargs)
                logger.info("Success!")
                return self.result
            except self.exceptions as e:
                self.attempt = attempt
                self._raised = e
                if attempt < self.max_retries:
                    wait = self.delay * (2 ** (attempt - 1))  # Exponential backoff
                    logger.warning(f"Failed: {e}. Retrying in {wait}s...")
                    time.sleep(wait)
                else:
                    logger.error(f"All {self.max_retries} attempts failed")
                    raise

# Simulate a flaky API call
def unstable_api_call():
    import random
    if random.random() < 0.7:
        raise ConnectionError("API timeout")
    return {"status": "ok", "data": [1, 2, 3]}

# Use it!
state = RetryState(max_retries=3, delay=0.5, exceptions=(ConnectionError,))
try:
    result = state.execute(unstable_api_call)
    print(f"Got result: {result}")
except ConnectionError:
    print(f"Failed after {state.attempt} attempts")

Best Practices Summary

  1. Always use with for resources — files, connections, locks, temp directories
  2. Use @contextmanager for simple cases — less boilerplate than class-based
  3. Use class-based for complex state — when you need to track data across the context
  4. Don't suppress exceptions unless intentional — return False from __exit__
  5. Use ExitStack for dynamic resource counts — when you don't know how many upfront
  6. Use suppress() for known, expected exceptions — like FileNotFoundError

Common Pitfalls

Pitfall 1: Forgetting to return self in __enter__

# ❌ This makes 'as f' be None
class BadManager:
    def __enter__(self):
        self.file = open("data.txt")
        # Forgot: return self

# ✅ Always return what the 'as' clause should bind to
class GoodManager:
    def __enter__(self):
        self.file = open("data.txt")
        return self  # or return self.file

Pitfall 2: Using yield in @contextmanager inside a loop

# ❌ Only the FIRST yield is used!
@contextmanager
def broken():
    for i in range(3):
        yield i

# ✅ Use ExitStack instead for multiple yields

Context managers are one of those Python features that make code both simpler and more robust. Once you start seeing resource management as a pattern rather than a special case for files, you'll use them everywhere.
