Cloudflare Workers: Serverless Code at the Edge

June 22, 2026 · 10 min read

Cloudflare Workers let you run JavaScript, TypeScript, or Python code on Cloudflare's global network — without managing servers. Your code runs in 300+ data centers worldwide, executing closer to your users for blazing-fast response times. No EC2 instances, no Kubernetes clusters, no DevOps overhead.

In this guide, we'll go from your first "Hello World" Worker to building real APIs, proxies, and edge applications — all deployable with a single command.

What Is Cloudflare Workers?

Cloudflare Workers is a serverless computing platform that runs code on Cloudflare's edge network. When a request hits your domain, Cloudflare can execute your code before forwarding it to your origin server — or return a response entirely from the edge.

Traditional serverless:
  User → Cloudflare → AWS Lambda (US-East) → Response
  (Latency: 200ms+ for EU/Asia users)

Cloudflare Workers:
  User → Cloudflare Worker (nearest data center) → Response
  (Latency: 10-30ms, anywhere in the world)

Key benefits:

  • 🌍 Global execution — code runs in the data center closest to each user
  • ⚡ Fast startup — no cold starts; Workers execute in under 1ms
  • 💰 Generous free tier — 100,000 requests/day on the free plan
  • 🔧 Easy deployment — one command via the Wrangler CLI
  • 🔒 Built-in security — DDoS protection, WAF, and bot management included

What Can Workers Do?

Workers are incredibly versatile. Here are common use cases:

  • 🔀 API Gateway — route, validate, and transform requests
  • 🔄 Reverse Proxy — add authentication, caching, or headers before reaching your origin
  • 📄 Static Sites — serve HTML/CSS/JS directly from the edge
  • 🔐 Auth & Rate Limiting — check API keys, enforce rate limits
  • 📝 A/B Testing — route users to different versions of your app
  • 🛡️ Bots & Scrapers — detect and block malicious traffic
  • 💾 Edge Storage — store data in Workers KV for fast key-value access

Setup: Install Wrangler

Wrangler is Cloudflare's CLI tool for managing Workers. Install it with npm:

# Install Wrangler
npm install -g wrangler

# Log in to your Cloudflare account
wrangler login

# This opens a browser — authorize Wrangler to access your account

Your First Worker

Let's create a Worker that responds with a JSON message:

# Create a new Worker project
wrangler init my-first-worker
cd my-first-worker

# Edit src/index.js
# (or create it manually if using the minimal template)

Here's your first Worker:

// src/index.js
export default {
    async fetch(request, env, ctx) {
        // Get the URL and path
        const url = new URL(request.url);
        const path = url.pathname;

        // Route based on the path
        if (path === "/" || path === "/api/hello") {
            return Response.json({
                message: "Hello from Cloudflare Workers! 🚀",
                timestamp: new Date().toISOString(),
                path: path
            });
        }

        // 404 for unknown routes
        return new Response("Not Found", { status: 404 });
    }
};

Routing with Multiple Endpoints

Build a proper API with multiple routes:

// src/index.js
export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        const path = url.pathname;
        const method = request.method;

        // Health check endpoint
        if (path === "/health" && method === "GET") {
            return Response.json({ status: "ok", uptime: Date.now() });
        }

        // Get a user by ID
        if (path.startsWith("/api/users/") && method === "GET") {
            const userId = path.split("/").pop();
            const user = await getUserById(env.USERS_KV, userId);
            
            if (!user) {
                return Response.json(
                    { error: "User not found" },
                    { status: 404 }
                );
            }
            
            return Response.json(user);
        }

        // Create a new user
        if (path === "/api/users" && method === "POST") {
            const body = await request.json();
            
            // Validate input
            if (!body.name || !body.email) {
                return Response.json(
                    { error: "name and email are required" },
                    { status: 400 }
                );
            }
            
            const user = {
                id: crypto.randomUUID(),
                name: body.name,
                email: body.email,
                created: new Date().toISOString()
            };
            
            // Store in Workers KV
            await env.USERS_KV.put(user.id, JSON.stringify(user));
            
            return Response.json(user, { status: 201 });
        }

        // List all users
        if (path === "/api/users" && method === "GET") {
            const { keys } = await env.USERS_KV.list();
            const users = await Promise.all(
                keys.map(key => 
                    env.USERS_KV.get(key.name, "json")
                )
            );
            return Response.json({ users: users.filter(Boolean) });
        }

        // Method not allowed
        if (path.startsWith("/api/users") && !["GET", "POST"].includes(method)) {
            return Response.json(
                { error: "Method not allowed" },
                { status: 405 }
            );
        }

        return Response.json(
            { error: "Not found" },
            { status: 404 }
        );
    }
};

// Helper function
async function getUserById(kv, id) {
    return await kv.get(id, "json");
}

Using Workers KV for Data Storage

Workers KV is a globally distributed key-value store. Perfect for configuration, caching, and simple data storage.

Configure KV in wrangler.toml

# wrangler.toml
name = "my-api-worker"
main = "src/index.js"
compatibility_date = "2026-06-22"

# Define a KV namespace
[[kv_namespaces]]
binding = "USERS_KV"
id = "your-namespace-id-here"
preview_id = "your-preview-namespace-id-here"

Create the namespace:

# Create a new KV namespace
wrangler kv:namespace create "USERS_KV"

# Output:
# {"id": "a1b2c3d4e5f6...", "preview_id": "f6e5d4c3b2a1..."}

# Update wrangler.toml with these IDs

KV Operations Cheat Sheet

// Store a value
await env.MY_KV.put("key", "value");

// Store JSON
await env.MY_KV.put("user:123", JSON.stringify({ name: "Hugo" }));

// Get a value as text (default)
const value = await env.MY_KV.get("key");

// Get a value as JSON
const user = await env.MY_KV.get("user:123", "json");

// Get with a default if key doesn't exist
const config = await env.MY_KV.get("app_config", "json") 
    || { debug: false, version: "1.0" };

// List keys with prefix
const { keys } = await env.MY_KV.list({ prefix: "user:" });

// Delete a key
await env.MY_KV.delete("key");

// Batch writes (write multiple keys at once)
const batch = [
    { type: "put", key: "config:debug", value: "true" },
    { type: "put", key: "config:version", value: "2.0" },
    { type: "delete", key: "old:key" }
];
await env.MY_KV.batch(batch);

Building a Reverse Proxy

One of the most common uses of Workers is adding functionality in front of an existing server:

// src/index.js — Reverse proxy with auth & caching
export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        // Strip the /api prefix before forwarding
        if (url.pathname.startsWith("/api/")) {
            // Check API key
            const apiKey = request.headers.get("X-API-Key");
            if (apiKey !== env.API_KEY) {
                return Response.json(
                    { error: "Unauthorized" },
                    { status: 401 }
                );
            }

            // Build the origin URL
            const origin = new URL(url.pathname + url.search, "https://your-origin-server.com");
            
            // Clone and modify the request for the origin
            const newRequest = new Request(origin, {
                method: request.method,
                headers: request.headers,
                body: request.method !== "GET" ? await request.text() : undefined
            });

            // Forward to origin and return the response
            const response = await fetch(newRequest);
            
            // Add custom headers to the response
            const modifiedResponse = new Response(response.body, response);
            modifiedResponse.headers.set("X-Powered-By", "Cloudflare Workers");
            modifiedResponse.headers.set("X-Response-Time", `${Date.now()}ms`);
            
            return modifiedResponse;
        }

        // Let all other requests pass through to origin
        return fetch(request);
    }
};

Caching Responses at the Edge

Workers can cache responses to avoid hitting your origin for repeated requests:

// src/index.js — Worker with built-in caching
export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        // Only cache GET requests
        if (request.method !== "GET") {
            return fetch(request);
        }

        // Check the cache first
        const cached = await caches.default.match(request);
        if (cached) {
            // Add a header to indicate it was cached
            const response = new Response(cached.body, cached);
            response.headers.set("X-Cache", "HIT");
            return response;
        }

        // Fetch from origin
        const response = await fetch(request);
        
        // Only cache successful responses
        if (response.status === 200) {
            // Clone the response (can only read body once)
            const responseToCache = response.clone();
            
            // Store in cache (waitUntil doesn't block the response)
            ctx.waitUntil(
                caches.default.put(request, responseToCache)
            );
            
            // Add cache header for debugging
            response.headers.set("X-Cache", "MISS");
        }

        return response;
    }
};

Rate Limiting

Protect your API from abuse with simple rate limiting using Workers KV:

// src/index.js — Rate limiter middleware
export default {
    async fetch(request, env, ctx) {
        const url = new URL(request.url);
        
        // Get client identifier (IP or API key)
        const clientIp = request.headers.get("CF-Connecting-IP");
        const rateKey = `rate:${clientIp}:${new Date().toISOString().slice(0, 60)}`;
        
        // Get current request count
        const count = parseInt(await env.RATE_LIMIT_KV.get(rateKey) || "0");
        
        // Block if over limit (10 requests per minute)
        if (count >= 10) {
            return Response.json(
                { error: "Rate limit exceeded. Try again in 60 seconds." },
                { status: 429, headers: { "Retry-After": "60" } }
            );
        }
        
        // Increment counter
        await env.RATE_LIMIT_KV.put(rateKey, String(count + 1), {
            expirationTtl: 60  // Key expires after 60 seconds
        });
        
        // Add rate limit headers
        const response = await handleRequest(request, env, ctx);
        response.headers.set("X-RateLimit-Limit", "10");
        response.headers.set("X-RateLimit-Remaining", String(10 - count - 1));
        
        return response;
    }
};

async function handleRequest(request, env, ctx) {
    // Your actual request handling logic here
    return Response.json({ message: "OK" });
}

Deploying to Your Own Domain

Instead of using the .workers.dev subdomain, route through your own domain:

# Add a route in wrangler.toml
# wrangler.toml
name = "my-api-worker"
main = "src/index.js"
compatibility_date = "2026-06-22"

# Route all /api/* requests to this worker
routes = [
    "api.example.com/*",
    "example.com/api/*"
]

# Deploy
wrangler deploy

You'll need a DNS record pointing to Cloudflare (orange cloud/proxied) for your domain.

Combining Workers with Cloudflare Tunnel

Pair Workers with Cloudflare Tunnel for end-to-end edge computing:

# Architecture:
# User → Cloudflare Worker (auth, rate limit, transform) 
#       → Cloudflare Tunnel (encrypted) 
#       → Your Server (localhost:8080)

# 1. Deploy your Worker (handles edge logic)
wrangler deploy

# 2. Set up Cloudflare Tunnel (secure origin connection)
cloudflared tunnel create my-app
cloudflared tunnel route dns my-app api.example.com

# 3. Run the tunnel
cloudflared tunnel run my-app --url http://localhost:8080

# Now requests flow:
# Worker → Tunnel → Your Server
# (Everything encrypted, no public IPs exposed)

Common Errors

"TypeError: Failed to fetch"

When calling fetch() from a Worker, the target URL must use HTTPS or be on an allowed plain IP list. You cannot fetch plain HTTP URLs unless they're on the allowlist.

"Script exceeded timeout of X ms"

Free tier Workers have a 10ms CPU time limit. Optimize your code, use caching, or upgrade to a paid plan for more CPU time.

"KV namespace not found"

Make sure your namespace IDs in wrangler.toml match the IDs from wrangler kv:namespace create. Preview and production IDs are different.
