CSS Selectors, Specificity & the Cascade: How Browsers Decide Which Styles Win

July 5, 2026 · 9 min read

You've written your CSS, but the browser is applying the wrong color, the wrong size, the wrong padding. You add !important and it "works" — but now your stylesheet is a mess of hacks. The root cause? Not understanding CSS selectors, specificity, and the cascade.

This guide explains exactly how browsers decide which style rule wins when multiple rules target the same element. Once you understand this system, you'll never need !important again.

What Are CSS Selectors?

CSS selectors are patterns that tell the browser which elements to apply styles to. They're the "who" in your CSS rules — the "what" (properties and values) comes after the curly braces.

Every CSS rule has the form:

selector {
    property: value;
}

There are several types of selectors, each with different power and specificity:

Type Selectors (Element Selectors)

The simplest selector — match elements by their HTML tag name:

/* Targets all <p> elements on the page */
p {
    color: #333;
    font-size: 16px;
}

/* Targets all <h1> elements */
h1 {
    font-size: 32px;
    margin-bottom: 16px;
}

Type selectors have the lowest specificity. They're great for setting baseline styles across your entire page.

Class Selectors

The most commonly used selector — match elements by their class attribute:

/* Targets elements with class="btn" */
.btn {
    padding: 8px 16px;
    border-radius: 4px;
    cursor: pointer;
}

/* You can reuse classes on any element */
.btn-primary {
    background-color: #4f46e5;
    color: white;
}

/* Multiple classes on one element */
.btn.btn-primary {
    font-weight: bold;
}

HTML usage:

<button class="btn btn-primary">Sign Up</button>
<a class="btn btn-primary" href="/login">Log In</a>

ID Selectors

Match elements by their id attribute. IDs should be unique per page:

/* Targets the element with id="main-nav" */
#main-nav {
    display: flex;
    justify-content: space-between;
    padding: 16px 24px;
}

HTML usage:

<nav id="main-nav">
    <h1>My Site</h1>
    <ul>...</ul>
</nav>

Attribute Selectors

Match elements based on their attributes — useful for forms and inputs:

/* Any input with a type attribute */
input[type="text"] {
    padding: 8px 12px;
    border: 1px solid #ccc;
}

/* Elements with a data attribute */
[data-theme="dark"] {
    background-color: #1a1a2e;
    color: #eee;
}

/* Attribute starts with "icon-" */
[class^="icon-"] {
    display: inline-block;
    width: 16px;
    height: 16px;
}

Combinators: Selecting by Relationship

So far we've matched single elements. Combinators let you select elements based on their position in the HTML tree.

Descendant Combinator (Space)

Select any element nested inside another, at any depth:

/* Any <a> inside a <nav>, no matter how deep */
nav a {
    text-decoration: none;
    color: #666;
}

/* <li> → <div> → <a> also matches! */
/* <nav> → <ul> → <li> → <a> also matches! */

Child Combinator (>)

Select only direct children — one level deep:

/* Only <li> that are direct children of <ul> */
ul > li {
    list-style: none;
    padding: 4px 0;
}

/* This would NOT match: <ul> → <div> → <li> */

Adjacent Sibling (+) and General Sibling (~)

/* The <p> immediately after <h2> */
h2 + p {
    font-size: 1.2em;
    color: #555;
}

/* ALL <p> siblings that come after <h2> */
h2 ~ p {
    margin-left: 16px;
}

CSS Specificity: The Scoring System

When two rules target the same element, the browser uses specificity to decide which one wins. Specificity is calculated as a three-part score: (a, b, c)

  • a = number of ID selectors
  • b = number of class selectors, attribute selectors, and pseudo-classes
  • c = number of type selectors and pseudo-elements

The higher score wins. Compare left to right — (0, 1, 0) beats (0, 0, 999) because the b column is higher.

Specificity Examples

/* Specificity calculations */
p                         → (0, 0, 1)   /* type selector */
.btn                     → (0, 1, 0)   /* class selector */
#header                  → (1, 0, 0)   /* ID selector */
nav > ul.menu > li a     → (0, 1, 3)   /* 1 class + 3 types */
.nav-link:hover          → (0, 2, 0)   /* 1 class + 1 pseudo-class */
div.container > p        → (0, 1, 2)   /* 1 class + 2 types */
input[type="email"]      → (0, 1, 1)   /* 1 attribute + 1 type */

Worked Example: The Battle

<div id="sidebar" class="widget">
    <p>This is sidebar text</p>
</div>

Three rules target the <p>:

/* Rule 1: specificity (0, 0, 1) */
p { color: red; }

/* Rule 2: specificity (0, 1, 1) */
.widget p { color: blue; }

/* Rule 3: specificity (1, 0, 1) */
#sidebar p { color: green; }

Winner: Rule 3 — the text is green. Even though Rule 2's class score (1) is higher than Rule 3's class score (0), Rule 3 wins because the ID column (1) is higher than all others (0). Compare column by column, left to right.

The Cascade: What Happens When Specificity Is Equal?

When two rules have the same specificity, the browser uses the cascade order:

  1. Origin — browser defaults < user styles < author styles
  2. Importance — normal < !important
  3. Specificity — higher wins
  4. Source order — later rules win (last rule in the file)

Source Order: Last One Wins

/* These have the SAME specificity (0, 1, 0) */

/* Rule A — appears first */
.card {
    background-color: white;
}

/* Rule B — appears LATER, so it wins */
.card {
    background-color: #f5f5f5;
}

The card's background is #f5f5f5 because Rule B comes after Rule A, and both have equal specificity. This is why organizing your CSS file matters — put base styles first, component styles later, and overrides at the end.

Inheritance: Which Properties Travel Down the Tree?

Not all CSS properties are inherited. Understanding what gets inherited saves you from writing redundant rules.

Inherited Properties (travel to children)

/* Font styles inherit automatically */
body {
    font-family: 'Inter', sans-serif;
    font-size: 16px;
    color: #333;
    line-height: 1.6;
}

/* No need to set these on every child element */
/* <p>, <span>, <li>, <a> all get these styles automatically */

Other inherited properties: letter-spacing, text-align, visibility, cursor.

Non-Inherited Properties (set per element)

/* These do NOT inherit — each element sets its own */
div {
    margin: 16px;
    padding: 24px;
    border: 1px solid #ddd;
    background-color: #fff;
    width: 100%;
    display: block;
}

Non-inherited properties: margin, padding, border, background, width/height, display, position, overflow.

Forcing Inheritance with the inherit Keyword

/* Make anchor tags inherit the body text color */
/* (browsers default <a> to blue by default) */
a {
    color: inherit;
}

Real-World Example: Building a Card Component

Let's put it all together. Here's a clean card component using proper selector strategy:

<div class="card">
    <img class="card__image" src="photo.jpg" alt="Demo">
    <div class="card__body">
        <h3 class="card__title">Card Title</h3>
        <p class="card__text">Card description text...</p>
        <a class="card__link" href="#">Read more →</a>
    </div>
</div>
/* Base card container */
.card {
    max-width: 360px;
    border: 1px solid #e5e7eb;
    border-radius: 8px;
    overflow: hidden;
    /* specificity: (0, 1, 0) */
}

/* Image area */
.card__image {
    width: 100%;
    height: 200px;
    object-fit: cover;
    /* specificity: (0, 1, 0) */
}

/* Content area */
.card__body {
    padding: 20px;
    /* specificity: (0, 1, 0) */
}

/* Title — inherits font-family from body */
.card__title {
    font-size: 18px;
    font-weight: 600;
    margin: 0 0 8px;
    /* specificity: (0, 1, 0) */
}

/* Text */
.card__text {
    font-size: 14px;
    color: #6b7280;
    line-height: 1.5;
    margin: 0 0 16px;
    /* specificity: (0, 1, 0) */
}

/* Link — inherits font-family, overrides color */
.card__link {
    color: #4f46e5;
    text-decoration: none;
    font-weight: 500;
    /* specificity: (0, 1, 0) */
}

/* Hover state — higher specificity than .card__link */
.card__link:hover {
    text-decoration: underline;
    /* specificity: (0, 2, 0) — class + pseudo-class */
}

Best Practices: Avoiding Specificity Nightmares

  1. Prefer class selectors over ID selectors for styling. IDs have high specificity and can't be reused.
  2. Avoid deep nesting like div > ul > li > a. Use a single class like .nav-link instead.
  3. Never use !important as a solution. If you need it, your selector strategy is wrong.
  4. Use BEM or utility naming to keep specificity flat and predictable.
  5. Keep specificity low and equal — make most selectors (0, 1, 0) so source order is the only tiebreaker.
  6. Use CSS custom properties (variables) for theming instead of overriding with more specific selectors.

Quick Reference: Specificity Cheat Sheet

Selector                    Specificity
────────────────────────────────────────
*                           (0, 0, 0)
p                           (0, 0, 1)
p:first-child               (0, 1, 1)
.class                      (0, 1, 0)
.class1.class2              (0, 2, 0)
#id                         (1, 0, 0)
!important                  ∞ (infinity)
inline style                (1, 0, 0)

Practice Exercise

Try this: What color is the text in this HTML?

<div id="main" class="content">
    <p class="highlight">What color am I?</p>
</div>

/* 1 */ .content p         { color: red; }     /* (0, 1, 1) */
/* 2 */ p.highlight        { color: blue; }    /* (0, 1, 1) */
/* 3 */ #main .highlight   { color: green; }   /* (1, 1, 0) */
/* 4 */ div p              { color: orange; }  /* (0, 0, 2) */

Answer: green. Rule 3 has specificity (1, 1, 0) which beats everything because of the ID selector. Between rules 1 and 2 (both (0, 1, 1)), rule 2 wins by source order — but rule 3 wins over both.

Summary

CSS specificity and the cascade are not optional knowledge — they're the foundation of every stylesheet you'll write. Remember the key principles:

  • Specificity is scored as (IDs, classes, types)
  • When specificity ties, the last rule wins
  • Font and color properties inherit, layout properties do not
  • Flat, class-based selectors are easier to maintain
  • !important should be a last resort, never a first choice

Master these concepts, and your CSS will be predictable, maintainable, and free of hacks.
