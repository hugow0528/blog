CSS Container Queries: Responsive Components That Adapt to Their Parent

July 8, 2026 9 min read

For years, CSS media queries have been the only way to make layouts responsive. But media queries listen to the viewport (the browser window), not the component's actual container. This leads to a common problem: a card looks great in a wide grid on desktop, but when that same card is placed in a narrow sidebar, it still renders as if it's in a wide layout. CSS container queries solve this by letting you query the size of a parent element instead of the viewport.

The Problem with Media Queries

Consider a product card component:

/* Media queries respond to the VIEWPORT, not the card's container */
@media (min-width: 768px) {
    .product-card {
        display: flex;
        flex-direction: row;
    }
}

@media (max-width: 767px) {
    .product-card {
        display: flex;
        flex-direction: column;
    }
}

Now imagine placing this card in a narrow sidebar on a desktop. The viewport is 1400px wide, so the card tries to lay out horizontally — but the sidebar is only 250px. The layout breaks. You'd need another media query specifically for the sidebar, which couples your component to where it's placed. Container queries fix this.

Declaring a Container

First, declare which element is a query container:

/* Method 1: Named container */
.card-wrapper {
    container-type: inline-size;
    container-name: card;
}

/* Method 2: Shorthand (named) */
.sidebar {
    container: sidebar / inline-size;
}

/* Method 3: Unnamed container (queries any ancestor) */
.grid-item {
    container-type: inline-size;
}

The container-type property tells the browser to track this element's size. The two main values are:

  • inline-size — Query based on width (most common)
  • size — Query both width and height (use cautiously — creates a new block formatting context)

Writing Container Queries

Once a container is declared, write queries with @container:

/* Query the "card" named container */
@container card (min-width: 400px) {
    .product-card {
        display: flex;
        flex-direction: row;
        gap: 1rem;
    }
    
    .product-card .image {
        width: 180px;
        flex-shrink: 0;
    }
    
    .product-card .details {
        flex: 1;
    }
}

/* Default (narrow) layout — no container needed */
.product-card {
    display: flex;
    flex-direction: column;
    gap: 0.75rem;
}

.product-card .image {
    width: 100%;
}

The key insight: .product-card now adapts based on .card-wrapper's width, regardless of the viewport size. Put it in a wide grid, it goes horizontal. Put it in a narrow sidebar, it goes vertical.

Container Query Examples

1. Responsive Navigation Component

A navigation bar that shows a hamburger menu in narrow containers:

/* Container declaration */
.nav-container {
    container-type: inline-size;
}

/* Narrow: hamburger menu */
.nav-list {
    display: none;
}

.nav-toggle {
    display: block;
}

/* Wide: show full menu */
@container (min-width: 600px) {
    .nav-list {
        display: flex;
        gap: 1rem;
    }
    
    .nav-toggle {
        display: none;
    }
}

This navigation component works in a header, a sidebar, or an embedded iframe — it adapts to wherever it lives.

2. Card Grid with Auto-Responsive Cards

Cards that switch from list to grid view based on available space:

/* The container — could be any element */
.content-area {
    container-type: inline-size;
}

/* Compact card for narrow spaces */
.blog-card {
    display: flex;
    flex-direction: column;
    padding: 1rem;
}

.blog-card .card-image {
    width: 100%;
    aspect-ratio: 16 / 9;
}

.blog-card .card-title {
    font-size: 1rem;
}

/* Expanded card in wider spaces */
@container (min-width: 500px) {
    .blog-card {
        flex-direction: row;
        padding: 1.25rem;
    }
    
    .blog-card .card-image {
        width: 200px;
        aspect-ratio: 1 / 1;
        flex-shrink: 0;
    }
    
    .blog-card .card-title {
        font-size: 1.25rem;
    }
    
    .blog-card .card-excerpt {
        display: -webkit-box;
        -webkit-line-clamp: 3;
        -webkit-box-orient: vertical;
        overflow: hidden;
    }
}

3. Conditional Layout with Container Styles

Container queries can also respond to styles, not just size:

.theme-container {
    container-type: inline-size;
    container-name: theme;
}

/* Dark mode variant within container */
@container theme (min-width: 300px) {
    .card {
        background: #1a1a2e;
        color: #eee;
    }
    
    .card:hover {
        background: #16213e;
    }
}

4. Multiple Breakpoints in One Query Block

Combine conditions with and, or, and not:

/* Between 400px and 700px */
@container (min-width: 400px) and (max-width: 700px) {
    .card {
        flex-direction: row;
    }
}

/* OR conditions */
@container (width < 300px) or (width > 800px) {
    .widget {
        grid-template-columns: 1fr;
    }
}

/* NOT condition */
@container not (min-width: 600px) {
    .sidebar-nav {
        display: none;
    }
}

/* Named container + condition */
@container sidebar (min-width: 280px) {
    .sidebar-content {
        padding: 2rem;
    }
}

Container Query Units

Use container-relative units to scale elements proportionally:

.responsive-container {
    container-type: inline-size;
}

/* cqi = container query inline (width) */
.responsive-title {
    font-size: clamp(1rem, 4cqi, 2.5rem);
}

/* cqh = container query block (height) */
.responsive-image {
    height: 50cqh;
}

/* cqb = container query block (for block-sized containers) */
.responsive-padding {
    padding: 2cqi;
}

Container query units let you create truly fluid components that scale with their parent — no JavaScript needed.

Container Queries vs Media Queries: When to Use Each

Use Media Queries When... Use Container Queries When...
Adjusting global layout (header, footer) Making a component responsive to its slot
Targeting device capabilities (orientation, hover) A component that lives in multiple places
Changing font sizes site-wide Card, widget, or module layouts
Dark/light mode (prefers-color-scheme) Nested responsive design
Mobile-first page structure Component libraries and design systems

Browser Support

Container queries are supported in all modern browsers:

  • Chrome/Edge — 105+
  • Firefox — 110+
  • Safari — 16+

For older browsers, the @container rules are simply ignored — the default (narrow) layout still works. This makes container queries inherently progressive-enhancement-friendly.

Debugging Container Queries

Use Chrome DevTools to inspect container sizes:

/* Make containers visible during development */
@media (forced-colors: active) {
    [container-type],
    [container] {
        outline: 2px dashed lime;
    }
}

/* Or add a custom property to mark containers */
.debug-containers {
    container-type: inline-size;
}

.debug-containers::before {
    content: "container: " var(--container-width, "checking...");
    position: absolute;
    top: -20px;
    left: 0;
    font-size: 10px;
    color: #666;
}

💡 Pro Tip: Use @container in CSS-in-JS and CSS Modules

Container queries work everywhere CSS works — including CSS modules, Tailwind CSS (with the @container directive), and CSS-in-JS libraries like Styled Components. No framework-specific syntax needed.

Real-World Pattern: Component Library with Container Queries

Build a reusable alert component that adapts to any context:

/* Container declaration — add to any parent */
.alert-wrapper {
    container-type: inline-size;
}

/* Base: compact stacked layout */
.alert {
    display: flex;
    flex-direction: column;
    gap: 0.5rem;
    padding: 1rem;
    border-radius: 8px;
    border-left: 4px solid #3b82f6;
    background: #eff6ff;
}

.alert-icon {
    width: 24px;
    height: 24px;
}

.alert-title {
    font-weight: 600;
    font-size: 0.9rem;
}

.alert-message {
    font-size: 0.85rem;
    color: #4b5563;
}

.alert-actions {
    display: flex;
    flex-direction: column;
    gap: 0.5rem;
}

.alert-actions button {
    width: 100%;
    padding: 0.5rem;
}

/* Medium: icon + text in a row */
@container (min-width: 350px) {
    .alert {
        flex-direction: row;
        gap: 0.75rem;
        align-items: flex-start;
    }
    
    .alert-icon {
        flex-shrink: 0;
        margin-top: 2px;
    }
    
    .alert-body {
        flex: 1;
        display: flex;
        flex-direction: column;
        gap: 0.25rem;
    }
}

/* Wide: actions inline */
@container (min-width: 500px) {
    .alert-actions {
        flex-direction: row;
        margin-left: auto;
    }
    
    .alert-actions button {
        width: auto;
        padding: 0.5rem 1rem;
    }
}

Summary

CSS container queries are the missing piece for component-level responsive design. Key takeaways:

  • Declare containers with container-type: inline-size or the container shorthand
  • Query containers with @container — just like media queries but scoped
  • Name containers to avoid accidentally querying the wrong ancestor
  • Combine with media queries — they work together, not instead of each other
  • Use container units (cqi, cqh) for proportional scaling
  • Progressive enhancement — fallbacks work naturally when browsers don't support @container

Container queries don't replace media queries — they complement them. Use media queries for page-level layout decisions and container queries for component-level adaptability. Together, they give you full control over responsive design at every level.
