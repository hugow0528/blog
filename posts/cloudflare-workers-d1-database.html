Cloudflare Workers + D1 Database: Build Serverless Apps with SQL

July 7, 2026 · 11 min read

Cloudflare Workers lets you run code at the edge without managing servers. D1 is Cloudflare's native SQL database built on SQLite. Together, they form a powerful serverless stack: write a Worker, bind a D1 database, and you have a complete web application running on 300+ data centers worldwide.

Best part? The free tier includes 100,000 daily requests, 5 million D1 reads, and 100,000 D1 writes per day. That's enough for real production workloads.

Why Workers + D1?

Traditional serverless platforms (AWS Lambda, Vercel, Supabase) work well, but Workers + D1 offers unique advantages:

  • Speed: Your code runs at the edge, close to users worldwide. No cold starts.
  • Cost: Generous free tier. Only pay when you exceed limits.
  • SQL: D1 is SQLite — familiar syntax, JOINs, indexes, transactions.
  • Ecosystem: Integrate with Cloudflare KV, Queues, R2, AI, and more from the same platform.
  • Security: No public server IPs. Everything runs behind Cloudflare's network.

Setup: Install Wrangler

Wrangler is Cloudflare's CLI tool for managing Workers, D1, and other services:

# Install Wrangler (requires Node.js 18+)
npm install -g wrangler

# Login to your Cloudflare account
wrangler login

Step 1: Create a Worker Project

# Initialize a new project
npm create cloudflare@latest my-app
# Choose: Worker
# Choose: TypeScript (recommended) or JavaScript

cd my-app

This creates a project with a wrangler.toml config file and a src/index.ts entry point.

Step 2: Create a D1 Database

# Create a D1 database
wrangler d1 create my-db

# You'll get output like:
# ⌛ Creating worker 'my-db'...
# Success! Your DB name is 'my-db'
# Your D1 database ID is: abc123-def456

# Add it to your wrangler.toml

Update wrangler.toml to bind the database:

[d1_databases]
bindings = [
  { binding = "DB", database_name = "my-db", database_id = "abc123-def456" }
]

Step 3: Define Your Schema with Migrations

D1 uses migration files to define your database schema. Create a migrations directory:

mkdir migrations

Create your first migration file (migrations/001_create_users.sql):

-- migrations/001_create_users.sql

CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    published INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX idx_posts_user_id ON posts(user_id);
CREATE INDEX idx_posts_published ON posts(published);

Apply the migration to your local database:

# Run migration locally (uses SQLite)
wrangler d1 execute my-db --local --file=migrations/001_create_users.sql

# Run migration on Cloudflare (production)
wrangler d1 execute my-db --remote --file=migrations/001_create_users.sql

Step 4: Build CRUD Endpoints

Here's a complete Worker with full CRUD operations:

// src/index.ts
export interface Env {
  DB: D1Database;
}

export default {
  async fetch(request: Request, env: Env) {
    const url = new URL(request.url);
    const path = url.pathname;
    const method = request.method;

    // ---- USERS ----

    // GET /api/users — List all users
    if (path === "/api/users" && method === "GET") {
      const result = await env.DB.prepare("SELECT * FROM users ORDER BY created_at DESC").all();
      return Response.json(result.results);
    }

    // POST /api/users — Create a user
    if (path === "/api/users" && method === "POST") {
      const body = await request.json();
      const { name, email } = body;

      if (!name || !email) {
        return Response.json({ error: "name and email are required" }, { status: 400 });
      }

      const result = await env.DB.prepare(
        "INSERT INTO users (name, email) VALUES (?, ?)"
      ).bind(name, email).run();

      return Response.json({ id: result.meta.last_row_id, name, email }, { status: 201 });
    }

    // GET /api/users/:id — Get a single user
    const userMatch = path.match(/^\/api\/users\/(\d+)$/);
    if (userMatch && method === "GET") {
      const userId = userMatch[1];
      const result = await env.DB.prepare(
        "SELECT * FROM users WHERE id = ?"
      ).bind(userId).first();

      if (!result) {
        return Response.json({ error: "User not found" }, { status: 404 });
      }

      return Response.json(result);
    }

    // ---- POSTS ----

    // GET /api/posts?published=1 — List posts (with optional filter)
    if (path === "/api/posts" && method === "GET") {
      const published = url.searchParams.get("published");

      let query = "SELECT posts.*, users.name as author FROM posts JOIN users ON posts.user_id = users.id";
      const bindings: (string | number)[] = [];

      if (published !== null) {
        query += " WHERE posts.published = ?";
        bindings.push(parseInt(published));
      }

      query += " ORDER BY posts.created_at DESC";

      const stmt = env.DB.prepare(query);
      bindings.forEach((b) => stmt.bind(b));
      const result = await stmt.all();

      return Response.json(result.results);
    }

    // POST /api/posts — Create a post
    if (path === "/api/posts" && method === "POST") {
      const body = await request.json();
      const { user_id, title, body: postBody } = body;

      if (!user_id || !title || !postBody) {
        return Response.json({ error: "user_id, title, and body are required" }, { status: 400 });
      }

      // Verify user exists
      const user = await env.DB.prepare(
        "SELECT id FROM users WHERE id = ?"
      ).bind(user_id).first();

      if (!user) {
        return Response.json({ error: "User not found" }, { status: 404 });
      }

      const result = await env.DB.prepare(
        "INSERT INTO posts (user_id, title, body) VALUES (?, ?, ?)"
      ).bind(user_id, title, postBody).run();

      return Response.json({ id: result.meta.last_row_id, user_id, title }, { status: 201 });
    }

    // PATCH /api/posts/:id/publish — Publish a post
    const publishMatch = path.match(/^\/api\/posts\/(\d+)\/publish$/);
    if (publishMatch && method === "PATCH") {
      const postId = publishMatch[1];

      const result = await env.DB.prepare(
        "UPDATE posts SET published = 1 WHERE id = ?"
      ).bind(postId).run();

      if (result.meta.changes === 0) {
        return Response.json({ error: "Post not found" }, { status: 404 });
      }

      return Response.json({ published: true });
    }

    // 404 for everything else
    return Response.json({ error: "Not found" }, { status: 404 });
  }
};

Understanding D1 Query Methods

D1 provides three query methods depending on your needs:

Method Returns Use Case
.all() Array of all rows SELECT queries returning multiple rows
.first() Single row object SELECT queries expecting one result
.run() Metadata (changes, last_row_id) INSERT, UPDATE, DELETE (no data returned)

Example of each:

// .all() — Get all results
const allPosts = await env.DB.prepare("SELECT * FROM posts").all();
// { results: [{id: 1, title: "..."}, ...], success: true }

// .first() — Get first result only (more efficient)
const post = await env.DB.prepare(
  "SELECT * FROM posts WHERE id = ?"
).bind(1).first();
// { id: 1, title: "Hello", body: "...", ... }

// .run() — Execute without returning rows
const result = await env.DB.prepare(
  "DELETE FROM posts WHERE id = ?"
).bind(1).run();
// { changes: 1, last_row_id: 0, success: true }

Parameterized Queries: Never Concatenate SQL

Always use parameterized queries with .bind() to prevent SQL injection:

// ✅ SAFE — parameterized query
await env.DB.prepare(
  "SELECT * FROM users WHERE email = ?"
).bind(userInput).all();

// ❌ DANGEROUS — SQL injection vulnerability
await env.DB.prepare(
  `SELECT * FROM users WHERE email = '${userInput}'`
).all();

You can bind multiple values:

await env.DB.prepare(
  "SELECT * FROM posts WHERE user_id = ? AND published = ?"
).bind(userId, 1).all();

Batch Queries with Transactions

For multiple operations that should succeed or fail together, use D1's batch API:

// Execute multiple queries atomically
const result = await env.DB.batch([
  env.DB.prepare("INSERT INTO users (name, email) VALUES (?, ?)").bind("Hugo", "hugo@example.com"),
  env.DB.prepare("INSERT INTO posts (user_id, title, body) VALUES ((SELECT id FROM users WHERE email = ?), ?, ?)")
    .bind("hugo@example.com", "First Post", "Hello world!"),
  env.DB.prepare("UPDATE users SET name = ? WHERE email = ?").bind("Hugo W.", "hugo@example.com"),
]);

All queries either succeed together or none execute. This is essential for operations like creating a user and their default settings, or transferring money between accounts.

Performance Tips

  • Use indexes wisely: Add indexes on columns you filter or sort by. Too many indexes slow down writes. The rule of thumb: index columns used in WHERE and JOIN clauses.
  • SELECT only what you need: SELECT id, name FROM users is faster than SELECT * FROM users.
  • Use LIMIT: Always add LIMIT to queries that might return large result sets.
  • Cache at the edge: Use Cloudflare's edge cache or Workers KV for frequently read data. Query D1 only when you need fresh data.
  • Batch operations: Instead of N separate queries, use D1's batch API for atomic multi-query operations.
  • Handle D1 latency: D1 replication can take up to 60 seconds. Avoid write-then-read patterns; use idempotent operations when possible.

Real-World Example: URL Shortener

Here's a complete URL shortener in under 80 lines:

// migrations/001_create_urls.sql
CREATE TABLE IF NOT EXISTS urls (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    short_code TEXT NOT NULL UNIQUE,
    original_url TEXT NOT NULL,
    clicks INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

// src/index.ts
export interface Env { DB: D1Database; }

function generateCode(length = 6) {
  const chars = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789";
  let result = "";
  for (let i = 0; i < length; i++) {
    result += chars.charAt(Math.floor(Math.random() * chars.length));
  }
  return result;
}

export default {
  async fetch(request: Request, env: Env) {
    const url = new URL(request.url);

    // Shorten URL: POST /api/shorten?url=https://example.com
    if (url.pathname === "/api/shorten" && request.method === "POST") {
      const body = await request.json();
      const { url: originalUrl } = body;

      if (!originalUrl) {
        return Response.json({ error: "url parameter required" }, { status: 400 });
      }

      const code = generateCode();
      await env.DB.prepare(
        "INSERT INTO urls (short_code, original_url) VALUES (?, ?)"
      ).bind(code, originalUrl).run();

      return Response.json({ short_url: `${url.origin}/${code}` });
    }

    // Redirect: GET /:code
    const match = url.pathname.match(/^\/([a-zA-Z0-9]{6})$/);
    if (match) {
      const code = match[1];

      // Get URL and increment clicks in a batch
      const result = await env.DB.batch([
        env.DB.prepare("SELECT original_url FROM urls WHERE short_code = ?").bind(code),
        env.DB.prepare("UPDATE urls SET clicks = clicks + 1 WHERE short_code = ?").bind(code),
      ]);

      const row = result[0].results?.[0];
      if (!row) {
        return Response.json({ error: "Short URL not found" }, { status: 404 });
      }

      return Response.redirect(row.original_url, 302);
    }

    // Stats: GET /api/stats/:code
    const statsMatch = url.pathname.match(/^\/api\/stats\/([a-zA-Z0-9]{6})$/);
    if (statsMatch) {
      const code = statsMatch[1];
      const row = await env.DB.prepare(
        "SELECT clicks, created_at FROM urls WHERE short_code = ?"
      ).bind(code).first();

      if (!row) {
        return Response.json({ error: "Not found" }, { status: 404 });
      }

      return Response.json(row);
    }

    return new Response("Welcome to the URL Shortener! POST to /api/shorten", {
      headers: { "Content-Type": "text/plain" },
    });
  }
};

Monitoring and Limits

Track your D1 usage in the Cloudflare dashboard:

  • Database size: Free tier allows 5 GB. You'll get notified at 80%.
  • Reads/Writes: Monitor via the API — wrangler d1 info my-db
  • Execution time: D1 queries are limited to 15 seconds. Optimize slow queries with indexes and EXPLAIN.
# Check database info
wrangler d1 info my-db

# Sample a query to check performance
wrangler d1 execute my-db --local --execute="EXPLAIN QUERY PLAN SELECT * FROM posts WHERE user_id = 1"

Common Gotchas

  • D1 is eventually consistent: After writing, reads may return stale data for up to 60 seconds. Design your app around this.
  • No joins across databases: Each D1 database is isolated. Plan your schema carefully.
  • SQLite syntax: D1 uses SQLite, not PostgreSQL or MySQL. Some syntax differs (e.g., AUTOINCREMENT behavior, INTEGER PRIMARY KEY auto-increments).
  • Migration files must be sequential: Name them 001_..., 002_... etc. Running them out of order will fail.
  • Local vs Remote: Always test migrations locally first with --local, then push to production with --remote.

Cloudflare Workers + D1 gives you a complete serverless application platform. Write code, define your schema with migrations, and deploy globally in seconds. The free tier is generous enough for production workloads, and the edge network ensures your app is fast everywhere.
