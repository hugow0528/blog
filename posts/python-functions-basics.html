Python Functions: def, Parameters, Return Values & *args/**kwargs — Complete Beginner's Guide

July 17, 2026 12 min read

Functions are the building blocks of every Python program. They let you package code into reusable, named blocks that you can call anytime. If you've been writing Python by repeating the same code, functions will change everything. Let's build a complete mental model from zero to production-ready.

Why Functions Matter

Without functions, your code looks like a wall of logic. You repeat yourself, you make mistakes when copying, and nobody can read your code. Functions solve all three problems.

# ❌ Without functions — repeating yourself
# Calculate tax for order 1
total1 = 99.99
tax1 = total1 * 0.08
final1 = total1 + tax1
print(f"Order 1: ${final1:.2f}")

# Calculate tax for order 2
total2 = 249.50
tax2 = total2 * 0.08
final2 = total2 + tax2
print(f"Order 2: ${final2:.2f}")

# Calculate tax for order 3... (you see the pattern)
# ✅ With functions — write once, use everywhere
def calculate_price(subtotal, tax_rate=0.08):
    tax = subtotal * tax_rate
    return subtotal + tax

print(f"Order 1: ${calculate_price(99.99):.2f}")
print(f"Order 2: ${calculate_price(249.50):.2f}")
print(f"Order 3: ${calculate_price(50.00, 0.10):.2f}")  # Different tax rate

The function captures the logic once. You just change the inputs. This is called D.R.Y. — Don't Repeat Yourself.

Defining Your First Function

Use the def keyword, followed by the function name, parentheses for parameters, and a colon. Everything indented underneath is the function body.

def greet(name):
    """Say hello to someone."""
    message = f"Hello, {name}!"
    return message

# Call the function
result = greet("Hugo")
print(result)  # Output: Hello, Hugo!

Three key parts:

  • Name (greet) — describes what the function does
  • Parameters (name) — inputs the function needs
  • Return value (return message) — what the function gives back

Parameters: Positional vs Keyword Arguments

Python gives you two ways to pass arguments into functions. Understanding both is essential.

def create_user(username, email, age):
    return {"username": username, "email": email, "age": age}

# Positional arguments — order matters
user1 = create_user("alice", "alice@example.com", 28)
# user1 = {'username': 'alice', 'email': 'alice@example.com', 'age': 28}

# Keyword arguments — order doesn't matter, self-documenting
user2 = create_user(
    age=32,
    email="bob@example.com",
    username="bob"
)
# user2 = {'username': 'bob', 'email': 'bob@example.com', 'age': 32}

Rule of thumb: Use positional arguments for simple, obvious cases. Use keyword arguments when the function has 3+ parameters or when the meaning isn't immediately clear from the value.

Default Parameter Values

Set defaults so callers don't have to specify everything:

def connect_to_database(host="localhost", port=5432, timeout=30):
    """Connect to a PostgreSQL database with sensible defaults."""
    return f"Connecting to {host}:{port} (timeout={timeout}s)"

# Use all defaults
conn1 = connect_to_database()
# Output: Connecting to localhost:5432 (timeout=30s)

# Override just what you need
conn2 = connect_to_database(host="db.prod.example.com", timeout=60)
# Output: Connecting to db.prod.example.com:5432 (timeout=60s)

Important: Parameters with defaults must come after parameters without defaults.

# ✅ Correct — required params first
def process_file(filepath, mode="r", encoding="utf-8"):
    ...

# ❌ SyntaxError — required param after default
def process_file(filepath="data.txt", mode):
    ...

The Dangerous Default Mutable Argument

This is the #1 Python interview question and the #1 source of subtle bugs:

# ❌ DON'T DO THIS
def append_to_list(item, my_list=[]):
    my_list.append(item)
    return my_list

print(append_to_list(1))  # [1]
print(append_to_list(2))  # [1, 2] ← Oops! It remembered the previous call
print(append_to_list(3))  # [1, 2, 3] ← Still the same list!

Why? Because [] is evaluated once when the function is defined, not each time it's called. The same list object is reused.

# ✅ DO THIS instead
def append_to_list(item, my_list=None):
    if my_list is None:
        my_list = []
    my_list.append(item)
    return my_list

print(append_to_list(1))  # [1]
print(append_to_list(2))  # [2] ← Fresh list each time
print(append_to_list(3))  # [3] ← Perfect

Use None as the default, then create the mutable object inside the function. This pattern applies to lists, dicts, and sets.

*args: Arbitrary Positional Arguments

Use *args when you don't know how many positional arguments will be passed:

def add_all(*args):
    """Add any number of numbers together."""
    total = 0
    for num in args:
        total += num
    return total

print(add_all(1, 2, 3))        # 6
print(add_all(10, 20))         # 30
print(add_all(1, 2, 3, 4, 5))  # 15

Inside the function, args is a tuple of all passed values. The asterisk is just a convention — you could write *numbers if that's clearer.

**kwargs: Arbitrary Keyword Arguments

Use **kwargs when you want to accept arbitrary named parameters:

def build_url(base, **params):
    """Build a URL with query parameters."""
    query = "&".join(f"{k}={v}" for k, v in params.items())
    return f"{base}?{query}" if params else base

url1 = build_url("https://api.example.com/data")
# https://api.example.com/data

url2 = build_url("https://api.example.com/data",
                 page=1,
                 limit=20,
                 sort="date")
# https://api.example.com/data?page=1&limit=20&sort=date

Inside the function, params is a dictionary of all keyword arguments.

Combining Everything

Python lets you mix all parameter types. The order is strict: required → defaults → *args → **kwargs.

def send_notification(user_id, message, priority="normal", *channels, **metadata):
    """
    Send a notification through multiple channels.
    
    Args:
        user_id: The recipient's ID (required)
        message: What to send (required)
        priority: "normal", "high", or "urgent" (default: "normal")
        *channels: Any number of delivery channels
        **metadata: Extra tracking data
    """
    print(f"[{priority.upper()}] To user {user_id}")
    print(f"Message: {message}")
    print(f"Channels: {channels}")
    print(f"Metadata: {metadata}")

send_notification(
    42,
    "Your order shipped!",
    "high",
    "email", "sms", "push",
    order_id="ORD-12345",
    campaign="summer_sale"
)

# Output:
# [HIGH] To user 42
# Message: Your order shipped!
# Channels: ('email', 'sms', 'push')
# Metadata: {'order_id': 'ORD-12345', 'campaign': 'summer_sale'}

Lambda Functions: One-Liner Functions

Use lambda for quick, anonymous functions — especially when passing a function as an argument:

# Regular function
def square(x):
    return x ** 2

# Equivalent lambda
square = lambda x: x ** 2

# Where lambdas shine — sorting with a key
users = [
    {"name": "Alice", "age": 28},
    {"name": "Bob", "age": 22},
    {"name": "Charlie", "age": 35},
]

# Sort by age
users_by_age = sorted(users, key=lambda u: u["age"])

# Sort by name length
users_by_name_len = sorted(users, key=lambda u: len(u["name"]))

# Map — transform every element
prices = [10.99, 24.50, 5.99]
with_tax = list(map(lambda p: round(p * 1.08, 2), prices))
# [11.87, 26.46, 6.47]

When NOT to use lambda: If the function needs more than one expression, needs a name for debugging, or has complex logic — use def. Lambda is for simple, throwaway functions.

Docstrings: Document Your Functions

A docstring is a string literal as the first line in your function. It's read by help(), IDEs, and tools like Sphinx:

def calculate_shipping(weight, distance, express=False):
    """
    Calculate shipping cost based on weight and distance.
    
    Args:
        weight: Package weight in kilograms (float)
        distance: Delivery distance in kilometers (float)
        express: Use express delivery for 2x cost (bool, default: False)
    
    Returns:
        float: Total shipping cost in dollars
    
    Examples:
        >>> calculate_shipping(2.5, 100)
        12.5
        >>> calculate_shipping(2.5, 100, express=True)
        25.0
    """
    base_cost = weight * 2 + distance * 0.02
    if express:
        base_cost *= 2
    return round(base_cost, 2)

# Access the docstring
help(calculate_shipping)

Real-World Pattern: Function Composition

Build complex behavior by chaining small, single-purpose functions:

def fetch_users_from_api():
    """Simulate fetching users from an API."""
    return [
        {"id": 1, "name": " Alice ", "email": "alice@example.com", "active": True},
        {"id": 2, "name": "bob", "email": "  BOB@EXAMPLE.COM  ", "active": False},
        {"id": 3, "name": "  charlie  ", "email": "charlie@example.com", "active": True},
    ]

def clean_name(name):
    """Strip whitespace and capitalize a name."""
    return name.strip().title()

def normalize_email(email):
    """Strip whitespace and lowercase an email."""
    return email.strip().lower()

def is_active(user):
    """Check if a user is active."""
    return user.get("active", False)

def format_user(user):
    """Format a single user record."""
    return {
        "id": user["id"],
        "name": clean_name(user["name"]),
        "email": normalize_email(user["email"]),
        "active": user["active"],
    }

# Pipeline: fetch → clean → filter → format
raw = fetch_users_from_api()
cleaned = [format_user(u) for u in raw]
active = [u for u in cleaned if is_active(u)]

for user in active:
    print(f"{user['name']} <{user['email']}>")
# Alice <alice@example.com>
# Charlie <charlie@example.com>

Each function does one thing well. Together, they form a data processing pipeline. This pattern scales: replace the fetch function with a real API call, swap the filter for different criteria, add new formatting — everything stays testable.

Summary

Here's your function checklist:

  • Use def name(params): to define functions
  • Prefer keyword arguments for 3+ parameters
  • Set defaults for optional parameters (but never use mutable defaults!)
  • Use *args for variable positional arguments, **kwargs for variable keyword arguments
  • Use lambda for one-line functions passed as arguments
  • Always write docstrings for functions that others will use
  • Build pipelines by composing small functions

Functions are the foundation. Master them, and every other Python concept — classes, decorators, generators, async — builds on top of what you know now.
