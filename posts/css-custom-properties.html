CSS Custom Properties (Variables): Build Themes and Design Systems

June 27, 2026 · 10 min read

Before CSS Custom Properties, sharing a color across your stylesheet meant repeating #2563eb in dozens of places. Change it once and you'd have to update every single occurrence. CSS variables solved this problem and unlocked powerful new patterns like dark mode, theming, and design systems.

CSS Custom Properties (commonly called "CSS variables") are user-defined values that you can set once and reuse throughout your stylesheet. They cascade like any other CSS property, which makes them incredibly flexible.

Key idea: CSS variables are values stored in a named container. Unlike preprocessor variables (Sass/Less), CSS variables live in the browser — they can be changed dynamically with JavaScript, respond to media queries, and even be inherited differently per element.

Syntax: Declaration and Usage

CSS variables use a -- prefix to declare and var() to reference:

/* Declare a variable */
:root {
  --primary-color: #2563eb;
  --text-color: #1e293b;
  --border-radius: 12px;
  --spacing-unit: 8px;
}

/* Use the variable */
.header {
  background-color: var(--primary-color);
  color: var(--text-color);
  border-radius: var(--border-radius);
  padding: calc(var(--spacing-unit) * 3);
}

Notice :root — this targets the <html> element, making the variable globally available. You can also declare variables on any selector for more local scope.

Fallback Values

Always provide a fallback in case a variable is undefined:

.card {
  /* Uses --card-bg if defined, otherwise falls back to white */
  background: var(--card-bg, white);

  /* Fallback works with calc too */
  margin: var(--card-margin, calc(var(--spacing-unit) * 2));
}

Why CSS Variables Beat Preprocessor Variables

Sass and Less variables compile away before reaching the browser. CSS variables are different:

  • Cascade — CSS variables follow the normal cascade. You can override them per component.
  • JavaScript access — Read and write variables at runtime.
  • Responsive — Change variables inside media queries without duplicating entire rule sets.
  • No build step — Works in plain CSS, no compilation needed.
/* This Sass pattern... */
$primary: blue;
.button { background: $primary; }

/* Becomes this CSS pattern with more power */
:root { --primary: blue; }
.button { background: var(--primary); }

/* Override just for dark mode */
.dark .button { --primary: #60a5fa; }

Building a Dark Mode with CSS Variables

This is the most popular use case. Define light and dark palettes as variable sets:

/* Light theme (default) */
:root {
  --bg-primary: #f8fafc;
  --bg-surface: #ffffff;
  --text-primary: #1e293b;
  --text-secondary: #64748b;
  --border-color: #e2e8f0;
  --accent: #2563eb;
  --shadow: 0 4px 6px -1px rgb(0 0 0 / 0.1);
}

/* Dark theme */
[data-theme="dark"] {
  --bg-primary: #0f172a;
  --bg-surface: #1e293b;
  --text-primary: #f1f5f9;
  --text-secondary: #94a3b8;
  --border-color: #334155;
  --accent: #60a5fa;
  --shadow: 0 4px 6px -1px rgb(0 0 0 / 0.3);
}

/* Use variables everywhere */
body {
  background: var(--bg-primary);
  color: var(--text-primary);
}

.card {
  background: var(--bg-surface);
  border: 1px solid var(--border-color);
  box-shadow: var(--shadow);
  color: var(--text-secondary);
}

Toggle dark mode with one line of JavaScript:

// Toggle dark mode
document.documentElement.setAttribute(
  'data-theme',
  document.documentElement.getAttribute('data-theme') === 'dark' ? 'light' : 'dark'
);

// Persist preference
localStorage.setItem('theme',
  document.documentElement.getAttribute('data-theme')
);

// Load saved preference on page load
const saved = localStorage.getItem('theme');
if (saved) {
  document.documentElement.setAttribute('data-theme', saved);
}

You can also respect the user's system preference automatically:

/* Apply dark theme if user prefers dark mode */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    --bg-primary: #0f172a;
    --bg-surface: #1e293b;
    --text-primary: #f1f5f9;
    --text-secondary: #94a3b8;
    --border-color: #334155;
    --accent: #60a5fa;
  }
}

CSS Variables with calc() for Spacing Systems

Create a consistent spacing system using a base unit:

:root {
  --space-unit: 0.25rem; /* 4px base unit */
}

/* Usage — every spacing value is a multiple of 4px */
.padding-sm { padding: calc(var(--space-unit) * 2); }  /* 8px */
.padding-md { padding: calc(var(--space-unit) * 4); }  /* 16px */
.padding-lg { padding: calc(var(--space-unit) * 8); }  /* 32px */
.padding-xl { padding: calc(var(--space-unit) * 12); } /* 48px */

.margin-top-sm { margin-top: calc(var(--space-unit) * 2); }
.margin-top-md { margin-top: calc(var(--space-unit) * 4); }

/* Font sizes */
.text-sm { font-size: calc(var(--space-unit) * 3); }  /* 12px */
.text-base { font-size: calc(var(--space-unit) * 4); } /* 16px */
.text-lg { font-size: calc(var(--space-unit) * 5); }   /* 20px */
.text-xl { font-size: calc(var(--space-unit) * 6); }   /* 24px */

Component-Level Variable Overrides

Since CSS variables cascade, you can define defaults globally and override them per component:

/* Global defaults */
:root {
  --btn-bg: #2563eb;
  --btn-text: #ffffff;
  --btn-radius: 25px;
  --btn-padding: 0.5rem 1rem;
}

.button {
  background: var(--btn-bg);
  color: var(--btn-text);
  border-radius: var(--btn-radius);
  padding: var(--btn-padding);
  border: none;
  cursor: pointer;
}

/* Override for danger button */
.button--danger {
  --btn-bg: #ef4444;
}

/* Override for outline button */
.button--outline {
  --btn-bg: transparent;
  --btn-text: var(--btn-bg, #2563eb);
  border: 2px solid var(--btn-text);
}

Browser Support and Gotchas

CSS Custom Properties are supported in all modern browsers (Chrome 49+, Firefox 31+, Safari 9.1+, Edge 79+). They work great, but watch out for these common mistakes:

  • Whitespaces matter — --color: red (trailing space) becomes red as the value, which can break functions like rgb().
  • Invalid values cascade — If a variable has an invalid value for a property, the property falls back to its inherited value (not the variable's fallback).
  • No type checking — CSS doesn't warn if you use a color variable in a size property. Be careful with var(--spacing) used as background-color.
  • Custom properties on :root vs body — Use :root for global variables. body has a slightly higher specificity and can cause confusing overrides.
/* Common gotcha: invalid value breaks calc() */
:root {
  --size: 16px;
}

.bad { width: calc(var(--size) / 2); }     /* Works: 8px */
/* Don't do this: */
:root { --size: 16px ; }  /* trailing space = "16px " */
.worse { width: calc(var(--size) / 2); }   /* Fails! */

CSS Variables + Container Queries

The newest superpower: combine CSS variables with container queries for component-level responsiveness:

.card-container {
  container-type: inline-size;
  container-name: card;
}

.card {
  --font-size: 1rem;
  --padding: 1rem;
}

@container card (min-width: 400px) {
  .card {
    --font-size: 1.25rem;
    --padding: 1.5rem;
  }
}

@container card (min-width: 600px) {
  .card {
    --font-size: 1.5rem;
    --padding: 2rem;
  }
}

Summary

CSS Custom Properties are the foundation of modern CSS architecture. They enable:

  • ✅ Easy dark mode and theming
  • ✅ Consistent design systems with shared tokens
  • ✅ Component-level customization without class explosion
  • ✅ Dynamic style changes with JavaScript
  • ✅ Responsive values that adapt without duplicating rules
