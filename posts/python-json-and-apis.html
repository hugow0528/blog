Python JSON and APIs: Working with External Data — Complete Beginner's Guide

July 12, 2026 · 10 min read

Almost every Python application needs to talk to external services — fetch data from a weather API, send notifications to Slack, read configuration from a JSON file, or parse a response from a database. The universal language for this kind of communication is JSON (JavaScript Object Notation).

This guide covers everything from parsing JSON strings to building a complete API client with error handling, retry logic, and response caching. By the end, you'll be comfortable working with any REST API from Python.

What Is JSON?

JSON is a lightweight data format that represents data as key-value pairs and arrays. It maps naturally to Python data types:

JSON TypePython Equivalent
object {}dict
array []list
stringstr
number (int)int
number (float)float
true / falseTrue / False
nullNone

Python's built-in json module handles all conversions automatically.

Parsing JSON Strings

The most common operation is converting a JSON string into a Python dictionary:

import json

# A JSON string (notice double quotes)
json_string = '{"name": "Alice", "age": 30, "skills": ["Python", "Docker"]}'

# Parse JSON string into Python dict
data = json.loads(json_string)

print(data["name"])       # "Alice"
print(data["age"])        # 30
print(data["skills"][0])  # "Python"
print(type(data))         # <class 'dict'>

The json.loads() function reads a string and returns a Python object. Conversely, json.dumps() does the opposite — converts Python objects to JSON strings:

# Python dict → JSON string
person = {"name": "Bob", "age": 25, "active": True}
json_output = json.dumps(person)
print(json_output)
# {"name": "Bob", "age": 25, "active": true}

# Pretty-print JSON with indentation
json_pretty = json.dumps(person, indent=2)
print(json_pretty)
# {
#   "name": "Bob",
#   "age": 25,
#   "active": true
# }

Reading and Writing JSON Files

JSON data often lives in files. Python makes reading and writing JSON files straightforward:

import json

# Writing a dict to a JSON file
config = {
    "app_name": "MyApp",
    "version": "1.0",
    "database": {
        "host": "localhost",
        "port": 5432,
        "name": "mydb"
    },
    "features": ["auth", "logging", "cache"]
}

# Method 1: Read/write with open() + json
with open("config.json", "w") as f:
    json.dump(config, f, indent=2)

# Method 2: Read back
with open("config.json", "r") as f:
    loaded = json.load(f)

print(loaded["database"]["host"])  # "localhost"
print(loaded["features"])          # ["auth", "logging", "cache"]

Key tip: Always use with open() (context manager) to ensure the file is properly closed, even if an error occurs.

Handling JSON Files with Non-Standard Keys

Some APIs use camelCase or kebab-case for field names. Here's how to normalize them:

import re

def camel_to_snake(name):
    """Convert CamelCase to snake_case"""
    s1 = re.sub('(.)([A-Z][a-z]+)', r'\1_\2', name)
    return re.sub('([a-z0-9])([A-Z])', r'\1_\2', s1).lower()

# Example
api_response = {"userId": 42, "firstName": "Alice", "createdAt": "2026-01-01"}
normalized = {camel_to_snake(k): v for k, v in api_response.items()}
print(normalized)
# {"user_id": 42, "first_name": "Alice", "created_at": "2026-01-01"}

Making HTTP Requests with requests

The requests library is the standard way to make HTTP requests in Python. Install it first:

pip install requests

GET Requests — Fetching Data

import requests

# Fetch data from a public API
response = requests.get("https://jsonplaceholder.typicode.com/posts/1")

# Check status code
print(response.status_code)  # 200 (success)

# Parse JSON response (built-in!)
data = response.json()

print(data["title"])    # "sunt aut facere repellat..."
print(data["userId"])   # 1
print(data["body"])     # "qui est esse..."

The response.json() method automatically parses the JSON body — no need to call json.loads() manually.

GET Requests with Query Parameters

import requests

# Pass query parameters as a dict (automatically URL-encoded)
params = {
    "q": "python",
    "per_page": 5,
    "page": 1
}

response = requests.get("https://api.github.com/search/repositories", params=params)

repos = response.json()
for repo in repos["items"]:
    print(f"{repo['full_name']}: {repo['stargazers_count']} stars")

POST Requests — Sending Data

import requests
import json

# Send JSON data to an API
url = "https://jsonplaceholder.typicode.com/posts"
payload = {
    "title": "My New Post",
    "body": "This is the content of my blog post.",
    "userId": 1
}

response = requests.post(url, json=payload)

print(response.status_code)  # 201 (created)
print(response.json())       # Your data back with an "id" added

Pass data with json=payload (not data=payload) — the library handles serialization and sets the Content-Type: application/json header automatically.

PUT and DELETE Requests

import requests

url = "https://jsonplaceholder.typicode.com/posts/1"

# PUT — Update an existing resource
response = requests.put(url, json={
    "id": 1,
    "title": "Updated Title",
    "body": "Updated content.",
    "userId": 1
})
print(response.status_code)  # 200

# DELETE — Remove a resource
response = requests.delete(url)
print(response.status_code)  # 200

Working with API Authentication

Most real APIs require authentication. Here are the common patterns:

import requests

# 1. API Key in header
response = requests.get(
    "https://api.example.com/data",
    headers={"Authorization": "Bearer YOUR_API_KEY"}
)

# 2. API Key in query parameter
response = requests.get(
    "https://api.example.com/data",
    params={"api_key": "YOUR_API_KEY"}
)

# 3. Basic auth (username/password)
response = requests.get(
    "https://api.example.com/data",
    auth=("username", "password")
)

# 4. Custom headers (e.g., for OpenWeatherMap)
response = requests.get(
    "https://api.openweathermap.org/data/2.5/weather",
    params={"q": "Tokyo", "appid": "YOUR_KEY", "units": "metric"}
)

Error Handling — The Professional Way

APIs fail. Networks are unreliable. Professional code handles errors gracefully:

import requests

def fetch_weather(city):
    """Fetch weather data with comprehensive error handling"""
    url = "https://api.openweathermap.org/data/2.5/weather"

    try:
        response = requests.get(url, params={
            "q": city,
            "appid": "YOUR_API_KEY",
            "units": "metric"
        }, timeout=10)  # Never wait forever!

        # Raise exception for 4xx/5xx status codes
        response.raise_for_status()

        data = response.json()

        return {
            "city": data["name"],
            "temperature": data["main"]["temp"],
            "description": data["weather"][0]["description"],
            "humidity": data["main"]["humidity"]
        }

    except requests.exceptions.Timeout:
        print("⏰ Request timed out. Server didn't respond in 10 seconds.")
        return None

    except requests.exceptions.ConnectionError:
        print("🔌 Connection error. Check your internet connection.")
        return None

    except requests.exceptions.HTTPError as e:
        if response.status_code == 401:
            print("🔑 Authentication failed. Check your API key.")
        elif response.status_code == 404:
            print(f"🏙️ City '{city}' not found.")
        elif response.status_code == 429:
            print("⚠️ Rate limited. Try again later.")
        else:
            print(f"❌ HTTP Error: {e}")
        return None

    except requests.exceptions.RequestException as e:
        print(f"💥 Unexpected error: {e}")
        return None

    except (KeyError, TypeError):
        print("📦 Response format changed. Check the API documentation.")
        return None

# Usage
result = fetch_weather("Tokyo")
if result:
    print(f"🌤️ {result['city']}: {result['temperature']}°C, {result['description']}")

This function handles six different failure scenarios: timeouts, connection errors, specific HTTP error codes, generic request exceptions, and malformed response data.

Building a Reusable API Client

When you work with the same API repeatedly, create a dedicated client class:

import requests
from functools import wraps

class GitHubClient:
    """Reusable client for the GitHub API"""

    BASE_URL = "https://api.github.com"

    def __init__(self, token=None):
        self.session = requests.Session()
        self.session.headers.update({
            "Accept": "application/vnd.github+json",
            "X-GitHub-Api-Version": "2022-11-28"
        })
        if token:
            self.session.headers["Authorization"] = f"token {token}"

    def get(self, path, params=None):
        """GET request with automatic error handling"""
        url = f"{self.BASE_URL}{path}"
        response = self.session.get(url, params=params, timeout=10)
        response.raise_for_status()
        return response.json()

    def get_user(self, username):
        """Get user profile"""
        return self.get(f"/users/{username}")

    def get_repos(self, username, sort="updated"):
        """Get user's public repositories"""
        return self.get(f"/users/{username}/repos", params={"sort": sort})

    def get_repo(self, owner, repo):
        """Get specific repository details"""
        return self.get(f"/repos/{owner}/{repo}")

# Usage
gh = GitHubClient()

# Fetch user profile
user = gh.get_user("python")
print(f"{user['login']}: {user['public_repos']} public repos")

# Fetch repositories
repos = gh.get_repos("python")
for repo in repos[:5]:
    print(f"  ⭐ {repo['name']}: {repo['description'][:50]}")

The requests.Session() reuses TCP connections across requests, which is faster and more efficient than creating a new connection for each call.

Complete Project: API Wrapper with Caching

Let's combine everything into a practical project — an API client with built-in caching to reduce unnecessary requests:

import requests
import json
import os
import time
from datetime import datetime

class CachedAPIClient:
    """API client with file-based caching"""

    def __init__(self, base_url, cache_dir=".api_cache", ttl=3600):
        self.base_url = base_url
        self.cache_dir = cache_dir
        self.ttl = ttl  # Time-to-live in seconds
        os.makedirs(cache_dir, exist_ok=True)
        self.session = requests.Session()

    def _cache_key(self, url, params):
        """Generate a unique cache key from URL and parameters"""
        import hashlib
        key = f"{url}_{json.dumps(params, sort_keys=True)}"
        return hashlib.md5(key.encode()).hexdigest()

    def get(self, path, params=None):
        """GET with automatic caching"""
        url = f"{self.base_url}{path}"
        cache_file = os.path.join(self.cache_dir, f"{self._cache_key(url, params)}.json")

        # Check if cache exists and is still valid
        if os.path.exists(cache_file):
            with open(cache_file, "r") as f:
                cached = json.load(f)
            age = time.time() - cached["_cached_at"]
            if age < self.ttl:
                print(f"  💾 Cache hit ({age:.0f}s old)")
                return cached["data"]
            else:
                print(f"  🕐 Cache expired ({age:.0f}s old)")

        # Fetch fresh data
        print(f"  🌐 Fetching from {url}")
        response = self.session.get(url, params=params, timeout=10)
        response.raise_for_status()
        data = response.json()

        # Save to cache
        cache_entry = {
            "data": data,
            "_cached_at": time.time(),
            "_cached_at_human": datetime.now().isoformat()
        }
        with open(cache_file, "w") as f:
            json.dump(cache_entry, f, indent=2)

        return data

    def clear_cache(self):
        """Remove all cached files"""
        for filename in os.listdir(self.cache_dir):
            os.remove(os.path.join(self.cache_dir, filename))
        print(f"  🗑️ Cleared {len(os.listdir(self.cache_dir))} cache files")

# Usage
api = CachedAPIClient(
    base_url="https://jsonplaceholder.typicode.com",
    ttl=300  # Cache for 5 minutes
)

# First call — fetches from API
posts = api.get("/posts", params={"_limit": 5})
print(f"Got {len(posts)} posts")

# Second call — served from cache
posts = api.get("/posts", params={"_limit": 5})
print(f"Got {len(posts)} posts (from cache)")

Best Practices Summary

  • Always set a timeout — never let a request hang indefinitely
  • Handle HTTP errors with response.raise_for_status() and specific exception types
  • Use requests.Session() for multiple requests to the same API (connection reuse)
  • Pass json=payload instead of data=payload for POST/PUT requests
  • Use query parameter dict instead of manual URL string building
  • Store API keys in environment variables, never hardcode them
  • Respect rate limits — implement retry logic with exponential backoff
  • Cache responses when the data doesn't change frequently
  • Validate response data before accessing nested keys (use .get() or try/except)
