Cloudflare DNS: Record Types, TTL, Propagation & Automation — Complete Beginner's Guide

July 17, 2026 11 min read

DNS (Domain Name System) is the phonebook of the internet. It translates human-readable domain names like example.com into machine-readable IP addresses like 93.184.216.34. Cloudflare manages DNS for over 40 million websites, and their free tier gives you enterprise-grade DNS that's blazing fast and highly available. Let's learn everything from the basics to automating DNS changes with Python.

How DNS Works: The Quick Tour

When you type hugow.dev into your browser, here's what happens:

  1. Your computer asks the recursive resolver (usually your ISP or Google's 8.8.8.8)
  2. The resolver checks its cache — if found, done. If not, it asks the root servers
  3. Root servers point to the TLD servers (the .com, .dev, .org servers)
  4. TLD servers point to your nameservers (Cloudflare in our case)
  5. Cloudflare returns the IP address from your DNS records
  6. Your browser connects to that IP

Cloudflare sits at step 5. You configure DNS records in their dashboard, and they answer queries from resolvers worldwide from their anycast network of 300+ data centers.

Essential DNS Record Types

Every domain uses a combination of these record types. Let's learn each one with real-world examples.

A Record — IPv4 Address

The most common record. Maps a name to an IPv4 address.

Name     Type   Value               Proxied
@        A      203.0.113.10        Orange cloud ☁️
www      A      203.0.113.10        Orange cloud ☁️
api      A      203.0.113.20        Grey cloud ⚪

The @ symbol means the root domain (hugow.dev). The www entry points www.hugow.dev to the same server. The orange cloud means traffic goes through Cloudflare's proxy (SSL, CDN, DDoS protection). Grey means DNS-only — the IP is exposed directly.

AAAA Record — IPv6 Address

Same as A record, but for IPv6:

Name   Type   Value
@      AAAA   2001:db8::1
www    AAAA   2001:db8::1

Always set both A and AAAA records. Modern browsers and phones prefer IPv6 when available, and it's faster.

CNAME Record — Alias / Canonical Name

Points one name to another name (not an IP). Use when your actual IP might change:

Name     Type    Value
blog     CNAME   hugo.pages.dev
docs     CNAME   hugo.gitbook.io
shop     CNAME   hugow.myshopify.com

When pages.dev changes their IP, you don't touch your DNS — Cloudflare follows the chain. The only restriction: you cannot CNAME the root @ record to another name (DNS standard limitation). Cloudflare solves this with CNAME Flattening — if your CNAME points to an A record, Cloudflare automatically resolves it.

MX Record — Mail Exchange

Tells the world where to deliver email for your domain:

Name    Type   Priority   Value
@       MX     10         mail.hugow.dev
@       MX     20         backup.mail.hugow.dev

Priority is lower = more preferred. Mail servers try priority 10 first, then 20 as backup. The mail.hugow.dev needs its own A record pointing to your mail server.

TXT Record — Text Metadata

Stores arbitrary text. Used for:

# SPF — who can send email as you
Name    Type   Value
@       TXT    "v=spf1 include:_spf.google.com ~all"

# Domain verification (Google, GitHub, etc.)
Name      Type   Value
@         TXT    "google-site-verification=abc123..."
_csha     TXT    "verify=github-xyz789"

# DKIM — email signing
Name        Type   Value
default._domainkey  TXT   "v=DKIM1; k=rsa; p=MIGfMA0GCS..."

SPF is critical — without it, your emails land in spam. The ~all means "soft fail" (flag suspicious emails but still deliver). Use -all for "hard fail" once you're confident.

SRV Record — Service Location

Points to a specific service on a specific port:

_sip._tcp    SRV    Priority=10 Weight=5 Port=5060 Target=sip.hugow.dev
_xmpp._tcp   SRV    Priority=20 Weight=5 Port=5222 Target=xmpp.hugow.dev

Most common for VoIP (SIP), gaming servers, or XMPP chat. Rare for typical web projects.

CAA Record — Certificate Authority Authorization

Restricts which CAs can issue SSL certificates for your domain:

@    CAA   0 issue "letsencrypt.org"
@    CAA   0 issuewild ";"

This blocks anyone except Let's Encrypt from issuing certs for your domain, preventing accidental or malicious certificate issuance.

TTL: Time-to-Live Explained

TTL controls how long resolvers cache your DNS record before rechecking:

TTL of 60s    = resolvers recheck every 1 minute
TTL of 300s   = 5 minutes (Cloudflare default)
TTL of 86400s = 24 hours

Low TTL strategy: Before migrating servers, lower TTL to 60 seconds 24 hours before the change. After the migration, raise it back to 300s. This ensures the switchover is felt by users within 1 minute instead of 24 hours.

DNS Propagation: Why Changes "Take Time"

Cloudflare DNS changes propagate globally in under 60 seconds — that's their infrastructure. But you might see different results for hours. Why? Because resolvers outside Cloudflare cache your old records according to the TTL.

Check propagation yourself:

# Check from Google's DNS (8.8.8.8)
dig @8.8.8.8 hugow.dev A

# Check from Cloudflare's DNS (1.1.1.1)
dig @1.1.1.1 hugow.dev A

# Check from your ISP
dig hugow.dev A

If all three show the new IP, propagation is complete. If yours differs, wait for the old TTL to expire or flush your DNS cache (sudo resolvectl flush-caches on Linux, ipconfig /flushdns on Windows).

Managing DNS with the Cloudflare API

The Cloudflare dashboard is great for manual changes, but what if you need to manage 50 records across 5 domains? Automation saves hours. Here's how to use Python with the Cloudflare API:

import requests
import json

# Get your API token from: https://dash.cloudflare.com/profile/api-tokens
# Create a token with: Zone.DNS (Edit), Zone.Read (Read), Account.Read (Read)
API_TOKEN = "your-api-token-here"
EMAIL = "you@example.com"

headers = {
    "Authorization": f"Bearer {API_TOKEN}",
    "Content-Type": "application/json"
}

# Step 1: List your zones (domains)
zones_resp = requests.get(
    "https://api.cloudflare.com/client/v4/zones",
    headers=headers,
    params={"per_page": 100}
)
zones = zones_resp.json()["result"]
print(f"Found {len(zones)} zones")

# Find the zone ID for your domain
zone_id = None
for zone in zones:
    if zone["name"] == "hugow.dev":
        zone_id = zone["id"]
        break

if not zone_id:
    print("❌ Zone not found!")
    exit(1)

print(f"✅ Zone ID: {zone_id}")

Now let's read all existing DNS records:

def get_all_records(zone_id):
    """Fetch all DNS records for a zone."""
    all_records = []
    page = 1
    while True:
        resp = requests.get(
            f"https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records",
            headers=headers,
            params={"page": page, "per_page": 100}
        )
        data = resp.json()
        all_records.extend(data["result"])
        if page >= data["result_info"]["total_pages"]:
            break
        page += 1
    return all_records

records = get_all_records(zone_id)
for r in records:
    print(f"  {r['type']:6s} {r['name']:25s} -> {r['content']}")
# A      hugow.dev                -> 203.0.113.10
# CNAME  www.hugow.dev            -> hugo.pages.dev
# TXT    hugow.dev                -> v=spf1 ...

Creating and Updating Records with Python

Let's build a practical script that can create, update, and delete DNS records:

def create_record(zone_id, record_type, name, content, ttl=300, proxied=True):
    """Create a new DNS record."""
    data = {
        "type": record_type,
        "name": name,
        "content": content,
        "ttl": ttl,
        "proxied": proxied
    }
    resp = requests.post(
        f"https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records",
        headers=headers,
        json=data
    )
    if resp.status_code == 200:
        result = resp.json()["result"]
        print(f"✅ Created: {record_type} {name} -> {content} (ID: {result['id']})")
        return result
    else:
        print(f"❌ Failed: {resp.json()['errors']}")
        return None

def update_record(zone_id, record_id, **kwargs):
    """Update an existing DNS record."""
    # First get current record
    resp = requests.get(
        f"https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records/{record_id}",
        headers=headers
    )
    current = resp.json()["result"]
    # Merge updates
    updated = {**current, **kwargs}
    resp = requests.put(
        f"https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records/{record_id}",
        headers=headers,
        json=updated
    )
    if resp.status_code == 200:
        print(f"✅ Updated record {record_id}")
        return resp.json()["result"]
    return None

def delete_record(zone_id, record_id):
    """Delete a DNS record."""
    resp = requests.delete(
        f"https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records/{record_id}",
        headers=headers
    )
    if resp.status_code == 200:
        print(f"✅ Deleted record {record_id}")
        return True
    return False

# Create a new A record
create_record(zone_id, "A", "staging.hugow.dev", "203.0.113.50", proxied=False)

# Create a TXT record for verification
create_record(zone_id, "TXT", "@", "google-site-verification=abc123xyz")

# Create a CNAME for a subdomain
create_record(zone_id, "CNAME", "app.hugow.dev", "hugo.vercel.app", proxied=True)

Real-World Script: DNS Health Checker

Here's a production-ready script that audits your DNS records and flags issues:

import requests
import subprocess
import sys

API_TOKEN = "your-token"
headers = {"Authorization": f"Bearer {API_TOKEN}"}

def check_dns_resolution(domain, record_type="A"):
    """Verify a domain resolves using dig."""
    result = subprocess.run(
        ["dig", "+short", domain, record_type],
        capture_output=True, text=True, timeout=10
    )
    return result.stdout.strip()

def audit_dns(zone_id):
    """Audit DNS records for common issues."""
    records = get_all_records(zone_id)
    issues = []

    # Check for records with no proxy (grey cloud)
    for r in records:
        if r["type"] == "A" and not r["proxied"]:
            issues.append(f"⚠️  Unproxied A record: {r['name']} -> {r['content']}")

    # Check SPF exists
    has_spf = any(
        r["type"] == "TXT" and "v=spf1" in r["content"]
        for r in records
    )
    if not has_spf:
        issues.append("⚠️  No SPF record found — emails may go to spam!")

    # Check root has both A and AAAA
    has_a = any(r["type"] == "A" for r in records)
    has_aaaa = any(r["type"] == "AAAA" for r in records)
    if has_a and not has_aaaa:
        issues.append("ℹ️  No AAAA record — consider adding IPv6")

    return issues

# Run audit
issues = audit_dns(zone_id)
if issues:
    print("DNS Audit Report:")
    for issue in issues:
        print(f"  {issue}")
else:
    print("✅ DNS looks healthy!")

Best Practices Checklist

  • Proxy everything you can — Orange cloud gives free DDoS protection, CDN, and SSL
  • Always add AAAA records — IPv6 is the future and often faster
  • Set SPF, DKIM, and DMARC — Without these, your email reputation suffers
  • Lower TTL before changes — Set to 60s at least 1 hour before migrating
  • Use API for bulk changes — Dashboard is fine for 1-2 records, API wins at scale
  • Enable DDoS protection — It's on by default with the orange cloud, verify in Security settings
  • Don't point @ to a CNAME — Use CNAME Flattening or A records for the root domain
  • Monitor with external tools — Use Pingdom DNS Check or dig from multiple locations
